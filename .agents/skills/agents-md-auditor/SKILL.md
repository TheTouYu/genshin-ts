# AGENTS.md 注入文件审计器

## 机制事实（审计的出发点）

- `AGENTS.md` 会被代理工具**按目录自动注入**：读写某目录下文件时，该目录及祖先目录的 AGENTS.md 进入上下文。`index.md`/`README.md` 没有此待遇，只能显式引用——导航/规则文档要被读到，命名必须是 `AGENTS.md`。
- 双刃剑：内容新 = 每次进入目录都带上正确地图（奇效）；内容旧 = 每次都注入错误指引（拖累，比没有更糟）。本技能就是把"拖累"找出来修掉。

## 流程

### Step 1 盘点与元数据

```bash
for f in $(git ls-files '*AGENTS.md' '*CLAUDE.md' | sort); do
  printf "%4s | %s | %s\n" "$(wc -l < "$f")" "$(git log -1 --format=%as -- "$f")" "$f"
done
```

分组：近期维护组（正常）vs 长期未动组（重点核对）。**未动≠过时**：原则级写法（不罗列易变细节）的文件天然耐老；罗列型（命令表/索引/ID 清单）才易腐。

### Step 2 机械校验（脚本）

```bash
node .agents/skills/agents-md-auditor/scripts/audit.mjs
```

检查相对链接/反引号路径存在性 + npm 脚本引用（就近 package.json，避免把模板包脚本误判为根包脚本）。已知误报源：通配符路径（脚本已跳过）、面向最终用户的模板文件（`create-genshin-ts/templates/start/`，按其自身包校验）。

### Step 3 内容级核对（机械查不出的，逐文件对照现实）

对每个罗列型文件，拿"文件声称的"对照"仓库实际的"：

- 命令表 vs `src/cli/` 实际文件；工具清单 vs `tools/` 实际文件（**注意改名残留**：如 trace-gia-* → trace-gil-*）。
- 索引/阅读顺序 vs 目录实际文件（找"成文但未收录"的章节；核对头部"最近校验"日期是否严重滞后）。
- 被取代口径 grep：根 AGENTS/CLAUDE 里带日期的"用户更正/作废"条目，去下级文件搜旧口径残留（例：节点预算 3000→2000）。
- 新规则传导：根文件新增的高频坑（带日期），下级相关目录文件是否有指针（不必复制全文，加指针即可，遵守精简原则）。

### Step 4 缺口分析（哪些目录需要新增）

```bash
for d in <候选目录>*/; do
  echo "$(git log -1 --format=%as -- "$d") | $(git log --oneline --since=<30天前> -- "$d" | wc -l) | $d"
done
```

判定标准：
- **建议新增**：活跃（近期多提交）+ 有实证素材（PROGRESS/复盘/可提炼的不变量）+ 当前无锚点文件。
- **不建议**：静默 demo、单轮实验、或已被上级 AGENTS.md 覆盖的子目录（如 docs/* 已被 docs/AGENTS.md 路由）。
- 路由表型（如 examples/ 根）：子目录多、定位易混、需要"进门前先看表"的目录。

### Step 5 修复过时项（可自主，按自主提交范围）

- **先读后改**（编辑器观察策略要求新鲜读取后才允许 edit）。
- 历史文档（handover/复盘/plans/todo 历史条目）**不修改**，只在受影响的索引处标注滞后口径。
- 精确暂存本次相关文件提交；工作区常有其他任务的未提交改动，禁止扫入。
- 修复后更新受影响文件头部的"最近校验"日期。

### Step 6 新增文件（必须用户选定）

新增 = 永久上下文成本，用 ask_user_question 给数据驱动 shortlist（附活跃度证据），用户选定后才创建：
- 范本风格：目录头部 quote 写关键 ID/入口文档 → 不变量清单（每条带实证来源 commit/轮次）→ 验证纪律 → 安全边界。参照 examples/football/AGENTS.md、examples/rubik-3x3/AGENTS.md。
- 内容只写已证实的（从 PROGRESS/复盘提炼），禁止推测 ID 或状态。
- 路由表型文件加"状态列最近核对日期 + git log 复核提示"，防自身腐化。
- 创建后**实证注入**（读写该目录下一个文件，确认 system-reminder 出现新文件内容）再提交。

### Step 7 报告与记录

- 按三栏门禁报告：已验证（注入实证/引用完整性/提交内容）/ 尚未验证 / 需用户确认；遗留项单列。
- 把本次审计摘要追加到 `references/audit-log.md`（日期/范围/发现/修复提交号/遗留），下次审计先读它作基线。

## 红线

- 新增 AGENTS.md 必须用户选定，不得自主添加。
- 不修改历史记录类文档内容；只加滞后标注。
- 审计不改变游戏文件，无需游戏核验；报告里不要虚增证据层级。
- 触发词里没有"审计/巡检/健康检查"字样时，不要主动跑全量流程（避免误触发打扰）。
