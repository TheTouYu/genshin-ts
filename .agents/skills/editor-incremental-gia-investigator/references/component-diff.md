# 组件域差分：相邻快照 → 组件槽级结论

> 领域：静态 GIL 组件（definition/instance 组件槽）。适用：用户在编辑器添加/移除/修改组件后的差分归因。
> 来源：2026-08-13 魔方 P4 组件调查（基础运动器/命中检测/物件镜头三轮差分 + 1849 历史样本复核）
> 验证层级：真实编辑器保存 + 相邻快照逐字节差分 + 用户确认组件名；尚未游戏验证处单独标注

## 何时使用

用户在编辑器对元件/实体做组件操作（添加、移除、改参数）并保存后，需要回答：
- 哪个 definition/instance 的哪个组件槽变了？
- 新增槽的类型码、完整 hex、内嵌字符串是什么？
- 与已知组件快照表（docs/game-engine-knowledge/components.md）是否逐字节一致？

## 标准流程

1. **保存 before 快照**：用户操作前，cp <地图.gil> 到备份目录 + sha256sum 双写记录。
2. **等用户编辑器保存**：保存后先核对 hash 变化，确认落盘。
3. **跑组件差分**：

```bash
npx tsx .agents/skills/editor-incremental-gia-investigator/scripts/component-diff.ts \
  <before.gil> <after.gil> [--id <prefabId>] [--json]
```

输出按 definition/instance 分组：types 前后对照 + 新增/移除/修改槽（type、hex、内嵌中文名）。
4. **对照已知快照**：新增槽 hex 与 components.md 锁定快照逐字节比对；未知 hex 记录为待确认。
5. **结论登记**：type→组件名映射更新到 components.md；本轮快照登记到 manifest。

## 核心教训（2026-08-13，避免第三次犯同类错误）

1. **UI 组件面板显示 ≠ GIL 组件槽**：元件"角块"GIL 槽 = [18,1,3,19,6,14]，但编辑器 UI 只显示
   [1,3,6]（自定义变量/单位状态/特效播放）。18/19/14 是引擎系统内部组件（UI 不显示）。
   → 不能靠 UI 组件列表对应槽位顺序，必须以差分新增槽为准。
2. **元件名不可推断组件归属**：1849 元件命名"组件比对-基础运动器"（[18,1,3,19,6,14,4]），
   曾误导把模板自带的 18 当基础运动器；实际该元件相对模板基线新增的槽是 4。
   → "哪个槽是用户加的"只能由相邻快照差分回答，模板基线要单独盘点。
3. **模板自带组件**：空模型/基础元件模板自带 [18,1,3,19,6,14]（部分 UI 可见）。
   "模板没有组件"是错误表述（2026-08-13 修正）。
4. **组件名确认**：以用户"添加时看到的名字"+"差分新增槽 type"配对为准；同一个组件
   两次添加的 hex 必须逐字节一致才能登记 CONFIRMED。
5. **游戏行为归因**：控制器能转（有 type 4）vs 角块不能转（无 type 4）是运动器组件
   前置依赖的对照证据；此类对照优先于任何静态推断。
