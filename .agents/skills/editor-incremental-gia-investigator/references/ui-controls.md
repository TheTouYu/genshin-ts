# UI 控件（root9 控件段）wire 规则速查

> 状态：部分已验证（真实 .gil 相邻快照差分）
> 来源：地图 1073741907（ui-inject-diff）图片控件差分（2026-08-22）；灯阵/UI 解析（2026-08-17/18）。
> 配套：本技能 SKILL.md「UI 差分实战经验」；知识书 `docs/game-engine-knowledge/ui-controls.md`。
> 注意：root9 同时承载**素材段**（素材库）与**控件段**（屏幕控件），两者都是 root9 field 502 记录，
> 但记录结构不同——`assets:ui list` 会把素材库记录误读为控件（名字「图片」的组被当成控件），
> 差分时先按记录结构区分，不要只看 root9 field 502 数量。

## 已闭合规则

### 图片控件 = 模板 + 实例 两条记录（2026-08-22 差分闭合）

添加一个图片控件在 root9 新增两条 502 记录：

| 记录 | 特征 | 说明 |
| --- | --- | --- |
| 模板（definition） | 无 `f504`；`f502[type4]` 自标识 | 图片控件本体，含图片源配置 |
| 实例（instance） | `f504` = 布局 ID；`f502[type3]` = `{f13={f501=模板ID}}` | 引用模板，注册进布局 |

实例 `f502[type3].f13.f501` → 模板 ID；模板 `f502[type4]` 自标识。

**双向引用**：模板 `f502[type4].f14.f501` = packed 实例 ID 列表（back-reference），
布局引用时追加新实例 ID。

### 官方预制控件 vs 自定义模板（2026-08-22 第五轮差分闭合）

| 路径 | 记录数 | 结构 |
| --- | --- | --- |
| 自定义模板 | 2 条（模板+实例） | 模板 `f502[type4]` 无 `f504`；实例 `f502[type3]` `f504`=布局 |
| 官方预制控件 | 1 条 | `f502[type5]` 单条，`f504`=布局，直接含图片源 `f505[f502=38]` |

图片源引用素材路径两者一致：`f505[f502=38].f503.f31.f6.f4` = 素材索引 ID。

### 布局引用规律（2026-08-22 差分闭合）

「把控件模板放进布局」= 三步联动：
1. 新建实例记录（`f504`=布局 ID，`f502[type3]` 引用模板）；
2. 实例 ID 追加进布局的 `f503` packed 列表；
3. 模板 `f502[type4].f14.f501` 追加实例 ID（back-reference）。

- 默认布局 `1073741825`：`f503` = 14 官方预置 + 用户新增实例。
- 控件组容器 `1073741840`：`f503` = 尚未放入布局的实例列表。

### 图片源引用素材的 wire 路径（核心）

```
f505[f502=38]            ← 图片源组件（type 38）
  f503
    f31 (msg)            ← 图片源 = 静态引用
      f3 (msg) = {f501: -1}   ← 无颜色覆盖
      f4 (varint) = -1        ← 无颜色覆盖
      f6 (msg) = {f2:1, f3:8, f4:<素材索引ID>}  ← 素材引用
      f10 (bytes 0B)
    f501 = 22
    f502 = 38
    f503 = 1
    f504 (msg) = {f2:1, f3:8, f4:<自身ID>}  ← 自引用
```

**素材索引 ID（= 素材库容器 ID）存在 `f505[f502=38].f503.f31.f6.f4`。**

> 两个独立样本确认（2026-08-22）：`f6.f2=1`、`f6.f3=8` 是固定常量；`f3={f501:-1}`、`f4=-1` 是「无颜色覆盖」标记。

### 控件记录通用结构（2026-08-17/18 灯阵/UI 解析）

- 控件记录顶层：`f501`=控件 ID、`f502`×N（组件槽，type 码区分）、`f504`=布局 ID（实例才有）、`f505`×N（内容/载体/图片源等）。
- `f505` 每条带 `f501`（序号）+ `f502`（type 码）+ `f503`（内容）。type 码：15=名字、12=载体（transform 槽）、38=图片源、23=其他。
- 控件位置在 `f505[f502=12].f503.f13.f12.f501[n].f502.f504` = `{f501:X, f502:Y}`（f32 fixed32，屏幕中心相对偏移）。
  尺寸在 `f505[f502=12].f503.f13.f12.f501[n].f502.f505` = `{f501:W, f502:H}`。
  坐标换算：wire 偏移 = 编辑器绝对坐标 − (800, 450)（1600×900 设计分辨率）。
- 布局 packed 列表：`layout.503` 是 packed varint（控件 ID 列表），用 `readVarint` 流式读，不要用消息解析器。

## 未闭合（OBSERVED，勿当规则用）

- `f3={f501:-1}`、`f4=-1` 配置颜色后如何变（颜色覆盖 wire）——需配置颜色后差分。
- 图片源为「动态引用/道具/状态/技能/单位状态」时的 wire 差异。
- root21/root29 编辑器自动登记语义（CLI 创建控件后编辑器首存会补，尚未闭合）。
- 图片控件在游戏内是否真的显示该素材——需游戏核验。

## 差分要点

- 图片控件差分：先 `compare-gil-root-wire.py` 确认只有 root9（+root46 审计噪声）变化，再定点 diff root9 field 502 记录集合差，定位新增记录，最后沿 `f505[f502=38].f503.f31.f6` 解码素材引用。
- 等长内容变更（如改名字/内容）记录总长不变，必须逐字节记录 diff，不能只看 root 层大小。
- 通用递归解析会把 packed/原始字节误当消息——只沿已知路径替换，未知子块保留原始字节。

### 已闭合规则

1. **添加悬浮交互页 = 6 条新 root9 502 记录**（无删除）：
   - 模板（type4 自标识，`f502[type4].f14.f501` = packed back-ref [实例ID]）
   - 实例（type3，`f502[type3].f13` = packed [模板ID]，`f504` = 控件组容器 1073741840）
   - 固有容器素材组 ×2（type6 槽 `f12.f501=2`，`f503` = packed 成员素材 ID 列表，显示名在 **t43 组件** `f501`=UTF-8「固有容器」——不在 t15，`assets:ui list` 因此显示 `(空)`）
   - 交互页关闭按钮素材 ×2（type6 槽 `f12.f501=3`，`f504` = 所属素材组）
2. **控件种类标识**：t44 组件 = `{f502: 330001}`（悬浮交互页 kind 常量；模板与实例一致）。
3. **固有容器引用**：t42 组件 `f503.f501` = varint(素材组ID)。模板 t42 → 一组、实例 t42 → 另一组（模板/实例各带一份固有容器组）。
4. **顶层索引**：root9 f501 = packed varint 列表 = 所有 parent=None 记录 ID（模板/布局/容器/素材组；不含实例与素材）。编辑添加模板插最前、素材组追加在后。
5. 容器 1073741840 `f503` packed 追加实例 ID（96B→104B）——三步联动第 2 步在控件组容器上同样成立。
6. f505 组件通用骨架：`f501`=序号、`f502`=type 码、`f503`=内容、`f504`=`{f16:1, f24:8, f32:自身ID}` 自引用（图片控件里是 `{f2:1,f3:8,f4:ID}`，字段号随上下文不同，三元组 1/8/ID 相同）。
7. 载体 t12 组件含 4 个设备槽（键鼠/移动触屏/主机手柄/移动手柄）`f503.f13.f12.f501[n]`。
