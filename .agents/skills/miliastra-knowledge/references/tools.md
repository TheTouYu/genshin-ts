# 工具参数与行为参考（miliastra-knowledge）

## 统一调用方式

**首选助手脚本**（自动处理 301 跳转、超时、信封解包、错误提示）：

    bash <技能目录>/references/query.sh <tool> [参数...]

- 模式A（推荐）：直接传参数，脚本自动构造 JSON：bash …/query.sh get_node_info 碰撞触发器
- 模式B：首参以 { 开头则视为完整 JSON：bash …/query.sh rag_search '{"queries": ["x"], "top_k": 3}'
- 多个参数 = 批量查询，一次调用完成

**兜底：手工 curl**（脚本不可用时）：

    curl -sS -m 30 -L -X POST https://ugc.070077.xyz/api/v1/skills/miliastra-knowledge/tools/<tool> \
      -H "Content-Type: application/json" -d '<json>'

响应统一包裹：{"success":true,"data":{"skill":"miliastra-knowledge","tool":"<tool>","result":...},"error":null}，取 data.result。

## get_node_info

### 参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| names | list[str] | 是 | 节点名称列表，支持模糊匹配，可批量传入 |

### 调用

    bash …/query.sh get_node_info 定点位移
    bash …/query.sh get_node_info 受到攻击时 攻击命中时 播放限时特效 定点发射投射物
    bash …/query.sh get_node_info '{"names": ["随机", "向量"]}'

### 行为

- **子串匹配**：query 是 target 的子串即命中，如"运动器"命中"投射运动器"
- **子序列匹配**：query 的每个字符按顺序出现在 target 中即命中，如"觉醒"可命中"角色技能觉醒"
- 两种方式任一命中即返回，**不区分大小写**
- 单次调用可传多个名称，结果按传入顺序逐项返回
- 注意区分服务端节点和客户端节点（返回的 side 字段）

### 返回结构

## list_documents

### 参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keywords | list[str] | 否 | 过滤关键词列表，支持模糊匹配；空列表时返回全部文档 |

### 调用

    bash …/query.sh list_documents            # 浏览全部文档
    bash …/query.sh list_documents 运动器
    bash …/query.sh list_documents 运动器 触发器 战斗   # 多关键词批量

### 行为

- keywords 为空列表时返回全部文档（guide + tutorial + FAQ，300+ 条）
- 传入多个关键词时逐个过滤，**按关键词分组**返回各自结果
- 对 title 和文件名均做子串/子序列匹配
- 返回结果只含 title 和 file 路径，不含正文（正文需用 get_document）

### 返回结构

单关键词（keywords=["运动器"]）：

        "keyword": "运动器",

无关键词：

## get_document

### 参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| titles | list[str] | 是 | 文档标题或关键词列表，支持模糊匹配，可批量传入 |

### 调用

    bash …/query.sh get_document 仇恨配置
    bash …/query.sh get_document 碰撞触发器 碰撞触发源 额外碰撞
    bash …/query.sh get_document 造物状态决策节点图 复杂造物技能 能力单元

### 行为

- 文件系统只扫描一次，所有 titles 共享同一候选列表，批量时无额外开销
- 每个 title 独立进行子串/子序列匹配，结果按传入顺序逐项返回
- 每项结果附带 status 字段：
  - "ok" — 命中 1–5 篇，返回全文 + related_nodes
  - "too_many" — 命中 >5 篇，仅返回标题列表，需用更精确关键词重查（宽泛词如"节点"会触发）
  - "not_found" — 未命中，返回 available_titles_sample 供参考
- related_nodes 由同一 title 关键词触发节点模糊匹配，可能为空列表

### 返回结构

    [
      {"query": "碰撞触发器", "status": "ok", "documents": [
        {"title": "碰撞触发器", "file": "official/guide/…_碰撞触发器.md",
         "content": "---\ntitle: 碰撞触发器\n…", "related_nodes": [{"title": "进入碰撞触发区", "content": "…"}]}
      ]},
      {"query": "不存在的标题", "status": "not_found",
       "message": "未找到匹配「不存在的标题」的文档", "available_titles_sample": ["读前须知", …], "related_nodes": []},
      {"query": "节点", "status": "too_many", "message": "匹配到 8 篇文档，请用更精确的关键词。",
       "matches": [{"title": "执行节点", "file": "…"}], "related_nodes": […]}
    ]

## rag_search

### 参数

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| queries | list[str] | 是 | — | 自然语言问题或描述列表，越具体越精准，可批量传入 |
| top_k | int | 否 | 5 | 每个查询最多返回 top_k 条结果 |

### 调用

    bash …/query.sh rag_search 嘲讽目标设置仇恨值让怪追玩家
    bash …/query.sh rag_search '{"queries": ["实体高速穿过碰撞触发器时不触发效果", "运动器向量方向不符"], "top_k": 3}'

### 行为

- DB 连接和环境变量只初始化一次，批量调用时共享，逐 query 执行嵌入 + 向量检索
- similarity 低于 0.3 的结果被静默过滤，total_results 可能小于 top_k
- 结果为空的 query 返回空 results 数组，不报错，不影响其他 query 结果
- 对含错别字或描述模糊的 query 仍可返回合理结果，但精确描述效果更好

### 返回结构

    [
      {
        "query": "角色受击后播放特效",
        "total_results": 4,
        "results": [
          {"title": "特效播放", "h1_title": "执行节点", "file_name": "…_特效播放.md",
           "similarity": 0.812, "text_snippet": "播放限时特效节点可在指定位置播放一次性特效…"}
        ]
      }
    ]

## 已知坑（来自实测）

1. **http 会 301 到 https**：手工 curl 必须加 -L，否则请求体丢失导致 404/异常（脚本已处理）
2. **基础引擎节点远程查不到**（520 旋转运动器/668 实体重绑/365 激活/337 GetVar/323 SetVar 等）：
   不要反复重试远程 API，走 SKILL.md「本地回退」节（项目本地打包数据 + docs/game-engine-knowledge/）
3. **宽泛词会 too_many**：get_document 用"节点"这类词会命中 >5 篇只返回标题；先 list_documents 找精确标题
4. **get_node_info 注意 side 字段**：服务端节点和客户端节点是两套，别混用
