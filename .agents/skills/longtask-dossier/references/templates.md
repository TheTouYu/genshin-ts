# 模板与字段说明

每份文件只回答一个层次的问题。下面是"该写什么/不该写什么"的判据，配合 `scripts/longtask_new.py` 生成的骨架使用。

## INDEX.md（L0）

- **该写**：三句话任务说明、现在在哪（表格，每轮改）、按任务选读的指针表、更新分工、三条硬规矩。
- **不写**：具体读数细节（放 `03-state.md`）、历史（放 `04-timeline.md`）。
- **判据**：一个新模型只读这份，能说出"这任务要什么、现在在哪、下一步读哪份"。

## 01-charter.md（L1 宪章）

| 小节 | 内容 | 判据 |
|---|---|---|
| 目标 | 用户原话（带日期/会话/seq），不是转述 | 每条都能 grep 到会话里的原句 |
| 验收判据 | 可判、可数（G1/G2…） | 每条能回答"怎么算完成" |
| 边界 | 已拍板不再讨论的事 | 每条有出处 |
| 权威文件表 | 冲突时以谁为准 | 路径可达 |
| 证据三层 | 结构/行为/用户 | 防止把"能编译"说成"好用" |

## 02-xinfa.md（L1 心法）

**一条的固定形状**：

```markdown
### X# 一句话标题（动词开头）
**要做什么**：可执行的动作，正向表述。
**为什么**：不做会怎样（一句）。
**判据**：怎么检查我做到了（命令/读数/自问）。
> YYYY-MM-DD：「用户原话」
```

- 只收**用户给的**方法论，不收自己的感想；自己的推论写在 dossier 里。
- 同一主题有多条时合并，别按日期堆。
- 用户改口了：改这一条，并在 `04-timeline.md` 记一行（旧说法作废要留痕）。

## 03-state.md（L1 现状）

- 每张读数表标**测量时间**；空闲/负载两种场景必须分开报。
- "断点"要具体到"等谁给什么"或"下一步命令是什么"。
- 每次收尾至少改：当前阶段、断点、读数里变过的行、最近三笔提交。

## 04-timeline.md（L2 决策日志）

| 列 | 要求 |
|---|---|
| 日期 | `MM-DD` 或 `YYYY-MM-DD` |
| 发生了什么 | 一句事实，不写评价 |
| 用户原话/决策 | 逐字摘，太长就截断加 `…` |
| 影响/产物 | 文件路径、commit、规则条目 |

只 append；纠错就再加一行「更正：…」。

## 05-open.md（L2 缺口）

四段固定：A 用户诉求未满足 → B 缺陷/技术债 → C 待拍板 → D 已否决。
编号 `O-YYYY-MM-DD-n`；关闭时移到"已关闭"段并写证据（命令/读数/commit）。

## dossiers/*.md（L3 子主题）

- 开头一句"这个子主题要做什么"，然后：能力/成色表、关键工具、已踩的坑、权威指针。
- **只做摘要与指针**：细节放权威文件，避免两处漂移。
- 每个 dossier 收口后归档（见 `archive/README.md`）。

## archive/

历史记录，不参与"当前入口"。归档件只加一行 `> 归档于 YYYY-MM-DD`。
