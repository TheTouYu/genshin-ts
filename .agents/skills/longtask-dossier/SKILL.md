# 长期任务档案（Longtask Dossier）

长期任务失败的头号原因不是能力不够，而是**知识只活在会话里**：压缩一次就少一块，换个会话就从头找。
本技能把"这个任务是什么、现在在哪、为什么这样、还剩什么"固化成**分层文件**，每层有固定读法与行数预算，
让接手的模型按需读、读得起，并把"更新档案"变成收尾的固定动作。

## 一、什么时候用

| 场景 | 动作 |
|---|---|
| 任务已跨 ≥2 个会话，或将持续 ≥1 天 | **CREATE**：建档案骨架 |
| 每轮收尾、压缩上下文前、交接前 | **UPDATE**：写现状/决策/缺口 |
| 新会话接手、怀疑文档过期 | **AUDIT**：跑校验器，修过期指针 |
| 上下文已经丢了、要补回细节 | 先 `context-loss-recovery`，再回到 UPDATE |

## 二、分层模型（本技能的核心设计）

| 层 | 文件 | 回答什么 | 行数预算 | 变更频率 |
|---|---|---|---|---|
| L0 | `INDEX.md` | 这是什么任务 / 现在在哪 / 我该读哪份 | ≤120 | 每轮 |
| L1 | `01-charter.md` | 目标、判据、边界（用户原话） | ≤200 | 用户改目标时 |
| L1 | `02-xinfa.md` | 方法与纪律（每条可执行 + 出处） | ≤300 | 用户给新方法论时 |
| L1 | `03-state.md` | 读数、在跑、断点 | ≤200 | 每轮 |
| L2 | `04-timeline.md` | 决策链（只 append） | ≤400 | 有转折时 |
| L2 | `05-open.md` | 未满足/待拍板/已否决 | ≤200 | 有变化时 |
| L3 | `dossiers/*.md` | 子主题档案（各 ≤200） | 按子主题 | 有进展时 |
| — | `archive/` | 历史快照（只 append） | 不限 | 超预算时 |

**为什么这样分**：新模型最贵的是"第一次读"的成本。L0 是目录，L1 是可以一口气读完的"当前真相"，
L2 是"为什么"，L3 是"要用时再查"。任何一份超过预算就说明该拆——**一个大文档等于没有文档**。

## 三、CREATE：建立档案

1. 先问清三件事（缺就按现有证据写，标"待确认"）：任务目标与完成判据、当前阶段、谁在维护。
2. 生成骨架：
   ```bash
   python3 .agents/skills/longtask-dossier/scripts/longtask_new.py \
     --dir docs/longtask --title "<任务名>" --goal "<一句话目标>"
   ```
   默认生成 `docs/longtask/`；也可指定别的目录（例：`--dir docs/longtask-gui`）。
3. 填 L1：**charter 用用户原话**（带日期/会话/seq），**xinfa 每条带出处**。
4. 在仓库入口挂指针（新会话才会读到）：根 `CLAUDE.md` 或 `AGENTS.md` 加一行指向 `INDEX.md`；
   同时更新 `docs/documentation-map.md`。注意 `AGENTS.md` 有 16KB 硬限、`CLAUDE.md` 有 12KB。
5. 跑体检：`python3 .agents/skills/longtask-dossier/scripts/longtask_check.py --dir docs/longtask`。

字段与模板见 `references/templates.md`。

## 四、UPDATE：每轮收尾三件套

**收尾时按顺序做完这三件，再说"完成"**：

1. **`03-state.md`**：改「当前阶段/断点」与读数；写清测量时间。过期读数比没有更危险。
2. **`04-timeline.md`**：只在本轮出现**会改变后续行为的决策**时 append 一行（有则加，无则跳过）。
3. **`05-open.md`**：新缺口开条目，解决的移到"已关闭"并写证据。

另外两种情况：
- **用户给了新方法论/心法** → 加进 `02-xinfa.md`，格式：要做什么 / 为什么 / 判据 / 出处。
- **用户改了目标或判据** → 改 `01-charter.md`，并在 timeline 记一行（因为这会改变所有后续判断）。

> 压缩上下文之前先做上述更新：写进文件的东西不会被压缩掉，留在会话里的会被。

## 五、AUDIT：体检与追踪

```bash
python3 .agents/skills/longtask-dossier/scripts/longtask_check.py --dir docs/longtask
```

检查项：文件齐全、状态头（`状态：` + `最近校验：`）、行数预算、`INDEX.md` 指针可达、`最近校验` 是否落后于 git 最近提交。
输出 `PASS` / 逐条 `FAIL`，退出码 0/1，可直接进门禁。

追踪任务进展的三种读法：
- **快照**：只读 `INDEX.md` §二「现在在哪」。
- **趋势**：`git log --oneline -- docs/longtask/` 看档案怎么变，比读时间线快。
- **健康度**：`05-open.md` 的 A 段（用户诉求）条目数不增、缓慢下降，就是真的在推进。

## 六、质量判据（新会话能不能真的接手）

接手者读完 L0+L1 后，应能不看别的材料回答：

1. 这个任务要交付什么？**判据是什么**？
2. 现在到哪一步？**断点在哪**？
3. 哪几条纪律最容易违反？违反了会怎样？
4. 还剩什么没做？哪些路线已经被否决？

答不出 → 档案不合格：补 L0/L1，而不是让接手者去翻会话。

## 七、常见坑

- **写成一个大文档**：超过 300 行就拆；每份文件只回答一个层次的问题。
- **只有结论没有出处**：所有关键结论带日期 + 用户原话或命令读数，否则下一个人无法判断它是否过期。
- **状态头缺失**：`docs/` 下必须有 `> 状态：` 与 `> 最近校验：`，否则 `doc_health` 会拦提交。
- **指针指向归档件**：归档 = 历史，当前入口必须指向活的文件。
- **只写不接**：档案不进任何注入入口（CLAUDE/AGENTS/技能），新会话就不会读它。
- **把交接写进 `/tmp`**：重启即失。落仓库路径。
- **更新时不写测量时间**：读数会悄悄过期，后来人当真。

## 八、与其它技能的分工

| 技能 | 分工 |
|---|---|
| `context-loss-recovery` | 上下文已经丢了 → 先把细节捞回来（本技能负责捞回来之后写进档案） |
| `task-command-center` | 会话开始/切换/收尾的调度决策（本技能是它的"档案载体"） |
| `task-retrospective` | 一波任务闭环后的复盘（复盘结论进 `05-open.md` 与 `02-xinfa.md`） |
| `document-governance` | 提交门禁与文档规范（本技能的体检器与其互补） |

`references/recovery-flow.md` 记录了一次真实恢复的完整流程（2026-10-22），可直接照抄命令。
