# 长期任务档案（Longtask Dossier）

长期任务失败的头号原因不是能力不够，而是**知识只活在会话里**：压缩一次就少一块，换个会话就从头找。
本技能把"这个任务是什么、现在在哪、为什么这样、还剩什么"固化成**分层文件**，每层有固定读法与行数预算，
让接手的模型按需读、读得起，并把"更新档案"变成收尾的固定动作。

## 一、什么时候用

| 场景 | 动作 |
|---|---|
| 任务已跨 ≥2 个会话，或将持续 ≥1 天 | **CREATE**：建档案骨架（含 `LINES.md`） |
| 有 ≥2 条互不归属的活在并行（足球 / 2D / GUI…） | **LINES**：每线一行，各有判据/断点/恢复入口（§二点五） |
| 每轮收尾、压缩上下文前、交接前 | **UPDATE**：四件套（线表那一行 → 本线 dossier → 共享现状 → 缺口） |
| 新会话接手、怀疑文档过期 | **AUDIT**：跑校验器（含 `--selftest`），修过期指针 |
| 上下文已经丢了、要补回细节 | 先 `context-loss-recovery`，再回到 UPDATE |

## 二、分层模型（本技能的核心设计）

| 层 | 文件 | 回答什么 | 行数预算 | 变更频率 |
|---|---|---|---|---|
| L0 | `INDEX.md` | 这是什么任务 / 现在在哪 / 我该读哪份 | ≤120 | 每轮 |
| **L0.5** | **`LINES.md`** | **有哪几条线 / 各自断点 / 谁在推 / 共享资源归谁** | ≤150 | 开关线时 + 每轮改本线那一行 |
| L1 | `01-charter.md` | 目标、判据、边界（用户原话） | ≤200 | 用户改目标时 |
| L1 | `02-xinfa.md` | 方法与纪律（每条可执行 + 出处） | ≤300 | 用户给新方法论时 |
| L1 | `03-state.md` | **共享面**（机器/服务/门禁）+ 标了线 id 的分线读数 | ≤200 | 每轮（只改本线分节） |
| L2 | `04-timeline.md` | 决策链（只 append） | ≤400 | 有转折时 |
| L2 | `05-open.md` | 未满足/待拍板/已否决（**每条标线 id**） | ≤200 | 有变化时 |
| L3 | `dossiers/*.md` | 子主题/单线档案（各 ≤200） | 按子主题 | 有进展时 |
| — | `archive/` | 历史快照（只 append） | 不限 | 超预算时 |

**为什么这样分**：新模型最贵的是"第一次读"的成本。L0 是目录，L1 是可以一口气读完的"当前真相"，
L2 是"为什么"，L3 是"要用时再查"。任何一份超过预算就说明该拆——**一个大文档等于没有文档**。

## 二点五、多线并行（2026-10-24 起；这是本技能的第二根支柱）

> 触发原话：「我们现在是有两条线并行的…现在的系统没有考虑到多任务并行的情况，所以你得到的就只有一个任务。」
> 失败形态很具体：整个档案只有一组「当前在哪/断点」，于是**两条线的断点互相覆盖**，接手的人只拿到一条任务。

**线的定义**：一条线 = 有独立判据 + 独立断点 + 独立恢复入口的一组活（例：`football` / `sim-2d` / `gui-agi`）。
伞目标（"三个 3D 游戏"）不是线，它指向各条线。

**四条规则**（写进 `LINES.md` §一/§四，并由体检器机械校验）：

| # | 规则 | 为什么 | 怎么机检 |
|---|---|---|---|
| 1 | **线由用户指定**，没点明就问，不按 mtime / 最新提交猜 | 猜会接到别的会话正在推的线 | 人判（判据：会话首句有指定或有一次提问） |
| 2 | **一轮一条线**：同时最多一条「活跃」 | 两条线同时动 = 两份断点都不准 | 体检：`活跃` > 1 条 → FAIL |
| 3 | **收尾只改本线**：本线那一行 + 本线 dossier + `03-state.md` 本线分节 | 断点是别人的资产，覆盖一次丢一轮 | 提交层面人判（`git show --stat` 只涉一条线） |
| 4 | **共享独占资源先仲裁**：屏幕/真机/编辑器/同图存档 | 两条线抢同一块屏，等于互相破坏 | `LINES.md` §三 表（人判 + 设备侧已有 `ys-gui-slot`/`ys-screen-grant` 拦） |

**分线读数放在哪**：单线细节在 `dossiers/<line>.md`；`03-state.md` 只留**共享面**（机器/服务/门禁）与
**标了线 id 的分节**（`[football]` / `[global]` …）。`05-open.md` 每条开放项必须标线 id，否则没人知道该谁关。

**开线/关线**：开线过三问（有判据 / 断点可接手 / 不抢别线独占资源）→ `LINES.md` §二 加一行 + 建 dossier；
关线状态改 `已闭环` 并写证据，**不删行**（删了下次会重开）。

## 三、CREATE：建立档案

1. 先问清三件事（缺就按现有证据写，标"待确认"）：任务目标与完成判据、当前阶段、谁在维护。
   **再加一条**：现在有**几条线**在跑（≥2 就按多线建，见 §二点五），首条线的 id 用 kebab-case。
2. 生成骨架（含 `LINES.md` 与首条线的 `dossiers/<line>.md`）：
   ```bash
   python3 .agents/skills/longtask-dossier/scripts/longtask_new.py \
     --dir docs/longtask --title "<任务名>" --goal "<一句话目标>" --line <line-id>
   ```
   默认生成 `docs/longtask/`；也可指定别的目录（例：`--dir docs/longtask-gui`）。
3. 填 L1：**charter 用用户原话**（带日期/会话/seq），**xinfa 每条带出处**；填 `LINES.md` §二 的判据与断点。
4. 在仓库入口挂指针（新会话才会读到）：根 `CLAUDE.md` 或 `AGENTS.md` 加一行指向 `INDEX.md` + `LINES.md`；
   同时更新 `docs/documentation-map.md`。注意 `AGENTS.md` 有 16KB 硬限、`CLAUDE.md` 有 12KB。
5. 跑体检（含自证）：`python3 .agents/skills/longtask-dossier/scripts/longtask_check.py --dir docs/longtask`
   —— 基线要 `PASS`；再跑 `--selftest` 确认判定器抓得到 6 类破坏（抓不到=门禁空转）。

字段与模板见 `references/templates.md`。

## 四、UPDATE：每轮收尾四件套（多线版）

**收尾时按顺序做完这四件，再说"完成"**：

1. **`LINES.md` §二 本线那一行**：状态 / 断点 / 上次读数（**只改自己那一行**）。
2. **本线 `dossiers/<line>.md`**：§现状读数（带测量时间）+ §断点；闭环的块移到"已闭环"。
3. **`03-state.md`**：只改**共享段**与标了本线 id 的分节；新增读数带线 id。过期读数比没有更危险。
4. **`05-open.md`**：新缺口开条目并**标线 id**，解决的移到"已关闭"并写证据。

另外三种情况：
- **用户给了新方法论/心法** → 加进 `02-xinfa.md`，格式：要做什么 / 为什么 / 判据 / 出处。
- **用户改了目标或判据** → 改 `01-charter.md`，并在 timeline 记一行（这会改变所有后续判断）。
- **开/关/切线** → 改 `LINES.md` §二 并在 `04-timeline.md` append 一行（跨线决策才进 timeline）。

> 压缩上下文之前先做上述更新：写进文件的东西不会被压缩掉，留在会话里的会被。

## 五、AUDIT：体检与追踪

```bash
python3 .agents/skills/longtask-dossier/scripts/longtask_check.py --dir docs/longtask
python3 .agents/skills/longtask-dossier/scripts/longtask_check.py --dir docs/longtask --selftest   # 判定器自证（6 类注入）
```

检查项：文件齐全（含 `LINES.md`）、状态头（`状态：` + `最近校验：`）、行数预算、`INDEX.md` 指针可达、
`最近校验` 是否落后于 git 最近提交，以及**多线字段**：
- `LINES.md` §二 每行 8 列、线 id 写成 `` `kebab-case` ``、状态 ∈ 词表、**`活跃` 同时最多一条**、恢复入口链接可达；
- `INDEX.md` / `03-state.md` 不得再出现"活动分支"这类单线口径；
- `05-open.md` 的开放条目（A/A2/B/C 段）每行第 2 列必须标 `[line-id]`。

输出 `PASS` / 逐条 `FAIL`，退出码 0/1，可直接进门禁。**改判定器必须跑 `--selftest`**：基线 PASS + 每类注入被抓到，否则等于没判。

追踪任务进展的四种读法：
- **快照（多线）**：`LINES.md` §二 —— 哪几条线、各自断点、谁在推。
- **快照（全局）**：`INDEX.md` §二。
- **趋势**：`git log --oneline -- docs/longtask/` 看档案怎么变，比读时间线快。
- **健康度**：`05-open.md` 的 A 段（用户诉求）条目数不增、缓慢下降，就是真的在推进；某条线的条目长期不降＝那条线停着。

## 六、质量判据（新会话能不能真的接手）

接手者读完 L0 + `LINES.md` + 本线 dossier 后，应能不看别的材料回答：

0. **我在哪条线？这条线的判据与断点是什么？**（多线模型的第一问，答不出＝线表不合格）
1. 这个任务要交付什么？**判据是什么**？
2. 现在到哪一步？**断点在哪**？
3. 哪几条纪律最容易违反？违反了会怎样？
4. 还剩什么没做？哪些路线已经被否决？

答不出 → 档案不合格：补 L0/L1，而不是让接手者去翻会话。

## 七、常见坑

- **把多线写成一条串行线**（"当前在哪/断点"只留一组）：第二条线的断点会被覆盖，接手者只拿到一条任务——这正是 2026-10-24 用户点名的系统缺陷。
- **改别线的行**：`LINES.md` 里别的线的那一行、别线 dossier 的断点，归那条线的执行者改；顺手改＝覆盖别人的断点。
- **按时间戳选线**：看到最新提交/最新档案就当作"该做这条"，会接到别的会话正在推的线。
- **写成一个大文档**：超过 300 行就拆；每份文件只回答一个层次的问题。
- **只有结论没有出处**：所有关键结论带日期 + 用户原话或命令读数，否则下一个人无法判断它是否过期。
- **状态头缺失**：`docs/` 下必须有 `> 状态：` 与 `> 最近校验：`，否则 `doc_health` 会拦提交。
- **指针指向归档件**：归档 = 历史，当前入口必须指向活的文件。
- **只写不接**：档案不进任何注入入口（CLAUDE/AGENTS/技能），新会话就不会读它。
- **把交接写进 `/tmp`**：重启即失。落仓库路径。
- **更新时不写测量时间**：读数会悄悄过期，后来人当真。

## 八、与其它技能的分工

| 技能 | 分工 |
|---|---|
| `context-loss-recovery` | 上下文已经丢了 → 先把细节捞回来（本技能负责捞回来之后写进档案） |
| `task-command-center` | 会话开始/切换/收尾的调度决策（本技能是它的"档案载体"） |
| `task-retrospective` | 一波任务闭环后的复盘（复盘结论进 `05-open.md` 与 `02-xinfa.md`） |
| `document-governance` | 提交门禁与文档规范（本技能的体检器与其互补） |

`references/recovery-flow.md` 记录了一次真实恢复的完整流程（2026-10-22），可直接照抄命令。
