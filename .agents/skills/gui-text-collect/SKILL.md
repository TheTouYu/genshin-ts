# 游戏正文采集生产线（gui-text-collect）

> 诞生：2026-10-23 旅行者故事页 `.02` 复采（.01 产物字符错乱 → .02 三通道互证全对）。
> 定位：**阅读型正文**（故事/对话/设定，大段中文、静态、可滚动或单屏）→ 结构化文档。
> 单帧控件感知走 `gui-world-state`；日志取数走 `device-playtest-loop`；OCR 通道细节走 `paddle-vl-ocr`。

## 流程总览（七步，别跳步）

```
① 查旧产物 → ② 只读看界面 → ③ 定裁窗(宁宽+右缘告警) → ④ 单屏完整性判定
→ ⑤ ys-text 行框 → ⑥ 双通道互证+像素裁定 → ⑦ 组装(行级原文+段落+修正登记+README)
```

### ① 先查旧产物（跨轮复用是最大提速点）
`ls gui-test/.0*/  .scratch/**` 找同类采集；**旧云端 VL 读数可直接当第二意见**
（.02 就是靠 .01 留的 `ocr/*/doc_0.md`（PaddleOCR-VL 逐字符）定案了 3 处破折号）。
旧产物错≠全废——错的常是裁窗/拼接，字符读数仍可用。

### ② 只读看界面（不抬窗、不申请）
```bash
. tools/ys-editor/ys-env.sh
tools/ys-editor/ys-capture latest --out /tmp/f.png --format png
tools/ys-screen /tmp/f.png --json        # text[] 每条带 bbox；containers 看面板归属
```

### ③ 定裁窗：宁宽勿窄 + 右缘截断告警
**正文文字列的右缘经常超出你第一版估计**（旅行者故事页：文字列 x≈1757–2490，裁到 2450 吞掉
满/野/。）。规则：
- 裁窗右缘放到文字列实测右缘 +50px 以上；
- `ys-text` 已内置截断告警：行 bbox 贴住裁窗边缘（±3px）时 stderr 报
  `裁窗截断嫌疑 N 处`，回执 `source.edge_truncation_suspects`。**看到非 0 必须扩窗重跑**，不许带病组稿。

### ④ 单屏完整性判定（先怀疑根本不用滚动）
- 先做**一次探针滚动 + 文字位置对比**（行 bbox y 不变 = 面板没滚）；
- 正文一屏完整（最长的故事也只有 ~19 行）时，**跳过整个滚动+拼接链路**；
- 帧间 md5 差异可能全部来自背景动画相位，不是内容滚动；
- 判到底用「帧 seq 前进过的两帧 md5 相等」——同 seq = daemon 同一帧，不是稳定证据
  （`gui-test/.02/collect02.sh::settle` 是修正后的参考实现）。

### ⑤ 行框提取
```bash
tools/ys-editor/ys-text FRAME --region X Y W H --json-out out.json
```
- bbox 是**帧坐标**（已加回偏移）；
- 行文本来自本地 RapidOCR（CUDA 常驻，~0.3s/行条）。

### ⑥ 双通道互证 + 像素裁定（本生产线的核心价值）
本地 RapidOCR 的**系统性缺陷**（2026-10-23 实测）：
1. **吞/并破折号**：—— → 一 / — / 无（三行全犯过）；
2. 行尾标点偶丢（满/。/」曾在窄窗下整字丢失——那是裁窗问题，右缘告警可防）。

裁定通道（按成本升序）：
| 通道 | 成本 | 适用 |
|---|---|---|
| 紧条 3× 局部重 OCR | ~0.3s | 单字符分歧（，vs；） |
| 邻近短行同区参照对比 | 0 成本 | 右缘暗角区判「行尾有没有字符」（阈值法在那里必失效） |
| 云端 VL（旧产物或新提） | ~20-60s/条串行 / 并发≈最慢一条 | 破折号、成段核对 |
| 整面板 VL（非行条） | ~1 次 | 段落分组参考 |

**裁条纪律（VL 幻觉防线）**：条必须**紧贴墨迹**（bbox±6px），放大 2×；
大空白条（行内容只占条的 10%）云端会幻觉（实测读出「y la 1000-000」「2023」）。
孤立破折号行条连云端也会读错——**破折号要带上下文整行/整面板读**。

### ⑦ 组装与证据链
参考实现 `gui-test/.02/assemble02.py`：
- 每行带 `{text, score, bbox}`；修正行登记 `fix_from + fix_basis`（可审计）；
- 段落=启发式（显示无段间距时靠标点+语义分组，**标注「已人工核对」**）；
- **显示文本省略的行尾标点按原样保留，不擅自补全**（story1 末行无。是游戏显示如此）；
- 交付三件：`stories/*.md`（正文+行级原文）、`data/stories.json`（机器可读）、
  `evidence/panel-*.png`（裁条证据，全帧太大不入库）+ README（裁定表+复现命令）。

## 本地 vs 远端实测（52 条中文行条，2026-10-23，GT=.02 裁定行文本）

| 变体 | 秒/条 | 字符准确率 | 全对率 |
|---|---|---|---|
| 本地 RapidOCR CUDA 1x | 0.29 | 0.898 | 41→38/52 (0.731) |
| 本地 RapidOCR CUDA 2x | 0.28 | **0.927** | 41/52 (0.788) |
| 远端 PaddleOCR-VL 2x（jobs=6） | **0.28（队列空）~4.2（高峰）** | 0.871 | **46/52 (0.885)** |
| **混合：本地2x初筛→31%分歧行提云端→取优** | ≈本地+少量上行 | — | **48/52 (0.923)** |

**分布差异比均值重要**：远端「对得更多、错得更狠」——全对率最高（尤其**破折号全对**：story2-10/story3-09 双双 1.000，而本地两变体全错），
但小行会幻觉尾巴（3字行读出「UUA##」）；本地2x均值最高但破折号全灭、且 2x 偶尔引入 1x 没有的错（威胁→感胁）。
**上行触发条件**（实测只占 31%）：`1x读数≠2x读数` 或 `2x acc<1` 或行内应含破折号。
**残余 4 条三个通道都错**（行——孤立条/种种幻影…/短行空白）：只能靠像素裁定或带上下文整面板读——回到⑥节裁定表。

远端时延双峰（同日实测）：队列空时 52 条 14s（jobs=6）；高峰单条 20~60s。多图一律 `--jobs`；
成本估算按当日实测，别用历史数字。

细目与逐条对照：`gui-test/.02/bench/report.json`，重跑：`python3 gui-test/.02/bench/run.py build|local|remote|report`。

## 陷阱速查（全部实测踩过）

| 坑 | 症状 | 防线 |
|---|---|---|
| 裁窗右缘吞字 | 行尾缺 满/野/。/」 | ys-text 截断告警；宁宽勿窄 |
| md5 相等误判稳定 | 提前判到底/白滚 | settle 校验 frame.seq 前进 |
| 滚轮无效还狂滚 | 26 步空转 | 探针滚动+行位置对比先行 |
| VL 大空白条幻觉 | 「2023」「y la 1000-000」 | 紧贴墨迹裁条+2× |
| 孤立破折号条 | 云端也读不出 ——（三通道全错） | 带上下文整行/整面板读 |
| 短行幻影标点 | 「种种」被两通道都读成「种种…」 | 像素裁定（行尾零墨逆） |
| 服务端双重编码 | '噩梦…'→'å™©æ¢¦…'（同图确定性复现） | 客户端已自动 latin-1→UTF-8 修复 |
| 右缘暗角区阈值法 | 全列"有墨"误判 | 邻近短行同区参照对比 |
| 显示省略行尾标点 | 以为 OCR 丢字 | 双通道都无→按原样保留并注明 |
