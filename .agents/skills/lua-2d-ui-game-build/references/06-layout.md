# 06 布局（单屏 / 双屏 / 满幅 / 画布自适应）

> **本章的核心教训**：布局问题看起来是"文字挤/位置怪"，但本次三个最贵的布局 bug 里**两个的真因不在布局**——
> 一个是**函数中途抛错导致后半段没执行**（`layoutDual` 的 nil 全局），另一个是**层序遮挡**。
> 所以排查布局问题前，先按 `14-diagnosis.md` 确认"函数跑完了吗、元素被盖住了吗"。
>
> 出处：`18-evidence.md` D 组 4 条 + C6 + L1；代码：`lua/main.lua:3150+`（`FN.layoutDual`）、`3128`（`placeBoard`）。

## 1. 坐标系与基准（抖屏/布局共用一套真源）

**规则**：元素的"基准坐标"在创建时存进实例表，之后**所有位移都基于基准 + 偏移**，不要用字面量重算。

```lua
-- 抖屏实现里的注释（原文，说清了这条规则）
-- 基准坐标在创建时存进 cellBX/cellBY/frameBX/frameBY（唯一真源，不再由字面量重算）。
```

**为什么**：抖屏、布局重排、双屏偏移三者会叠加。如果每处都自己算，改一个就会和别处错位。
- 双屏：`g.boardOX` 是盘偏移，抖屏坐标 = **基准 + 盘偏移 + 抖动**。
- 布局重排：先复位抖动（`stopShake(true)`），再按基准重算。

**判据**：能回答"这个元素现在的坐标由哪几项相加而成"，并且只有一处代码在写它。

## 2. 双屏布局（本项目定版参数）

| 项 | 值 | 理由 |
|---|---|---|
| 两盘中心 | `±280`（从 `±320` 收窄） | 用户要求"往中间移动一点"（T11） |
| 键位说明 | **分列两盘正下方**：P1 左 / P2 右，各 520 宽 | 放在棋盘投影区外，不被格子压 |
| 中缝 | 席位染色 + 分割装饰 | 让"两盘"读起来是两个玩家 |
| HUD（每盘） | 收在各自栏内（不要写死 `x=400`） | 写死会落到右盘内部（真实翻车） |

**真实翻车清单**：
1. `keyA-C` 硬编码 `x=400` → 在 1600 画布下落在右盘内部 → "AI 盘 HUD 压进棋盘"。修法：挪进右栏空区（`x=600 / 360 宽`）+ 字号 14 防裁。
2. 准备提示 `hint` 没在双屏布局里摆位 → 压在底栏操作提示上。修法：`hint` 上移（`-(halfH - 96)`）。
3. `G[2]` 的 `renderHud` 覆盖了 `keyA-C` → 右侧叠字。修法：HUD 摆位**单源收口**（只由 `layoutDual` 写）。

**判据**：
- 双屏必须**单独出图**核对（单屏图上永远看不出双屏问题——这是本次的教训：只验了休闲单屏，双屏的三个布局问题全靠用户箭头标出来）。
- 布局用例断言**关键元素坐标**（本项目 `25-ai-battle-dual-layout` 有 8 条断言）。

## 3. 布局函数的三个坑

### 坑 1：引用别处的 local（nil 全局）
```lua
-- ❌ 错误：halfH 是 layout() 里的 local，在 layoutDual() 里是 nil
place(botBanner, 0, -(halfH - 96), W - 180, 48)
-- ✅ 正确：画布尺寸在函数内现算
local _, H = game:GetCanvasSize()   -- 或从 CANVAS_H 取（模块级、由 layout 写入）
```
**症状**：每帧抛 `attempt to perform arithmetic on a nil value (global 'halfH')` → **函数从中断点返回** → 后半段（HUD 复位 / 隐藏收口 / `hudNext` 归位 / 结尾 print）**全不执行** → 外观是"文字挤压/双影/标签贴顶"。
**判据**：搜 `lua-error`；或看函数**结尾的锚点日志**在不在。

### 坑 2：双写位被 layout 复活
布局复位段里如果有 `SetVisible(true)` 或重新 `setText`，会把"已隐藏的 textbox 份"重新显示 → 双份文字。
**判据**：`grep -n 'SetVisible' lua/main.lua` 逐条确认没有复活隐藏位。

### 坑 3：文字位没参与布局
新增一个文字位（如常驻提示）忘了加进布局循环 → 它的坐标是创建时的默认值 → 压在别的东西上。
**判据**：布局函数里有**统一的"文字位名单"循环**，新增位必须进名单（不是散装 `place()`）。

## 4. 满幅三栏（画面不要"空一大片"）

**症状**：1280 画布下内容挤在中间一窄条，或 1600 画布下四周空旷。
**解法**：**满幅三栏**——左（HUD/预览）/ 中（棋盘）/ 右（对手或信息），三栏按画布宽度分配，而不是"把棋盘放大到溢出"。

**判据**：出图里画面的左右边缘到画布边缘的留白 ≤ 一个 gutter 宽。

## 5. 画布自适应（**这是一个会失败的方向，别和别人混做**）

**症状**：按 1280 设计的布局，在 1600×900 下棋盘只有固定 300px 宽、四周空旷、卡片被拉开。

**我们试过并回退的方案**（务必读，避免重踩）：
- 做法：棋盘/卡片/字号整套按画布等比缩放（乘一个 `SC` 因子）。
- 第一次出图：标题「俄罗斯方块」**整行消失**——因为字号×SC 了但**框高没跟**（1.45 判据被破）。
- 第二次出图：双屏出现**多实例坐标系错位**（棋盘外框与格子不同步、HUD 文字横穿棋盘），**比放大前更糟**。
- 决策：**回退**，先部署"完整但四周留白"的基准布局，把 scale 列为"需要独立打磨窗口"的独立工程。

**为什么回退是对的**：
> 「这个优化方向是对的，但需要独立打磨窗口（等这轮系统稳了我单独做，**不和其他改动混**）。」
> 把"能玩的版本"和"实验性优化"混在一个 commit 里，会让回退变成灾难。

**如果要重做，前置条件**：
1. 所有尺寸都从 `CANVAS_W/H` 派生（**没有硬编码常量**）；
2. 框高/框宽判据全部按 SC 重算（字号、框高、宽度三者同比例）；
3. 单屏和双屏**各自出图**核对（双屏的实例坐标系是独立问题）；
4. **单独一个 commit + 单独一轮验证**，不和别的改动混。

## 6. 常驻提示的位置（用户明确要求）

**原话**（T19）：「准备之前，下面的建议操作提示，正式开始玩了，也不要移除呀。就几个字，不影响美观。你移除了，玩家记不住的。」

**规则**：准备页 + 局内都要有操作提示（局内小字灰色，按模式显示对应键位）。
**判据**：出图里局内底栏有键位提示；用例断言 `botBanner.text` 内容（控制断言读 text 字段，不受 visible 影响）。
**坑**：这条提示属于"常驻文字"→ 必须走双写（`05-layer.md`），否则被背景盖住（真实发生过）。

## 7. 布局交付自检

```bash
node qxqy/shot-style.mjs dual game        # 双屏 + 单屏各自出图
# 逐图核对：三栏满幅 / 两盘不重叠 / HUD 在自己栏内 / 键位说明在盘外下方 / 中缝装饰对齐
grep -n 'halfH\|CANVAS_H' lua/main.lua    # 检查布局函数引用的是哪个
grep -n 'SetVisible' lua/main.lua         # 确认没有复活隐藏位
node qxqy/runner.mjs 25 26 27 29          # 布局/键位/卡片的用例
```
**必答**：
1. 每个元素的坐标只有**一处**在写吗？
2. 双屏和单屏**各自**出图核对过吗？
3. 布局函数引用的画布尺寸是不是函数内的 local？
4. 新增文字位进布局名单了吗？
5. 常驻提示在局内还在吗？
