# 性能（帧预算/零分配/探针）

> 出处：复盘表 F1。用户原话「卡的要死玩不了一 点」。

## 1. 测量先行
- **交替对照法**：共享宿主负载污染 wall-clock（同版本两次 0.34 vs 9.8ms）→ 版本序列必须 A/B/B/A 交替取中位。
- 探针：`playStep` 每帧耗时（`/tmp` 下的探针脚本模式：playStart→循环 playStep+读 performance），报 mean/p90/p99。
- 目标：**p99 < 16.7ms**（60fps 帧预算）；>50ms 帧≈秒级掉帧。

## 2. 两个实测元凶（模拟器 Lua）
1. **无效特征计算**：权重已定 0 的评估特征仍全盘扫（每候选 ×34）→ **算完乘 0 扔掉**。修：权重全 0 时 `if` 短路跳过。
2. **JS-Lua 解释器的 GC**：每次评估建表/闭包触发分配（68 次/帧 → 26.6ms）→ **热路径零分配**：落-评-撤四格 + scratch 复用 + 坐标打包（避免每帧建表/建对象）。
- 通用：`模拟器 Lua 是 JS 实现的解释器，表/闭包创建比原生贵一个量级`——每帧多次调用的函数必须零分配。

## 3. 静态预算
- 背景池实例 ≤18（每模式 ≤14 组图元 + wash 1 件）；超了 `mode theme=X bg=N/M` 日志会报溢出（溢出=静默丢元素，v2.7 实测丢 2 个）。
- 每帧只写变化值（脏检查）；不要每帧重建实例。
