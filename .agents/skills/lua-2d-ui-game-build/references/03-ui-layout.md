# 渲染层（文字/控件/层序/双写/布局）

> 出处：复盘表 C1–C13、C7、C9。

## 1. 文字三判据
- **框高**：`h ≥ fontSize×1.45+4`，不满足**整行静默不画**（差 0.8px 也是零渲染）。
- **宽度**：超出 `width-4` 静默裁尾/裁半字（「得分1?2」「↓落卜」「R重升」——都是框不足，不是字体）。
- **对齐**：authoring 默认 Top；真机只收**枚举**（`Enum.TextHorizontalAlignment[值]`；字符串直传被 pcall 吞，日志 `ui fail`）。

## 2. 层序铁律（最有价值的一条）
- **运行时实例后建在上；服务端 textbox 永远在实例层之下**。
- 推论：任何常驻文字（HUD/横幅/提示/标题页）若同屏有背景/遮罩实例，**必被盖**。
- **解法=双写**：实例份可见 + textbox 份隐藏（仅保断言）。隐藏必须挂「必经路径末尾」（layout/layoutDual/startIfWaiting 三处都收口）——单点隐藏会被后续 place/SetVisible 亮回来。
- `setText` 单点收口：目标控件有同名实例就**同步写实例份 text**（否则 40+ 处 setText 写着但看不见）。
- `SetVisible(false)` 对运行时实例真机不生效（D581）→ 用**挪出画布**兜底。

## 3. 布局函数（C9 血泪）
- **画布尺寸在函数内现算**（`game.GetUICanvasSize()`）——引用别的函数的 local（如 `halfH`）会变成 nil 全局 → **每帧抛错、函数从中断点返回、后半段全不执行**（外观=双影/错位/贴顶）。
- 判据：`playGet().logs` 搜 `lua-error` + 关键锚日志（`layout dual`）存在。
- 双屏布局必须在**棋盘投影区外**（1600 画布下中央约 330 宽、手机画布更窄）：文字/键位卡放两侧 gutter；底部三块文案同行**不相交**（左键位 540 / 中提示 260 / 右状态）。

## 4. 满幅与模板
- 竖长玩法（10×20 棋盘）占高后左右必空 → 靠**两侧内容面板+上下横幅**填满，不靠放大棋盘。
- **模板越少越好**：每个客户端模板导入后可能重编号（真机 1073741849 vs authoring 1073742105）→ 用 `TEMPLATE_GUIDS={真机值,authoring值}` 逐个试；服务端 textbox 按 name 寻址最稳。
- **实例层审计**：出图机的 fits 只查布局 textbox，抓不到实例文字 → 写 `audit-inst` 逐节点读 `textLayout`（例子：115 条文字 0 违规）。

## 5. 文字分层原则
- 标题页文案走**实例文字**（服务端 textbox 被展台墙压住）。
- 局内 `botBanner` 是唯一常驻提示位，`bannerTimer` 是它的占用闸（事件横幅优先、到点恢复）。
- 结算明细行 `settleExtra` 放旁白；颜色走 `settleNoteRGB`，否则每帧被统一色覆盖。
