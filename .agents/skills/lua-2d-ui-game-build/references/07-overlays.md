# 07 浮层与模态（结算 / 倒计时 / 帮助 / 引导 / 终局冻结）

> 浮层是"玩家一眼看到的功能"，也是本次被抓最细的地方：结算被棋盘盖住、三个选项没主次、
> 一方死了另一方还能玩、帮助页不暂停、结算回不了主页、倒计时数字不显示。
> 每一条都有明确的**交互规则**和**判据**。
>
> 出处：`18-evidence.md` L2/L3/L5/E4/E5、C7；代码：`lua/main.lua:491-612`（结算层）、`2482`（倒计时）。

## 1. 浮层通用规则

| 规则 | 说明 |
|---|---|
| **整套实例化** | 浮层必须建在运行时实例层（服务端 textbox 永远在实例之下，会被棋盘吃掉） |
| **构建顺序 = 层级** | 遮罩 → 描边/边框 → 面板底 → 文字/按钮（实例"后建在上"） |
| **显式置顶** | 整页浮层最后再 `SetAsLastSibling` 一遍（防后续创建的实例插到上面） |
| **懒创建，不要"常驻+隐藏"** | 第一次需要时才 `pcall(build)`，用完 `Destroy`（幂等：重开/退出两个入口都调）。因为 `SetVisible(false)` 对运行时实例**真机不生效**（D581），"常驻+隐藏"在真机上会一直露着 |
| **生命周期成对** | `build` 与 `destroy` 必须成对；销毁用**固定槽 + 数字 for**（`ipairs` 遇 nil 会静默跳过） |
| **模板双形态** | 编辑器新建的容器模板可实例化；**GIA 导入的也可能可**（按存档区分，D639 修正 D582）→ 探测失败要退化到横幅方案，不能直接崩 |
| **键盘与鼠标共用动作表** | 结算的 R/V/Q 鼠标点击与键盘走**同一张动作表**（`SETTLE_ACT`），否则同帧双触发（V 被点两次） |
| **模态要真冻结** | 帮助/结算打开时，游戏主循环该停的部分必须停（见 §4/§5） |

**判据**：进出浮层两次，元素数量不变（否则销毁漏成员 → 第二次出现两个面板）。

## 2. 结算页：三选项必须有主次 + 三态

**用户原话**（T42）：「下面明明是三个框，但是高亮样式完全一样，没有区分度，**本质上都是没有审美**。」

**三级样式表（已验证）**：
| 层级 | 选项 | 样式 |
|---|---|---|
| **主** | 再来一局 `[R]` | 模式色**实心胶囊** + 金环 + 25 号白字 |
| **次** | 回主页 `[V]`/`[M]` | 白胶囊 + 金边 + 20 号 |
| **弱** | 明细 `[Q]` | 纯文字，次色，18 号 |

**三态**：
| 态 | 处理 |
|---|---|
| 常态 | 如上 |
| 悬停 | **加深 13%**（不要提亮——白字压在提亮的绿上对比会垮掉，实测） |
| 按下 | **加深 26% + 下沉 3px** |

**必须有的功能**（用户逐条点名）：
- `[V]/[M]` **回主页**（所有模式，全链复位）——原话：「进入结算之后，没有设计回到主页，玩家只能重新玩当前模式。」
- 胜负横幅提示"按 R 回菜单"；
- 对家战况（双屏时显示对方状态）；
- 结算页**不能被棋盘/遮罩压住**（见 `05-layer.md` §3 的构建顺序）。

**判据**：出图三态各一张、可区分；用例断言"回主页后模式正确、分数清零、HUD 复位"。

**遮罩只压暗实例层**：`dimColor` 这类压暗操作只作用于实例层，服务端 textbox 不会被压暗——
所以"用遮罩把旧界面压暗"这种做法对 textbox 无效（它们本来就在最底层，看不见；能看见的都是实例）。

## 3. 倒计时（"数字搞大一点，放在中间"）

**用户原话**（T19）：「还有倒计时，数字你搞大一点，放在中间不行吗？」

**定版参数**：
- 字号 **120**，屏幕**正中**；
- 框 **500×190**（框高必须 ≥ 1.45×120+4 = 178）；
- 每秒 **sin 缩放弹跳** 120→146；
- 用**运行时 textbox 实例**（不是服务端 textbox，否则被棋盘吃掉）。

**坑**：峰值字号 146 时的框高要按 **146** 算（不是 120）——否则峰值帧**整行不画**（真实翻车：倒计时大字在峰值瞬间消失）。

## 4. 帮助页：真时停 + 全局可用 + 容器隐喻

### 4a. 真时停
**用户原话**（T26）：「如果是单人模式，按下这个会时停，但是我实际测试，没生效。」

**规则**：局内打开帮助 → **重力 / AI / 计时 / DAS 全部停**（不是只画个遮罩）。
**判据**：用例断言"开帮助 2 秒后，棋盘状态与开启前一致"（块没下落、计时没走、AI 没动）。

### 4b. 全局可用
**用户原话**（T26）：「按下h查看帮助，应该是全局存在的。不然玩家怎么知道呢」

**规则**：H 在**标题页、准备页、局内**都能开；标题页要有**可见的 H 提示**（不是只写在代码里）。
**判据**：出图里标题页有 H 提示；每个模式都能开到帮助页。

### 4c. 容器隐喻（为什么被打回三次）
**打回链**：T6（加说明）→ T26（要高亮/时停/全局）→ T37（「字体很模糊……纯黑白，让人没有看的欲望」）→ T40（「说了要用新的ds模型，空上下文去做。打回重做。」）

**关键学习**：帮助页不是"规则堆砌"，要有**容器隐喻**：
- 定稿版 = **「冒险家协会·委托板」**：奶油纸面 + 描金圆角框 + 派蒙气泡（阅读顺序）+ 左栏键帽胶囊 7 行 + 右侧四张模式委托卡 + 底部算分标签（100/300/500/800 四角色色阶梯）+ 两条难度机制说明。
- 其他备选隐喻：派蒙的旅行手记 / 凯瑟琳的委托板 / 冒险家协会公告。
- **目标不是"信息完整"，是"玩家愿意读"**。

**排版判据**：
- 字号 **≥19**（16 号在真机糊）；
- 关键行用**模式强调色**高亮（≥2 色，不要纯黑白）；
- 左栏是键帽胶囊（一行一个键位），正文是卡片不是长文本墙。

## 5. 终局冻结（一方失败后另一方不许继续）

**用户原话**（T11）：「并且，一方失败了，另外一方还可以继续操作。」

**规则（MODE_OVER 状态）**：任一盘死亡 →
- **双方输入全部拒收**；
- 重力 / DAS / AI 全停；
- 只推结算层动画；
- `R` 回菜单。

**判据**：用例断言"一方死后，另一方按键无效果、棋盘不再变化"（本项目 `33-modeover-freeze`，5 条断言）。

## 6. 引导页（双人/合作模式必须有）

**用户原话**（T6）：「设置双人，为什么没有引导，那玩家怎么知道要怎么操作？」

**规则**：
- 准备态显示「按 XX 键准备」+ ready 进度（`P1 ✓ / P2 ✓`）；
- 引导卡：P1/P2 各自动作说明（键位胶囊）；
- 任意键确认 → 3-2-1 大字倒计时 → 开局；
- **键位说明分列两盘正下方**（不在盘内，不被压）。

**判据**：双人模式下出图能看到两份独立的键位说明；用例断言双方 ready 后才能进倒计时。

## 7. 浮层交互的通用检查

| 检查 | 判据 |
|---|---|
| 浮层能被打开 | 每个入口（键/鼠标）都有用例 |
| 能关闭 | 关闭后游戏状态正确恢复（不是"半开"） |
| 不遮挡关键信息 | 出图：浮层在自己该在的层，没盖住要读的东西 |
| 模态真冻结 | 帮助/结算期间状态不变 |
| 销毁干净 | 进出两次元素数不变 |
| 有主次 | 同级按钮视觉可区分（出图三态） |
