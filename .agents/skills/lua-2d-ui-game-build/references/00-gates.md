# 00 阶段门（Phase Gates）

> **这份文件解决什么问题**：25 小时里有 **12 次用户打回**，没有一次是"不会写代码"，全部是**在错误的阶段宣布完成**——
> 规则还没算清就开始写界面；界面还没出图就说"修好了"；真机还没部署就说"请试玩"。
> 所以本技能的第一件工具不是代码模板，是**阶段门**：每个阶段有明确的"进入条件 / 交付物 / 过关判据 / 不许跨越的红线"。
>
> **出处**：`18-evidence.md` G 组（验收方法）、F 组（部署）、§0 代价总账（12 次打回）。

## 0. 全景

```
P0 规则设计 → P1 画布与骨架 → P2 最小可玩 → P3 界面成形 → P4 手感与反馈
                                                        → P5 完整度（多模式/对抗/AI/文案）
                                                        → P6 模拟器体感 → P7 真机交付
```

**三条永不跨越的红线**（跨了就是本技能记录过的那 12 次打回）：
1. **没有出图就宣布界面已修** → 用户会说"和没修一样"（T43）。
2. **模拟器（网页）没过就通知用户去真机** → 用户会说"我不信你了"（T5）；原话（T41）：「模拟器上得先通过了才通知我去游戏真机测试」。
3. **用例全绿就宣布功能可用** → 用例只覆盖 L1 逻辑；L2 渲染、L3 宿主全靠别的仪器。

## P0 规则设计

**进入条件**：需求已到手（哪怕只是一句话）。

**做什么**：
1. 把需求拆成**可算的规则**：每个数值、每个判定、每个模式的状态转移。
2. 每个数值都问一句"**能手算复现吗**"——不能就别写进代码。
3. 列出**模式 × 界面 × 文字**矩阵（后面 P3/P5 要靠它逐格核对）。
4. 需要外部算法就**先查论文/规范**，不要手调（见 `10-ai.md` §1）。

**交付物**：设计文档（规则/数值/模式状态机/矩阵表）。

**过关判据**：
- [ ] 每个数值有推导或出处（不是"感觉差不多"）。
- [ ] 每个断言的数学命题真值为真（见下方"判据自己写错"）。
- [ ] 模式矩阵覆盖所有模式 × 所有界面。

**本阶段真实翻车（必读）**：
| 翻车 | 后果 | 教训 |
|---|---|---|
| 断言写成「任意连续 **12** 块必含全部 7 种」 | 命题为假（袋 A 尾 6 + 袋 B 头 6 可同缺一种），当前种子下侥幸没踩到 → **用例假绿** | 窗口最小正确值是 **13**（6+7 或 7+6）。任何"保底"类断言都要构造反例验证 |
| 验收线写成「hard 档消行率 ρ ≥ 0.50」 | 物理不可能（每块 4 格 / 每行 10 格 ⇒ 上限 0.40）→ 被实现者驳回 | 先算物理上界，再定验收线；强弱的真判据是**盘面平整度**不是 ρ |
| 规则"想当然"（出块纯随机、AI 与玩家两套账） | 到用户在真机上玩，才暴露"不公平/没反馈" | 需求里的每个形容词都要翻成数值或判据（"不公平"= 需要一个保底机制） |

**该读**：`02-gameplay.md`、`10-ai.md`、`09-copy.md`（如果需求里有文案/世界观）。

## P1 画布与骨架

**进入条件**：P0 的设计文档存在（哪怕粗糙）。

**做什么**：控件树/画布/帧循环/输入注册/模块加载/日志锚点。

**过关判据（真机日志里必须逐行出现）**：
```
canvas <W>x<H>          ← 画布尺寸探测成功
tpl guid=<n> / hit=<n>  ← 必填模板探测成功（不是占位符）
cellCount=<n>           ← 批量实例化的元素数对得上
listen ok ×N            ← 每个键位都注册成功（N = 键位数）
module ok <mod> ×M      ← 每个 require 模块都加载成功（M = 模块数）
```
- [ ] 模拟器启动 → 日志出现上述全部行。
- [ ] 真机启动 → 日志出现上述全部行（**本阶段就要验一次真机**，别等到 P7——200-local 这类错误只有真机报）。

**红线**：
- **不要**在骨架阶段写完整玩法。骨架先证明"能画出一个方块 + 收到一个按键"。
- **必须**在骨架里就放**版本指纹**（`menu stage n=` / `hud inst n=` 之类），后面每次"还是老板版"都靠它定位（`12-deploy.md` §4）。

**该读**：`19-starter.md`（12 个部件清单）、`12-deploy.md`（首次部署）、`13-device.md`（真机限制）。

## P2 最小可玩（逻辑闭环）

**进入条件**：P1 的日志锚点全绿。

**做什么**：输入 → 状态 → 渲染的最小闭环 + **可复跑的用例**。

**过关判据**：
- [ ] `node qxqy/runner.mjs` 全绿（此时用例数通常 10~20）。
- [ ] 用例覆盖：每个键位一条、规则闭环（碰撞/消行/计分）、结束态可达、重开。
- [ ] **手算能复现**用例里的每个数字（得分/消行/等级）。
- [ ] 固定种子探针能复现同一局面（否则后面调 AI/难度无法对照）。

**红线**：
- **改 lua 必须先 build**（runner 读的是存档副本），否则你测的是上一次的代码——这是"假绿"的第一号来源（`01-verification.md` §3）。
- 用例断言里的期望值**不许凭感觉填**；`rho`/概率类断言必须写清统计口径（多少块、多少次、什么种子）。

**该读**：`01-verification.md`、`02-gameplay.md`、`03-input.md`。

---

## P3 界面成形（本次最贵的一关）

**进入条件**：P2 全绿。

**做什么**：标题页 / HUD / 结算 / 帮助页 / 引导 —— 全部页面成形。

**过关判据（少一条都不许进 P4）**：
- [ ] **出全部页面图**（标题 / 游戏内 / 双屏 / 结算 / 帮助）× **每张都 `read_image` 逐字读过**。
- [ ] 每张图逐字核对：**没有裁字**（半字、错字、首字缺失）、**没有遮挡**（文字压文字、被背景盖）、**没有双份**（同一信息出现两次）、**没有超出画布**。
- [ ] 每个常驻文字位的层级正确（见 `05-layer.md`：服务端 textbox 永远在运行时实例之下）。
- [ ] 每个框的框高满足 `h ≥ 1.45×size + 4`；框宽 ≥ 最长文案宽度（见 `04-text.md`）。
- [ ] 模式 × 文字矩阵逐格核过（不该出现的玩家编号/键位不许出现）。

**为什么这一关要这么严**：本技能记录里用户在这一关打回 **≥6 次**，其中 4 次是「接线了/代码改了」但**画面没有变化**。
> 用户原话（T41）：「不要太自信，要去看实际渲染出来的画面。」
> 用户原话（T45）：「不要偷懒，把所有页面的渲染的图片，全部自己读取一下。」

**红线**：
- **不许**用"控件属性/探针读数"代替出图（`01-verification.md` §2 陷阱 1）。
- **不许**只出"改动的那一页"——改动会通过层序/布局函数波及其他页（真实案例：修双屏布局把单屏 HUD 弄丢了）。
- **不许**把"我自己看代码没问题"当结论。

**该读**：`04-text.md`、`05-layer.md`、`06-layout.md`、`07-overlays.md`、`08-art.md`。

## P4 手感与反馈

**进入条件**：P3 全绿（全部页面出图无问题）。

**做什么**：DAS/锁定延迟/音效/动画/鼠标三态/hover 音。

**过关判据**：
- [ ] 每键位一条断言（含"松开后立即停"这类行为断言）。
- [ ] 交互三态（常态/悬浮/按下）在画面上**可区分**——出图对比三张。
- [ ] 有音反馈的动作有日志/用例记录（音频断言只在 runner 里做，不靠耳朵）。
- [ ] 动画帧数/时长有具体数字（"多做几帧""更丝滑"要翻成帧数与插值曲线）。

**红线**：**按住类操作必须有时间上限兜底**——平台的"松开"事件可能丢失，只靠事件必然出现"按一下一直走"（`03-input.md` §2）。

**该读**：`03-input.md`、`07-overlays.md`、`11-performance.md`（动画/特效是帧预算大户）。

---

## P5 完整度（多模式 / 对抗 / AI / 文案）

**进入条件**：P4 全绿。

**过关判据**：
- [ ] **每个模式一条端到端用例**（进模式 → 玩 → 结束 → 回主页全链）。
- [ ] 模式 × 文字矩阵全过；不该出现的文案已清（全文件扫描一遍关键词确认只剩合法分支）。
- [ ] AI 有强度判据（ρ + 盘面平整度）且**演示/代打档位正确**（`10-ai.md` §3）。
- [ ] 对抗机制有公平性论证（洞位/序列不能影响对手的随机性）。
- [ ] 文案落点 ≥3 通道（标题/局内/结算），不是只挂在标题页。
- [ ] HUD 计分在**全部模式**都有绑定（AI 消行也计分、也出声、也抖屏）。

**红线**：**每个模式单独出图**。双屏模式的布局问题在单屏图上永远看不出来（真实案例：只验了休闲单屏，双屏的三个布局问题全是用户后期用箭头标出来的）。

**该读**：`02-gameplay.md`、`09-copy.md`、`10-ai.md`、`06-layout.md`。

---

## P6 模拟器体感（上真机前的最后一道）

**进入条件**：P5 全绿。

**做什么**：在网页模拟器里**自己完整玩一遍**（不是看用例，是玩）。

**过关判据**：
- [ ] 每个模式各玩一局（含"怎么输"）。
- [ ] 按键手感自己感受过（单击/长按/连移/硬降/暂存）。
- [ ] 结算 → 回主页 → 换模式全链走过。
- [ ] 帮助页/引导页在**每个模式下**都能打开并关闭。
- [ ] 期间日志面板开着，看到预期的锚点行（`das stop` / `hold swap` / `menu stage` …）。

**红线（本技能最硬的一条）**：
> **P6 没过，不许通知用户去真机测试。**

用户原话（T41）：「模拟器上得先通过了才通知我去游戏真机测试。」
代价：真机每一次试玩都要用户手动切图重载、等游戏启动、描述现象——**用户在替我们做测试**，而这类本可以自己发现的问题出现了 4 次。

**该读**：`13-device.md`（模拟器特有的坑：按键五重门、浏览器音效策略、服务僵死）。

## P7 真机交付

**进入条件**：P6 全绿。

**过关判据**：
- [ ] 部署三处 + 多模块 register 全过（`12-deploy.md`）。
- [ ] 真机日志的**版本指纹**逐项对账（证明跑的是新版）。
- [ ] `grep -cE '^local '` ≤150（200-local 预防）。
- [ ] 真机日志全链路：`module ok` ×M、`tpl guid=`、`cellCount=`、`hud inst n=`、`listen ok` ×N、`lua-error` 零条。
- [ ] **让用户切出地图再切回**（内存版会覆盖写盘/不重载）。

**交付报告必须三栏**（`01-verification.md` §4）：
1. 已验证什么（注明层级：编译/注入/结构 = 结构层；日志 = 行为层；出图 = 渲染层）
2. 尚未验证什么
3. 需要用户确认什么

**红线**：真机编译错误**不进 runner**；`pcall` 会吞掉 API 报错。所以真机首试必须自己看弹窗/日志，别只信 CLI。

### 用户不在场时，我能自证到哪一层（边界说明）

| 层 | 能不能自己完成 | 说明 |
|---|---|---|
| L0 规则 / L1 逻辑 | ✅ 能 | runner 用例全自动 |
| L2 渲染（模拟器出图） | ✅ 能 | `shot-style` + `read_image`，不需要用户 |
| 模拟器体感（网页） | ⚠️ 部分 | 能起服务、能读日志；"手感"要人 |
| L3 真机（加载/编译/日志） | ❌ 不能 | 真机日志要用户开图触发；**但部署动作与静态预检可以自己做完** |
| 用户级确认 | ❌ 不能 | 只能由用户给 |

**结论**：用户不在场时，把 P0–P6 全部做到绿，并把 P7 的**部署 + 静态预检**做完（三处 sha、registryEntries、注入版数字形态、local 预算），
然后交付一份"待你触发真机"的最小动作清单。**不要**把"我已部署"说成"真机通过"。
