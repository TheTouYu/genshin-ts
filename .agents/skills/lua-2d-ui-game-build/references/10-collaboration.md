# 协作（多代理/提交/部署纪律）

> 出处：复盘表 G1–G5。团队自己踩的坑，代价=数小时返工。

## 1. 多代理同文件纪律（三次覆盖事故）
1. **写盘前**：`git diff HEAD --stat` + `git diff HEAD <file> | head` 看全量工作树，发现别人未提交的段先停下来问。
2. **单元即 commit**：每完成一个可验证单元立即 commit（单文件多任务时，commit 消息注明归属）。
3. **落树即广播**：写盘后立刻告知并行队友「文件已变」。
4. **禁整文件重放**：不许整文件 write/checkout/replay 覆盖（重放=只重建自己的差异段）。
5. **提交边界渗透**：改动在 HEAD + 用例绿 = 完成（归属写进 commit message），不要为了「纯净」反复回滚重放。

## 2. 提交卫生
- 精确暂存：`git add` 列具体文件；提交前 `git status --short` 核对不卷别人。
- **commit 后哨兵**：`git show HEAD:<file> | grep -c <自己的标记>`（防空壳 commit——message 对而内容没进）。
- 大文件/图片单独提交（不卷入代码 commit）。

## 3. 模型可靠性
- 队友连续 failed（glm）时：**关键路径换强模型**（DS），并把任务拆成「每轮独立可交付」。
- 子代理空上下文任务书必须自包含（路径/命令/判据/验收/约束），不能引用「上一轮」。
- 等待子代理时禁止空转轮询（完成会主动回报）。

## 4. 交付节奏
- 用户定的验收流程：**模拟器出图逐字核对 → 图给用户 → 用户确认 → 才通知真机**。
- 每轮收尾四件套：`LINES.md` 断点行 + 本线 dossier + `03-state.md` 读数 + `05-open.md` 缺口。
- 用户反馈の翻译：感受（「卡」「丑」「不太会」）→ 数值/判据（帧耗时/对比度/ρ+stack）→ 再实现。
