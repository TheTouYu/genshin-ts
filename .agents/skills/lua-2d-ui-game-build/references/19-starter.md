## 0. 脚手架从哪来（"连一个能出图的工程都没有"怎么破）

不知道 4173 试玩服务怎么起。三条路：

| 起点 | 怎么做 |

**试玩服务**：`http://127.0.0.1:4173/editor`（`/play` 直开 404，必须从编辑器点「▷ 试玩 ↗」）。
保存位置：**模拟器工作区** `~/qxqy-workspace/<proj>.save.json` 才是网页读的那份（仓库那份给 runner 用，见 `12-deploy.md` §1）。

> **边界**：本章负责"工程已有、要按什么顺序建 12 个部件"；"怎么从零把生产线搭起来"属于 `simulator-2d-route`，

## 2. 建造顺序（对应阶段门）

**过关**：标题/游戏内/双屏/结算/帮助**各出图 + 逐字核对**（`01-verification.md` §4 的八项清单）。

## 3. 最小骨架的"必须项"清单（少一个后面必返工）

```
□ 模块加载有回退（模块缺了要报错并走 textbox 兜底，不能整段死）
□ 实例表结构（单例状态 → per-instance），双屏前就做好
□ 画布尺寸探测 + 全局常量（不要硬编码 1280）
□ 文字收口 setText（一次做对，后面 40 处调用都受益）
□ 框高/框宽统一函数（不要每处手算）
□ 棋盘基准坐标存表（抖屏/布局共用）
□ KEYMAP 表驱动 + act() 路由（不要散装 listen）
□ DAS 时间上限兜底（从第一天就有）
□ 每帧步进上限（防卡顿雪崩）
□ 启动指纹日志（每个关键组件的计数）
□ 固定种子（可复现的探针）
□ runner 用例骨架（先有一条能跑通的）
```

## 4. 可以直接照搬的四个"结构决定"

| 决定 | 为什么 |
|---|---|
| **状态收进 `g` 实例表**，用 `G[1]/G[2]` 数组 | 双屏/多人需要两套独立状态；文件级单例会让第二盘共享第一盘的状态（本次重构 58 个变量、~570 引用点） |
| **服务端 textbox 只做断言，显示全走实例** | 层序铁律（`05-layer.md`） |
| **函数用 `FN.x = function()` 而非 `local function`** | 真机 200-local 硬限（`13-device.md` §1） |
| **事件回调第一行 `g = routePlayer(...)`** | 多盘模式下 `g` 会被帧循环改掉（`03-input.md` §5） |

## 5. 起步时的三次自查（每次改动后）

```bash
# ① 静态
grep -cE '^local ' lua/main.lua          # ≤150
lua5.3 -e 'assert(loadfile("lua/main.lua"))'   # 语法门（必须在这里先过）

# ② 逻辑
node qxqy/build.mjs                      # 生成 save.json（改 lua 必做）
node qxqy/runner.mjs                     # 全量或选择性

# ③ 渲染
node qxqy/shot-style.mjs all             # 出图 + 框高机检
#   ⚠️ 该脚本无 process.exit ⇒ 退出码恒 0；必须 grep 输出里的 "✗" 或 "文本判据失败"
```
