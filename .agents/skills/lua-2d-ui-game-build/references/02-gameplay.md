# 02 玩法规则（数值 / 出块 / 暂存 / 计分 / 难度 / 判负）

> 这一章的价值不在"俄罗斯方块怎么玩"，而在**每条规则的判据长什么样**——
> 用户的 8 点需求里有 5 点是玩法规则，而我们犯过两个**数学错误**（12≠13 窗口、ρ≥0.5 不可能），
> 还犯过一个**设计错误**（难度只有速度，玩家升到 12 级就卡）。
>
> 出处：`18-evidence.md` A 组全部 10 条；代码：`lua/main.lua:190-216`、`lua/tetris/config.lua:98-111`。

## 1. 出块保底（7-bag）与「13 窗口」断言

**需求原话**（T1）：「修复出方块的逻辑，太随机了会导致游玩不公平，需要在随机的基础上有保底」。

**实现**（`lua/main.lua:190-216`）：每袋 7 种各一个，Fisher-Yates 洗牌，首袋排除 S/Z 开局。
```lua
local function refillBag()
  local t = { 'I', 'O', 'T', 'S', 'Z', 'J', 'L' }
  for i = #t, 2, -1 do                 -- Fisher-Yates：6 次 rand()，确定性与均匀性
    local j = rand(i)
    t[i], t[j] = t[j], t[i]
  end
  if g.bagSeq == 0 and (t[1] == 'S' or t[1] == 'Z') then   -- 首袋排除 S/Z 开局
    for i = 2, #t do
      if t[i] ~= 'S' and t[i] ~= 'Z' then t[1], t[i] = t[i], t[1] break end
    end
  end
  g.bagSeq = g.bagSeq + 1
  for i = 1, #t do g.bagQ[#g.bagQ + 1] = { name = t[i], bag = g.bagSeq } end
end
```

**断言必须写 13，不是 12**（数学命题，务必抄对）：
> 「任意连续 **13** 块必含全部 7 种」成立，因为 13 = 6+7 或 7+6，任一 13 块窗口必然完整覆盖至少一袋。

**反例（12 为什么不行）**：袋 A 的尾 6 块（恰好缺 X）+ 袋 B 的头 6 块（恰好缺 X）= 连续 12 块可以同时缺 X。
> 这个错误是**我们自己写进用例的**，靠 review 抓出（commit `db00dce2`）。当前种子下侥幸没踩到反例——**这就是"用例绿但命题是假的"**。
> **教训**：任何"保底/覆盖"类断言，都要**主动构造反例**验证一遍。

**判据**：固定种子跑 100 块，滑动窗口 13 逐窗断言含全 7 种。

## 3. 暂存 Hold（含"防滥用"设计）

**需求演化**：
- T1：「增加储存一个方块的功能」
- T27（用户自己设计的防滥用规则）：「存入的时候如果已经存入了，则直接下来存入的快，并且把当前没有下落的快也下落。这么设计，稍稍给存入增加一点操作难度，以免玩家滥用这个功能。」

**规则表**：
| 情形 | 行为 |
|---|---|
| 槽空 | 当前块存入（正常） |
| 槽非空（交换） | **两块各进一格**：当前块先下落一格；槽里的块取出到出生位并立刻下落一格 |
| 交换时贴底/碰撞 | **当前块直接锁定**（`hold forced lock`，代价） |
| 一块内第二次 hold | `canHold` 闸拒绝（不能重复 hold） |

**键位**：模拟器键池**没有字母 C** → 用 **G = `KeyboardCraftspersonKey14`**。

**日志锚**（真机实测出现）：`hold swap in=O out=S cur_drop=1` / `hold swap out_drop=1`。
**判据**：交换后两块 y 各 +1；贴底场景出现 `hold forced lock`；bag 不受影响。

## 4. 计分：四条链路必须都通

用户的第 4 点其实是**一条可测的需求**：「ai操控游玩的，应该和玩家共享通用的游戏链路，音效和记分等反馈都不能少」。

**四条链路清单**（缺一条就是"AI 玩起来像假的"）：
1. 消行**计分**（进玩家/AI 各自的账本）
2. **进 HUD**（显示出来）
3. **响音效**
4. **抖屏**

**真实翻车**：v2 首版 AI 走"静音旁路"（四处 `if not isAI then` 把反馈全跳过）→ 用户报"AI 演示没有反馈"。
**修法**：去掉四处旁路，让 AI 与玩家走同一函数（`1a0e9e0f`）；但 `best`（历史最高分）**不记 AI 分**。

**计分表（实测值，`config.lua:48-53`）**：
```lua
SCORE   = { 100, 300, 500, 800 }   -- 1/2/3/4 行基础分（Tetris Guideline）× 等级
SOFT    = 1                        -- 软降每格加分
HARD    = 2                        -- 硬降每格加分
COMBO   = 50                       -- 连击：50 × (combo-1) × level
B2B     = 3/2                      -- 连续两次四消：基础分 ×1.5
```
**三条易错点**：
- `level` **从 1 起**，公式里用 `level` 不是 `level+1`；
- **空落（没消行的落块）必须同时打断 combo 与 b2b**（只打断一个是最常见的错）；
- 速度表要逐档可读——判据是"人手能否完成一次操作"，不是"数字好看"。

**难度二机制**（非速度轴，T37 要求"至少两个"）：
```lua
-- config.lua（用户定版，lead 批准 A+B）
DRYNESS_N = { 14, 10, 7 },   -- 机制A：连续 N 块无消行 → 顶起 1 行带洞垃圾（按等级段取值），到阈值清零重计
OBSTACLE  = { 0, 1, 2, 3 },  -- 机制B：开局障碍行数（Lv1-4 无 / Lv5-7 一行 / Lv8-10 两行 / Lv11+ 三行）
```
**判据**：两种机制都能在日志里观察到（`garbage n=` / 开局障碍行数），且**双盘独立洞位**。

## 5. 双人准备：必须双方各自确认

**需求原话**（T19）：「双人模式，这个准备你给我真的作好呀，要两个人都准备好了，才开始倒计时呀」。

**规则**：
- P1 按任意键 ready；P2 用 **P2 键组**（方向键 / X / F）ready；
- `ready` 状态**实时显示**（✓）；
- **双方都 ready** 才进 3-2-1；
- 倒计时：**120 号大字屏幕正中** + 每秒缩放弹跳（120→146）；
- AI 对抗模式：AI 预置就绪 + 玩家单键开始。

**判据**：一人 ready 时**不**倒计时（用例必须覆盖）；日志有 `guide ready p1` / `p2` 锚。

## 6. 判负：标准 topout

**需求原话**（T20）：「ai演示，ai操控是，游戏结束的判定提早了。实际上，还可以继续玩」。

**正确规则**：
- **唯一判负点 = 新块 spawn 时不可放置**（`spawn` 内判定）。
- 活动块被垃圾行顶到 → **不立即判死**，进入 0.5s 锁定延迟，玩家可自救。
- 不要"只查当前块所在列"就判定 top out（这是错误实现）。

**判据**：构造「顶到但还能救」的局面 → 不判负；construct「spawn 位置被占」→ 判负。

## 7. 对抗机制（垃圾行）

| 消行数 | 送给对手 |
|---|---|
| 2 | 1 行 |
| 3 | 2 行 |
| 4 | 4 行 |
| B2B（连续四消） | 额外 +1 |

**公平性要求**：
- 垃圾行的洞位用**独立的 `aiRand`**（不动主 bag 的 LCG），否则会影响双方出块序列；
- 受击有**抖屏**反馈；
- 重叠上移超出顶部 → 判负（这条要单独测）。

**判据**：日志 `garbage n=<k>`；双方 bag 序列互不影响（固定种子对拍）。

## 8. 旋转与 T-spin（**本项目未实现 SRS 踢墙**——照实写）

**实际实现**：包围盒旋转 `(r,c) → (c, n+1-r)`，**碰撞则放弃旋转**（无 kick 表，无 I 块专用形状）。
> **不要**在文档/汇报里说"我们实现了 SRS"——这次差点就这么写。

**T-spin 判定**：三面角判定（4 个角中 ≥3 个被占）。
> 因为无 kick，第四角常常悬空，所以"≥3 角"是本实现的合理口径。

**计分**：`400 × 行数 × 等级`，专属音效。
**用例**：正向（构造精确 3 角双消，跑了四轮迭代）+ **负向（不误报）**两条都要有。
**日志锚**：`tspin lines=2 bonus=800`。

## 9. 数值可复算（P0 的硬门）

每个数值都要能**手算复现**，写进文档：
- 消行基础分（1/2/3/4 行）、连击加成、等级系数、B2B、T-spin 加成、软降/硬降分；
- 出块序列（固定种子 → 已知前 N 块）；
- ρ（消行率）= 消行数 / 块数，**物理上限 0.40**（每块 4 格 / 每行 10 格）。

**判据**：用例里的每个期望值都能被手算或脚本复算出来；不能"看着差不多"。
