# 验证纪律（五层台阶 + 三栏报告 + 假绿清单）

> 出处：复盘表 G1–G5、D6、C8、C13。**每条判据的代价都真实发生过**。

## 0. 五层台阶（禁止用低级绿灯推断高级）

| 层 | 验什么 | 仪器 | 绿灯≠ |
|---|---|---|---|
| L0 规则 | 玩法规则/数值/难度（ρ、stack、计分表） | 手算+探针读数 | 逻辑正确 |
| L1 逻辑 | 状态机/输入/模式 | `runner.mjs` 用例 | 画面正确 |
| L2 渲染 | 控件/文字/层序/布局 | 模拟器出图 + read_image 逐字 | 真机正确 |
| L3 宿主 | 脚本/模板/挂载/编译 | 真机日志+弹窗 | 玩法正确 |
| L4 协作 | 多代理/提交/部署 | git log + 哨兵 grep | 代码正确 |

**铁律**：「UI 修复算完成」的定义=**L2 出图逐字核对通过**（G5：我三次说「接线了」，用户三次在画面里看不到）。
**铁律**：真机脚本改动后，「编译通过」只有 L3 日志/弹窗能证（D4：本机 lua5.3 loadfile 放过、真机编译报错）。

## 1. 三栏报告（每次交付必写）

```
### ① 已验证（标层级）
- L0/L1/L2/L3：具体命令+退出码+关键日志行
### ② 未验证（写清为什么）
### ③ 需用户在游戏内确认（可勾选清单）
```

## 2. 四元组（每个命令都报）

`跑了什么 / 工作目录 / 退出码 / 关键日志行`。缺一样=嘴验。

## 3. 假绿清单（每条都付过代价）

| 假绿形态 | 案例 | 防法 |
|---|---|---|
| 没 build 就跑 runner | 用例全绿但跑旧代码（G3） | 改 lua→build→runner；存档副本行数=磁盘行数+新标识符进档 |
| commit message 有、内容没进 | 空壳 commit（G2） | **commit 后哨兵**：`git show HEAD:<file> \| grep -c <标记>` |
| 控件属性对 ≠ 画面可见 | visible=true 但被盖（C7） | L2 出图核对 |
| 日志缺失 ≠ 行为不存在 | 日志窗关闭当反证（D6） | 先证日志通道活着（有 onstart/锚） |
| 本机语法门过 ≠ 真机编译过 | 200-local（D4） | 真机首试看弹窗/日志 |
| 模拟器网页 headless 无输入 ≠ 游戏无响应 | 五重门 artifact（D6） | 按 canvas 焦点/首快照/epoch/映射表逐条自证 |

## 4. 探针写法

- **日志锚**：每个关键路径一行动词化日志（`guide stage=`/`settle build ok`/`layout dual`/`bag=`/`hold swap`）。
- **锚缺失=该路径没跑**（C9：`layout dual` 缺失查出函数中途抛错）。
- **Lua 运行时错误默认静默**：`playGet().logs` 搜 `lua-error`（runner 只报断言红）。
- **交替对照法**：共享宿主性能测量必须版本交替（A/B/B/A）取中位，防负载漂移（F1）。
