# 08 审美与视觉系统（为什么我们的设计被打回三次）

> **这一章是用户最看重的**：他三次用同样的词打回——「太丑了」「做出自己的审美和分格来」「本质上都是没有审美」。
> 而我们对"审美"的第一反应（改颜色、加动画、换素材）**每一次都是错的**。
> 真正的教训是：被打回的是**结构与层级**，不是色相。
>
> 出处：`18-evidence.md` E 组全部 9 条。

## 1. 三版打回史（照着这个顺序理解"什么不是审美"）

### 第 1 版：彩色卡片（被否）
- 做法：标题页四张彩色大卡片横排在棋盘区中间 + 深空霓虹配色 + 棋盘压暗 45%。
- 用户（T12）：「游戏开始页面，这四个菜单，简直在**乱摆放**。应该自然的摆放在两边的空闲区域。还有，这个**颜色风格和大方块的搭配太丑了**，做出自己的审美和分格来！」
- **两个问题**：① 位置错（横排在中央棋盘区，把主角挡住了）② 色板与内容不搭（深空霓虹 + 彩色方块 = 眼神打架）。

### 第 2 版：两列卡片 + 收敛色板（仍被否）
- 做法：左右两列各两张（避开中央）+ 统一深底卡 + 模式色只做左缘色标条 + 选中放大 1.04。
- 用户（T19）：「游戏开始的那个界面不好看，**那四个款，太丑了**，我不喜欢那个风格。还有，下面那个动画一点都不好看，**还不如之前的字体放大动画**。」
- **两个问题**：① **卡片容器本身**被判死（用户不喜欢"四个色块"这种容器化设计）② **动效堆砌是负分**——三段轮播/滑动下划线/箭头 不如"字体放大呼吸"。

### 第 3 版：A2「主机列表」（接受，但仍是半成品）
- 做法：**去掉卡片容器**，每项只剩「左缘模式色细柱 + 38 号大字模式名 + 小字特色句」；选中 = 字放大 38→44 + 左柱加粗 + 整行高亮 + 其余淡出。
- 结果：用户接受方向，后续微调。
- **这版之后才懂**：用户要的是**"字与层级的克制"**，不是"更多装饰"。

### 帮助页：三次打回（同样的病）
- T6 加说明 → T26 要高亮/时停/全局 → T37「字体很模糊……**纯黑白**，让人没有看的欲望」→ T40「说了要用新的ds模型，**空上下文**去做。打回重做。」
- **定稿**才过：换成容器隐喻「冒险家协会·委托板」（奶油纸面 + 描金框 + 派蒙气泡 + 键帽胶囊 + 四张模式委托卡 + 底部算分色阶梯）。
- **教训**：**不是"改字号/加颜色"能救的，必须换结构（容器隐喻）**。

## 2. 审美方法论：五条可执行规则

### 规则 1：先定**容器隐喻**，再谈配色
空页面上的文字/数字永远是"堆"；给它一个**现实世界的容器**，信息才有位置和阅读顺序。

| 场景 | 差的写法 | 好的写法（容器隐喻） |
|---|---|---|
| 帮助页 | 43 行规则文字墙 | 冒险家协会**委托板**：左侧键帽胶囊 + 右侧四张委托卡 + 底部算分标签 |
| 结算页 | 三行等价文字 | 主行动**胶囊按钮** + 次行动描边 + 明细纯文字 |
| 标题页 | 四张彩色卡片 | 主机式**列表**（字 + 色标柱 + 一行特色句） |
| 引导页 | 一行键位说明 | 分列两盘的**键位卡**（键帽胶囊 + 动作名） |

**判据**：能用一句话说出"这个界面的容器是什么"（委托板/展台/记分牌/胶囊按钮组）。说不出来 = 还没设计。

### 规则 2：**层级**必须在视觉上可区分（主/次/弱）
用户对"三个框长得一样"的判词是"**本质上都是没有审美**"。

**做法**：任何一组同级元素，至少在三项里有差异：**尺寸 / 填充（实心 vs 描边 vs 纯文字）/ 色重**。
- 主：实心 + 最大 + 强调色
- 次：描边 + 中等
- 弱：纯文字 + 次色

**判据**：把界面缩小到 25% 看——主次还能分辨吗？能，才算有层级。

### 规则 3：**克制**——动效少即是多
用户明确否掉了：三段轮播、滑动下划线、箭头、"多做几帧更丝滑"式的堆砌。
用户明确接受了：**字体放大呼吸**（单一、循环、幅度小）。

**规则**：
- 一个界面**最多一个**持续动效（呼吸/脉冲），其余动效只在交互时触发；
- "突出变化"靠**幅度与节奏**（44 号字放大到 52 + 缓动），不靠"加更多元素"；
- 底层跑马灯/轮播类**默认不要**（信息密度高但阅读体验差）。

### 规则 4：每个可见图形都必须有**语义**
用户指着标题页一个方块问：「这个方块**意义不明**」。

**规则**：玩家看到的每个图形，必须能回答"它代表什么"。
- 装饰性图形 → 要么加标签/图例，要么删掉；
- 图标 → 必须配文字（真机上图标语义弱）；
- 模式色/角色色 → 必须在别处被复用（否则是随机颜色）。

**判据**：给每个图形写一行"它代表 X"，写不出来就是缺陷。

### 规则 5：**成体系**（配色 / 角色 / 字号 / 间距是一套，不是逐处挑）
本次定稿体系（可直接抄）：

| 维度 | 定稿 |
|---|---|
| 风格关键词 | 可爱 / 清新 / 原神 / 卡通（用户给的原话） |
| 底色 | 清透天空墙（近白 `#F7FCFF`）+ 奶油/描金组件 |
| 四模式色 | 休闲=纳西妲草绿 / AI对抗=刻晴雷紫 / 双人=少女樱粉 / 合作=甘雨冰蓝 |
| 棋盘 | 纸白格 + 模式色描边 |
| 字号阶梯 | 标题 38~44 / 副标 22~26 / 正文 19~21 / 小字 14~16 |
| 圆角 | 无原生圆角图元 → **2 块矩形 + 4 个角圆同色叠加** |
| 切风格 | `config.lua` 顶部 `STYLE_VARIANT='D'` + `STYLE_A/B/C/D` 四张表（chrome/modes/modeTheme/deco/bg）；main 只读 `THEME.*` / `MODE_THEME[mode].{bg,plate,frame,accent}` / `THEME.deco`。改一行 → build → 出图对照，零代码改动 |
| 具体色值（定稿 D） | 墙 `#F7FCFF` · 奶油 `#FFFDF8` · 描金 `#E8C88A`/`#B98A3C` · 墨 `#3E4A63`；休闲=纳西妲 `#7FCF6A` · AI对抗=刻晴 `#B39BEA` · 双人=少女 `#FFA8C8` · 合作=甘雨 `#8FD8F0` |

**为什么"角色色"有效**：给抽象的模式绑一个具体角色意象，配色就有了**依据**（不是"我觉得这个紫好看"，而是"刻晴的雷紫"），四个模式的差异也有了叙事。

## 3. 视觉工作的**流程**（比规则更重要）

### 必须用**空上下文的视觉模型**
用户原话（T12）：「请创建新的模型（用deepseek，因为它有视觉）去完成任务。」
（T40）：「说了要用新的ds模型，**空上下文**去做。打回重做。」
（T46）：「你那两个队友是glm吧，不可靠。创建新的队友，用ds」

**为什么空上下文**：带历史的代理会**沿用旧思路**——帮助页就是被同一个代理多轮小改（字号 16→19、加高亮色）而**始终不换容器**，三次打回。

### 视觉任务的标准循环（本次验证有效）
```
① 先出图（现在的状态）
② 自己用视觉能力看，列出 ≥5 条具体问题（不是"感觉不好看"，是"标题与卡片重叠 12px"）
③ 提 2~3 个**方案**（要结构不同，不是换色）
④ 选一个实现 → 出图 → 复看 → 迭代（至少两轮）
⑤ 交付时给：最终图 + 改动清单 + 为什么这么改
```
**关键**：**方案必须"真的不同"**。本次要求"不继承现有三栏文字墙的思路——卡片/手风琴/分页/图标化/对话气泡都可以，要真的不同不是换色"。

### 出图数量：多试
本次从 **44 张变体图**里筛出 A（甘雨雪山）/ B（纳西妲草木）/ C（刻晴紫雷）/ D（融合）四套，D 定稿。
**经验**：审美是**筛选**出来的，不是"一次想对"。给足候选再选。

## 4. 浅色 UI 的坑（本次踩过）

| 坑 | 现象 | 修法 |
|---|---|---|
| 浅底 + 霓虹字 | 对比度不足、发灰 | 浅底用**墨色**文字（不用霓虹青） |
| 全屏遮罩用深色 | 变"黑窗" | 遮罩用**低透明度暗色**，或浅色场景用奶白半透明 |
| 封闭舞台留 ghost | 半透明墙后面透出上一个界面 | 墙用 **A=255 不透明**（同时保留"舞台感"） |
| `imageColor` 透明度 | **真机不可靠**（A 通道未验证） | **胶囊/卡片用不透明预混色**（半透明重叠会露接缝，实测；渐暗只做在 `fontColor` 的 alpha 上）；设计要能在"忽略 alpha"时仍成立 |
| 渐暗/压暗作用域 | `dimColor` 只压暗**实例层** | 服务端 textbox 不会被压暗（它们本来在最底层） |

## 5. 动画的具体参数（可抄）

| 用途 | 参数 |
|---|---|
| 底栏提示呼吸 | 字号 20→24，周期 1.2s，缓动 ease-in-out |
| 选中项强调 | 字 38→44（0.15s）+ 色柱加粗 |
| 模式名入场 | 26→64 渐变，独占期 0.5s（期间任意键不打断） |
| 结算滑入 | 面板从边缘内滑入（不要从屏幕外，否则面板不透明时正文会在外面飘 0.35s） |
| 倒计时 | 120 号 + sin 弹跳 120→146（框高按 146 算） |
| 抖屏 | 4 档幅度 `{7,10,13,17}px` + 9Hz，时长 `{0.18,0.20,0.23,0.28}s` |

**性能提示**：抖屏会一次性写 200 格 × 2~9 帧 = 1200~1800 次 `SetAnchoredPosition`——**只在 `shakeT > 0` 的帧写**，平时一帧都不写。

## 6. 交付前自检（审美）

```
□ 能用一句话说出每个界面的"容器隐喻"吗？
□ 缩到 25% 看，主次还分得出来吗？
□ 有没有超过一个持续动效？
□ 每个图形都能说出"它代表什么"吗？
□ 配色/角色色/字号/间距是一套吗（还是逐处挑的）？
□ 视觉方案是"结构不同"还是"换了个色"？
□ 有没有让空上下文的视觉模型看过图？
```
