## 5. 阶段 2：UI 布局与文字（三条硬判据）

### 5.1 R1 框高：`h ≥ fontSize × 1.45 + 4`

- **来源**（可复核）：`studio/play/text-layout.js`，`lineHeight = 1.2×size` + `blockInset = 0.25×size + 4`；只画「完整放得下」的行（`visibleLineCount` 截断）。
- **症状**：不满足时**整行静默不画**，无报错、无日志、控件树正常。
- **实测**：64 号配 96 高（需 96.8）→ 整块消失；26 号配 40 高（需 41.7）→ 消失；34 号配 46 高（需 53.3）→ 消失。**差 0.8px 也是零渲染**。
- **怎么验**：先算需求高度再写控件（`workspace/tetris/lua/main.lua:279`、`:1009`、`:1520` 的注释就是当年算式），然后 `shot.mjs` 出图确认字在屏上；批量核对用 `scripts/textbox-fit.py <save.json>`（扫 `transformByPlatform.*.size.y` 并逐平台报违规）。
- 反例：字不显示先怀疑「文本为空」——正确第一嫌疑是框高不足（D566）。

### 5.2 R2 宽度：超出 `width − 4` 静默裁尾，不做缩放

- 实测：22 号 / 460 宽下 `SCORE 300 LINES 2 LV 1 FILLED 0` 最后一个 `0` 被裁成 `U` 样；改 20 号通过。
- 怎么验：文案最长那一条单独出图，尾部字符必须完整；中文文案按全角算宽，英文/数字按半角。
- 反例：「显示成别的字」不是字体问题，是裁尾。

### 5.3 R3 对齐与坐标

- `verticalAlignment` **必须有一处显式设成 `Middle`**：authoring 默认是 `Top`（实测 tetris 存档里 10 个布局 textbox 全是 `Top`），顶格会被切。可以在编辑器里写，也可以像本项目在 `layout()` 里运行时设（`main.lua:307-308`、`:565-566`）。
- 坐标 = `anchorMin/Max` + 像素 `offset`；`SetAnchoredPosition` 以画布中心为原点，左下→右上的 y 递增（tetris cell1=(-126,266) → cell200=(126,-266)）。
- **满幅铁律**（任何竖长玩法都会撞上）：10×20 棋盘宽高比 1:2，占满画布高度后左右必然各空一大片（1280×720 画布下棋盘宽仅约 330px，两侧空 ~950px）。填满靠**两侧内容面板 + 上下横幅**，不靠放大棋盘（放大到 PITCH 上限就会超高或比例变形）（D565）。
- `imageColor` 读回是**有符号 int32**（写 `0xFF1A1D26`=4279901478，读回 -15065818）⇒ 断言用有符号值，否则读回值对不上。

### 5.4 布局里的控件 vs 模板里的控件

- 同一控件「在布局还是在模板」**只由 `f504` 父指针决定**；两处可存在字段完全同构的两条记录（各 738B），没有额外「实例化标记」字段（D568）。
- 布局侧 UI 的合法形态是**一整棵子树**：`客户端控件容器(f502=23)` → `容器节点(f502=86)` → 子控件；默认布局的 `f503` 成员表只登记容器组 id。
- 含义：想「导入即能玩」，落地顺序必须是 ①容器组+容器节点 → ②控件挂容器节点（`f504`）→ ③模板进模板区 → ④更新被挂载的脚本/挂载指向 → ⑤备份 + Save_Level + Temp 同步（D568「触发条件→动作」）。

### 5.5 模板越少越好

- 每个客户端模板都可能在真机导入后被**重新编号**（`cell` 在模拟器 authoring 值 1073742105，真机 1073741849）⇒ 每多一个模板 = 多一处导入后校准。
- 对策一：`TEMPLATE_GUIDS = {真机值, authoring 值}` 逐个试，第一个成功者胜出（`main.lua` 常量；D566）。
- 对策二：**服务端 textbox 按 name 寻址**（`root:GetChild(name)`）跨宿主最稳，引导层因此零模板。
