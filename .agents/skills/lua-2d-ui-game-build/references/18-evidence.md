## A 玩法规则组（10 条）

> 落点：`02-gameplay.md`。代价形态：**规则写错 → 断言自证错 → 用户玩出来不对**。

### A1 出块保底（7-bag）
- **原话**（T1 15:14）：「修复出方块的逻辑，太随机了会导致游玩不公平，需要在随机的基础上有保底」
- **判据**：任意连续 **13** 块必含全部 7 种（窗口 = 6+7 或 7+6，任一窗口必含完整一袋）；首袋排除 S/Z 开局。
- **代价**：第一版判据写成 **12** 窗口，数学上不成立（袋 A 尾 6 块 + 袋 B 头 6 块可同缺一种）——**我自己写的断言是错的**，靠 review 抓出，否则用例会假绿。commit `db00dce2` 修正 12→13。
- **实现**：`lua/main.lua:190-216`（`refillBag` Fisher-Yates + `bagSeq` 记录袋号）、`210-216`（`takeFromBag`）。

### A2 下两块预览
- **原话**（T1）：「增加下两个个方块的预览」
- **判据**：第二块缩 14px / 55% 亮度；预览只读 `bagQ` 队头，**不消耗** bag。
- **代价**：`f1697aed`。第二块若走 `takeFromBag` 会破坏 bag 序列——用一个只读视图。

### A3 暂存 Hold
- **原话**（T1）：「增加储存一个方块的功能」→（T27 10:00 追加）：「存入的时候如果已经存入了，则直接下来存入的快，并且把当前没有下落的快也下落。这么设计，稍稍给存入增加一点操作难度，以免玩家滥用这个功能。」
- **判据**：空槽=纯存入；非空槽=**两块各进一格**；贴底交换=当前块**直接锁定**（`hold forced lock`）。`canHold` 闸：一块内只能 hold 一次。
- **代价**：键位实证——**字母 C 不在模拟器键池**，改 **G**（`CraftspersonKey14`）。commit `6ad0b6d0`（初版）+ `7d8d01c6`（防滥用语义）。
- **日志锚**：`hold swap in=O out=S cur_drop=1` / `hold swap out_drop=1`（T49 真机日志实测出现）。

### A4 双人/双屏准备必须双方各自确认
- **原话**（T19 22:23）：「双人模式，这个准备你给我真的作好呀，要两个人都准备好了，才开始倒计时呀，还有倒计时，数字你搞大一点，放在中间不行吗？」
- **判据**：P1/P2 分别按确认 → ready 状态实时显示 ✓ → **双方都 ready 才 3-2-1** → 倒计时 120 号大字屏幕正中 + 每秒缩放弹跳。
- **代价**：v2.5 首版做成了"任意键开始"，被用户点名"要真的作好"。commit `13b2f8b9`（双 ready + 120 号倒计时）。coop 的 P2 键曾全算成 p1ready（用例 27 抓到）。

### A5 判负必须用标准 topout
- **原话**（T20 22:34）：「ai演示，ai操控是，游戏结束的判定提早了。实际上，还可以继续玩」
- **判据**：被顶碰撞 → 进入 **0.5s 锁定延迟可自救**（不是立即判负）。垃圾行顶推段不能只查当前块列。
- **代价**：AI 演示里提前判负，用户直接从画面看出来。修正后 35/35 绿。

### A6 对抗因素（垃圾行）
- **原话**（T1）：「对抗模式，需要设计合理的对抗因素，比如给对付增加障碍等等」
- **判据**：消 2/3/4 行 → 送 1/2/4 行垃圾；B2B +1；受击抖屏；**洞位用 `aiRand` 不动 bag**（公平性）。
- **实现**：`44bdb935`（`raiseGarbage` 跨盘送行 / 1 洞 / 重叠上移判死）。日志锚 `garbage n=`。

### A7 难度不能只有速度
- **原话**（T37 11:12）：「可以看到它到了等级12，我看到这个时候的速度很快了，ai计算不过来，有点卡了，下落速度很快，增加难度不只是提高速度，也设计一下其他的方式，至少两个。」
- **判据**：至少两种**非速度**机制 —— ①**垃圾行侵蚀**（连续 14/10/7 块不消行 → 顶起带洞垃圾行，每盘独立清零重计）②**开局障碍**（Lv5+ 预置 1-3 行障碍，进局首帧可见，双盘独立洞位）。
- **代价**：用户玩到 12 级发现"只有速度"既是设计缺陷也是性能问题（见 F2）。

### A8 吃住在 AI 辅助等级联动
- **原话**（T37）：「这个ai协助玩家操作……ai初始等级是4，可以自己大概完到等级4，后续提高等级，需要玩家自己的水平也提升，玩家越厉害，ai辅助就越厉害。」
- **判据**：AI 辅助初始 easy（陪练）→ 玩家 Lv5 normal → Lv8 hard；日志 `ai assist lv=`。
- **代价**：用户用"等级 4"这个具体数字表达设计意图，实现必须给出对应映射。

### A9 T-spin 判定与计分
- **原话**（T1 点 8）：「需要设计，进阶操作。」
- **判据**：3 角判定；`400 × 行数 × 等级`；专属音效；**负向不误报已验证、正向构造用例要补**（构造 3 角双消布局跑了四轮迭代）。
- **代价**：`ea979a1a`（T-spin 正向用例：O 塔 + I1 柱 + 横 I2 + 填行底座）。日志 `tspin lines=2 bonus=800` 双消对账。

### A10 计分链路必须四模式通用
- **原话**（T1 点 4）：「ai操控游玩的，应该和玩家共享通用的游戏链路，音效和记分等反馈都不能少」→（T26 五-1）「我大致游玩了四个模式，发现，全部的积分没有了，这不对呀」
- **判据**：AI 消行同计分 / 进 HUD / 响音效 / 抖屏——**四处静音旁路全清**；`best` 不收 AI 分；四模式 HUD 都要有绑定。
- **代价**：`1a0e9e0f`（去静音旁路 + 用例 13）。后来 v2.7 又把 HUD 弄丢一次（见 C1）。

## B 输入手感组（5 条）

> 落点：`03-input.md`。代价形态：**同一个 bug 报告 4 次 + 两次错判翻案**——本表最贵的一组。

### B1 DAS 连移（按一下方块一直走）
- **原话 4 次**：
  - T6 19:49：「而且移动也有问题，它怎么自己左右移动呀」
  - T19 22:23：「操作的时候，按下左，就会一直左，按下右，就会一直右」
  - T26 09:55：「之前我说按下左，然后这个方块和后续全部的方块，全部都会自己高速往左边移动……这个bug还在，你没修好。（我看到帮助里面说长按0.25后，会连续快速移动，但是实际上，我是单击也导致了这个因为，修改为长按触发就可以了呀）」
  - T44 12:13：「移动的bug也还照样有呀。到底在干什么。按下左它所有的方块都在快速朝左边移动了。而且这个在休闲模式下移动又是正常的。」
- **最终真因**：`Up` 回调清的是**全局 `g`**——`OnUpdate` 实例循环每帧把 `g` 留在最后一个实例（ai-battle 下 = AI 盘 `G[2]`）→ 松键清错了盘 → **玩家盘方向永不清** → 连移不停。休闲模式 `ACTIVE={1}` 只有一个实例，所以"正常"。**用户自己的定位线索（"只在 AI 对抗出现、休闲正常"）比我们前两轮所有猜测都准。**
- **修法**（一行根修 + 两道防御）：
  1. `Up` 回调**必须先路由**：`g = routePlayer(m.key)`（`lua/main.lua:4443-4450`）
  2. **时间上限**兜底：ARR 激活后累计 `DAS_HOLD`（0.35s）强制停，打印 `das stop reason=timeout hold=`（`4765-4782`）——不依赖平台的 Up 事件
  3. Up 回调只清"自己按住的那个方向"（`if m.action=='left' and g.das.dir==-1 then ...`），防误清
- **两次错判（务必记住形态，下次别重演）**：
  - 错判 1「用户跑的是旧构建，v2.7 起已修」→ 被推翻：**日志窗口异常关闭导致签名缺失，被当成"没有连移记录"的反证**。教训：日志缺失 ≠ 行为不存在（见 G3）。
  - 错判 2「模拟器网页按键转发链整链静默（缺陷在上游）」→ 被推翻：headless 实验没满足 play 页**五重门**（见 B5）。教训：实验方法本身可能是 artifact（见 G4）。
- **中间还加过一道错防御**：v2.1 的"连走满 12 格强制停"——治不了根因（Up 丢失时方块已经飞了 12 格），只是把"无限"变成"有限"。

### B2 键位必须实证，不能想当然
- **代价**：**字母 C 不在任何键池**（Hold 本想用 C）→ 改 G=`CraftspersonKey14`。方向键 = `CraftspersonKey36-39`；`Space`=JumpKey、`X`=DropKey。
- **判据**：枚举名**逐字完整**（`KeyboardCraftspersonKey38Down`）；拼错成 `KeyboardJumpDown` 时**静默吞键**，探针全静默却看似成功——判定法=日志查 `guide stage=1`。
- **键位全表**见 `02-gameplay.md` / `03-input.md`。

### B3 鼠标三态（关键交互要能点）
- **原话**（T26 四）：「我和你说了，这些关键的交互操作，也要支持鼠标点击，并且做好悬浮、按下、常态的不同样式的，不仅仅是这里，还是开局的那四个模式的，那么大的四个小菜单，结果鼠标移动过去没变化，也不能点击。设计的太敷衍了」
- **判据**：热区 = cursor 模板实例 + `AddCursorEventListener`（**只有 cursor/button 类有事件**，image/textbox 静默失效→降级键盘）；常态/悬浮/按下三档可区分。
- **代价**：cursor 实例**无 `imageColor` 字段**（实测报错 `cannot set imageColor, no such field`）→ 三态只能用文案色/字号/贴片表达（hover 提亮+放大一档 + 84ms 短音；press 下沉+加深 + 151ms；**Exit 静音**防来回扫双倍噪声）。

### B4 事件回调的实例路由（双屏）
- **判据**：任何事件回调第一行 `g = routePlayer(...)` 再执行动作；跨实例交互（垃圾行）走 save→切目标→操作→restore。
- **代价**：B1 的真因就是漏了这一条；`coop` 的 P2 键曾全算 `p1ready`（用例 27）；`G[2]` 的 `flashT` nil 每帧炸断 `OnUpdate`（v2.1 修）。

### B5 模拟器试玩页按键五重门（做 headless 实验前必读）
1. `keydown` 绑在 **canvas** 上（不是 document）——没点过画布/没 focus，按键进不来
2. 必须等**首个带 view 的快照**应用完成（"会话 running"不够）
3. **epoch 串行链**：任何 device/view 切换都会让排队中的按键静默丢弃
4. 合成键过滤（输入法/表单内的键被过滤）
5. 键必须在映射表内
- **代价**：不知道这五条 → headless 得出"网页按键转发零条"的**错误结论**，白写了一轮"上游缺陷报告"。

## C 界面文字与层序组（8 条）

> 落点：`04-text.md` / `05-layer.md`。代价形态：**控件"接线了/状态对了"，但屏幕上没有或不对**。

### C1 HUD 积分"全没了"（层序遮挡）
- **原话**（T26 五-1）：「我大致游玩了四个模式，发现，全部的积分没有了，这不对呀」
- **真因**：v2.7 的**全屏背景 wash（运行时实例）盖住了 HUD 文字（服务端 textbox）**——层序铁律：**服务端 textbox 永远在运行时实例之下**。
- **修法**：HUD **实例双写**（运行时 textbox 实例压在背景之上），日志锚 `hud inst n=9 (textbox hidden)`。

### C2 双写只覆盖一部分 = 全白做
- **原话**（T37 一-1）：「可以看到下面的简易操作指南是没有的，然后左边的文字，看起来是不是被挡住了一部分，常驻的h帮助也没有，并且我游玩的时候，没有看到ai将要接管的文字提示」
- **真因**：HUD 双写只覆盖了 `hud/best/keyA-C` 五个键，**漏了 `botBanner`/`topBanner`** → 底栏操作说明 / H 提示 / 接管提示全都在被盖住的那两个 textbox 上。
- **判据**：双写必须覆盖**全部**会被实例压住的常量文字位；漏一处=那一处永久不可见。

### C3 隐藏 textbox 份之后，40+ 处 `setText` 变成"写了但看不见"
- **原话**（T43 12:10）：「还有这个，三个问题也都还在呀。和没修一样。」（随后我出图确认：底栏空、H 提示无、键位卡裁字）
- **真因**：v3.3 把 textbox 份 `SetVisible(false)` 之后，全仓 **40+ 处** `setText(botBanner/hint/topBanner, …)` 全都写在隐藏的 textbox 上（出图实测：常驻键位提示、开场句、纳西妲接管文案**全都没有墨迹**）。
- **修法**：`setText` **单点收口**——凡目标控件有同名 HUD 实例，同步写实例份（`lua/main.lua:292-300`）：
  ```lua
  local function setText(ctl, value)
    setTextRaw(ctl, value)
    local inst = ctl and ctl.name and HUD_INST[ctl.name]
    if inst and inst ~= ctl then pcall(function() inst.text = value end) end
  end
  ```
  **为什么在收口而不逐处改**：调用点太多且分散在演出/结算/接管各段，单点漏一处就少一行字。

### C4 文字被裁（半字/错字）
- **原话**（T41 12:05 及之后）：「↑ 被裁成 T」、「软」被裁成「卜」、「开」被裁成「升」、「空格」→「各」、「得分」首字被裁……（用户用箭头在截图上标出来）
- **判据**：① 框高 `h ≥ 1.45×size+4`（32 号字配 50 高框 → **整行不画**）；② 框宽按**最长文案**重算（`文本宽恒为「框宽-4」` = 内容超宽）；③ 实例份的框高要跟着缩放，字号×SC 时框高必须×SC（否则标题整行消失）。
- **代价**：「得分 1?2」→「↑」→「T」这类裁字在整场出现 **≥5 次**，每次都要用户截图标注。

### C5 `ipairs({...})` 遇 nil 静默截断
- **代价形态（两个实例）**：
  1. 模板探测候选表 `{nil, 1073741849, …}` → `ipairs` 在第一个 nil 处停 → 候选表空 → 探测失败 → `error()` 无声死 → 真机白屏（见 F2）
  2. 结算层成员表若用 `ipairs({...})`，某个成员没造出来（如 border）→ 后续成员**静默跳过** → 销毁漏
- **判据**：**成员表用固定槽 + 数字 `for` 遍历**，不要 `ipairs({...})`。`lua/main.lua` 结算层注释原文：「固定 9 槽 + 数字 for 遍历，绝不能用 `ipairs({...})`」。

### C6 布局函数中途抛错 → 后半段全不执行
- **原话**（T43/T45）：用户报"三个问题也都还在""和没修一样"；表面症状是文字挤压/双影/标签贴顶。
- **真因**：`layoutDual()` 里 `-(halfH - 96)` 引用了 **`nil` 全局 `halfH`**（它是 `layout()` 里的 local）→ 每帧抛 `attempt to perform arithmetic on a nil value (global 'halfH')` → **函数从断点返回**，后半段（HUD 复位 / 隐藏收口 / `hudNext` 归位 / 结尾 `print('layout dual')`）全没执行。
- **判据两条**：① `playGet().logs` 里搜 `lua-error`（**runner 只报断言红，Lua 运行时错误默认静默**）；② 关键锚点日志（`layout dual`）**缺失** = 函数没跑到底。
- **教训**：布局函数里的画布尺寸一律从 `CANVAS_W/H` 取，不要引用别处的 local。

### C7 结算页灰雾（构建顺序）
- **原话**（T11 21:10）：「这个黑色窗口显示异常了，在真机里面显示就是一个很大的？号」
- **真因**：结算层先建**文字**、后建**半透明面板**——运行时实例「后建的在上面」→ 面板把文字压成灰雾。
- **判据**：层序固定为 **遮罩 → 边框 → 面板 → 文字**；遮罩要真全屏（盖住棋盘和左右栏）。

### C8 真机 API 三差异（文字乱位/大问号）
- **原话**（T11）：「在真机里面显示就是一个很大的？号」
- **真因**：真机日志抓到三条被 `pcall` 吞掉的 API 报错——① `SetVisible` **严格计参**（只收 1 参）；② `horizontalAlignment`/`verticalAlignment` **只收枚举不收字符串** → 所有对齐设置真机全 fail → 文字默认 Top/Left 乱位/裁切。
- **修法**：真机适配层（对齐双形态枚举映射 + `SetVisible` 实参分发），一处修 37 处调用点受益（`0b21ce86`）。
- **判据**：`pcall` 会吞掉 API 报错 → **必须把失败打出来**（`noteFail`/`ui fail` 日志），否则"没报错"是假象。

## F 部署与真机组（6 条）—— 每次都是"用户看不到新版"

> 落点：`12-deploy.md` / `13-device.md`。

### F1 用户质问"导入+挂载一条龙"（我们自己的技能没写）
- **原话**（T3 19:23）：「我们不是做了导入+挂载一条龙吗？技能没写吗？你找一下记忆」→（19:25）「完成了记得更新那个技能，下次不要我重复导入的事情了。」
- **处置**：`assets:scripts mounts` 查出**游戏实际执行的是 `main_2`（v1 旧码）**，而 `deploy.mjs` 只写 `main_1` 的 external → 这才是"每次都要手动同步/导入"的根源。用 `assets:scripts update` 一条龙直写（f5 内嵌 source + external + Temp 三同步）。
- **判据**：`--map-id` 必带，否则 `temp-sync=skipped`（编辑器读 Temp）；双址 sha 一致；guard 报的"悬空 children"要与**写前备份**对比判定存量。

### F2 真机白屏（注入版占位符）
- **原话**（T4 19:32）：「试玩了，没有看到游戏ui界面，你写了bug出来？看日志。」
- **真因**：`TPL_GUIDS.cell` 第一个候选是占位符 `__GUID_CELL__`（build 时注入）——我用 `lua/main.lua` **原文**直写 → 占位符是 `nil` → Lua 表构造 `{nil, 1073741849,…}` 被 `ipairs` 在第一个 nil 处截断 → 候选表空 → 探测失败 → `error()` 无声死（日志只打到启动链最前面两行（`canvas` 与设备行）就断，完全吻合）。
- **错误判据（踩过）**：用 `includes('__GUID')` 检查 → 注释文字里也有该串 → **误报为已注入**。
- **正确判据**：`grep -E '/cell = \{ [0-9]+/'`（**数字形态**）；且**注入点可能搬进模块**（如 `config.lua`），要扫全部脚本。

### F3 "还是老板版"（多模块漏 register）
- **原话**（T24 09:23）：「我去真机试玩了，感觉还是老板版，我给你提的问题，全部都在呀。你仔细检查一下，是不是id，挂载等等我老是和你强调的问题又犯了。」
- **真因**：v2.7 把单文件拆成 **main + config + widgets + audio 四模块**（`require` 加载），但**真机脚本登记表从没加过那 3 个模块** → 游戏里跑的一直是拆分前的单文件旧版。
- **修法**：`main_1/main_2` 更新 + **每个模块都 `register`** + 判据 `registryEntries == 主脚本数 + 模块数`；模块 external 落在 `<槽>/external_lua_file/default_import_file/lua/<proj>/`；require 路径=映射路径去 `.lua`（引擎补 `default_import_file/`）；**写完必须让用户切出地图再切回**（内存版会覆盖写盘）。
- **验证锚**：日志 `module ok config/widgets/audio ×3`（T49 真机实测出现）。

### F4 真机 Lua 200-local 硬限
- **原话**（T48 13:05）：「真机存在限制，修复并更新技能」
- **症状**：真机弹「脚本编译报错: ...too many local variables (limit is 200) in main function near '('」——**整段不编译、白屏、零日志**（编译错误**不进 runner**）。
- **事实**：本机 `lua5.3 loadfile` 放过（行首 local 141 个）；真机在第 200 个 `local function` 处报错——`local function` **占槽且近似双计** + 顶层循环变量也计。
- **修法**：8 个晚期大函数（`tickInstance/layoutDual/enterMode/exitToMenu/aiTickCore/aiDrop/skinBgItem/aiAutoFlag`）从 `local function X()` 改成挂表 `FN.X = function()`（表占 1 槽），调用点全量替换 → **141→134**（安全余量 66）。
- **判据**：`grep -cE '^local ' lua/main.lua` ≤150；改完**必须真机首试**看弹窗/日志。

### F5 版本指纹（自查"跑的是哪版"）
- **判据**：启动日志留稳定前缀——`menu stage n=` / `menu cards n= style=` / `hud inst n=` / `module ok` / `tpl guid=` / `cellCount=` / `listen ok`。
- **代价**：用户三次报"还是旧版"，每次都是先取真机日志看指纹才定位（例如 `menu stage n=22` 证明 v2.7 生效）。

### F6 部署三处（缺一处用户就看不到新版）
1. 仓库 `workspace/<proj>/<proj>.save.json`（runner 读）
2. 模拟器工作区 `~/qxqy-workspace/<proj>.save.json`（**网页 4173 读它**）
3. 真机：地图脚本记录 + external 文件（`deploy.mjs` 或零导入直写）
- **判据**：`sha256sum` 逐字节比对 + 版本指纹。

## G 验收方法组（7 条）—— 用户批评最狠的一组（"不要太自信"）

> 落点：`01-verification.md` / `00-gates.md`。

### G1 「接线了」≠「画面上有」
- **原话**（T41 12:05）：「还有这个，简易的操作说明，小草神的辅助文案，全局的h帮助说。这不是同一个问题吗?**不要太自信，要去看实际渲染出来的画面**。模拟器上得先通过了才通知我去游戏真机测试。」
- **代价**：core-mechanics 用探针读控件属性说"都接线了"，代码也确实接上了——但**没有人真正看渲染出来的画面**。我亲自出图后看到：底栏空、H 提示无、接管提示无、键位卡还有裁字。

### G2 必须读全部页面，不是抽查
- **原话**（T45 12:22）：「不要偷懒，把所有页面的渲染的图片，全部自己读取一下，至少保证模拟器上没有特别明显的问题了」
- **判据**：界面类修复的**交付前动作** = 出全部页面图（标题/游戏内/双屏/结算/帮助）× 人眼逐字核对；不是"我改了那一个地方所以只有那里变"。

### G3 日志缺失 ≠ 行为不存在
- **代价**：DAS 错判 1 的直接成因——用户那次试玩的**日志窗口异常关闭**，日志里没有 `das` 记录，被我们当成"没有连移"的反证。真相是**采集不在，不是行为不在**。
- **判据**：下"日志里没有 X ⇒ X 没发生"之前，先确认采集存活（日志文件有本次会话头、`canvas WxH` 等启动行在）。

### G4 实验方法本身可能是 artifact
- **代价**：DAS 错判 2——headless 实验"键盘事件到了页面但转发 POST 零条"被判成"模拟器上游缺陷"，实际是实验没满足**五重门**（B5）。
- **判据**：headless/脚本实验的负结论，先自检"被测链路的生效条件我满足了吗"，再谈"是它的 bug"。

### G5 控件状态 `visible=true` ≠ 渲染可见
- **代价**：层序遮挡时状态位全对（`visible=true`、位置也在），但被上层实例盖住。

### G6 探针只能证伪，不能证明
- **判据**：探针（读控件树/属性）用来**排除**（"这个控件根本不存在"），不用来**确认**（"所以玩家看得见"）。确认只能出图。

### G7 模拟器通过 ≠ 真机通过（但模拟器不通过一定不许上真机）
- **原话**（T41）：「模拟器上得先通过了才通知我去游戏真机测试。」
- **判据**：验证顺序 = 语法门 → runner 用例 → 出图逐字 → **模拟器体感** → 真机。任何一层不过，不许上真机找用户。

## I 效率与性能组（4 条）

> 落点：`16-efficiency.md` / `11-performance.md`。

### I1 性能必须先测量再动手
- **原话**（T6 19:49）：「网页试玩卡的要死，玩不了一点。」→（T7 20:20）「额外恶性bug，ai操作的时候，方块停止不动。」
- **真因**：AI 评估函数里有一段**已被证明无效的计算**（Dellacherie 特征权重已定 0，但代码还在每候选全盘扫）× 34 个候选 → 每帧吃掉 **9.5ms** → 网页帧率暴跌 → AI 思考是分帧推进的 → **低帧率下推进极慢 → 方块长时间悬停不动**（用户看到的"方块停止不动"）。
- **修法**：权重 0 时**短路跳过计算**。实测：帧耗时 9.55ms → **1.24ms**（+35 倍 → 归位），p99 105ms → **11.9ms**，掉帧清零；runner 从 308s → 63.6s；**副作用是 AI 变强**（ρ 0.30 → 0.34）。
- **判据**：性能问题先出**帧探针**（p50/p99/掉帧次数），再动手；`+35 倍` 这种量级一定来自"每帧都跑的无用计算"，不是"代码不够优化"。

### I2 拟人修正不能混进决策层
- **代价**：把拟人化（观察/犹豫/软降）的修正混进决策 → ρ 从 0.30 掉到 0.26；**分层后找回**。
- **判据**：**决策要纯，执行才拟人**（这句话是本次最有价值的设计定论）。

### I3 分帧计算要有时间预算
- **判据**：2-ply 搜索按 **8ms 切片**分帧推进；帧内不分配大表（GC 抖动在模拟器解释器上会被放大）。

### I4 用户报"卡"时先分清是哪个"卡"
- **代价**：用户说的"卡"先后对应两个完全不同的根因：①帧耗时爆表（性能）②AI 分帧被低帧率饿死（同一根因的表现）。而"移动自己走"是另一个根因（B1）。

## J AI 算法组（6 条）

> 落点：`10-ai.md`。

### J1 抄论文，不手调
- **原话**（T14 21:32）：「这个ai，随手截图的两张，这个操控行为实在是太蠢了。本质上来说，就是一个算法了，可以算出最优解的，自己写靠不住就去联网学习呀，学论文里面的算法呀。」
- **取证**：Thiery & Scherrer 2009《Building Controllers for Tetris》（ICGA Journal，2008 强化学习竞赛冠军方案 "BCTS"）。**8 特征、1 步前瞻**即可达 3500 万行（对比 Dellacherie 手调 66 万行）。权重（交叉熵优化，非手调）：
  ```
  −12.63·落地高度 + 6.60·消行格 − 9.22·行转移 − 19.77·列转移
  −13.08·洞 − 10.49·累计井 − 1.61·洞深度 − 24.04·带洞行数
  ```
- **我们缺的两个特征**：洞深度、带洞行数——这正是 AI 摆出"塔高不平、孤洞多"的直接原因。

### J2 ρ 的物理上限是 0.40（不是 0.50）
- **代价**：我在任务书里写了「hard 档 ρ≥0.50」，**物理上不可能**——每块 4 格、每行 10 格 ⇒ ρ 上限 = 4/10 = **0.40**。被负责实现的代理驳回。
- **判据**：ρ≥0.35 + **盘面判据**（平均高 ≤6 行、零崩盘）才是"会打/不会打"的区分。
- **改前改后**：旧版（手调 + 2-ply）ρ 0.34、盘面 4~13 行波动、**60 块必崩盘清空**；新版（BCTS 1-ply）ρ 0.35、**2~7 行极平、150 秒零崩盘**。

### J3 演示/代打必须强制 hard 档
- **原话**（T18 22:14）：「这就是你从论文找到的最强的算法的水平？不到5s就看出根本不太会。」
- **真因**：默认档是 `normal`（`pMistake=8%` 故意失误 + `topK=3` 从次优采样），标题页自演直接吃默认档 → 用户看到的是"会失手、会选次优"的 AI。
- **判据**：演示/AI 代打（标题自演、休闲接管）**强制 hard**（`pMistake=0 / topK=1 / 启用 hold`）；easy/normal 只保留为玩家主动选。

### J4 镜像局必须同步"下一个方块"预告
- **代价**：AI 盘 **62 块 0 消行**（用户报"右边 ai 一直在下落……落块数量明显不正常"→后来"ρ=0"）——根因是镜像局喂块时**没同步 `nextName`** → AI 的 2-ply **永远按"下一块是 T"规划** → 决策与真实出块系统性错位。
- **修法**：`feedMirror` 镜像主盘的 `nextName/nextBag` 预告。

### J5 对抗模式 AI 不该等玩家
- **原话**（T26 三-2）：「右边ai一直在等我操作，我的快没落下，它就不会动，等我下落才会出第二个块，这是明显的bug呀，对抗的时候，因为已经有了带保底的随机出块机制，不用两边出块一样也不用等呀」
- **判据**：**独立出块 / 各自 bag**（用 `aiRand` 独立洗袋，不动全局 LCG ⇒ 不影响既有断言）；公平性靠 7-bag 保底本身 + hard 档 AI，**不靠镜像等待**。

- 见 A8。
