# 04 文字渲染（不显示 / 被裁 / 双份 / 糊）

> 本次会话里文字类缺陷被用户用**箭头在截图上标出来**至少 5 次：
> 「↑」显示成「T」、「软降」成「卜降」、「空格」成「各」、「得分」首字没了、「下一个」贴顶被裁。
> 它们全部来自**三个可计算的判据**没满足。这一章把它们写成能机检的形式。
>
> 出处：`18-evidence.md` C4/C5、L7；代码：`lua/main.lua:3263-3327`；出图机检：`qxqy/shot-style.mjs`。

## 1. 框高判据：`h ≥ fontSize × 1.45 + 4`

**这是最重要的一条**：不满足时引擎**整行不画**（不是裁一半、不是缩小），所以看起来像"这个字根本没写"。

```lua
-- 正确算法（本项目 HUD 实例的写法）
local hh = math.floor(fs * 1.45 + 8)   -- 留余量
c:SetSizeDelta(w, hh)
```

**真实翻车**：
| 场景 | 数值 | 结果 |
|---|---|---|
| 32 号字配 50 高框 | 需 32×1.45+4 = 50.4 > 50 | **整行不画** |
| `topBanner` 排 34 号字但框高按 22 号算（39） | 需 34×1.45+4 = 53.3 > 39 | 出图判据报 `itopBanner 框=1480x39 需高=53.3 fits=false`，整行裁字 |
| 字号×画布缩放（SC）了但框高没跟着×SC | 比例失衡 | 标题整行消失（1600 画布上「俄罗斯方块」不见了） |

**规则**：**框高必须按"这个位置实际排的字号"算**，不能按"同类控件的默认字号"算。
如果一个框会显示不同字号的内容（如倒计时 120→146 的峰值弹跳），框高按**峰值**算。

## 2. 框宽判据：按最长文案重算

**判据信号**：如果发现「文本宽恒为 框宽-4」，说明**内容超宽**（引擎把它夹到框内了）。

**真实翻车**：
- `keyA-C` 常驻键位提示最长 **24 个全角字符**，20 号字约需 **480px**，而框宽只有 360 → 实例份字号降到 **14**（需 336 < 360-4）才 fits。
- 「得分 1?2」的 `?` 就是框太窄把字吃了。

**做法**：
```lua
-- 宽度 = 最长可能文案的估算宽（中文按 1.0em，英文/数字按 0.55em）+ 余量
-- 或者：先按目标字号算，fits 不过就降字号（保留可读性下限 ≥12）
```
**注意**：`textbox` 份和**实例份**可以设不同字号（本项目就是这么做的：textbox 份只用于断言，实例份用于显示）。

## 3. 对齐判据：`valign = Middle`（必须显式设）

模板缺省是 **Top/Left**，所以：
- 字**贴顶** → 顶部被框沿削掉（表现为「字顶被切」）；
- 字**贴左** → 左边距不匀。

**真机额外坑**：对齐字段**只收枚举不收字符串**（`13-device.md` §2）——传字符串会抛错、被 `pcall` 吞掉、对齐全 fail，表现为"文字乱位/大问号"。

```lua
trySet(c, 'verticalAlignment', 'Middle')   -- 适配层会自动映射成 Enum
```

## 4. 模式 × 文字矩阵（专治"这个页面上出现了不该有的东西"）

**用户原话**（T37）：「这个页面是和单人和ai对抗，明显不会出现p2玩家的。**这说明我们需要完整的检查全部的文字，现在混乱了**。」

**做法**（硬性要求，不是抽查）：
1. 列一张表：行 = 模式（casual / ai-battle / pvp / coop）× 列 = 每个文字位（keyA/keyB/keyC/topBanner/botBanner/hint/结算文案/引导文案）。
2. 每格填：该模式该位应该显示什么 / 显示为空 / 不适用。
3. **逐格对账**：代码里每个写入点，是否能落到正确的模式分支。
4. **全文件扫描**关键词确认干净：
   ```bash
   grep -n 'P2\|玩家2\|P1' lua/main.lua | grep -v 'pvp\|coop'   # 应该只剩合法分支
   ```

**为什么必须全量**：修了截图里指出的两处，用户下次还会发现第三处——因为问题不是"这两处写错了"，是"没有矩阵"。

## 5. 出图机检（把判据变成断言）

```bash
node qxqy/shot-style.mjs all
# 成功：末行 "✓ 全部 textbox 通过框高/宽度判据"
# 失败：逐条打印
#   ✗ <name> size= 框=WxH 需高=<需求> fits=false 文本宽=<w>
```

**这说明**：框高/框宽判据是**可以机检的**——不要靠肉眼发现裁字。

**补充：实例层审计**（服务端 textbox 之外，运行时实例也要查）
```js
// 思路（本项目 /tmp/audit-inst.mjs）：读 playGet().scene，遍历所有 textbox 实例，
// 用 textLayout 的实际文本框尺寸与字号复算 fits，逐条报违规
// 实测：115 条文字 / 0 违规
```
> **为什么需要它**：`shot-style` 的机检只覆盖服务端 textbox；**HUD 双写之后的可见文字是实例**，不在它的覆盖里。实例层违规肉眼很难发现（因为不报错）。

## 6. 双份文字（"两个都在显示"）

症状：同一信息出现两次（一大一小/一深一浅）。
**真因**：双写没隐藏 textbox 份，或某个 layout 复位段把它重新 `SetVisible(true)` 了。
**判据**：出图里同一信息只出现一次；`grep -n 'SetVisible, true'` 检查有没有"复活"点。
详见 `05-layer.md` §2。

## 7. 字模糊 / 对比度不够

用户原话（T37）：「打开这个帮助页面，可以看到**字体很模糊**，而且没有我要的关键字体颜色高亮，**纯黑白**，让人没有看的欲望。」

**判据**：
- 正文最小字号：**19~21**（16 号在真机上明显糊）；
- 关键行必须用**强调色**（≥2 种语义色：标题/强调/正文），不许纯黑白；
- 正文 vs 背景对比要够（浅底用墨色，不要用浅灰）。

## 8. 常见错误的形状速查

| 你看到的 | 真因 | 修法 |
|---|---|---|
| 整行不画 | 框高 < 1.45×size+4 | 按实际字号重算框高 |
| 尾部少字 / 出现 `?` | 框宽 < 文案宽 | 按最长文案重算；或降字号 |
| 字顶被切 | 缺 `valign=Middle` | 显式设 |
| 真机字乱位 / 大问号 | 对齐传了字符串 | 枚举双形态适配层 |
| 同一信息两份 | 双写没隐藏 textbox 份 | 隐藏 + `setText` 收口 |
| 字很糊 | 字号 < 16 / 对比度不够 | 提到 19~21 + 强调色 |
| 页面上出现不该有的人 | 缺模式×文字矩阵 | 建矩阵逐格对账 |

2. 每处框宽覆盖了**最长**文案吗？
3. 每个会变字号的控件（倒计时/弹跳）框高按峰值算了吗？
4. 模式矩阵逐格对过了吗？
