# 17 症状速查 + 反模式 + 自检

> **用法**：拿到一句用户描述或一个现象 → 在下表找到最像的一行 → 按「第一步做什么」动作 → 打开对应模块。
> **别从头读技能**。这张表就是技能的正门。
> 出处编号见 `18-evidence.md`。

## 1. 画面 / 文字类（最高频）

| 症状（用户怎么说 / 你看到什么） | 第一步做什么 | 去查 |
|---|---|---|
| 「这个字没了」「整行不显示」「标题消失了」 | 查框高：`h ≥ 1.45×size + 4`。32 号字配 50 高框 = 整行不画 | `04-text` §1 |
| 「↑」显示成「T」、「软降」成「卜降」、「空格」成「各」、「得分」首字没了 | 框宽不够（文本宽恒为「框宽-4」就是超宽）；按最长文案重算框宽 | `04-text` §2 |
| 字顶被切 / 贴顶 / 贴左 | 缺 `valign/halign`（默认 Top/Left），显式设 Middle/Center；**真机对齐要枚举不收字符串** | `04-text` §3 / `13-device` §2 |
| 「积分全没了」「底栏没有」「H 提示没有」「接管提示没有」 | 层序：服务端 textbox 永远在运行时实例之下 → 查双写是否**漏位** | `05-layer` §1-2 |
| 改了文案但画面上没变（"写了但看不见"） | 文字写在被隐藏的 textbox 上 → 查 `setText` 是否走单点收口 | `05-layer` §3 |
| 同一信息出现两份（一大一小） | 双写没隐藏 textbox 份，或某个 layout 复位段把它重新显示了 | `05-layer` §4 |
| 结算页文字是灰雾/暗字 | 构建顺序错：先文字后面板（实例"后建在上"）→ 改「遮罩→边框→面板→文字」 | `05-layer` §5 |
| 文字压在文字上 / 压在棋盘上 | 布局函数里 y 值撞车；或某块文案没参与布局排布 | `06-layout` §3 |
| 元素超出画布 / 被边缘切 | 坐标系写死（按 1280 设计跑在 1600）；或 pivot 不在中心 | `06-layout` §4 |
| 大画布下内容小一圈、四周空旷 | 尺寸是硬编码常量没跟画布缩放（注意：**缩放要独立打磨窗口，别和别的改动混**） | `06-layout` §4 |
| 三个同级按钮样式完全一样 | 没有主次层级 → 定"主/次/弱"三级（实心胶囊 > 描边胶囊 > 纯文字） | `07-overlays` §2 |
| 按钮看得出但点了没反应 | 热区没建（只有 cursor/button 类控件有事件）；或热区尺寸小于视觉 | `03-input` §4 |
| 鼠标移上去没变化 | 三态没做或只有命中判定；cursor 实例**无 imageColor**，三态要用文案色/字号/贴片 | `03-input` §3 |
| 帮助页"纯黑白、没有看的欲望" | 需要容器隐喻 + 关键行强调色高亮 + 字号 ≥19 | `08-art` §4 |
| 页面上出现不该有的玩家编号/键位 | 模式 × 文字矩阵没核；全文件扫关键词确认只剩合法分支 | `04-text` §4 |
| 某个图形"意义不明" | 玩家看到的每个图形都要有语义（图例/标签）；不会解释就别放 | `08-art` §4 |
| 颜色断言对不上 | `imageColor` 是**有符号 int32**；A 通道真机不可靠 → 用不透明预混色 | `08-art` §4 |
| 想隐藏一个运行时实例但真机还看得见 | `SetVisible(false)` 对运行时实例**真机不生效** → 挪出画布 / 懒创建+销毁 | `05-layer` §4b |
| 模板 GUID 对不上（authoring vs 真机） | 客户端模板导入后**会重编号** → 候选表逐个试；服务端 textbox 按 name 寻址最稳 | `13-device` §3 |
| 背景元素少了几件但没报错 | 背景池溢出**静默丢元素** → 看 `bg overflow !!` 日志；池容量 18 | `11-performance` §6 |
| 文案改了但用例红 | `PERSIST_TIP` 被 `tests/29` 断言**整串**（at=1.4s），改常驻文案要同步改断言 | `09-copy` §1c |

## 3. 部署 / 真机类（每次都是"用户看不到新版"）

| 症状 | 第一步做什么 | 去查 |
|---|---|---|
| 「还是老板版」「和真机不一样」「问题全在」 | 取真机日志看**版本指纹**（`menu stage n=` / `menu cards n= style=` / `hud inst n=`），证明跑的是哪版 | `12-deploy` §4 |
| 真机白屏、日志只打到启动链最前面两行（`canvas WxH` 及其后一行）就断 | 注入版占位符（`__GUID_*__` = nil → `ipairs` 截断候选表 → 探测失败 → `error()` 无声死） | `12-deploy` §2 |
| 真机白屏 + 零日志 + 弹「too many local variables」 | 真机 200-local 硬限：`grep -cE '^local '` ≤150，超了把大函数挂表 | `13-device` §1 |
| 真机文字乱位 / 一个巨大的问号 | 真机对齐只收枚举不收字符串 + `SetVisible` 严格计参（被 pcall 吞掉） | `13-device` §2 |
| require 全失败 / 只有主脚本生效 / 模块改动无效果 | 每个模块都要 `register`；`registryEntries == 主脚本数 + 模块数` | `12-deploy` §3 |
| CLI 说成功但真机没变 | 让用户**切出地图再切回**（内存版会覆盖写盘）；Temp 同步（`--map-id` 必带） | `12-deploy` §2 |
| 游戏实际执行的是旧脚本 | `assets:scripts mounts` 查**活跃容器挂的是哪条**（deploy 写的可能不是它） | `12-deploy` §1 |
| `GSTS_LOCALLOW_DIR` 报错找不到 BeyondLocal | CLI 要 `…/AppData/LocalLow`；`deploy.mjs` 要 `…/LocalLow/miHoYo/原神`（两个口径不同） | `12-deploy` §6 |
| 试玩服务僵死 / 页面打不开 | 重启服务，自证 pid + HTTP 200；旧页面会话失效需刷新 | `13-device` §6 |
| **布局里有客户端容器，游戏里什么都没有 / `mounts=0`** | ①`assets:ui container discover` 看**布局实例**节点在不在（空容器节点会被编辑器保存时剪掉 → CLI 自动补 1×1 占位子控件）②`assets:scripts mounts` 看挂载在**布局实例节点**还是模板节点 | `12-deploy` §9 |
| **编辑器保存后容器节点/占位件/挂载全消失，只剩两个空组**（2026-10-29 B 图事故） | 查**地图有没有 ClientUI 层级根 fam 87/88**（`ClientUIRootHierarchyRoot`/`ClientUIPrototypeHierarchyRoot`）：缺了编辑器会自建并丢弃/重编号容器子树；用 `container instantiate --system-donor <已有根的图.gil>` 先补根再交付 | `12-deploy` §9 硬前提 ③ |
| **容器里的子控件 ID 掉到 2xxx（<1073742500）** | 编辑器动态段，会被改分配成系统根/模板实例 → 子件消失；容器下新建子树件必须 ≥1073742500 | `12-deploy` §9 硬前提 ② |
| **换了地图／克隆后 Lua 探测模板全失败（`tpl guid=` 是旧数字 或 nil）** | 设备版 Lua 把模板 GUID 烘死在源码里（`T.tpl = {prim=…}`）。**走 `sim:import --apply` 落地时已自动重映射**（并会先跑只读分析报 `[DRIFT]`）；只有手工搬图/换图才需要重新 build（`FLOWER_PRIM/LABEL/HIT=… node qxqy/build-device.mjs`）再 `assets:scripts update` | `12-deploy` §9.3 / `13-device` §3 |
| **`external_lua_file` 不存在 / 游戏跑旧脚本** | `assets:scripts list` 看 `exists/size`；`maps:clone` 会把内联 source 物化到新图目录，手写路径要自己补 | `12-deploy` §9 |
| **CLI 写完脚本好好的，用户在编辑器里保存一次就废了**（`.gil` 从 15 万 B 掉到 3 万 B、root50 只剩几十字节、`assets:scripts list` 报 `external=MISSING`、界面空白但零报错） | **编辑器保存会把 root50 的内联源码外置**成 `external_lua_file/<filePath>`。只写内联 = 外置后两边都空。修法：写完必须同时落外置文件（`UTF8_BOM + source`，内容要是**重映射后**的源码）；判据 = `externalLuaDestOf(gilPath, entry.filePath)` 那个文件存在且含 BOM | `12-deploy` §9 硬前提 ④ / §9.3 |

## 8. 反模式清单（写代码时对照）

1. **拿控件属性/探针当画面**——用户看的是渲染，必须出图核。
2. **本机语法门当真的编译过**——真机 200-local、注入版占位符都是本机放过的。
3. **「接线了」当完成**——L2 未验 = 未完成。
4. **多模块只部署主脚本**——每个 require 模块都要 register。
5. **整文件重放覆盖队友**——单元即 commit；禁整文件重放。
6. **commit 不验证内容**——哨兵 grep。
7. **把"感受"直接当需求实现**——先翻成数值/判据（帧耗时/对比度/ρ+平整度）。
8. **装饰堆砌**（轮播/滑动下划线/箭头/卡片容器）——用户偏好克制；"字体放大呼吸" > 三段轮播。
9. **层序靠"后建在上"赌**——整屏浮层显式置顶；常驻文字双写。
10. **hidden textbox 只藏一处**——`setText` 单点收口，否则 40+ 处静默失效。
11. **手调 AI 权重**——抄论文。
12. **验收追 ρ≥0.5**——物理上限 0.40。
13. **镜像同步对手**——独立 bag。
14. **异步等待空转轮询**——子代理完成会回报；等待期做独立任务。
15. **布局函数里引用别处的 local**——每帧抛错 = 后半段全不执行。
16. **`ipairs({...})` 建成员表**——遇到 nil 静默截断；用固定槽 + 数字 for。
17. **只在单屏模式下验证**——双屏布局问题在单屏图上看不见。
18. **改了 lua 不 build 就跑用例**——测的是旧代码。
19. **用户报"还是旧版"就先改代码**——先看版本指纹证明跑的是哪版。
20. **遇到"上游 bug"结论不先自证实验有效性**——五重门。

## 9. 开工 / 交接自检（复制粘贴用）

```bash
# ① 代码健康
grep -cE '^local ' lua/main.lua            # ≤150（真机 200-local 预留余量）
grep -cE '^local function' lua/main.lua    # 每个都占槽且近似双计

# ② 工作树与提交

git -C /home/h/genshin-ts log --oneline -5

# 真机日志最新文件的指纹行：tpl guid= / cellCount= / hud inst n= / module ok

## 10. 三个完整剧本（照着走，不用想）

### 剧本 A：用户说「字看不见 / 被裁 / 挡住了」

```
① 先分类（问自己）：是"完全没有"还是"有但不对"？
   完全没有 → 层序问题（走 ②）  有但被裁 → 文字判据（走 ⑤）
② 层序：grep 该文字的写入点 → 它是服务端 textbox 还是实例？
   若是 textbox，而同屏有背景/棋盘实例 → 必被盖（05-layer §1）
③ 查双写覆盖：HUD_INST 名单里有它吗？日志有 `hud inst n=<名单长度>` 吗？
   名单少一个 = 那个位永远不可见（05-layer §2）
④ 查有没有"复活"：grep 'SetVisible' → 有没有 layout 段把它重新显示？
⑤ 文字判据机检：node qxqy/shot-style.mjs all → 看有没有 `✗ … fits=false`
   同时算：框高 ≥ 1.45×字号+4；框宽 ≥ 最长文案宽（04-text §1/§2）
⑥ 出图逐字核对：read_image → 每个文字块读到最后一个字（不是"看一眼"）
⑦ 若无 FAIL 但仍看不见 → 查 lua-error（可能是函数中途抛错，05-layer §5 / 14 §手段2）
⑧ 修完重出图 → 全部页面都看（不只改动那页，06-layout §3 坑 2）
```

### 剧本 B：用户说「按一下方块一直走 / 自己往左跑」

```
① 关键分流：只在多盘模式（AI 对抗/双人）出现吗？
   是 → 事件路由问题（走 ②）  所有模式都有 → 平台 Up 事件丢失（走 ④）
② 查事件回调第一行：是不是 g = routePlayer(...)？
   不是 → 就是它（OnUpdate 每帧把 g 留在最后一个实例 → 清错盘 → 方向永不清）
   证据：03-input §5 + 14-diagnosis 案例 1
③ 查 Up 回调是否"只清自己按住的方向"（左右同按不该互相抹）
④ 查时间上限兜底：有 DAS_HOLD 吗？超限有 `das stop reason=timeout` 日志吗？
   没有 → 加上（不依赖平台 Up）
⑤ 定案读数：开日志面板按几下左右 → grep '^move x=' 的条数
   一次按键 vs 一次 Down/Up 应恰好 1 条（03-input §2 判据）
⑥ 双屏模式单独再验一次（缺陷唯一露头的地方）
```

### 剧本 C：用户说「还是老板版 / 我提的问题全都在」

```
① 先取证，不改代码：取真机最新日志 → 找版本指纹
   `menu stage n=` / `menu cards n= style=` / `hud inst n=` / `module ok` / `tpl guid=`
② 指纹是旧的？→ 部署问题（走 ③）。指纹是新的？→ 代码/渲染问题（回 17-symptoms §1）
③ 部署四查（12-deploy §7）：
   a) 三处 sha 是否一致（仓库 save / 网页工作区 save / 真机）
   b) `assets:scripts mounts` → 活跃容器挂的是哪条？deploy 写的可能不是它
   c) 多模块：registryEntries == 主脚本数 + 模块数？
   d) 注入版：/cell = \{ [0-9]+/ 命中吗（不是 includes('__GUID')）
④ 静态预检：node …/scripts/audit-lua.mjs lua/main.lua → 看 fail 数
   重点看 local 预算（200-local 会让整段不编译、白屏零日志）
⑤ 让用户**切出地图再切回**（内存版会覆盖写盘/不重载）
