## 9. 阶段 6：数值与反馈

### 9.1 先 grep 现值，再对文献

- 任务书给的「经典表」常张冠李戴：本案 `{100,300,500,800}` 是 **Tetris Guideline** 表，NES 是 `{40,100,300,1200}` 且倍率 `×(level+1)`。判据：`grep -n "pts\s*=" lua/main.lua` 看现值，再对文献定义。
- **每条数值标四级**：【经典】NES / 【Guideline】现代规范 / 【实测】本工程读数 / 【推断】本文推算（数值策划 §10 依据分级总表）。交付时给选项而不是替用户拍板。

### 9.2 速度曲线：公式要按「有没有锁定延迟」选

- Guideline 公式 `t(L) = (0.8 − (L−1)×0.007)^(L−1)` 在 L10=0.064s/格、L15=0.007s/格——本工程 `collides` 立即 `doLock`（**无锁定延迟**），那两档物理打不了。
- 改用帧表：`SPEED_TICKS = {30,26,23,20,18,15,14,12,10,9,8,7}`（tick/格），`LEVEL_UP_LINES=10`，`LEVEL_CAP=12` ⇒ L12=0.117s/格（18 格 2.1s）是物理下限。
- 判据：写下任一档速度，问一句「人手在这个 tick 下能不能完成一次落块操作」，不能就是不可达难度。

### 9.3 难度模型：算容量赛跑，不算速度曲线

```
容量 C = ROWS×COLS − 出生行 = 20×10 − 30 = 170 格
每块净增长 = 4 − 10ρ  （ρ = 消行数/块数，上限 0.4 = 10 格/行 ÷ 4 格/块）
存活块数 N = 170 / (4 − 10ρ)     存活时长 T = N × τ   （τ = 每块实际耗时）
ρ=0.08 → 53 块；ρ=0.145（AI 实测）→ 67 块；ρ=0.35 → 340 块
```

**结论（决定设计动作）**：时长由 **ρ 与 τ** 决定，不由速度曲线决定。「消行率 20% + 单局 5~8 分钟」两个目标**互不相容**（20% → 85 块 → 1.4~2.8 分钟）。新手 2~4 分钟 ⇔ τ∈[2.3,4.5]s；要打到 12 级需 ρ≥0.346。

**怎么验**：τ 与 ρ 从日志读（每块耗时、消行次数/块数），把两组读数代进公式，与目标区间比；不要用「看起来差不多」判。

### 9.4 计分自洽三条

1. `level` 从 1 起 ⇒ 用 `level` 不用 `level+1`（否则首级就错一倍）。
2. 连击/B2B 必须被**空落打断**：`cleared == 0` 时同时 `combo = 0` 与 `b2b = false`；漏掉这条「四消→不消→四消」仍吃 ×1.5，实测差 2000 分。
3. 入场 AI 自演**不写玩家成绩**：`clearLines` 缺 `autoDriving` 守卫会把 AI 的分算进玩家（已观测：HUD 非 0 分、消行率被低估）⇒ 玩家接管瞬间归零 `score/lines/level/pieceCount/combo/maxCombo/b2b`。

**改动联动（改数值前先数调用点）**：`grep -n stepDown` 有 4 个调用点（↓/S/手机按钮/重力），漏改重力那处就是「重力白送分」；加硬降分会连红 4 条用例，新期望 = 旧值 + `2 × rows`。

### 9.5 反馈接线（音效 + 抖屏）

- **只在动作真发生时播**：`sfxFrame == frameSeq` 帧闸保证同帧最多一条（同帧连按两次左移只 1 条）；消行音优先于落地音。
- 音效调用包 `pcall` + `noteFail`；`game.PlayAudio2D(id)` 要整数 id。
- **音频断言只有一条通道**：runner 层的 `playGet().audio.recent`（= `rt.audioSnapshot()`，全量历史，上限 128）。用例断言的 `lua` kind 跑在**新建沙箱**里，读不到主脚本全局；`playRunCase` 的 report 也不含 audio（D589）。用例里写 `audioExpect`/`audioExclude`，缺/多都 FAIL。
- 音效 id 语义在无网环境**无法离线确认**（`audio-catalog.js` 只给时长）⇒ 按**时长**挑并声明为占位；选型/接入/试听走 `game-sfx-kit` 技能，目录读数见 `workspace/tetris/docs/音效资产目录.md`（1094 条六类区间，D606）。
- **抖屏 = 全体视觉元素同偏移平移**：基准坐标在创建时存（`cellBX/cellBY`，唯一真源），只在 `shakeT > 0` 的帧写 `base + offset`，`layout()` 与 `newGame()` 都复位（否则抖动中按 R 留歪棋盘）。
- 硬约束：幅度 < 1 格（30px）否则露黑边；`FLASH_T[n] < SHAKE_DUR[n]`；衰减 `exp(−3u)`、9Hz。
- **Lua main chunk 200 个 local 上限**：数值全收进单表 `local NUM = {...}`（`main.lua:68`），既避开上限又让「调平衡只改一段」成立。

**阶段门**：手算期望值与用例读数逐条对齐（33 / 332 / 3284 / 4000 / 8524 分）+ **负对照**（把 `NUM.COMBO` 改成 0，该红的用例必须红——全绿只证明没崩）。

## 12. 验收三栏模板 + 四元组

每次交付/每轮修完都写这三栏，禁止合并成一个 ✅：

```markdown
### ① 已验证（标证据层级）
- 结构层：编译 / 注入 / 读图 / 静态断言
  · 例：`explain-gil-node-graph` 三行核对通过；root9 字段序 + 索引同序 + 引用闭合；runner 12/12
- 行为层：日志帧值 / 用例读数 / 出图机器判据
  · 例：`guide stage=1`、`settle destroy n=10`、入场残留 0、音效计数 20007×1
### ② 未验证（写清为什么）
- 例：真机上 image 颜色 alpha 是否生效——拿不到真机读数，已用「只做文字渐变」消掉该变量
### ③ 需用户在游戏内确认（一条一条可勾）
- [ ] 结算面板出现/消失正常（含重开）
- [ ] 按键手感与文案一致
- [ ] 音效可辨、不刺耳
```

**四元组**（每次跑命令都汇报）：`跑了什么 / 工作目录 / 退出码 / 关键日志行`。缺一样，验证就只是嘴上的（这是「用命令验证」而非「用嘴验证」的最小形态）。

## 13. 反模式清单

| 反模式 | 症状 | 正确做法 |
|---|---|---|
| 拿我方解析器全绿冒充目标宿主验证 | 我们读得通、编辑器判损坏、游戏不跑 | 分三级取证：我方静态 → 新图「造→删→字节相等」对拍 → 用户打开图（D559） |
| 按形状改写结构 | 字段序「看起来等价」就重排 ⇒ 存档损坏 | 保持原字段序；差分按**记录集**（id/kind/name/path）比，不按 sha（D558、D568） |
| 一处抛错静默死 | 真机整段逻辑不执行，日志空白 | 平台 API 全包 `pcall` + 带名日志（`main.lua` 42 处） |
| build 前跑 runner | 四条该红的用例全绿 | 改 lua → build → runner；判据=存档副本行数与磁盘 lua 一致 + 新标识符进存档（D591） |
| 用行号当 patch 锚点 | 改两次后锚点漂走，改错位置 | 用 grep 锚点（`grep -c <新标识符>`）+ 判据先变 |
| 常驻 + `SetVisible` 藏浮层 | 开局白屏、重开残留 | 懒创建 + `DestroyClientUIControl`（D581） |
| 模拟器绿就交付 | 真机白屏/零日志/面板不消失 | 对照 §11 差异表逐行标「验过/未验过」 |
| 把「没生效」与「被抹掉」混为一谈 | 反复重试写入，越试越乱 | 比写入前后 SHA；查载入路径 vs 查写回覆盖（D314） |
| 探针只试一种形态就断言「没这个 API」 | 误判 API 不存在，绕路重写 | 每种形态 pcall + 逐条日志（`ServerSignal`、`playKey` 命名） |

## 12. 用户反馈谱系（2026-10 俄罗斯方块实录：六类反复出现的纠正）

> 来源：一个 2D 游戏从空工程到能玩，用户 30+ 次纠正，67 条消息归纳。
> **开工就按这六条自检**——每类附用户原话（原话是判据锚）。

### 12.1 「你有自己检查吗」—— 我方渲染 ≠ 目标宿主（最高频，7 次）
- 原话：「game over 触发的结算页面，**你自己检查了吗**？」「和网页试玩不一致」「这个结论我没听懂，是哪个控件不支持？」
- 症状：headless 截图 + 我方解析器断言「已修复」，用户在游戏里看到另一回事。
- **判据**：任何「已修复」必须标证据层级 —— 我方解析器 / 模拟器 / 真机截图 / 用户目视。
  跨层推断 = 未验证。见 §真机 vs 模拟器差异表。

### 12.2 「很可能是你的错误的假设」—— 先排基础错再推广结论
- 原话：「先检查有没有犯最基础的错误，**比如 id 对不上**」「我们现在有 cli 不是可以列出 id 吗？这个绝对是支持的」
- 我犯的：4 个 guid 返回 nil ⇒ 断言「引擎不支持容器模板」；真相是**我造的模板形态不对**（1 条 f502 vs 编辑器产物 3 条）。
- **判据**：能力断言前必排三类 —— ①同 id 是否跨 def/entity 两命名空间 ②子控件 vs 顶层模板形态 ③引用/挂载是否指向存在的 id。
  **同一结论连续两次失败 ⇒ 停止推广，回头逐字段差分。**

### 12.3 「用官方文档回答我」—— 每个参数都要能溯源
- 原话：「先说，你现在的音效的配置是拿来的？**用官方文档回答我**」——答案是「没有官方依据，按时长猜的」。
- **判据**：数值/常量/映射一律四级标注 —— `官方文档:行号` / `实测读数` / `我方知识库` / `推测`。
  推测必须写「占位·未试听/未验证」，不许混进已确认。

### 12.4 用户指路 = 待办清单
- 原话：「刚刚的日志你也有看呀，**不是还有两个实验要做吗**？」「记得加载对应的技能，省的走弯路」「记得更新技能」
- **判据**：逐条回执（做了/没做/为什么）+ 当场执行；结论写进技能/文档，别只留在回复里。

### 12.5 「我直接打开游戏就能试玩」—— 交付判据是「用户能玩」
- 原话：「我们做了功能就要用起来，**我直接打开游戏就能试玩**」「所有的按键都没有响应，为什么？上一个版本是可以正常玩的」
- **判据**：绿灯（编译/用例/截图）只证明本级；不能玩就明说差什么。
- **出事流程**（用户原话）：「首先**回到之前能玩的正常玩的版本**，然后我们来分析」——先回退到可玩基线，再二分定位。

### 12.6 手感类感受 ⇒ 先翻译成数值再实现
- 原话：「节奏太快，根本不是正常人的速度，一下就穿帮了」「这个操作看的让人窒息，居然不放在最左边」
  「计算好了之后，其实**可以演戏**：小一点下落、模拟人在观察、用一用加速下落」
- **判据**：把感受落成可验收参数（每块 1.5~3s、横移 0.12~0.18s/格、35% 概率中途软降、贴墙优先…），
  再用日志/逐帧读数自证节奏（`demo pace think=… move=… drop=…`），别让用户再看一遍。

### 12.7 用户会自己动手的三类场合（给他留接口，别抢着做）
1. **他自己做编辑器差分**：「我同时添加了文本和一个容器模板」「我保存了，挂载在角色上面，**你差分学习一下**」
2. **他要网页调参**：「做成网页，你根据名字先选，交给我优化——要点是方便试听并轻松替换」
3. **他演示完要你对标**：「我修复是修改了信号再改回来，让编辑器自己写盘」
⇒ 先问「能不能你做 10 秒操作给我个样本」，比在代码里猜十轮便宜。
