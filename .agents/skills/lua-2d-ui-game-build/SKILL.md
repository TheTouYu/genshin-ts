## 0.5 一条硬规矩（用户 2026-10-30 令，优先级高于下面的"经验"）

**「加一个好看、带按键、可点、有动态样式、有音效反馈的按钮」= 最基本的要求，必须做成组件、10 秒量产。**
- 手写第二遍就是违规：一律走 `references/21-controls-factory.md` 的工厂（`CTL.btn{...}` 一次调用）。
- 合格判据只有一条：`ctl dump` 里出现 `ctl <名字> px=… py=…`（= 命中注册过，指针够得到），
  且三态读数（normal/hover/down 的颜色与位移）+ 点击后的日志锚都能贴出来。
- 常见违规形态：只画胶囊不注册热区（能看不能点）、有热区不回注册表（点了没反应）、
  三态只改颜色不改位移、忘记键帽。

## 1. 十条铁律（每条都是 25 小时里被打回的真实原因）

| # | 铁律 | 忘了会怎样 | 细节 |
|---|---|---|---|
| 1 | 界面结论只能由**出图 + 人眼逐字核对**给出 | 控件"接线了"、`visible=true`、探针全对，但屏幕上什么都没有 → 用户连打 4 次"和没修一样" | `01` `05` |
| 2 | 验证顺序：语法门 → 用例 → 出图逐字 → 模拟器体感 → 才上真机 | 拿用户当真机测试机 → "我不信你了" | `00` |
| 3 | **服务端 textbox 永远在运行时实例之下**；常驻文字双写（实例可见 + textbox 隐藏 + `setText` 单点收口） | 积分/HUD/底栏成片消失；隐藏 textbox 后 40+ 处 setText 变"写了但看不见" | `05` |
| 4 | 改 lua 必须**先 build 再 runner** | 用例全绿但那不是你的代码（假绿） | `01` `12` |
| 5 | 部署三处；多模块**每个 require 都要 register** | 用户"还是老板版"；模块 require 全失败 | `12` |
| 6 | `--source-file` 必须是 **build 注入版**；判据用数字形态正则 | 真机白屏，日志只到 `canvas`/`device` 就断 | `12` |
| 7 | `grep -cE '^local '` ≤150；超了把大函数挂表 `FN.x = function()` | 真机 200-local 编译报错：整段不编译、白屏、零日志 | `13` |
| 8 | 文字三判据：框高 `h ≥ 1.45×size+4` / 框宽按最长文案 / `valign=Middle` | 整行不画、裁半字（「↑」→「T」、「空格」→「各」） | `04` |
| 9 | 布局/演出函数里别引用别处的 local；每帧抛错 = 后半段全不执行 | 文字挤压/双影/贴顶，查半天文案，真因是 nil 全局 `halfH` | `14` |
| 10 | 单元即 commit + **commit 后哨兵 grep**；写盘前核对全量 diff | 队友互相覆盖（一天 3 次）、空壳 commit | `15` |

## 4. 阶段门（总览，细节在 `00-gates.md`）

| 阶段 | 干什么 | 过关判据（少一条都不算过） |
|---|---|---|
| P0 规则设计 | 玩法/数值/模式/难度 | 每个数值能手算复现；规则无自相矛盾；模式×界面×文字矩阵建好 |
| P1 画布与骨架 | 控件树/画布/帧循环/输入注册 | 日志有 `canvas WxH` / `tpl guid=` / `cellCount=` / `listen ok ×N` / `module ok ×M` |
| P2 最小可玩 | 输入→状态→渲染闭环 | 一套 runner 用例全绿（输入/规则/结束/重开）；固定种子可复现 |
| P3 界面成形 | 标题/HUD/结算/帮助 | **每个界面出图 + 逐字核对 + 无裁字无遮挡无双份无越界** |
| P4 手感与反馈 | DAS/锁定/音效/动画/三态 | 每键一条断言；三态可区分（出图三张）；按住类有时间上限 |
| P5 完整度 | 多模式/对抗/AI/文案 | 每模式端到端用例；模式×文字矩阵全过；AI 档位正确；文案 ≥3 落点 |
| P6 模拟器体感 | 网页真跑 | **你自己**每模式玩一局（不是看用例） |
| P7 真机 | 部署 + 真机日志 | 版本指纹全对 + `module ok` / `hud inst n=` + `lua-error` 零条 |

> **真机日志怎么取（2026-10-29 实证，别再踩）**：Lua 的 `print` 落在 `.gia` 的**记录字段 f23**，服务端节点图 print 落在 **f22**——
> `gia_log.py <log> text` 只解 f22，所以「text 里没有 `[前缀]` 行」**不能**证明 Lua 没跑；
> 用 `gia_log.py <log> lua` 取客户端脚本日志（官方教程第 8 节还要求日志面板**勾选「客户端脚本」**；
> 正常日志报不了错误时才在与脚本同目录生成 `ErrorLog.txt`；`game.PrintClientUITree()` 可把控件树打进日志）。
> 另：真机 `horizontalAlignment/verticalAlignment` **只收 `Enum.TextHorizontalAlignment/TextVerticalAlignment` 枚举**，传字符串报 `Text… expected, got string`（模拟器收字符串 ⇒ 先取枚举再回落）。

**三条红线**：P3 未过不许进 P7；P6 未过不许通知用户真机测试；P7 前所有"完成"必须写明验到第几层。
