## 1. 适用与不适用

**适用**：
- 纯 Lua 2D 玩法——整屏由 UI 控件构成，没有 3D 世界参与判定（俄罗斯方块、贪吃蛇、2048、扫雷、弹幕小游戏）。
- 3D 游戏里的**界面层**——HUD、结算面板、浮层、引导页、手机热区按钮。这套判据与 3D 世界无关：控件、画布、模板、浮层、结算信号在两类工程里是同一套（`workspace/tetris/docs/README.md` §1 工程构成）。
- 已有 2D 玩法要补「结算 / 数值 / 反馈 / 真机交付」中任意一环。

**不适用**（转对应技能）：
- 3D 世界建模、元件拼装 → `static-gil-model-builder`
- 服务端节点图逻辑与新图编写 → `dsl-nodegraph-development`
- 资产写回（变量/挂载/UI 控件/信号）的操作细节 → `genshin-ts-asset-operations`
- 真机开试玩、注入输入、取日志与取帧 → `device-playtest-loop`
- 工程 JSON 的字段与 patch op 速查 → `simulator-2d-route`

**边界说明**：3D 游戏界面层的差异只在「反馈的载体」——2D 里抖屏靠平移全部 UI，3D 里抖动可以交给相机【推断，未在本仓验证】；控件/文字/浮层/结算判据完全通用。

## 2. 阶段总表（0~7）

每阶段都写死三样：**输入 → 产出 → 验收门**。门不过不进入下一阶段；门过不了时先补判据，不要先补功能。

| 阶段 | 输入 | 产出 | 验收门（判据一句话） |
|---|---|---|---|
| 0 定玩法 | 一句玩法描述 | `docs/能玩定义.md`：6 条可断言清单 | 6 条都能写成一个用例断言 |
| 1 骨架 | 能玩定义 | `lua/main.lua` + `build/runner/shot` 三命令 | 改 lua → build → runner 全绿，且有变异回归证据 |
| 2 UI 布局 | 画布尺寸 + 文案 | 控件树 + `layout()` + 预览图 | 框高/宽度/对齐三条判据全过，出图机器判据全绿 |
| 3 状态机/输入 | 布局 | 状态机 + 键位表 + pcall 护栏 | 每键一条用例，状态迁移日志可读 |
| 4 浮层 | 布局基线 | 懒创建 + 销毁的结算/引导层 | 开局零浮层行，重开有 destroy 行，残留判据=0 |
| 5 真结算 | 浮层 | 信号定义 + 服务端图 + entity 挂载 | explain 三行核对 + 结算页真的弹 |
| 6 数值/反馈 | 可玩闭环 | 数值表 + 依据分级 + 音效抖屏 | 手算期望值与用例读数逐条对齐 + 负对照变红 |
| 7 真机交付 | 全绿工程 | GIA + 部署脚本 + 校准值 | 三查安全门 + 导入后三件事核对 + 试玩验收 |

**证据层级纪律**：结构层（编译/注入/读图/静态断言）≠ 行为层（日志帧值/用例读数）≠ 用户确认。三栏报告里三者分开写，不得合并成一个 ✅（`AGENTS.md`「修复报告三栏门禁」）。

## 3. 阶段 0：定玩法与「能玩」定义

**判据**：把「能玩」写成 6 条可断言清单，缺一条就是半成品。

| # | 清单项 | 可断言形式 | tetris 对应 |
|---|---|---|---|
| 1 | 输入能改状态 | 每个键位至少一条「按键→状态变化」断言 | `tests/03-move-left-right.json` |
| 2 | 规则闭环 | 碰撞/消行/计分至少一条断言 | `tests/04-line-clear-score.json` |
| 3 | 数值可复算 | 手算一个期望值，与代码读数逐位对齐 | 软降 3 格+硬降 15 格=33 分（D591） |
| 4 | 结束与重开 | 失败态可达 + 重开回初始态 | `tests/06-gameover-restart.json` |
| 5 | 有反馈 | 动作真发生时音效/动画有记录 | `tests/09-sfx-actions.json`、`10-shake-clear.json` |
| 6 | 有人真能玩 | 新手单局时长落在目标区间 | 结算页「用时」∈[2:00,4:00]（`docs/数值策划.md` §9，实测口径在 :626） |

**怎么验**：每条清单项后面写「测试文件名」或「日志关键字」；写完清单数一遍——有项写不出断言，就说明这项还不是验收项，只是愿望。

**反例**：「画面出来了」不是能玩——没有失败态与重开，玩家第二次进不去；没有数值可复算，改一行代码后无法判断是修好了还是碰巧了。

## 4. 阶段 1：工程骨架（单一真源 + 三道命令）

**推荐布局**（tetris 实测形态）：

```
工程/
├── lua/main.lua        # 唯一逻辑真源（含 UI 布局函数）
├── qxqy/build.mjs      # lua → save.json + 交付 GIA（唯一打包入口）
├── qxqy/runner.mjs     # 用例回归（含音效断言）
├── qxqy/shot.mjs       # 真实渲染出图（预览/证据）
├── qxqy/deploy.mjs     # 部署 + --calibrate 校准真机 guid
├── tests/NN-*.json     # 用例（编号=玩法顺序，便于定位）
└── docs/README.md      # 读数、判据、已验证/未验证清单
```

**判据 1（假绿门）**：runner 读的是**存档里的 Lua 副本**（`tetris.save.json` 的 `/assets/scripts/0/source`，实测 1961 行 / 72919 字符），不是磁盘上的 `lua/main.lua`。
- 怎么验（内容级）：存档内嵌源码的**行数 == 磁盘 lua 的行数**（build 注入 GUID 不改变行数）；再拿一个新加的标识符 `grep -c <标识符> <save.json>`，应为 1。
- 正确顺序：`改 lua → build.mjs → runner.mjs`。反例：直接跑 runner，**四条本该红的用例全绿**（D591），差点当成「改动无影响」。
- 注意 build 是**幂等**的：lua 没变时存档字节不变（实测 sha 稳定 4e316b7e），此时「sha 变了」不能当判据——用行数/哨兵，不用 sha。

**判据 2（语法门）**：`lua5.3 -e 'assert(loadfile("lua/main.lua"))'` exit 0。秒级，比启动模拟器便宜两个数量级，每次改完先过它。

**判据 3（断言咬得住规则）**：做一次**变异回归**——故意改错一条规则（重开键名改错 / 分数表错位 / 锁定时不消行），runner 必须报红。三组都红才证明用例在判东西；全绿只证明「没崩」。

**判据 4（出图必须是真实渲染）**：`shot.mjs` 走 `createStudio(存档) → playStart → playStep → playGet({view:true}).scene → renderScenePng`。
- 坑：`playRun(frames)` 内部会 `playStart()` 重开会话，注入的按键全丢（`qxqy/shot.mjs:19` 注释、D566 实测两帧字节完全相同）。
- 判据：出图脚本自己打机器断言（如「入场结算残留节点 = 0」「重开后残留 = 0」），不靠肉眼。

**现成脚本**：`scripts/rebuild-and-test.sh <工程目录>` 按「lua 语法门 → build → 存档副本校验 → runner」顺序跑，任一失败即停并打印四元组。

## 5. 阶段 2：UI 布局与文字（三条硬判据）

### 5.1 R1 框高：`h ≥ fontSize × 1.45 + 4`

- **来源**（可复核）：`studio/play/text-layout.js`，`lineHeight = 1.2×size` + `blockInset = 0.25×size + 4`；只画「完整放得下」的行（`visibleLineCount` 截断）。
- **症状**：不满足时**整行静默不画**，无报错、无日志、控件树正常。
- **实测**：64 号配 96 高（需 96.8）→ 整块消失；26 号配 40 高（需 41.7）→ 消失；34 号配 46 高（需 53.3）→ 消失。**差 0.8px 也是零渲染**。
- **怎么验**：先算需求高度再写控件（`workspace/tetris/lua/main.lua:279`、`:1009`、`:1520` 的注释就是当年算式），然后 `shot.mjs` 出图确认字在屏上；批量核对用 `scripts/textbox-fit.py <save.json>`（扫 `transformByPlatform.*.size.y` 并逐平台报违规）。
- 反例：字不显示先怀疑「文本为空」——正确第一嫌疑是框高不足（D566）。

### 5.2 R2 宽度：超出 `width − 4` 静默裁尾，不做缩放

- 实测：22 号 / 460 宽下 `SCORE 300 LINES 2 LV 1 FILLED 0` 最后一个 `0` 被裁成 `U` 样；改 20 号通过。
- 怎么验：文案最长那一条单独出图，尾部字符必须完整；中文文案按全角算宽，英文/数字按半角。
- 反例：「显示成别的字」不是字体问题，是裁尾。

### 5.3 R3 对齐与坐标

- `verticalAlignment` **必须有一处显式设成 `Middle`**：authoring 默认是 `Top`（实测 tetris 存档里 10 个布局 textbox 全是 `Top`），顶格会被切。可以在编辑器里写，也可以像本项目在 `layout()` 里运行时设（`main.lua:307-308`、`:565-566`）。
- 坐标 = `anchorMin/Max` + 像素 `offset`；`SetAnchoredPosition` 以画布中心为原点，左下→右上的 y 递增（tetris cell1=(-126,266) → cell200=(126,-266)）。
- **满幅铁律**（任何竖长玩法都会撞上）：10×20 棋盘宽高比 1:2，占满画布高度后左右必然各空一大片（1280×720 画布下棋盘宽仅约 330px，两侧空 ~950px）。填满靠**两侧内容面板 + 上下横幅**，不靠放大棋盘（放大到 PITCH 上限就会超高或比例变形）（D565）。
- `imageColor` 读回是**有符号 int32**（写 `0xFF1A1D26`=4279901478，读回 -15065818）⇒ 断言用有符号值，否则读回值对不上。

### 5.4 布局里的控件 vs 模板里的控件

- 同一控件「在布局还是在模板」**只由 `f504` 父指针决定**；两处可存在字段完全同构的两条记录（各 738B），没有额外「实例化标记」字段（D568）。
- 布局侧 UI 的合法形态是**一整棵子树**：`客户端控件容器(f502=23)` → `容器节点(f502=86)` → 子控件；默认布局的 `f503` 成员表只登记容器组 id。
- 含义：想「导入即能玩」，落地顺序必须是 ①容器组+容器节点 → ②控件挂容器节点（`f504`）→ ③模板进模板区 → ④更新被挂载的脚本/挂载指向 → ⑤备份 + Save_Level + Temp 同步（D568「触发条件→动作」）。

### 5.5 模板越少越好

- 每个客户端模板都可能在真机导入后被**重新编号**（`cell` 在模拟器 authoring 值 1073742105，真机 1073741849）⇒ 每多一个模板 = 多一处导入后校准。
- 对策一：`TEMPLATE_GUIDS = {真机值, authoring 值}` 逐个试，第一个成功者胜出（`main.lua` 常量；D566）。
- 对策二：**服务端 textbox 按 name 寻址**（`root:GetChild(name)`）跨宿主最稳，引导层因此零模板。

**阶段门**：出一组关键帧——入场/游戏中/消行/结算/重开——每张都带机器判据（节点数、关键文本、残留数），并对齐 §5.1–§5.4。

## 6. 阶段 3：状态机与输入

**状态机（判据式）**
- 状态要有**入口条件 + 退出动作**，且「入场键既开始也执行该动作」（不吞键，手感依赖它）。
- tetris 实测形态：stage0 等开始（玩家方块暂停，脚本 AI 自演）→ stage1 游戏中 → stage2 按 H 看键位表（暂停）→ 失败进结算层。

**帧循环**
- 固定步长：`acc += dt; while acc >= 1/60 do tick(); acc -= 1/60 end`，单帧最多 8 拍（防追帧雪崩）。
- `script:EnableUpdate(true)` **必须显式调用**，否则 `OnUpdate` 根本不派发（`README.md` §4）。
- 暂停 = 停重力/停推进，渲染与输入监听保持。

**键位**
- 官方具名键优先（`KeyboardCraftspersonKey36–39` = ←→↑↓、`KeyboardJumpKey`、`KeyboardCharacterSkill3Key`），比 CraftspersonKeyN 可读。
- 模拟器 `playKey(typeName)` 要**完整枚举名**（`KeyboardCraftspersonKey38Down`）。拼成 `...38DownDown` 时**不报错、不 warn、谁的监听都不命中** ⇒ 整份探针跑出「全静默」的假结论（D589）。
- `playStart()` 之后**先 step ≥ 1 帧**再注入按键；0 帧注入的键会丢（D589）。

**护栏**
- 真机一处抛错**整段死**（后续逻辑全不执行）：所有平台 API 调用包 `pcall`（`main.lua` 里 42 处）。
- 护栏必须**带名日志**：`noteFail('PlayAudio2D', err)`，静默 pcall 等于把故障埋进黑箱（`main.lua:213-214`）。
- 探测 API 存在性时**每种形态都试并逐条打日志**（如 `ServerSignal` 双形态，`main.lua:383-396`）；只试一种会把「形态不对」误判成「没有这个 API」。

**阶段门**：每个键位一条用例 + 状态迁移日志（`guide stage=N`）可读；改一处抛错能靠日志定位到函数名。

## 6.5 真机 Lua 上线三步门（2026-10-27 事故固化，血的教训）

**事故**：给足球线做「Lua 按键 → 服务端信号 → 客户端物理」的技术验证，CLI 侧 `assets:scripts register`
回显成功、挂载条目指向容器节点、`mounts list` 也正确，于是把「按键+物理+HUD」打包压给用户一次试玩。
结果日志里物理图跑了 389 条、**Lua 的 print 一条都没有**——脚本根本没执行，用户看到的是「一个按钮都看不到」。
**技能里早就写着「复制到磁盘 ≠ 真机已加载新代码」，但没有任何一条门要求我先证明脚本活着。**

**三步门（每步都要有可见读数，缺一步不许进玩法层）**：

| # | 门 | 判据 | 不过怎么办 |
|---|---|---|---|
| 1 | 结构在位 | `assets:scripts list` 有 `external=<字节数>`（非 MISSING）+ `mounts` 指向**容器节点** + 宿主控件在**活动布局**的 root9 树里可见 | 查登记表/挂载点/布局归属，别改 Lua |
| 2 | **脚本活着（最小可见证据）** | `OnStart` 第一件事：①写一条 HUD 文案（`c.text=`，官方无 SetText）②`print('[tag] onstart')`；**单独跑一轮**，看到字或日志才算活 | 按嫌疑排序：容器控件未 active/未可见 → 宿主挂载点层级 → 编辑器是否真的重载（f50 盘外写入必须重开地图） |
| 3 | 叠加玩法 | 前两步绿了才加键位/信号/物理；每加一层跑一轮 | 失败层可定位 |

**反向判据（最值钱的一条）**：一轮试玩里**没有** `onstart` 打印 ⇒ **停止推进玩法**，先修宿主。
否则你后面所有失败都分不清「脚本没跑」还是「逻辑错」——这正是本轮的浪费源（用户替我们跑了测试）。

**为什么 UI 文案比 print 更优先**：print 要去翻日志，文案是**用户一眼能看见**的存活信号；
两者都放（文案给人、print 给离线判读），成本几乎为零。


## 7. 阶段 4：运行时浮层（真机差异最大的一节）

浮层 = 运行时 `InstantiateClientUIControl` 出来的结算页/引导页。真机与模拟器在这一节分歧最大，判据按真机事实写。

| # | 事实（真机实测） | 做法 | 出处 |
|---|---|---|---|
| F1 | 开局就建浮层 + 靠隐藏 = 白屏风险 | **懒创建**：第一次需要时才 `pcall(build)`，建完立刻按当前画布摆位 | D581 |

## 9. 阶段 6：数值与反馈

### 9.1 先 grep 现值，再对文献

- 任务书给的「经典表」常张冠李戴：本案 `{100,300,500,800}` 是 **Tetris Guideline** 表，NES 是 `{40,100,300,1200}` 且倍率 `×(level+1)`。判据：`grep -n "pts\s*=" lua/main.lua` 看现值，再对文献定义。
- **每条数值标四级**：【经典】NES / 【Guideline】现代规范 / 【实测】本工程读数 / 【推断】本文推算（数值策划 §10 依据分级总表）。交付时给选项而不是替用户拍板。

### 9.2 速度曲线：公式要按「有没有锁定延迟」选

- Guideline 公式 `t(L) = (0.8 − (L−1)×0.007)^(L−1)` 在 L10=0.064s/格、L15=0.007s/格——本工程 `collides` 立即 `doLock`（**无锁定延迟**），那两档物理打不了。
- 改用帧表：`SPEED_TICKS = {30,26,23,20,18,15,14,12,10,9,8,7}`（tick/格），`LEVEL_UP_LINES=10`，`LEVEL_CAP=12` ⇒ L12=0.117s/格（18 格 2.1s）是物理下限。
- 判据：写下任一档速度，问一句「人手在这个 tick 下能不能完成一次落块操作」，不能就是不可达难度。

### 9.3 难度模型：算容量赛跑，不算速度曲线

```
容量 C = ROWS×COLS − 出生行 = 20×10 − 30 = 170 格
每块净增长 = 4 − 10ρ  （ρ = 消行数/块数，上限 0.4 = 10 格/行 ÷ 4 格/块）
存活块数 N = 170 / (4 − 10ρ)     存活时长 T = N × τ   （τ = 每块实际耗时）
ρ=0.08 → 53 块；ρ=0.145（AI 实测）→ 67 块；ρ=0.35 → 340 块
```

**结论（决定设计动作）**：时长由 **ρ 与 τ** 决定，不由速度曲线决定。「消行率 20% + 单局 5~8 分钟」两个目标**互不相容**（20% → 85 块 → 1.4~2.8 分钟）。新手 2~4 分钟 ⇔ τ∈[2.3,4.5]s；要打到 12 级需 ρ≥0.346。

**怎么验**：τ 与 ρ 从日志读（每块耗时、消行次数/块数），把两组读数代进公式，与目标区间比；不要用「看起来差不多」判。

### 9.4 计分自洽三条

1. `level` 从 1 起 ⇒ 用 `level` 不用 `level+1`（否则首级就错一倍）。
2. 连击/B2B 必须被**空落打断**：`cleared == 0` 时同时 `combo = 0` 与 `b2b = false`；漏掉这条「四消→不消→四消」仍吃 ×1.5，实测差 2000 分。
3. 入场 AI 自演**不写玩家成绩**：`clearLines` 缺 `autoDriving` 守卫会把 AI 的分算进玩家（已观测：HUD 非 0 分、消行率被低估）⇒ 玩家接管瞬间归零 `score/lines/level/pieceCount/combo/maxCombo/b2b`。

**改动联动（改数值前先数调用点）**：`grep -n stepDown` 有 4 个调用点（↓/S/手机按钮/重力），漏改重力那处就是「重力白送分」；加硬降分会连红 4 条用例，新期望 = 旧值 + `2 × rows`。

### 9.5 反馈接线（音效 + 抖屏）

- **只在动作真发生时播**：`sfxFrame == frameSeq` 帧闸保证同帧最多一条（同帧连按两次左移只 1 条）；消行音优先于落地音。
- 音效调用包 `pcall` + `noteFail`；`game.PlayAudio2D(id)` 要整数 id。
- **音频断言只有一条通道**：runner 层的 `playGet().audio.recent`（= `rt.audioSnapshot()`，全量历史，上限 128）。用例断言的 `lua` kind 跑在**新建沙箱**里，读不到主脚本全局；`playRunCase` 的 report 也不含 audio（D589）。用例里写 `audioExpect`/`audioExclude`，缺/多都 FAIL。
- 音效 id 语义在无网环境**无法离线确认**（`audio-catalog.js` 只给时长）⇒ 按**时长**挑并声明为占位；选型/接入/试听走 `game-sfx-kit` 技能，目录读数见 `workspace/tetris/docs/音效资产目录.md`（1094 条六类区间，D606）。
- **抖屏 = 全体视觉元素同偏移平移**：基准坐标在创建时存（`cellBX/cellBY`，唯一真源），只在 `shakeT > 0` 的帧写 `base + offset`，`layout()` 与 `newGame()` 都复位（否则抖动中按 R 留歪棋盘）。
- 硬约束：幅度 < 1 格（30px）否则露黑边；`FLASH_T[n] < SHAKE_DUR[n]`；衰减 `exp(−3u)`、9Hz。
- **Lua main chunk 200 个 local 上限**：数值全收进单表 `local NUM = {...}`（`main.lua:68`），既避开上限又让「调平衡只改一段」成立。

**阶段门**：手算期望值与用例读数逐条对齐（33 / 332 / 3284 / 4000 / 8524 分）+ **负对照**（把 `NUM.COMBO` 改成 0，该红的用例必须红——全绿只证明没崩）。

| 反模式 | 症状 | 正确做法 |
|---|---|---|
| 拿我方解析器全绿冒充目标宿主验证 | 我们读得通、编辑器判损坏、游戏不跑 | 分三级取证：我方静态 → 新图「造→删→字节相等」对拍 → 用户打开图（D559） |
| 按形状改写结构 | 字段序「看起来等价」就重排 ⇒ 存档损坏 | 保持原字段序；差分按**记录集**（id/kind/name/path）比，不按 sha（D558、D568） |
| 一处抛错静默死 | 真机整段逻辑不执行，日志空白 | 平台 API 全包 `pcall` + 带名日志（`main.lua` 42 处） |
| build 前跑 runner | 四条该红的用例全绿 | 改 lua → build → runner；判据=存档副本行数与磁盘 lua 一致 + 新标识符进存档（D591） |
| 用行号当 patch 锚点 | 改两次后锚点漂走，改错位置 | 用 grep 锚点（`grep -c <新标识符>`）+ 判据先变 |
| 常驻 + `SetVisible` 藏浮层 | 开局白屏、重开残留 | 懒创建 + `DestroyClientUIControl`（D581） |
| 模拟器绿就交付 | 真机白屏/零日志/面板不消失 | 对照 §11 差异表逐行标「验过/未验过」 |
| 把「没生效」与「被抹掉」混为一谈 | 反复重试写入，越试越乱 | 比写入前后 SHA；查载入路径 vs 查写回覆盖（D314） |
| 探针只试一种形态就断言「没这个 API」 | 误判 API 不存在，绕路重写 | 每种形态 pcall + 逐条日志（`ServerSignal`、`playKey` 命名） |

## 12. 用户反馈谱系（2026-10 俄罗斯方块实录：六类反复出现的纠正）

> 来源：一个 2D 游戏从空工程到能玩，用户 30+ 次纠正，67 条消息归纳。
> **开工就按这六条自检**——每类附用户原话（原话是判据锚）。

### 12.1 「你有自己检查吗」—— 我方渲染 ≠ 目标宿主（最高频，7 次）
- 原话：「game over 触发的结算页面，**你自己检查了吗**？」「和网页试玩不一致」「这个结论我没听懂，是哪个控件不支持？」
- 症状：headless 截图 + 我方解析器断言「已修复」，用户在游戏里看到另一回事。
- **判据**：任何「已修复」必须标证据层级 —— 我方解析器 / 模拟器 / 真机截图 / 用户目视。
  跨层推断 = 未验证。见 §真机 vs 模拟器差异表。

### 12.2 「很可能是你的错误的假设」—— 先排基础错再推广结论
- 原话：「先检查有没有犯最基础的错误，**比如 id 对不上**」「我们现在有 cli 不是可以列出 id 吗？这个绝对是支持的」
- 我犯的：4 个 guid 返回 nil ⇒ 断言「引擎不支持容器模板」；真相是**我造的模板形态不对**（1 条 f502 vs 编辑器产物 3 条）。
- **判据**：能力断言前必排三类 —— ①同 id 是否跨 def/entity 两命名空间 ②子控件 vs 顶层模板形态 ③引用/挂载是否指向存在的 id。
  **同一结论连续两次失败 ⇒ 停止推广，回头逐字段差分。**

### 12.3 「用官方文档回答我」—— 每个参数都要能溯源
- 原话：「先说，你现在的音效的配置是拿来的？**用官方文档回答我**」——答案是「没有官方依据，按时长猜的」。
- **判据**：数值/常量/映射一律四级标注 —— `官方文档:行号` / `实测读数` / `我方知识库` / `推测`。
  推测必须写「占位·未试听/未验证」，不许混进已确认。

### 12.4 用户指路 = 待办清单
- 原话：「刚刚的日志你也有看呀，**不是还有两个实验要做吗**？」「记得加载对应的技能，省的走弯路」「记得更新技能」
- **判据**：逐条回执（做了/没做/为什么）+ 当场执行；结论写进技能/文档，别只留在回复里。

### 12.5 「我直接打开游戏就能试玩」—— 交付判据是「用户能玩」
- 原话：「我们做了功能就要用起来，**我直接打开游戏就能试玩**」「所有的按键都没有响应，为什么？上一个版本是可以正常玩的」
- **判据**：绿灯（编译/用例/截图）只证明本级；不能玩就明说差什么。
- **出事流程**（用户原话）：「首先**回到之前能玩的正常玩的版本**，然后我们来分析」——先回退到可玩基线，再二分定位。

### 12.6 手感类感受 ⇒ 先翻译成数值再实现
- 原话：「节奏太快，根本不是正常人的速度，一下就穿帮了」「这个操作看的让人窒息，居然不放在最左边」
  「计算好了之后，其实**可以演戏**：小一点下落、模拟人在观察、用一用加速下落」
- **判据**：把感受落成可验收参数（每块 1.5~3s、横移 0.12~0.18s/格、35% 概率中途软降、贴墙优先…），
  再用日志/逐帧读数自证节奏（`demo pace think=… move=… drop=…`），别让用户再看一遍。

### 12.7 用户会自己动手的三类场合（给他留接口，别抢着做）
1. **他自己做编辑器差分**：「我同时添加了文本和一个容器模板」「我保存了，挂载在角色上面，**你差分学习一下**」
2. **他要网页调参**：「做成网页，你根据名字先选，交给我优化——要点是方便试听并轻松替换」
3. **他演示完要你对标**：「我修复是修改了信号再改回来，让编辑器自己写盘」
⇒ 先问「能不能你做 10 秒操作给我个样本」，比在代码里猜十轮便宜。
