# 字母/立体文字专业建模指南（2026-08-09 R6.1 用户核验反馈：A/G 太粗糙）

R6.1 教训：魔方及格但字母不达标——7×9 网格、1 格笔画、34 块只够"认出是 A"，G 拓扑错误（右侧封闭成方框）。本指南是字母模型的**专业标准**。

## 设计哲学：曲线与流线感（R6.2 用户核心要求）

**视觉目标：一眼看过去有曲线、流线、美感，不是板砖拼出的长方体。** 字母的斜边、弧线、笔画转折都要有"笔势"——粗细渐变、圆弧过渡，不能出现贯穿整个字形的大段无变化直线。

判断标准（自检前先问自己）：
- 这个字母的轮廓上有几个方向突变？突变处有没有阶梯过渡还是直角折？
- 斜边/弧线相邻块是"整面重叠"还是"点接"？（点接 = 板砖感）
- 笔画宽度从头到尾是否一致？（粗细渐变才有笔势）

### 拟合方法一：阶梯法（方块网格，适合 17×17 量级）

- 曲线/斜线段每 **2~3 行横移 1 列**（不是每行 1 列），且每次横移都保持相邻行重叠 ≥2 格——阶梯看起来密、面连接连续；
- 曲率大的弧段（如 G 的顶部弧）用**每行微移 + 中间补块**，让弧轮廓从 3 格到 13 格逐行展开（见 G 参考位图：13→11→… 逐行收/扩，不是一次跳 4 格）；
- 禁止出现"两段直线 45° 硬接"的折角：转折处补块或提前 2 行开始过渡。

### 拟合方法二：切向长条法（流线型外壳，适合鼠标/车辆等曲面体）

像建模鼠标流线外壳一样：先定义目标曲线/曲面（圆弧半径 R、控制点），按**细腻度**离散——曲率大处密、平缓处疏；每段用一个细长块（10009001 缩放成长条，长边沿切线方向）摆放，相邻段端部重叠 0~0.02 或留均匀小缝。

离散公式（生成器内断言）：
- 弧上相邻段中心沿弧步长 ≤ 块长边（保证覆盖）；
- 段端部间隙 = 中心距 − (两段长边和/2)，目标 0~0.02；
- 法向偏移 = 表面 + 半厚 + 0.005~0.01（与贴片同规则）。

选法原则：方块字模（字母）用阶梯法；曲面外壳（鼠标、圆润模型）用切向长条法。两者混合也可（主体阶梯 + 关键弧长条）。

## 字体规格（所有字母统一，同高同基线）

| 参数 | 值 | 说明 |
|---|---|---|
| 字模网格 | **≥ 15×17** | 7×9 太低，斜边成"点接点"阶梯 |
| 笔画厚度 | **3 格**（横杠 2 格） | 粗细统一是"专业感"第一来源；禁止斜边 1 格/支腿 2 格混用 |
| 块边长 EDGE | 0.28~0.48 | 与节距 PITCH=EDGE+GAP 一起决定字高（17 行）|
| 块间缝 GAP | 0.02 | 缝只是 4% 细节，盲目加大会让笔画更碎 |
| 深度层 | **2 层**（D=2×EDGE+GAP） | 单层像纸片；2 层有稳定侧面 |
| 块数 | A≈105、G≈140（≥30 太宽松） | 块数必须建立在正确字模上，否则是更密的错误轮廓 |
| 基线 | 三模型底面统一贴地（0~0.02） | 用包围盒最低点对齐，不用中心点 |

颜色：**分色不能切碎笔画轮廓**（红一条蓝一条像零件拼装）；正面统一色，需要层次用 2 层深度的前后层做明暗。

## 字母拓扑硬规则

- **A**：顶部 3 格宽中心帽（不是双块平顶）；斜边每 2~3 行横移 1 列（保证相邻行重叠 ≥2 格，整面连接不点接）；横杠在顶部往下 50~58% 高度、2 格厚；字腔三角形负空间稳定张开。
- **G**：先画开口 C（顶部弧 + 左竖 + 底部弧 + 右上开口），再在字腔加内横画；**右上必须留 ≥3×3 明确开口，右外竖只保留下半段**。禁止从封闭矩形框出发。
- 行方向：字模位图第 0 行=视觉顶部 → 世界 y 最大（R6 曾因行方向反了 A 倒置）。生成器自检必须断言"顶部行 y 最大"。

## 生成器骨架（所有字母通用，自检从参数表推导）

```python
EDGE, GAP, DEPTH = 0.48, 0.02, 2
PITCH = EDGE + GAP
def cuboid(pos, scale, rgb):   # 返回 item dict（scale 直接写边长！）
    return {'resourceId': 10009001, 'position': [round(v,6) for v in pos],
            'rotation': [0,0,0], 'scale': [round(float(s),6) for s in scale],
            'color': {'enabled': True, 'rgb': rgb, 'opacity': 100, 'overlay': 'overwrite'}}

def bitmap_to_items(rows, body_rgb, accent_rgb=None):
    """rows: 位图列表，rows[0]=视觉顶部。'#'=块；可选 'x'=强调色块。"""
    items = []
    H = len(rows)
    for j, row in enumerate(rows):
        for i, ch in enumerate(row):
            if ch not in '#x':
                continue
            rgb = accent_rgb if ch == 'x' else body_rgb
            for k in range(DEPTH):
                items.append(cuboid(
                    [(i - (len(row) - 1) / 2) * PITCH,
                     (H - 1 - j) * PITCH + EDGE / 2,  # j=0 顶部 → y 最大（防倒置）
                     (k - (DEPTH - 1) / 2) * PITCH],
                    [EDGE, EDGE, EDGE], rgb))
    return items

def self_check(label, items, expected_min_blocks, colors):
    assert len(items) >= expected_min_blocks, f'{label}: 块数 {len(items)} < {expected_min_blocks}'
    for it in items:
        assert abs(it['scale'][0] - EDGE) < 1e-9, f'{label}: scale={it["scale"][0]} != 边长 {EDGE}（半尺寸混入？）'
    assert len(colors) >= 5, f'{label}: 颜色数 {len(colors)} < 5'
    # 行方向防倒置：位图第 0 行=顶部，其 y 必须是最大值（R6 曾因 y 随行号递增而倒置）
    ys = sorted({round(it['position'][1], 6) for it in items})
    assert ys[0] + EDGE < ys[-1], f'{label}: 行方向可能倒置（顶部行 y 应最大）'
```

## 自检纪律（R6.1 反复 patch 的根因，必须遵守）

1. **断言数字全部从参数表推导**（EDGE/GAP/PITCH/块数），禁止手写魔数（如把 0.48 硬编码进断言）；
2. **颜色数断言 = 实际实现颜色**：魔方是 7 色（6 面彩 + 深灰体），断言 ≥5 而不是 ==5/6；字母含深灰/浅灰后 ≥5；
3. **一次跑完所有断言再报**：不要 fail-fast 一次只暴露一个错误（R6.1 因此迭代 8 次）；用循环收集全部失败一次打印；
4. **readback 断言排除参照块**：小样里的 1×1×1 尺寸参照、0.5 块等不属于目标模型，按 scale 白名单跳过；
5. 生成器写完**先本地 python 跑自检再进 CLI 候选**，别拿 CLI 当调试器。

## CLI 契约备忘（勿重复踩）

- `assets:static-assemblies inspect --format json`：`occupiedIds` 是 **dict**（键 `definitionAuxiliaries`/`instanceAuxiliaries`，值为 list），不是 list；`templateCandidates[].definitionAuxiliaryIds` 才是 list；
- `assets:entities import/apply-candidate/patch --format json`：stdout 纯 JSON（日志走 stderr），字段 `sourceSha256/candidateSha256/candidate|backup|writePerformed|previewOnly`；
- 命令输出管道一律 `2>/dev/null`；禁止 `2>&1` 把日志混进 JSON。
