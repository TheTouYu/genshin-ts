# GUI 真值标注（gui-annotation）

> 最近校验：2026-10-19（两轮用户亲手修改 `r006`/`r003` 后提炼 R1–R10）
> 配套工具（都在 `.scratch/gui-corpus/tools/`）：`rows_from_ocr.py`（行枚举）、`edges.py`（扫描线量边）、
> `boxer.py`（像素紧致边界）、`remeasure_grid.py`（同色连通域）、`prelabel.py`（预标/渲染 overlay/校验）、
> `audit_truth.py`（漏标体检）；记分器 `tools/ys-coverage`。

## 何时用本技能

- 要产出或复核 **bbox 级真值**（`truth*/<frame>.json`），或给检测器造数据集；
- 收到"漏标 / 错位 / 宽度不对"的反馈要**系统性修**，而不是逐点打补丁；
- 要把**老师/用户的修改 diff** 沉淀成可复用规则；
- 任何需要 `audit_truth.py` 通过（未覆盖文本 <3）的标注交付。

不适用：只要"这屏有什么"的自然语言描述；只要 OCR 文本（用 `ys-screen` 的 text 层即可）。

## 一、切块标注法（用户 2026-10-19 指定，实测比整帧标注准）

整帧标注时注意力被大画面吃掉，**成片列表和小图标成片漏**。改为：

1. **切块**：先按**大对象**把整帧切成 **5–8 块**，例如
   `顶栏 / 左侧栏（竖向整栏） / 中部网格 / 右侧属性面板 / 底部条 / 弹窗`。
   判据：块边界落在**空白缝**上（面板间 ≥40px 的纯背景带），不切断任何面板。
2. **块内标注**：每块单独当一张图看（用 `grid.py --crop x0,y0,x1,y1` 出带原帧坐标标签的裁剪图），
   坐标可以直接读原帧坐标（grid 标签就是原帧坐标）；手写数据时用**块内坐标**，汇总时加偏移。
3. **汇总**：`x_full = x_block + off_x`、`y_full = y_block + off_y`；**边界处按 IoU≥0.5 去重**
   （跨块的同一对象只留面积更大/更完整的一个），记一条 `merged_from` 便于回溯。
4. **回全图复核**：渲染 overlay（`prelabel.py render`），**人眼全图看一遍**：
   有没有框落在空白处（错位）、有没有明显没框的列表区（漏标）、四角有没有小件。
5. **按 R1–R10 补**（见下）：这一步是"系统性纠偏"，不是收尾装饰。

实测收益（2026-10-19）：整帧法在派蒙菜单漏**整条左图标栏**（=`[8,23,118,1385]`）与**网格大区**
（=`[138,448,870,963]`），切块法把左栏当独立块后一次就标出来。

## 三、工具链与命令（全部只读）

```bash
# ① 行枚举（只枚举"哪些 y 上有文字行"，不做判定）
python3 .scratch/gui-corpus/tools/rows_from_ocr.py <ocr.json> --region x0,x1,y0,y1 --pad 6
# ② 量边（面板/行带左右上下沿；沿"平坦带"扫描线最稳）
python3 .scratch/gui-corpus/tools/edges.py <frame.png> --axis x --line 800 --from 0 --to 600 --thr 12
# ③ 小图标像素紧致边界
python3 .scratch/gui-corpus/tools/boxer.py <frame.png> --roi 30,460,120,580
# ④ 平皮肤网格（同色连通域，前提与 ys-screen 无关）
python3 .scratch/gui-corpus/tools/remeasure_grid.py <frame.png> --roi 160,400,1000,1420 --truth <truth.json>
# ⑤ overlay（编号=json id）+ schema 校验
python3 .scratch/gui-corpus/tools/prelabel.py render <truth.json> --out <overlay.png>
python3 .scratch/gui-corpus/tools/prelabel.py check <truth-dir>
# ⑥ 漏标体检（门槛：每帧未覆盖 <3）
python3 .scratch/gui-corpus/tools/audit_truth.py --truth-dir <dir> --ocr-dir <ocr-dir> --json-out <audit.json>
# ⑦ 覆盖率复核（有检测器输出时）
tools/ys-coverage --truth <dir> --pred <pred-dir> --pred-format xyxy --require-kind tile=0.95,icon=0.6
```

`truth JSON` schema（与 `AGI-BAR §四` 一致）：`frame/image/size/annotator/criteria/layout/classes/units/_provenance/objects[]`，
`objects[]` 每项 `id/parent/bbox[x,y,w,h]/kind/text/clickable/state/badges/clipped/note`。

## 四、验收（三条缺一不可）

1. **audit 未覆盖 <3 / 帧**（`audit_truth.py` 退出后看每帧 `uncovered`）；全帧 `>=3` 判不通过、退回重标。
2. **overlay 必看**：至少抽 1–2 帧**人眼**看全图 overlay，检查错位/漏块（脚本查不出"框在空白处"）。
3. **coverage 复核**（有 pred 时）：`ys-coverage` 的 `hit/rate/fp` 与上一版对比，**分 kind** 看有没有掉；
   `--require-kind` 当门禁。

另加两条交付纪律：`_provenance.uncertain` 写"最没把握的 3 处"；`prelabel.py check` 必须全 OK（无越界/非法 bbox）。

## 五、已知陷阱（都是踩过的）

1. **bbox 口径有三种，混用会让数字静默归零**：
   - `tools/ys-screen` 的 `containers[].bbox` = **xyxy**（源码 `int(x0/scale)…int(x1/scale)`）；
   - **OCR `text[].bbox` = xyxy**（对象另带 `w`/`h` 字段，可用 `b[2]==x+w` 判定）；
   - `AGI-BAR` schema 与 truth JSON = **xywh**。
   判别法：拿对象自带的 `w/h` 或"两个框是否互相包含"验一次；**宁可加一行断言**。
   实测后果：记分器按 xywh 读 pred ⇒ f06/f07/f08 的 19 格全部 0 命中（SUMMARY 0.021）；`audit_truth.py`
   按 xywh 读 OCR ⇒ r022 报 6、r044 报 5 处假漏标。
2. **OCR 粘行**：OCR 会把相邻多行粘成一个高框（实测 `自定义` 高 231px 跨 5 行）。
   单框覆盖率永远 <0.6 ⇒ 覆盖率要按**真值框并集**算，不要按"与单框最大重叠"。
3. **编辑距外推**：等距外推（网格 pitch、卡片列距）只在小范围内可信；**首末两个必须实测**，
   中间按线性插值并在 `uncertain` 里写"±N px"。
4. **切块边界**：块与块之间的重叠区必须去重，否则同一对象出现两次，`coverage` 的 `units` 会虚高。
5. **HUD 不算单元**：`DXVK/FPS/GPU/min/max/UID/ms/i9/纯数字` 是宿主覆盖层；
   但**别把它们从 truth 里也删掉后再拿 audit 判**——audit 有自己的 HUD 词表。
6. **族名标签不可信**：交接时别人写的族名可能是错的（实测：`r013` 写"委托/任务"实为**邀约事件**；
   `r022` 写"好友/成就混合"实为**好友列表 + 角色展柜弹窗**）。**以画面为唯一判据**，并在 README 注明更正。

## 六、把老师反馈变成规则（这是本技能最值钱的部分）

用户/老师亲手改一份 truth 后，别只修那一帧，按这四步把 diff 变成规则：

1. **取 diff**：备份版在 `.scratch/gui-corpus/_backups/<时间戳>/`，与新文件逐对象对比
   （`kind/bbox/text` 三元组；新增对象 = 新 id 或空 text 且 未被匹配）。
2. **分类偏差**（每类给一条规则，别混）：
   - 位置系统性偏（例：顶栏 x 偏移 +393~+586）→ **定位方式错了**（左对齐 vs 右边缘）；
   - 尺寸普遍偏（例：宽 78~154px）→ **口径错了**（按文字长度 vs 按可见皮肤）；
   - 整类对象漏（例：整条左栏 / 网格大区）→ **扫描策略漏了**（四边/整栏没扫）；
   - 单个错到离谱（例：`dy=-1010`）→ **分区没先判**。
3. **量化**：每条规则写"用户 diff 的实测数字"（偏移量、宽度差、漏的 bbox）。**没有数字的规则不算规则。**
4. **落到"每帧必须写"的位置**：`_provenance.rules_applied` 逐条 + 下一批逐帧自证；
   再回灌本技能 §二（新规则追加编号，旧规则若有反例要改）。

**反例警戒**：只修一帧不回灌 ⇒ 同类偏差会在下一帧重演（本项目已连发两次：R1–R5 后仍有 R6–R10）。

## 七、交付物清单（每批）

- `<frame>.json`（truth schema + `_provenance`：`family/layout/rules_applied/tool_assist/uncertain`）
- `<frame>-overlay.png`（编号=id，供人眼抽查）
- `README.md`：逐帧 units + audit 结果 + 与上一批的差异 + 族名更正 + 未闭合项
- `_build_*.py`：数据表（改一处可重生成；**不要手写 20 份 JSON**）


## 六、质量闭环：打分必须修到可用（2026-10-19 用户点名）

> 用户原话：「别急呀，都话这么时间打分了，你怎么就不让这几个代理顺手修复到A级呢？」

- **评分只是中间产物**：质检产出 A/B/C 分级后，**同一批代理必须继续把 B/C 修到 A**，而不是交报告收工；
- C 级不是"剔除就完事"：能修的修（如 c19 只差 6 处、v088 只差 1 块），修不动才剔；
- **每轮质检都要带一份"可修清单"**（哪帧、差什么、预计几处改动、修完能否到 A）；
- 修完必须重跑 `audit_truth.py` 并**重出 overlay 人眼复核**（指标通过 ≠ 框对）。

## 七、生成器与人手修复并存 → 必须加覆盖守卫

- 本项目 `truth/_build_truth.py` 会用内嵌表重生成 f00–f13，**跑一次就抹掉人工修的 22 个区域框**；
- 对策：写前读目标 JSON，若含 `_provenance.qc_<日期>` 记录则 SKIP（需显式 `--force`）；
- 通用规则：**凡"生成器 + 人手修过的产物"并存，生成器必须能识别并保护人工成果**。
