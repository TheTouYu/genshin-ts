# 千星编辑器操作面覆盖计划（AGI 级目标）

> **目标（用户 2026-10-19 18:52 定义）**：本轮结束时，把千星编辑器里 **99.5% 的操作点**覆盖并**资产化**。
> **状态**：执行中。分母、判据、工具、台账四件套在本文定义；读数在 `ops-ledger.tsv`。
> **为什么不是"手工点一遍"**：编辑器有 13 大类界面 / 60+ 小节，手工枚举必然漏且不可复算。
> 覆盖率必须是**机器可复算的读数**，不是"我觉得都点过了"。

## 一、什么叫"一个操作点"（分母定义）

**操作点 = （界面路径, 控件, 动作）三元组的一个具体实例。**
判据：在某个确定的界面状态下，屏幕上有**一个可独立触发**的交互元素（按钮/页签/菜单项/开关/滑块/输入框/场景操作），
触发它会产生**可与"不触发"区分开**的观测差异。

- ✅ 算：`系统菜单 > 角色特殊管理 > 新建条目`、`实体摆放 > 工具栏 > 吸附开关`、`地形编辑 > 笔刷半径滑块`
- ❌ 不算：纯文字标签、装饰图、立绘、同一按钮的不同文案（同一个点）、不可交互的提示条
- ⚠️ 同一控件在不同**模式**下（地形/实体/元件库/战斗预设）算**不同操作点**——它们真的不同

## 二、分母从哪来（两条独立通道，必须对账）

| 通道 | 来源 | 优点 | 缺点 |
|---|---|---|---|
| **A 文档面** | `docs/ui-tutorial/official-guide-editor-interface.md`（2576 行，13 大类 60+ 小节） | 官方权威、不依赖我们爬到哪 | 与当前版本可能有差异；描述未必等于控件 |
| **B 爬取面** | 实时爬 UI：进入每个面板，枚举可交互元素 | 反映真实界面 | 爬不到"需要前置条件才出现"的控件 |

**分母 = A ∪ B 去重后的人工裁决集**。
两条通道的差集本身就是产出物（A−B = 文档有但界面上没有/改了名；B−A = 界面上有但文档没写）——
这也正好检验"官方文档候选可支持面"原则。

## 三、覆盖率怎么算（可复算）

```
covered(P) ⟺ 台账里存在一行 P，且该行同时有：
   ① 调用方式（坐标 或 名字解析结果）—— 可重放
   ② 观测差异（前后帧差异区 / 落盘物 / 状态迁移 / 文本变化 至少一项）—— 行为读数
   ③ 判据值（具体的数字或字符串，不是"看起来变了"）
覆盖率 = covered 数 / 分母
```

**99.5% 的语义**：分母 ≤ 400 时，未覆盖 ≤ 2 个；分母 400–800 时未覆盖 ≤ 3–4 个。
每个未覆盖点必须写明**具体原因**（缺外部前置 / 破坏性且不可在一次性存档里复现 / 需要另一名玩家）。

## 七、与 GUI AGI 模块的关系（这轮真正要回答的问题）

覆盖率不是目的，**它是一次"GUI 模块够不够 AGI"的压力测试**：

- 如果每覆盖一个点都要我手写坐标，那说明模块只是我的"手"，不是"眼+手"；
- 如果模块能**自己枚举候选、自己判断点了有没有用、自己记账**，覆盖率就是它自己跑出来的数。

所以每推进一段，都要记录：**这一段里有多少个操作点是"模块自己找到的"，多少是"我喂给它的"**。
这个比例就是当前 GUI 模块离 AGI 的真实距离。
