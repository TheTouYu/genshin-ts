## 二、立场：融合，不是重做（用户原话）

> 「我不是要重做，然后通过关键补充，把我们的系统，提高到一个更宏大的体系上，进一步接近 agi。」

用户的六个补充**没有一条需要新建子系统**，全是在既有接口背后换实现或加字段：

| 补充 | 接到现有哪里 | 接口 |
|---|---|---|
| 对象检测 | `ys-screen` 的 `containers[]` 内部引擎 | 不变 |
| 切块 + 并行 OCR | `ys-screen` 的 `run_ocr()` 内部 | 不变 |
| 返回下一稳态 | `tools/ys-editor/ys-state`（稳态）+ `tools/ys-editor/ys-do` 的 `post`（后置断言） | 不变 |
| 过渡态报告 | `tools/ys-editor/ys-state` 补 `LOADING` + `ys-do` 账本 | 加字段 |
| 切片按需返回 | `ys-screen` 新增 `slices[]` + `tools/ys-editor/ys_lookd.py` 缓存 | 加字段 |
| 判据注入 | `tools/ys-editor/ys-do` 的 `post`：固定 `wait` → 可注入判据 | 加字段 |

**既有六样骨架不能丢**（它们正是"补充能接上"的前提）：判据单一源（门槛⑤）、`tools/ys-editor/ys-do` 的 pre/post 硬约束、失败账本（每笔失败配防线）、性能门禁、`tools/ys-editor/ys_lookd.py` 常驻服务、回归集（24 帧双通道）。

## 三、第 0 轮：把 AGI 体系建成票（不先写代码）

按 `docs/maintenance/ticket-driven-workflow.md`，在 `.scratch/gui-stack/` 的 `issues/` 下一票一文件，**票面必须带验收读数**。

建票顺序建议（读完语料后自行判断，可调）：

1. **对象检测换路线** —— 底层地基。切块、并行 OCR、切片索引、按需返回**全部建立在「先有对象」之上**
2. `clipped` 判据（数据已有：f08 顶部 `174×64` vs 完整 `174×156`）
3. `LOADING` 态 + 过渡态报告（耗时 / 加载态内容）
4. `state` 字段 + 组（group）—— 状态是**组内相对属性**，没有组判不出选中
5. 切片索引 + 按需局部返回（目标 <50ms）
6. 判据注入（模型定义"什么算完成"）
7. 「不存在」类结论的安全闸门

## 四、铁律（用户定的，不可妥协）

1. **验收上限 = 用户在环反馈轮**；脚本用例是**下限补充**，不是上限。
   用户先发现 → 固化成脚本 → 防退化
2. **阈值必须由实测/物理地板倒推**，不许先写后回填（本仓已犯 3 次：9000ms / `<10ms` / 缓存 `<10ms`）
3. 下「不存在」结论前**必须先扫全可滚区域**；单帧只能支持「这一屏没看到」
4. 回答用户之前**必须重新取帧**，不许拿上一帧的结论继续讲
5. 关键仪器未过验收门槛不进下游任务；失败必须落账并配防线
6. **看到工具报了字段，先确认它是「读数」还是「截断」** —— 实证：`controls` 8 帧恒为 40，
   是 `tools/ys-screen:77 MAX_CONTROLS = 40` + `:621 kept[:MAX_CONTROLS]` 的截断，不是「界面有 40 个控件」

## 五、反馈轮怎么做（用户认证"最稳"的进化方式）

```
用户真实操作界面 → 我重新取帧 → 逐帧对比「人眼看到的 vs 工具输出的」
     → 差异即缺口（归入能力分类）→ 修 → 用同一批帧复验（给前后数字）→ 下一轮
```

每轮产出四样：①新帧 + 逐帧差异表（进 `.scratch/gui-corpus/`）②缺口登记（open-items / 失败账本）
③修复 + 同批复验读数 ④语料沉淀（进回归集或成为下轮素材）

**为什么这条比脚本用例硬**：用例只能测我想到的东西，用户会踩到我想不到的。
本轮 14 帧里，最大的发现（容器命中率 0.8%、"派蒙菜单没有千星入口"是错的）全部来自这条路。

## 附录：两个已验证的工程坑（省你半小时）

1. **`doc_health` 的 BOARD HEAD 检查**：只在**提交该文件时**校验，且比对的是**当时的 HEAD**（提交前仍是父提交）。
   ⇒ 正确做法是把 BOARD 的 HEAD 设成**父提交**再单独提交；设成新提交哈希会自指死循环。
2. **gitignore 两个语法坑**：①不支持行尾注释——`pattern  # 注释` 会被当成整个模式，规则**静默失效**；
   ②尾斜杠只匹配目录，目标是文件时不能带 `/`。两处都用 `git check-ignore -v <path>` 验证。
