## 三、形态：A 方案（用户 2026-10-18 裁决「A，这就是我要的」）

```
屏幕 → 常驻感知服务(ys-lookd 常驻，库加载一次)
      ├ L1 对象检测(GPU ≤10ms) → objects[]
      ├ 切片+分块 OCR(并行)    → slices[]
      ├ L2 分组 / L3 状态 / L4 可点性 → groups[] / state{}
      └ 帧时间线 + 变化事件    → transitions[]
      ↓
单一世界状态（唯一 schema，全仓读写它）
      ↓
三个动词：look() / act(target) / wait_until(判据)
      ↓
编排层：意图→plan→执行→证据→成功固化成技能 / 失败自愈三招
      ↓
真机验收台（三游戏共用回归剧本）
```

**四条不可让步的形态决定**：

1. **一个 schema，不是一堆工具各自的 JSON**——否则 L2/L3/L5 无处落脚。
2. **三个动词，不是 81 个命令**——`ys-screen` = look 的实现，`ys-do` = act 的实现，旧工具退化为内部细节。
3. **返回回执，不返回像素**——"点一下就到达稳态"本身才是能力。
4. **预算写进契约**——每个返回带 `budget_ms` + `degraded`；超预算**降级并说出来**，不假装正常（静默失能已犯 6 次）。

**部署形态**：1 个常驻服务 + 1 份 schema 文档 + 3 个工具 + 1 条预算门禁 + 1 个技能。不是 81 个脚本，也不是巨型 prompt。

## 四、世界状态 schema（草案 v0，票 23–27 共同演进）

```jsonc
{
  "frame_id": "sha256:…",          // 内容寻址；同帧复用免重算
  "captured_at_ms": 0,
  "state": { "name": "EDITOR", "evidence": [...], "channel": "fast|full" },
  "objects": [{
    "id": 7, "parent": 2, "bbox": [x,y,w,h], "kind": "tile|card|button|row|panel|chip|icon|avatar",
    "text": ["…"], "text_source": "slice-ocr|fullframe",
    "glyphs": [], "badges": [{"type":"red|scroll|crown|claimed|lastopen","bbox":[]}],
    "state": {"selected":false,"focused":false,"disabled":false},   // L3 新增
    "affordance": {"clickable":"yes|no|unknown","evidence":[]},     // L4
    "clipped": {"edges":["top"],"cut_by":"screen","px":92},         // L5
    "confidence": 0.0
  }],
  "groups": [{"id":1,"role":"section|row|grid|tabs","members":[7,8],"parent":0}],  // L2
  "slices": [{"object_id":7,"path":".cache/slices/<sha>.png","local_bbox":[0,0,174,156]}],
  "transitions": [{"from":"PLAYTEST","to":"LOADING","ms":0}],       // 过渡态
  "budget_ms": {"total":50,"detect":10,"ocr":0},
  "degraded": []                                                   // fail-closed：降级必须自述
}
```

**三条硬约定**：结构不猜语义（`kind` 只描述形状/角色，不猜"这是抽卡按钮"）／每对象必带 `evidence`／判不出来就 `degraded` + 说明，不编。

## 五、六样既有骨架：融合不重做（用户 seq 6348 原话「我不是要重做」）

| 骨架 | 保留什么 | 本阶段怎么用 |
|---|---|---|
| 判据单一源（`ys-state`） | 全仓状态名/阈值/模板只此一处 | 世界状态的 `state` 字段直接引用它 |
| `ys-do` pre/post 硬约束 | "不存在没有 post 判据的动作" | `act()` 的契约由它承载 |
| 失败账本 append-only | 每笔失败配防线 | 自愈三招的输入 |
| 性能门禁（`ys-perf`） | 防退化 | 加 §一 的预算项 |
| 常驻服务（`ys-lookd`） | 进程复用、socket | **A 形态的核心承载**，扩成世界状态服务 |
| 回归集（24 帧 + 26 样本） | 三道自动门禁 | 每票收轮必跑 |

## 六、反馈轮协议（用户唯一注意点：**难或不确定 → 把用户引入**）

**触发即停手找用户的三类**（写死在每张票的验收项里）：

1. **需要新权限/新依赖**：装包、下权重、占 GPU、改共享工具默认行为、动游戏文件/地图。
2. **判据本身不确定**：真值标不出来、两个判据给出相反结论、阈值只能拍不能测。
3. **连续 2 轮同一项无进展**，或改完发现"进步"无法被第三方复算。

**一轮五步（10–20 分钟）**：用户操作 → 我**重新取帧** → 逐帧「人眼 vs 工具」差异表 → 缺口归类并登记 → 同批复验给**前后两个数字**。
**每轮四样产出**：新帧 + 差异表 / 缺口登记 / 修复与前后读数 / 语料沉淀（进回归集或下轮素材）。
**纪律**：你说"看"就重新取帧（不许用上一帧）；下"不存在"前必须滚全；工具字段先确认是读数还是截断（`controls` 恒 40 = `MAX_CONTROLS` 截断）。

## 九、路线图巩固（2026-10-19，训练进行中复盘）

> 本节回答两件事：**AGI 愿景到底是什么**、**我们现在走到哪、下一步怎么验收**。
> 上一版票表（§八）被本节取代为分层路线：票是手段，层是目标。

### 9.1 愿景（一句话与三条判据）

**一句话**：让代理**像人一样看屏幕**——一眼给出"这一屏有什么、它们在什么关系里、各自什么状态、能不能点、还有没有更多、什么时候可以断言不存在"。

**三条判据（都可量化）**：
1. **一眼**：同屏重复识别 ≤100ms（已达成：底板路径 96ms / 帧缓存 15–45ms）；
2. **看懂**：六层 L1–L6 全部有读数（当前 L1 有、L2 部分、L3–L6 基本没有）；
3. **敢断言**：任何"不存在/不可点/已完成"的结论必须先扫全（L6 否定闸门），否则只能说"没看到"。

**它不是"一个 UI 检测器"**：检测器只是 L1 的一部分。真正的产物是**世界状态服务**（形态 A：look / act / wait_until + 单一 schema），检测/OCR/结构/状态都是它的内部实现。

### 9.2 通用性从哪来（借游戏/编辑器做测验，但模块是通用的）

| 通用性来源 | 为什么通用 | 现状 |
|---|---|---|
| **空间先验**（界面=矩形+层级+对齐） | 任何 GUI 都成立，与内容无关 | CV 容器：tile 100% |
| **多帧共识**（静止底板 + 差量） | 任何界面"大部分时间静止"；动的是渲染不是语义 | 已验证：同页微变 96ms |
| **学习型补短板**（只学 CV 抓不到的） | 微调不需要大语料，几百–几千实例即可 | 训练 v1 进行中 |
| **反馈轮校准**（老师改 → 规则 → 技能） | 把人的判断变成可复用规则（R1–R10 已沉淀成技能） | 两轮教学已验证 |
| **按需精读**（先结构后文字） | 先给"有哪些块"，需要时再 OCR 那一块 | OCR 按对象/底板路径 |

### 9.3 分层路线（取代 §八 票表）

| 阶段 | 目标 | 验收读数 | 状态 |
|---|---|---|---|
| **D1 语料** | A 级标注语料覆盖游戏+编辑器 | 44 帧 / 1664 实例；编辑器 ≥30%（现 36%）；audit 全帧 <3 | ✅ |
| **D2 检测器 v1** | L1 对象检测（8 类）可训练、可评估 | 留族验证 micro-recall；每类 recall 表 | 🔄 训练中（loss 修好后 val 0.14→） |
| **D3 结构层（L2）** | parent/groups 从标注学习 + 几何派生 | 分组 precision/recall ≥0.8 | ⬜（标注里已有 parent） |
| **D4 状态层（L3）** | 选中/焦点/红点/禁用/已领取 | 每状态 precision/recall；相对属性对齐 | ⬜ |
| **D5 可点性（L4）** | clickable ∈ {yes,no,unknown} + 证据 | 与人工标注一致率 ≥0.9 | ⬜ |
| **D6 完整性（L5）** | 滚动补全：跨帧条目 + 位移 | 补全后信息完整率；滚动检测准确率 | ⬜（已有跨帧证据） |
| **D7 否定闸门（L6）** | 扫全才允许断言不存在 | 事故复现集 0 假否定 | ⬜ |
| **E 真机闭环** | 用世界状态驱动动作完成任务 | 5 条真实任务成功率；失败可归因 | ⬜ |
| **F 跨应用泛化** | 同模型/规则跑新 App | 新 App 零样本可用度 ≥X%（待定） | ⬜ |

### 9.4 今晚新增的四条硬证据（写进判据，别再走回头路）

1. **抓帧不能持续**：10fps 抓 15 分钟（≈9000 次）会把 DXVK presentation 拖死（GPU 0%、画面冻结）⇒ 只允许按需单帧，或按页采 N 帧后停。
2. **差量必须按"多帧共识底板"**：单帧基线与固定网格都失败（动画让 2–18% 像素散布全帧）；多帧中值+动态掩码后，同页微变 96ms、动态像素仅 0.03–1%。
3. **训练不涨先做 overfit 测试**：CenterNet focal loss 在 20 目标/图的小数据上被背景淹没（heatmax 0.98→0.23），换 BCE+pos_weight=200 后 0.97；**过拟合都做不到=代码 bug，与数据量无关**。
4. **标注质量要分级且门禁可执行**：A/B/C 分级 + `audit_truth.py`（含 `--ignore-title`/`--rules`）+ 生成器覆盖守卫（防重生成抹掉人工修复）。

### 9.5 反馈轮（用户要求，已落地）

- **审阅页**：`tools/ys-review`（只读点评）+ `tools/ys-annotate`（可改可补，等距补全）+ **自动保存服务**（`ys-annotate-serve`，改动即时落盘）；
- **补丁闭环**：`ys-annotate-apply` 把人工修改写回真值（删除/更新/新增 + `_human_edits` 记录），代理据此"知道你改了什么"并按规律外推；
- **教学沉淀**：每轮 diff → 规则（R1–R10）→ 技能（`.agents/skills/gui-annotation`）；
- **三类触发即停手**：需要新权限/依赖、判据不确定、连续两轮无进展 → 找用户。

## 十、标准复核（2026-10-19 11:0x，用户点破"标准在滑"）

> 用户原话：「我们做的 agi，一个操作之后可能要被重复执行 1 万次都算少的，一定不要随意放低标准。」

**这是一次自我审计**：我在对话里多次把"实测值"当成"及格线"，典型的滑坡是
`≤200ms/帧`（2026-10-18 已犯过一次，§一 有记录）→ 现在又对"滚动 7–8s""读屏 0.11s"满意。

### 10.1 原口径（不降）

| 项 | 硬指标 | 依据 |
|---|---|---|
| **单次动作**（点击/滚动，不含抓帧） | **≤50ms** | §一 口径 1「ms 级」 |
| 单次默认路径（判态/定位/取数） | **≤50ms** | §一 口径 1 |
| 缓存命中 | **≤5ms** | 已实测 0–3ms |
| 对象检测单帧 | **≤10ms** | 实测 27.6ms ⇒ **仍超标 2.8×** |
| 冷启动 | 不计入，但必须常驻规避 | — |

### 10.2 当前实测（2026-10-19 11:0x，`time` 实测）

| 项 | 实测 | 对 50ms 的倍率 | 判定 |
|---|---|---|---|
| `ys-gui-slot` 空跑（含取焦点+还原） | **1.38–2.31s** | **28–46×** | ❌ 严重超标 |
| 抓帧（daemon grab，XShm+JPEG） | **0.51s** | 10× | ❌ 超标 |
| `ys-list`（daemon OCR，热/冷） | 0.11s / 0.32s | 2.2× / 6.4× | ⚠️ 热态接近，冷态超标 |
| 对象检测 | 27.6ms（v2 41.3ms） | 2.8–4× | ❌ 超标 |
| 拖动 200px（动作本体） | ~0.4s | 8× | ❌ 动作本身也超标 |
| 滚轮 40 格 | ~0.05s | ✅ | 唯一达标项 |

### 10.3 若要按 10^4 次重复算（用户的尺度）

| 路径 | 单次 | ×1e4 | 判定 |
|---|---|---|---|
| 现在（每动作一次槽位+两次抓帧） | ~7s | **19.4 小时** | 不可接受 |
| 批量化（10 动作/槽位） | ~0.7s | 1.9 小时 | 仍不可接受 |
| **目标（动作 ≤50ms + 验证 ≤50ms）** | ~0.1s | **17 分钟** | 可接受 |

### 10.4 达成路径（三条必须做，不是优化建议）

1. **焦点租约（focus lease）**：一次取焦点 → 保持 T 秒 → 期间所有动作直接注入（零槽位开销）→ 到期自动还原。
   目标：动作路径 **≤50ms**。风险：长租约会占用用户桌面 ⇒ 租约上限 + 看门狗 + 显式声明。
2. **验证只在必要时做**：动作后置断言用**增量信号**（像素差/文本变化）而不是整帧重读；整帧读 **≤5ms**（缓存命中）。
3. **抓帧去编码**：验证用 1/4 缩放灰度（约 0.05s），不进 JPEG/PNG。

**纪律**：以上三条写进 `AGI-BAR §十` 后，**任何"实测值"都不得自动成为新及格线**；要改标准必须显式写进本节并说明理由。
