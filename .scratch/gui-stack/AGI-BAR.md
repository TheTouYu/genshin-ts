| 层 | 要什么 | 现状（实测） | 票 |
|---|---|---|---|
| **L1 感知** | 这一屏有哪些独立可交互对象：bbox + 类型 | 仅不透明纯色格有效（f06/f07 38/38，f08 19/19）；半透明/插画/纯图标 0–67%；纯图形无文字块（f08 六个图标、角色头像）全漏 | 23,24 |

| **L3 状态** | 选中/焦点/红点/禁用/已领取/上次打开 | **schema 无 `state` 字段**；f12「语言」选中 0 检出，绝对亮度判据失效（背景 96→189 单调递增，语言 168 < 账户 173）；f08 红点 6 对漏 2；皇冠角标非红色未认 | 27 |
| **L4 可点性** | 这对象能不能点、点哪里 | `affordance.clickable` **恒 unknown**；无 hover/按下态通道；f05 两个「前往」按钮与正文同为 `kind=content` | 28 |

## 三、形态：A 方案（用户 2026-10-18 裁决「A，这就是我要的」）

```
屏幕 → 常驻感知服务(ys-lookd 常驻，库加载一次)
      ├ L1 对象检测(GPU ≤10ms) → objects[]
      ├ 切片+分块 OCR(并行)    → slices[]
      ├ L2 分组 / L3 状态 / L4 可点性 → groups[] / state{}
      └ 帧时间线 + 变化事件    → transitions[]
      ↓
单一世界状态（唯一 schema，全仓读写它）
      ↓
三个动词：look() / act(target) / wait_until(判据)
      ↓
编排层：意图→plan→执行→证据→成功固化成技能 / 失败自愈三招
      ↓
真机验收台（三游戏共用回归剧本）
```

**四条不可让步的形态决定**：

1. **一个 schema，不是一堆工具各自的 JSON**——否则 L2/L3/L5 无处落脚。
2. **三个动词，不是 81 个命令**——`ys-screen` = look 的实现，`ys-do` = act 的实现，旧工具退化为内部细节。
3. **返回回执，不返回像素**——"点一下就到达稳态"本身才是能力。
4. **预算写进契约**——每个返回带 `budget_ms` + `degraded`；超预算**降级并说出来**，不假装正常（静默失能已犯 6 次）。

**部署形态**：1 个常驻服务 + 1 份 schema 文档 + 3 个工具 + 1 条预算门禁 + 1 个技能。不是 81 个脚本，也不是巨型 prompt。

## 四、世界状态 schema（草案 v0，票 23–27 共同演进）

```jsonc
{
  "frame_id": "sha256:…",          // 内容寻址；同帧复用免重算
  "captured_at_ms": 0,
  "state": { "name": "EDITOR", "evidence": [...], "channel": "fast|full" },
  "objects": [{
    "id": 7, "parent": 2, "bbox": [x,y,w,h], "kind": "tile|card|button|row|panel|chip|icon|avatar",
    "text": ["…"], "text_source": "slice-ocr|fullframe",
    "glyphs": [], "badges": [{"type":"red|scroll|crown|claimed|lastopen","bbox":[]}],
    "state": {"selected":false,"focused":false,"disabled":false},   // L3 新增
    "affordance": {"clickable":"yes|no|unknown","evidence":[]},     // L4
    "clipped": {"edges":["top"],"cut_by":"screen","px":92},         // L5
    "confidence": 0.0
  }],
  "groups": [{"id":1,"role":"section|row|grid|tabs","members":[7,8],"parent":0}],  // L2
  "slices": [{"object_id":7,"path":".cache/slices/<sha>.png","local_bbox":[0,0,174,156]}],
  "transitions": [{"from":"PLAYTEST","to":"LOADING","ms":0}],       // 过渡态
  "budget_ms": {"total":50,"detect":10,"ocr":0},
  "degraded": []                                                   // fail-closed：降级必须自述
}
```

**三条硬约定**：结构不猜语义（`kind` 只描述形状/角色，不猜"这是抽卡按钮"）／每对象必带 `evidence`／判不出来就 `degraded` + 说明，不编。

## 五、六样既有骨架：融合不重做（用户 seq 6348 原话「我不是要重做」）

| 骨架 | 保留什么 | 本阶段怎么用 |
|---|---|---|
| 判据单一源（`ys-state`） | 全仓状态名/阈值/模板只此一处 | 世界状态的 `state` 字段直接引用它 |
| `ys-do` pre/post 硬约束 | "不存在没有 post 判据的动作" | `act()` 的契约由它承载 |
| 失败账本 append-only | 每笔失败配防线 | 自愈三招的输入 |
| 性能门禁（`ys-perf`） | 防退化 | 加 §一 的预算项 |
| 常驻服务（`ys-lookd`） | 进程复用、socket | **A 形态的核心承载**，扩成世界状态服务 |
| 回归集（24 帧 + 26 样本） | 三道自动门禁 | 每票收轮必跑 |

## 六、反馈轮协议（用户唯一注意点：**难或不确定 → 把用户引入**）

**触发即停手找用户的三类**（写死在每张票的验收项里）：

1. **需要新权限/新依赖**：装包、下权重、占 GPU、改共享工具默认行为、动游戏文件/地图。
2. **判据本身不确定**：真值标不出来、两个判据给出相反结论、阈值只能拍不能测。
3. **连续 2 轮同一项无进展**，或改完发现"进步"无法被第三方复算。

**一轮五步（10–20 分钟）**：用户操作 → 我**重新取帧** → 逐帧「人眼 vs 工具」差异表 → 缺口归类并登记 → 同批复验给**前后两个数字**。
**每轮四样产出**：新帧 + 差异表 / 缺口登记 / 修复与前后读数 / 语料沉淀（进回归集或下轮素材）。
**纪律**：你说"看"就重新取帧（不许用上一帧）；下"不存在"前必须滚全；工具字段先确认是读数还是截断（`controls` 恒 40 = `MAX_CONTROLS` 截断）。

## 七、本文档的由来（防再丢）

2026-10-18 18:5x，我在新会话里答复"做到什么程度"时把口径降成 `≤200ms/帧`、把学习型检测判为"只离线"，
用户纠正：「大方向没错。但是程度不对，我们要达到agi基准，同时你丢细节了。」
查证：`grep -rl 'L6\|否.*闸门\|自动下滑' docs/maintenance/design-2026-10-18-gui-*.md .scratch/gui-stack/` → **0 命中**。
**结论**：六层清单与四条量化口径当时只活在会话记录里，压缩即失。本文档即修复；任何"按 AGI 标准"的讨论先读它。

**九条已证伪路线**（防重走）：长直边投影找面板边框／均匀面连通域／同色块连通域／颜色区域生长／OCR 抓 W-S 小图标判可滚／容器边缘纹理判裁切（真实裁切仅 15.5%）／末行距容器下沿判可滚／同行尺寸离群判裁切／像素平坦度解释漏检。
详见 [`retrospective-2026-10-18-gui-structure.md`](../../docs/maintenance/retrospective-2026-10-18-gui-structure.md) §4。
