# 千星 GUI 操作栈（gui-stack）设计稿

> 状态：**待裁决**（2026-10-17 用户点题后设计；来源=当天 15 条错误的实测归因 + 用户三条要求）
> 用户原话：「GUI 操作是你整个链路未知数最多也是你最不擅长的部分，一定要花足够多的时间，
> 做一个好一个方便你递归自进化的设计，**既要在工程设计上想办法弥补你在多模态上的不足，
> 也要设计多个监控体系，来应对复杂和未知**。」
> 适用范围：所有需要驱动千星编辑器 / 沙箱 / 试玩窗口的自动化；游戏生产（三个 3D 游戏）消费本栈。

## 〇、一句话设计

> **把「我记得要验证」变成「系统不可能不验证」。**

今天的 15 条错误里，**没有一条是被测对象出错**——全部落在仪器、前提、判据三类。
而我其实**已经把这些教训写进了技能**（`device-playtest-loop` 铁律 0-8），当天照样全犯，
连那份技能本身都**没加载**。⇒ 写给人（模型）看的纪律不构成保障；**只有让正确路径成为唯一路径才算**。

## 二、设计原则（五条，全部可验证）

| # | 原则 | 判据（怎么知道做到了） |
|---|---|---|
| P1 | **读数必须自带新鲜度证明** | 任何读数 API 都可能返回 `STALE`；取不到新鲜读数时**报错而不是返回旧值** |
| P2 | **动作必须带后置判据** | 不存在"只点击不验证"的动作入口；账本里每行都有 `post` 读数与判定 |
| P3 | **定位按语义不按坐标** | 坐标只作为匹配结果的副产物出现；代码里不出现裸坐标常量 |
| P4 | **多传感器投票，不一致要出声** | 每个状态至少 2 个独立判据；不一致返回 `AMBIGUOUS` 而非猜一个 |
| P5 | **GUI 层的一切推断都要能被非 GUI 真值证伪** | 每轮必须有至少一条**不经过屏幕**的判据（文件/日志/进程） |

## 三、四层架构

```
L3 编排  ys-loop   ── 一轮 = 一串 ys-do + 产物检查 + 账本 + report
                       ↑ 每轮产出 uncertainties.md（下一轮的探针任务）
L2 动作  ys-do     ── 意图级动作：{前置态, 定位, 动作, 后置态, 超时} → 写账本
                       ↑ 不存在没有 post 判据的动作
L1 状态  ys-state  ── 全界面态判据机（多判据投票）+ 显式状态迁移图 + 回归样本
                       ↑ 返回 UNKNOWN/AMBIGUOUS 而不是猜
L0 观测  ys-observe── 唯一取数入口：新鲜度证明 + 降级链 + 区域裁剪
```

### L0 观测层 `ys-observe`

**唯一取数入口**，产出结构化读数：

```json
{"kind":"px","probe":"300,300","value":"70,94,62","fresh":true,
 "frame":{"id":"f-0007","diffFromPrev":3849,"window":"0x01400001","atop":true},
 "source":"peek","at":"2026-10-17T08:12:03Z"}
```

- **新鲜度证明**：抓两帧必须**不相同**（`diffFromPrev > 阈值`）；相同 → `fresh:false` + `STALE` 退出码。
  今天的 0 像素差分就是反面教材。
- **降级链（代价从低到高，能用低的绝不用高的）**：
  `文件/日志/进程` → `像素探针` → `模板匹配` → `区域差分` → `视觉读图`
- **区域裁剪**：默认只抓必要矩形，裁在图外，不用整屏。
- **绝对化一切外部路径**（今天的 cwd 陷阱）。

### L1 状态层 `ys-state`

覆盖全部已知界面态，**每态至少两个独立判据**：

| 态 | 判据 A（像素/通道序） | 判据 B（模板/文本） |
|---|---|---|
| EDITOR | px(100,400) 绿主导 | 左栏地图名模板 |
| MENU | px(300,300) 三通道 >200 | 侧栏「存档管理」图标模板 |
| SAVELIST | px(300,300) **蓝主导**且暗 | 存档卡标题模板命中 |
| LOADING | 进度条区域亮蓝 | — |
| PLAYTEST | 右下「奇域试玩中」水印模板 | 游戏 HUD 元素 |
| PAUSE | 三按钮模板（继续/重新/中断挑战） | — |
| SETTLE | px(1000,600) 纯白 + px(1280,700) 暗蓝 | 「离开」按钮模板 |

- **投票**：A 与 B 不一致 → `AMBIGUOUS`（今天的草地误判会被 B 拦下）。
- **状态迁移图**：显式记录「哪个动作从哪个态到哪个态」；动作后置态不符 → 立刻报错，不继续往下点。
- **回归样本**：`calib/regress/*.png` + 期望态。改任何判据后 `ys-state --regress` 必须全绿。
  **这等于给 GUI 判据写单元测试**——判据失效会在改动的当刻暴露，而不是等到我在游戏里白烧一轮。

### L2 动作层 `ys-do`

```bash
ys-do playtest-start      # 前置态 MENU → 试玩磁贴 → 直接上传 → 开始游戏 → 后置态 PLAYTEST
ys-do playtest-stop       # 前置态 PLAYTEST/PAUSE → 中断挑战 → 离开 → 后置态 EDITOR + 日志新增
ys-do open-map <名>       # 前置态任意 → 存档管理 → 定位该卡「编辑」→ 确认 → 后置态 EDITOR + 身份=该图
```

每个意图 = 一张显式表：

```json
{"intent":"playtest-stop",
 "pre":["PAUSE","PLAYTEST"], "post":["SETTLE","EDITOR"],
 "steps":[{"locate":"btn-abort-challenge","do":"click"},
          {"locate":"btn-leave","do":"click"}],
 "artifacts":["Beyond_Debug_Log/*.gia mtime 前进"]}
```

- **动作账本**（append-only JSONL，`~/ys-round/<ts>/ledger.jsonl`）：
  每步记 `意图 / 前置态读数 / 定位来源与置信度 / 实际注入的 evdev 键或坐标 / 后置态读数 / 判定 / 证据图路径`。
- **不可能静默失败**：任一步 `FAIL` → 全轮中止 + 打印账本行号 + 前后证据图。
  今天"跑完一轮不知道哪环断"从此消失。
- **焦点**：所有注入强制经 `ys-gui-slot`（**唯一通道**，裸调 ydotool 在 shim 层就被拒）。

### L3 编排层 `ys-loop`

一轮 = `离开图 → CLI 构建 → 进入图 → 试玩 → 注入 → 退出 → 取日志 → 判定`，每步走 `ys-do`。

- **产物检查（P5 的非 GUI 真值）**：磁盘 SHA、`Beyond_Debug_Log/*.gia` 是否新增、原始字节里有无预期标记。
- 产出：`report.md`（人读）+ `ledger.jsonl`（机读）+ `evidence/`（图）+ **`uncertainties.md`**（下一轮输入）。

## 四、六路监控体系（用户明确要求"多个"）

**为什么要多路**：单一监控会被单点故障骗过。今天我就是"只有一路（截图）+ 没有新鲜度"，于是一路错到底。
六路**互相独立**，任何一路报警就停下：

| # | 监控 | 盯什么 | 判据 | 独立性 |
|---|---|---|---|---|
| **M1** | 窗口/焦点 | 原神是否在栈顶、焦点在谁手里 | `ys-wins` + `getactivewindow` | **不依赖截图** |
| **M2** | 界面态 | 现在哪个界面、是否卡住 | `ys-state` 多判据投票 | 依赖截图 |
| **M3** | 动作 | 每步前后态与判定 | 动作账本 | 独立记录 |
| **M4** | **产物** | 磁盘 SHA / 新日志 / 日志标记 | 文件系统 + 原始字节 | **完全不经过 GUI** ← 终极真值 |
| **M5** | 新鲜度 | 读数是否陈旧 | 两帧差分 | 元监控（监控监控） |
| **M6** | 进程健康 | 编辑器/游戏存活、重连风暴 | `ys-editor-guard status` | 独立于 GUI |

**M4 是压舱石**：GUI 层所有推断都必须能被它证伪。
今天我说"玩家没移动"只能靠看，而"日志里有没有 `YJ-BOOT`/`PLEN`"才是真值——**这条今天没建立起来**。

**看门狗**：任一监控连续 N 次异常 / 单步超时 → 停止本轮 + 落盘现场（截图+账本+进程快照），**不继续往下点**。

## 五、递归自进化机制

用户要"方便递归自进化"。核心是：**每次运行都产出下一轮要补的探针**。

### 5.1 标定库 `calib/controls.json`

```json
{"name":"试玩磁贴","locate":{"kind":"template","file":"templates/playtest-tile.png"},
 "calibrated":"2026-10-17T07:50:00Z","evidence":"evidence/…png",
 "conditions":{"screen":"2560x1440","theme":"default"},
 "confidence":0.97,"lastVerified":"2026-10-17T07:50:00Z","failures":0,"status":"OK"}
```

- **带证据、带时间、带适用条件**——坐标是**会话态**，模板+条件是**资产**。
- 失败一次 `failures++`；超阈值自动置 `SUSPECT` 并**要求重新标定**（不允许继续用可疑标定）。
- 分辨率/主题变化 → `conditions` 不匹配 → 拒绝使用。

### 5.2 不确定性清单 `uncertainties.md`（每轮必产）

- 本轮哪些读数不可信（`fresh:false` 次数）
- 哪些动作没验到后置态
- 哪些判据是"猜的"（单判据、无回归样本）
- → **直接变成下一轮的探针任务**

### 5.3 失败归因四分类（每轮必做）

`仪器 / 前提 / 判据 / 被测对象`。
**今天：仪器 5 / 前提 3 / 判据 1 / 被测对象 0。**
这个分布本身是信号——它说"先修仪器，别急着做游戏"。

### 5.4 递归判据（怎么知道在变好）

> **每轮「未验证的动作数」与「单判据态数」应当单调下降。**

把"我慢慢学会操作 GUI"变成"判据覆盖率单调上升"——**可度量、可递归**。

## 六、用工程弥补多模态不足（用户点题，七条）

| # | 手段 | 为什么有效 |
|---|---|---|
| 1 | **降级链优先不用眼睛** | 文件/日志/进程读数比看图便宜 100 倍且不会看错 |
| 2 | **视觉只用于「发现」，不用于「确认」** | 发现新控件是一次性成本 → 立刻固化成模板/判据，之后不再看 |
| 3 | **差分代替理解** | "变了没有"比"是什么"便宜且可靠；今天的陈旧帧正是差分能抓的 |
| 4 | **区域裁剪** | 只读必要矩形，token 降一个数量级 |
| 5 | **坐标不落代码** | 定位走模板；坐标只出现在标定库且带失效条件 |
| 6 | **界面态投影成字符串** | 我读 `EDITOR`/`SAVELIST` 而不是读图 |
| 7 | **判据可回归** | 判据 = 代码 + 样本；改坏了当场红，而不是在游戏里白烧一轮 |

**加一条元手段**：**把「发现」也自动化** —— `ys-probe` 主动扫一块区域、
报告"这里有个新控件（与已知模板都不匹配）"，我只需裁决它是什么。这样新界面不用我逐个目视。

## 八、为什么这样排（与"直接做游戏"的取舍）

- **不做栈直接做游戏**：今天的实证是**每轮 15 分钟里 ≥10 分钟花在仪器问题上**，且失败**不可归因**。
  先修栈是**回报率最高**的投入。
- **栈做完再回头做游戏**：阶段 C 的每票都用新栈跑，**栈的问题会在使用中继续暴露**——这本身就是递归。
- **风险**：过度工程。对策=每票都有"能挡住今天哪条错误"的显式对应；
  挡不住的票不做。**今天 10 条错误 → 阶段 A/B 八票全覆盖**。

## 九、待用户裁决的分叉

1. **粒度**：阶段 A 是否合并为 2 票（观测+状态 / 动作+编排）？合并省时间、拆开好定位。
2. **要不要 `ys-probe`（票 08）**：主动发现新控件很诱人，但没有它也能靠"我目视一次 + 固化"过。
3. **阶段 C 是否与 A/B 交织**：每做完一票就用它推进一点游戏（更早看到成果，但切换成本高）。
4. **是否现在就停游戏线**：阶段 A 期间完全不碰地图，避免"半成品 + 新栈"双向失血。
