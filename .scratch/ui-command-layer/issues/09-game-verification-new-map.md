# 09 — 游戏内核验：新地图全程跑真实命令（配合用户）

**What to build:** 在一张**全新地图**上，从零开始与用户协作完成 UI 命令层（List/改动识别、Create、Edit、Delete）
的真实核验闭环：AI 逐步执行真实命令（候选→SHA→备份→写回），用户在**游戏内**逐项确认视觉与行为；
随后用户自己在游戏/编辑器做细排动作，AI 用 list/anchor/diff **读回**玩家改动并汇报——证明"AI 写、游戏对、
玩家动、AI 读"全链路真实可用。发现问题立即修（修复轮），全部通过后把结果并入票08 关账。

**Blocked by:** 票05/06/07（代码层已字节级闭合）；票08 的游戏段由本票承载，验收结果回灌 08 关账。

**Status:** ready-for-agent

## 验收标准

- [ ] A. 新地图基座：新建干净地图 → 确认 UI 承载（默认布局/控件组库容器就位或按已学规则种子）→
      保存基线快照并锁定 SHA（恢复点）；全程只在新地图写回，备份每次写回前自动生成
- [ ] B. 命令逐条游戏核验（每条约 1-3 分钟游戏确认）：
      Create：按钮/文本框/图文输入框/消息队列 布局面各一条 + 存为模板（官方源或实例源）→
      游戏内确认：显示、位置大致正确、按钮可点击、输入框可输入、队列正常渲染、模板化后实例仍在
      Edit：改名/文本/字号/对齐(左中右)/文字颜色/位置 → 游戏内逐项看视觉变化正确
      Delete：删一条布局控件（先预览 removed 清单）→ 游戏内确认消失且无报错/无残留
- [ ] C. 玩家动作读回（真实核验）：用户在编辑器/游戏做细排动作（拖位置、改文字、增删控件等 ≥2 类）→
      AI 用真实 CLI（list --flat / anchor / diff）读出玩家改动并与动作逐项对上（差异报告给用户复核）
- [ ] D. 收尾：核验记录落盘 ui/verification（每步三栏：已验证/未验证/需用户确认）；发现的问题当场开修复轮至通过；
      结果回灌票08（复盘/PKC/知识入库/看板划掉在 08 统一执行）

## 执行协议（写回红线）

- 每步：SHA 锁定 → 候选 → 用户确认 → 备份 → 写回 → 回读 → 提醒重新加载（编辑器内存不感知磁盘写）
- 新地图一次性授权窗口仅限本票地图；目标路径/ID 变化即停
- 用户游戏确认是唯一行为层证据；结构层证据（对拍/读回）分层报告，不混称
