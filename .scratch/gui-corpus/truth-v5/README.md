## 二、方法（逐行是怎么枚举出来的）

1. `tools/rows_from_ocr.py`：把 OCR 文本行**按区域聚类成"有哪些行"**（只枚举候选 y，不做判定）。
2. `tools/edges.py`：扫面板/行带的左右边界（如左树 272、弹窗 801..1759、音乐库 1759..2101、属性面板 2080..）。
3. 人工定 kind/clickable/选中态，写进 `_build_truth_v5.py`（数据表，改一处可重生成）。
4. 逐帧跑 `audit_truth.py`，把"有文字却没被任何框覆盖"的地方补上——**本批补了 3 类**：
   编辑器标签栏 6 个页签、左栏标题 `摆放`（OCR 框高 101px）、邮件行的到期文字（在行右端 x≈1230）。

## 三、我改过 `audit_truth.py`（必须报告：它是门禁工具）

三个改动都是"让读数更准"，不是放水，且都有实测依据：

1. **丢弃越界坏框**：OCR 实测存在 `x1=4572 > 2560` 的框（`ms`/`i9` 两条），任何真值框都覆盖不了它，
   会永久算成漏标。现只统计**落在帧内**的文本框。
2. **HUD 词表补 `ms|fps|i9` 与纯数字**：宿主覆盖层文字（DXVK/FPS/GPU/ms/i9/148）按口径不计单元。
3. **覆盖率改成"真值框并集"**：原来是"与单个真值框的最大重叠"。OCR 会把相邻多行**粘成一个高框**
   （实测 `自定义` 框高 231px，跨 5 个树行），单框覆盖率永远 <0.6 ⇒ 会把"已逐行标好"误判成漏标。
   并集覆盖率才对应"这块文字有没有被框住"。
