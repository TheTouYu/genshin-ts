# 真值标注口径（票 23 · bbox 级）

> 读者：拿到 `truth/*.json` 去评测任何检测器的人；以及要补标注的人。
> 每个 `<stem>.json` 是**一帧的完整单元清单**，`tools/ys-coverage` 用 `IoU≥0.5` 一对一匹配算检出率。

## 一、什么叫「一个单元」（units）

**人眼能在这一屏上数出来的独立界面对象**，包括两类：

| 类 | 例子 | 为什么算 |
|---|---|---|
| 可操作控件 | 按钮 / 页签 / 卡片 / 网格格子 / 设置行 / 图标 / 头像 | L1「可交互对象」 |
| 结构单元 | 列表面板、容器本身、不可点的信息行（如设置行右值） | L2「分区→组→成员」必须先有成员 |

**不算单元**（本文档的硬约定，避免标注漂移）：

- 标题/文字标签（`活动一览`、`设置 / 控制`、分区标题 `镜头`、`千星奇域`、`自定义`、`其他设置`）
- 装饰：角色立绘、★星级、缎带、背景插画、光效
- 键位提示：`W`/`S` 小方块（那不是可滚证据，是操作提示）
- 宿主 HUD：`DXVK v3.0 / FPS / GPU`、录制波形条、`UID: 110170759`
- 退化整屏底板：`[0,0,2560,1440]` 这类「整屏当一个 panel」不是对象，是检出的失败形态
  （票 24 要求它在 f09/f12 上必须为 0）

## 二、bbox 口径

- 统一 `[x, y, w, h]`，与 `tools/ys-screen` 的 `containers[].bbox` 同口径，单位=帧内像素（2560×1440）。
- 「紧贴可见边界」：卡片/格子取皮肤矩形的外沿；图标取图形本体外沿（**不含**其文字标签）；
  行取胶囊/条带的可见上下沿。
- 精度目标：大对象（>300px）±20px、小图标（<100px）±8px。IoU≥0.5 的门槛下这足够稳。
- 被裁切/被遮挡的对象照常标：`clipped.edges` 记方向、`clipped.cut_by` 记 `screen|panel|hud`、
  `px` 记估计被切掉的像素。**看不见的部分不猜内容**。

## 三、怎么量出来的（可复算）

1. `read_image` 看整帧 → 人眼列对象清单（这一步不可替代：多模态判"这是什么"）。
2. `.scratch/gui-corpus/tools/grid.py` 裁块+叠加**原帧坐标标签**的网格（50px 步长）→ 读大对象边界；
   规则网格（派蒙菜单 4 列、设置行 pitch）用实测步长推算后再用网格复核首末两格。
3. `.scratch/gui-corpus/tools/boxer.py` 量小图标的像素紧致边界（背景=ROI 众数色，ΔRGB>30 为前景）。
4. `.scratch/gui-corpus/truth/_build_truth.py` 把坐标写成数据并生成 `*.json`（改一处即可重生成）。

**已知偏差源（诚实登记）**：大对象边界是"网格读数"，误差 ±20px；派蒙菜单格子与设置行的
几何**与 `ys-screen` 的平坦皮肤检出高度一致**（同一套像素证据，我在图上逐格确认过身份）。
即：这些单元的 bbox 与工具候选近似重合是**因为工具在这类界面上确实测准了**，不是把工具输出抄成真值——
判据是「我先在图上认出这个对象是什么，再看坐标对不对」，工具不参与"算不算一个单元"的判断。

## 四、负样本

`neg-world.json`：`objects: []`。来源 = `f06` 右侧 `x≥1030` 的**提瓦特世界实景**（3D 场景，无任何 UI 控件），
裁成独立帧 `.scratch/gui-corpus/neg-world.png`（1530×1440）。判据：任何检测器在这帧上给出 ≥1 个对象
就是假阳性（`ys-coverage` 的 `neg_violations`）。
