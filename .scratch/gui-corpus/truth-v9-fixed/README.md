### 1.1 假阳性（170 / 219 = 78%）
- **头号来源是「同一框多类别」而不是纯背景误检**：92 对预测互相 IoU≥0.7，绝大多数是**同一 bbox 同时挂 tile/chip/icon/button/card/avatar**。r004 一帧就有 65 对（97 个预测里；例：`[180,44,200,183]` 同时被 tile/button/chip/avatar/card 命中，`[141,29,855,405]` 同时被 panel/row/button/card 命中）⇒ 分类头在跨皮肤帧上几乎只在猜"这块是不是某种容器"，且**NMS 是按类做的**，所以同一个框能活 5 次。
- 按预测类统计：`row 42`、`icon 31`、`chip 31`、`tile 26`、`button 21`、`panel 15`、`card 3`、`avatar 1`。→ **row/chip/icon 三类是假阳性重灾区**（模型把行内文字块、图标底色、横向文字带都当成了行/胶囊）。
- **14.6%（32/219）预测越界**：负坐标或超出 2560×1440（如 `[-15,-14,174,1451]`、`[-544,212,1328,1256]`、`[1808,-4,1297,1272]`），说明**坐标回归没有裁剪到画面内**，脱框严重时整块区域都是空的。
- 尺度失控：`panel` 类常给出整屏级大框（`[1808,-4,1297,1272]`、`[-280,198,1536,1283]`），与 R7 区域框混在一起无法区分是"区域"还是"误检"。

### 1.2 漏检（117 / 166 = 70%）
按真值类：`row 32`、`card 31`、`button 19`、`tile 10`、`unknown 10`、`panel 9`、`icon 6`。主要漏：
1. **成片列表/网格的每一项**（角色卡 31、设置行/任务卡 32）：模型只在整块区域上给 1~2 个"大 panel"，**不拆行**。r024 25 张角色卡只命中 1~3 张；r009 的 8 个任务卡只命中 1 个。
2. **区域级对象反而漏**（panel 9）：除误检出的整屏框外，真正的「左导航栏整条 / 网格区 / 弹窗整块 / 详情区」没框 —— 与质检报告"游戏族普遍缺区域级对象"一致。
3. **四角小件 10/10 全漏**（左上 DXVK/FPS/GPU、左下 min/max ms、右下 UID）：位置固定、形态固定，纯属训练里没见过。
4. **纯图标**（icon 6）：左图标栏、奖励图标、评价操作钮，无文字可依时几乎不召回。
5. r023 是灾难性漏检：**主弹窗（884×1242）整体没框**，16 个弹窗内单元全漏，10 个预测全落在屏幕边缘。

## 3. 下一轮该补什么（按性价比排序）

1. **训练里加"同框多类"的负样本 + 按类 NMS 改类无关 NMS**：92 对重复里绝大多数是同一框多类，改 NMS 一行就能去掉约一半假阳性（r004 65 → 预计 <10）。
2. **坐标回归裁剪到画面内**（32 个越界框）：损失里加 clamp 或在解码后 clip，代价几乎为零。
3. **行/卡网格的拆分数据**：漏检 117 个里 63 个是"行/卡"，而成片列表恰恰是训练最缺的形态（模型只给整块 panel）。优先补「列表区 + 每行」成对标注（本目录 5 帧正好是这种形态）。
4. **区域级正样本**（panel 类）：明确「左导航栏整条 / 网格区 / 弹窗整块」这些大框为正样本，且与"误检整屏"用 area 上界区分（区域框面积上限 ~60% 屏）。
5. **四角固定小件**：位置固定（`[0,0,128,96] / [0,1292,300,34] / [2250,1395,260,45]`），可直接作为后处理规则先兜住，再谈模型学。
6. **icon↔tile↔chip 的尺度先验**：用"框面积 / 所在容器面积"作为特征/后处理约束，把容器内的小框从 tile 改判 icon。
