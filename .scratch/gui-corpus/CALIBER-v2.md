# GUI 感知评测口径 v2（2026-10-19）

> 状态：**当前口径**｜依据：2026-10-19 反馈轮实测（menu/world 8 帧 + 真值 + glyph-v1 通道）
> 读者：负责数据治理与训练的两个代理。**两个人都按这一份口径对齐，不许各自定义。**

## 为什么要有 v1 → v2

v1（历史默认）是「8 类混在一起报一个 micro mAP」。今天实测证明它在三个方向上误导决策：

1. **micro 会掩盖结构性失效**。menu 的 `P=1.000 / R=0.463`——框全对但只看得见 46% 的对象；micro 把这个说成"中等水平"，实际是"精度满分、召回腰斩"。
2. **世界 HUD 上 micro=0 不说明"差"，说明"判据前提不成立"**：116 个位置簇里 104 个被尺寸闸门卡掉、平坦度 0.04–0.47（对照 tile 0.80+）、含界面文本仅 0.5%。这是**通道缺失**，不是模型弱。
3. **单帧与多帧不是强弱关系，是 trade-off**：多帧 P=1.00/R=0.31，单帧 P=0.60/R=0.56，F1 0.47 vs 0.58。报单一数字会把取舍藏起来。

## v2 口径（五条，全部可机检）

### 1. 必须分 kind 报，且单列两个关键类
- 逐类报 `P / R / F1`，**不许只给 micro**。
- **`row` 与 `glyph_icon` 必须单独一行**：前者是列表类界面的瓶颈（v2 模型 row 0.276），后者是今天新增的"无底图标"通道（世界 HUD 的唯一出路）。
- 报 kind 分布（每类样本数），否则 F1 无法解读。

### 2. 必须按界面族分开报
至少三族：**游戏界面族（menu/bag/friends/map…）/ 编辑器族 / 世界 HUD 族**。
留出验证必须**按族留出**（同族不同帧），不许随机切分——之前随机切分让同界面帧泄漏进验证集。

### 3. 必须给"真值覆盖率"，否则精度数字不可读
每个数字旁边标：该帧真值覆盖了几个应标单元、有没有跑 `audit` 未覆盖检查。
> 已踩过：32 个假阳性里 6 个其实是"真图标但真值没有"。**"误提升"和"缺真值"长得一模一样。**

### 4. 必须给"单帧 / 多帧"两套数
- 单帧口径：尺寸 / 长宽比 / 对比度 / 局部平坦度
- 多帧口径：N 帧出现率 + 位置抖动
- 两者都报，并给 `单帧/多帧` 的 P 与 R 比值。**不许只报一个。**

### 5. 每次训练必须带"未退化"证据
同一份验证集上，**上一版模型的读数必须复跑一份**并列。
- 正样板的底线：menu 族的 `P` 不许低于 1.000，tile 检出率不许低于 18/20。
- 任何"提升"如果以 menu 族退化为代价，判失败。

## 已踩过、别再踩的坑

1. **bbox 口径**（xyxy vs xywh）：不换算时 P/R 差 **20 倍**且不报错。
2. **单帧计数不能当基线**：同一界面 8 帧计数差 2–3 倍；任何"N 个"必须注帧数。
3. **真值不全会让"误提升"和"缺真值"长得一模一样**。
4. **`audit_truth.py` 的 HUD 正则与 `_rules.md` 不同源**会造成结构性假失败（已在 2026-10-19 修过一轮）。
5. **生成器会抹掉人工修复**：`truth/_build_truth.py` 重生成时必须带覆盖守卫（已有 `_provenance` 判据）。
6. **白名单重建会静默丢字段**：缓存/序列化一律"断言字段集相等"，缺字段就抛错。


## 数据规模口径（2026-10-19 实测，trainer 提供判据）

**「73 帧」≠ 73 个独立界面**：按「同界面重复帧」判据（同尺寸 + 像素/结构重合度），实测 **73 帧 ≈ 58 个独立界面**。
- `m01–m08` 完全重合 ⇒ **1 个界面**；`w01–w08` 完全重合 ⇒ **1 个界面**
- `f07↔f08` 重合 0.967；`f09↔c18` 重合 0.957（同一界面的两次采集）
**规矩**：任何"样本量"结论必须写**独立界面数**，不只写帧数；分族留出按**独立界面**切，不能按帧切（否则同界面帧会跨折泄漏）。


## quality_grade 定义（2026-10-19 补充：audit 依据是什么）

| 等级 | 判据 | audit 依据 |
|---|---|---|
| **A** | `audit 未覆盖 = 0` 且 `area_max_frac ≥ 0.10` | **工具信号**：`audit_truth.py --rules` 用 ys-screen 的 `text[]`（OCR 输出）核对人工标注的**覆盖** |
| **B** | 未覆盖 1–2 处，或 `area_max_frac < 0.10` | 同上 |
| **C** | 未覆盖 ≥3 处（或超 15 分钟/帧预算，见 `grade_reason`） | 同上 |

**关键口径**：`A` 的含义是「**被工具 OCR 覆盖检验过**」，**不是**「被人工逐帧复核过」。
本批 16 帧的 OCR 对照来自 `.scratch/gui-corpus/pred/*.json`（ys-screen 自己的输出）——这是**正当用法**
（用工具信号验人工标注的覆盖），但必须写清来源，避免后来者误读为人工复核。
凡 `grade_reason` 里写「无 OCR 对照」的帧，表示当时没有可用的文本信号，**不是**"没有漏标"。

## 新增 kind：`bar`（2026-10-19）

HUD 状态条（元素能量/护盾条、生命值条）按口径**不是 `glyph_icon`**（无图标语义、不是无底图标）：
- 判定特征：长宽比 ≥ 8、高 ≤ 30、渐变填充（实测 16.2 与 11.7）
- **不进检测器类表**（`gui_det.KINDS`）——只有 2 个实例、8 帧同界面，训不出来
- 但**任何消费者都必须看得见**：`gui_det.NON_DETECTED_KINDS = ("bar",)`、`eval_v2.NON_SCORING_GT_KINDS`，
  报告里必须出现 `bar=N`（不计分），**不得静默丢弃**
- 数字文本（如 `生命值数值 13557/38734`）归 `row` 且 `scoring: false`


## world_hud 族的独立界面数 = **1**（2026-10-19 实测判据）

拿 `truth-merged` 里 family=world_hud 的 w01–w08 做去重复核，四条判据全部通过：

| 判据 | 阈值 | 实测 |
|---|---|---|
| A 尺寸一致 | 8/8 帧同分辨率 | **8/8 = 2560×1440** ✅ |
| B HUD 锚点帧间差 | 中位 ≤10 **且小于**同帧背景对照区 | 小地图 2.8 / 左上图标 2.8 / 右上带 6.7 / 队伍头像列 3.8 / 技能Z **1.8** / 底部血条 8.8；背景对照 中部场景1 **10.9**、地面 5.1、中部场景2 4.3 ✅（HUD 带普遍更稳） |
| C 恒定文本 | ≥15 条文本 8/8 帧出现 | **19 条**：`UID:110170759` `Lv.80` `E/Q/Z` `13557/38734` `0%` `沃雅妮莎` `称赞` … ✅ |
| D 动态差分布 | 差异集中在场景中部、HUD 四带无大块动态 | 动态孤岛最大 `[969,230,493,1022]`（角色/背景），HUD 四带无 ✅ |

**结论：w01–w08 是同一个界面（开放世界 HUD·冰窟）的 8 次连拍，只有动态内容不同。**
⇒ **该族不能靠"增加同界面帧数"提升泛化**；要提升 world_hud 只能**增加不同界面**（见下节清单）。

## 需要采集的 world_hud 不同界面（给反馈轮抓帧用）

| # | 界面 | 为什么与现有世界 HUD 不同（一句判据） | 优先级 |
|---|---|---|---|
| 1 | **战斗 HUD** | 出现敌人血条/伤害飘字/锁定框/技能冷却环——这些容器在探索态**不存在** | **高** |
| 2 | **元素视野** | 整屏去色 + 高亮描边（饱和度骤降、亮度分层），与彩色探索态是相反的配色分布 | **高** |
| 3 | **队伍切换特写** | 4 个头像放大居中 + 名字条，HUD 从"边角散布"变成"中心大图" | 高 |
| 4 | **元素战技/爆发就绪提示** | 技能键出现高亮环/数字倒计时，键位图标形态改变 | 中 |
| 5 | **交互提示密集态**（可交互物旁） | 屏中出现"F/Enter"提示条与高亮描边，位置随对象变化 | 中 |
| 6 | **夜间/雨天等环境态** | 同布局但整体亮度/对比分布不同，检验检测器对光照的鲁棒性 | 中 |
| 7 | **低血量/元素反应态** | 血条变红 + 屏幕边缘泛红，HUD 颜色语义变化 | 低 |
| 8 | **不同分辨率/窗口化** | 检验尺度泛化（当前 8 帧全是 2560×1440） | 低 |

> 采第 1、2、3 项各 3–5 帧，就能把 world_hud 的独立界面数从 **1 提到 4**，这是该族唯一有效的扩样方式。
