# 分块差量 OCR（`cmd=ocr_blocks`）——2026-10-19

> 仓库 `/home/h/genshin-ts`｜`ys-lookd` 常驻引擎（GPU，rec_batch=16）｜语料 = 110 帧 reps + 合成小变化对
> 实现：`tools/ys-editor/ys_lookd.py` 新增 `cmd=ocr_blocks`（旧命令零变化）

## 切块方案（参数）

```
帧 2560×1440
  grid = 3×3（默认，可 req 传 grid:[r,c]）
  core  = 网格单元（哈希只算 core）
  crop  = core 向外扩 margin=96px（clamp 到帧内）→ 送 det+rec
  归属  = 文本框中心落在哪个 core，就归哪个块（天然跨块去重；另加 IoU>0.5 兜底去重）
  变化块占比 = 未命中块数 / 总块数
    ≥ 0.6（默认）→ 回退**整帧 OCR**（并把结果按核心归属回填块缓存 + 行缓存）
    < 0.6        → 只对变化块跑 det+rec
  块内差量：16×16 格子均值（阈值 6/255）判定哪些格子变了；
            检测出的行若不碰变化格子（±1 格外扩）→ 直接复用该位置上一帧的文本，只有碰到的行才 rec
```

## 实测（v000 基准帧 + 三处合成小变化）

| 场景 | 块命中 | 行复用/重识别 | 总耗时 | 说明 |
|---|---|---|---|---|
| 同帧重复（9/9 命中） | 9/9 | — | **22–32ms** | 块缓存直接返回（含 9 块哈希 ~22ms） |
| 冷帧 / 换页（≥60% 变化） | 0/9 → 回退整帧 | — | **366–506ms** | 回退整帧 OCR（对象路径 333ms 量级）+ 块/行缓存回填 |
| 小变化 tiny1（右上角 40×100px） | 8/9 | 7 复用 / 4 重识别 | **247–287ms** | det 45ms + 4 行 rec（含宽行）+ 哈希 22ms + 合并 |
| 小变化 tiny2（中部 40×200px） | 8/9 | 7 复用 / 14 重识别 | **400–461ms** | 变化的格子覆盖到 14 行（密集编辑器 UI） |
| 小变化 tiny3（左上 60×300px） | 8/9 | 5 复用 / 11 重识别 | **248–316ms** | 同上 |

**字符召回（vs 全帧 `cmd=ocr`）**：base **98.59%** / tiny1 **98.48%** / tiny2 **98.94%** / tiny3 **97.57%**
⇒ **低于 98.9% 的门槛**（块内裁块（96px 扩边）切掉/截断了少量跨块文本行）。

## 结论（诚实版）

- **同一屏重复看**：块缓存很有效（22–32ms），但和现有 `ocr_objects` 的帧级缓存（15–45ms）**没有数量级差别**。
- **小变化**：**未达标**（247–400ms，目标 <100ms）。分解：变化块 det **45ms**（整块跑）+ 变化行 rec
  （密集 UI 里一个小改动会碰到 4–14 行，宽行批 50ms 级）+ 9 块哈希 **22ms** + 合并。要进 100ms 必须再往下切一层：
  **只在"变化格子"的 bbox（+margin）上跑 det**，并只 rec 该小区域里的行 —— 本轮没做（时间/上下文用尽）。
- **召回未达标**（97.6–98.9% < 98.9%）：扩边 96px 仍会在密集 UI 上切到行。
- **换页/冷帧**：回退整帧（366–506ms），比基线 333ms 高 ~10–50%（块/行缓存回填 + 帧哈希），不满足"不劣于 333ms(+10%)"的上沿。

## 第二轮（Lead 给的一轮机会）：只在变化格子上 det+rec + 扩边 160px + 真实同屏对验收

实现追加：① 块内 **16×16 格子均值差量**判定变化格子；② **只在「变化格子 bbox + margin 160px」上跑 det+rec**（不再整块）；
③ 未变化的旧框保留、变化区域的框替换并去重；④ **格子级"视觉未变"命中**（JPEG 复查噪声会让逐字节 crc 全 miss，实测 real pairs 精确命中 0/9）。

### 结论：**块级差量在当前模型/硬件上不成立**

1. **真实"小变化"对不是小块变化**：像素差 2.3–17.6%，散布在 3–9 个块上（不是 1–2 块）⇒ 大多数对直接触发回退整帧（565–1024ms）；
2. **走进块路径的两对召回崩了**（90.67% / 71.64%）：子区域 det 只能看到变化格子附近的文本，被"变化格子相交"判掉的旧框如果不在子区域里就再也拿不回来 ⇒ 丢整行；这比不优化严重得多；
3. **块内格子签名开销 ~90–120ms**（9 块 × 16×16 均值，Python 循环）⇒ 连"同帧重复"都从 15–45ms 退化到 114–138ms；
4. 冷帧 565–1008ms（这批 2561×1440 游戏截图的文本量约是 reps 的 2 倍，整帧 OCR 本身就要 500–900ms）。

**最终建议**：`cmd=ocr_blocks` 保留为**实验开关**（独立命令、默认不参与主路径，旧命令零影响）；
主路径维持 **`ocr_objects`（帧级缓存 15–45ms + 按对象切片缓存）**，不再投入块级差量。

## 建议下一步（要一个决断）

1. **只在变化格子区域跑 det+rec**（预计小变化 60–90ms），同时把扩边加大到 ~160px 修召回；
2. 或者**放弃块级差量**，把预算花在"帧级缓存 + 按对象切片缓存"上（现有能力：同帧 15–45ms，冷帧 333ms）。

## 第三轮（用户口径）：**对象级基线差量**（`cmd=ocr_page`，非网格）

实现：基线 = 上一帧 det 框集合（整份缓存、**不重跑 det**）；每框 8×8 缩略签名比对（容差 6/255）→ 没变复用文字、变了只跑 rec；
**新增对象兜底** = 整帧 1/4 降采样差 → 找未被旧框覆盖的成片区域（面积>1600@1/4）→ **只在这些区域**补 det（旧框一个不丢）；
变化框占比 ≥0.4 或基线缺失 → 整帧 det 重建。

### 结论：**对象级基线差量在真实语料上同样不成立**
1. **真实对是动画游戏场景**：像素差 2.3–18% 散布全帧 ⇒ 大部分框都"变了"，基线框对不上新帧（两对召回 82.6% / 50.3%）；
2. 每框签名（76–90 框 × 8×8 缩略）+ 整帧降采样差 + scipy 连通域 ≈ **60–110ms 固定开销** ⇒ 连"同帧重复"都到 67–107ms（目标 15–45ms）；
3. "新增对象兜底"在成片变化时会触发多次区域 det（单对 det 累计 1148ms）；
4. 冷帧 456–887ms（这批图文本量约是 reps 的 2 倍，整帧 OCR 本身 500–900ms）。

**总判**：对象级基线在**真正静止的 UI 页面**（菜单/面板）上才可能成立；用户给的验收语料是动画场景，**六对全部不达**。
建议：`cmd=ocr_page` 与 `cmd=ocr_blocks` 都保留为实验命令（默认不参与主路径），主路径维持 `ocr_objects`（帧级缓存 15–45ms + 对象切片缓存）。

## 第四轮（用户纠正）：**多帧共识底板**（`cmd=ocr_plate`，实验命令）

实现（按用户口径 + 文献）：`action=build` 用 N 帧逐像素**中值**建静态底板，并算**动态掩码**（多帧中偏差>12 的帧占比>0.5 → always-dynamic）；
底板**只 OCR 一次**（离线）；`action=query` = 新帧 vs 底板变化掩码（1/4 尺度、阈值 12、剔除动态区）→ 连通域 → **只对变化区域 det+rec**；
底板框未被变化覆盖的直接复用文字，被覆盖的只重跑 rec；变化区域补 det 捡新对象（旧框不丢）；去重合并。

### 结论：**多帧底板方向成立，但当前实现没过验收；且真实簇的查询帧往往不是"同页小操作"**
1. **最好的一簇（g5）**：0 个变化区域、1 个框重识别 → **128ms / 召回 97.47%**（目标 <100ms、≥98.9%，都差一点）；
2. **另两簇**：查询帧与底板差得多（3–18 个变化区域）→ 区域 det 累计 683–965ms、召回 84.2%/59.4%——**这些查询帧实际上已经不是"同页小操作"**（是换页/大变化，应走重建）；
3. **动态掩码有效**：动态像素只占 0.03–1%，说明"动画隔离"这条是对的；问题在**查询帧的变化量**与**底板文本的时效性**；
4. 缺的一环（本轮没做）：**查询前先判"是不是同一页"**——变化面积占比超阈值（如 40%）就该重建底板而不是硬用旧底板；g3/g4 的崩溃都源于此。

**总判**：底板思路在"同一页、变化很少"时最接近目标（128ms/97.5%）；一旦查询帧偏离底板，必须重建而不是硬套。建议把 `action=query` 前置一个"页面一致性判据"（变化面积占比/变化区域数阈值），超阈值转 `build`——本轮未实现，按你的口径收口。

## 第五轮（收尾两步）：页面一致性闸门 + 变化框只 rec / 小区域补 det

实现：
- **闸门**（写进返回字段 `gate`）：`变化连通域数 ≥3` 或 `变化像素占比 ≥5%` → **直接 rebuild 底板**（不再硬套）；
- **查询路径**：底板框未变 → 复用文字；变了 → **只 rec 这些框**（不跑整块 det）；**只有"未被任何底板框覆盖"的变化区域**才补 det 捡新对象（旧框一个不丢）；
- `build` 支持 `dir` + `pattern`（给目录即可批量建板）。

### 总判（按验收口径）
- **同页微变 <100ms**：g5 **118ms**，差 18ms（mask ~50ms + 1 个变化框 rec ~60ms + 解码）；
- **召回 ≥98.9%**：g5 **97.47%**、rebuild 两簇 97.4–98.4%——差在"未变框复用旧文本"：**像素变化低于阈值但文字其实变了**（动画/JPEG 抖动）的框会被复用成旧字；
- **换页自动重建**：✅ 闸门正确触发（g3/g4），但 rebuild 1203–1267ms 比这批图的整帧 OCR（500–900ms）还慢约 20–40%（rebuild = 中值板+OCR 一次+掩码），**"不劣于现有"未达成**。
- 结论：**底板方向在"同页微变"上已接近验收（118ms/97.5%），但两道差距（<100ms、≥98.9%）本轮没跨过**；下一步要么把复用阈值调严（提召回、多付 rec），要么把变化框 rec 的批处理做小（提速度）。

## 第六轮（最终收口）：闸门回落 + 文字掩码比较器

- **闸门触发不再重建底板**：`regions≥3` 或 `px≥5%` → **回落到标准 `ocr_objects` 路径**返回本次结果，底板标 `stale=True`（留给后台/下次 build），`mode=plate_fallback_objects`。
- **比较器换成文字掩码**：框裁切 → 灰度 → **Otsu 二值化** → XOR 比例 > 2%（`_PLATE_TEXT_CHANGE_RATIO`）判"文字变了"→ 只对变了的框 rec；另保留"区域掩码均值>5%"作为并发判据。

### 对照验收
- **换页 ≤ ocr_objects 冷帧**：✅ 365–578ms，与同帧直接跑 ocr_objects 同量级（这批 2561×1440 图本就是 500–900ms 量级）；不再有 1.2s 重建。
- **同页微变 <100ms**：✅ **96ms**（文字掩码判出 2 个变化框、rec 2 个框；掩码比较 ~20ms）。
- **同页微变召回 ≥98.9%**：❌ **97.47%**——文字掩码已抓住"亮度接近但文字变"的框；剩余 ~2.5% 是框内**分词/标点差异**（与之前 98.9% 均值同族），不是整块丢字；2%→0.5% 可提召回但多付 rec。

**一句话**：两条都落地，**速度验收全过（96ms / 365–578ms）**；**召回仍差 2.5pp**，根因是框级分词差异而非丢字，属"阈值换速度"的取舍，按你的口径收口。
