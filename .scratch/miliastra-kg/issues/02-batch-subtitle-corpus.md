# T02 · 批量取教程文本（字幕轨优先）→ 本地语料库

**Status**: ⬜ 未开工
**Blocked by**: T01 ✅
**目标（用户视角端到端）**: 当我要查"千星里 X 怎么做才优质"时，我有一个**本地可 grep 的教程语料库**，而不是只能逐个点开视频看；且我知道**哪些源拿得到文本、哪些拿不到**（覆盖率透明，不含糊）。

## What to build

1. **全量探测**（不抽样）：对 T01 的 S+A 级源（50 个）逐个探测字幕轨，落盘**有无**结论。
2. **下载有轨的**：多分P 逐 P 取 `cid` → `x/player/wbi/v2` → `aisubtitle` CDN → Markdown。
3. **覆盖率账本**：能取到文本的源数 / 总源数；**拿不到的登记为"待 ASR 兜底"**，不静默跳过。
4. **术语校正**：B 站 AI 字幕对千星术语系统性误识别（见 `bilibili-learn` 技能千星表），
   语料落盘时**保留原文**（取证），另建校正映射供学习阶段用。

## 验收项（全勾才可收轮）

- [ ] S+A 级 50 个源**全部**探测字幕轨，无一遗漏（不是"抽几个看看"）
- [ ] 探测结果落盘 `search/subs-probe.json`（字段：bvid/分P数/每P有无轨/lan_doc）
- [ ] 有轨的全部下载为 Markdown，落 `learn/<BV>/P<N>-<标题>.md`
- [ ] 合并全文 `learn/<BV>/ALL.md`（含分P标题与时长）
- [ ] 覆盖率账本写入 `CORPUS.md`：有轨 X/50、无轨 Y 个（逐个列名 + 结论"待 ASR"）
- [ ] 语料总字数统计（可 grep 的语料规模量化）

## 反模式

- ❌ 探测失败就断言"这个视频没字幕"——要区分"API 报错"与"确实无轨"
- ❌ 只取第 1 个分P（长教程的精华常在后面的分P）
- ❌ 无轨的直接放弃不登记（用户需要知道知识图谱的语料边界在哪）
- ❌ 拿不到字幕就上 tiny ASR 模型（术语全错，学了等于没学）
