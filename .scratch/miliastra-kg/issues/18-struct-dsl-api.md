## ⚠️ 为什么必须先做差分（2026-09-16 补，用户裁定）

写票时以为「节点定义已在库 → 缺的只是运行时封装」。研究三件套的官方语义后**推翻了这个判断**：

**拼装 / 拆分 / 修改结构体都是「泛型节点」**（官方原文）：

> 「在服务端节点图中，结构体以及结构体列表是一种较为特殊的_泛型引脚_。需要选择特定的结构体
> 或结构体列表后，才能将对应节点确定为特定的结构体或结构体列表类型」
> 「选择对应的结构体后，**该节点会显示结构体定义中的所有成员变量**」

→ 也就是说：**这三个节点的引脚布局不是固定的，而是由「选了哪个结构体」动态展开的**。
这解释了为什么现在的 API 是 `args: []` 的空壳——**不是漏写参数，而是缺了「结构体类型」这一整层表达**。

**结论：本票不是「加几个参数」，而是「让 DSL 能表达结构体类型」。**
在知道「选了结构体之后，实例记录里到底写了什么」之前设计这套表达，就是在猜。

### 需要的差分清单（每轮一个原子操作，一轮一保存）

| # | 用户操作 | 要闭合的问题 |
|---|---|---|
| 1 | 在图里放一个**拼装结构体**节点并选定结构体 | 实例记录如何带 structId？成员引脚怎么展开？ |
| 2 | 再放一个**拆分结构体** | 两侧引脚形态差在哪（输入/输出方向）？ |
| 3 | 放一个**修改结构体**并**勾选部分成员** | 「是否设置_<成员名>」引脚如何驱动「只有勾选的被改」？ |
| 4 | 给已建结构体**加一个成员** | 既有节点实例的引脚是同步、失配还是被清空？（票 17 D6 的图侧对应） |
| 5 | 建一个 **struct 类型变量**并在图里 set/get | 引用传递在 wire 上长什么样？ |

**建议顺序**：1 → 2 → 3 → 5 → 4（第 4 项有破坏性，放最后）。
每项都是一次「放节点 / 改设置后保存」，属于编辑器里的十秒操作。

## 起点（写票时实测）

```ts
// src/runtime/value.ts:458-467 —— 全部实现就这些
export class struct extends value {
  declare private readonly __brandStruct: 'struct'
  constructor() { super() }
  override toIRLiteral(): Argument { return { type: 'struct', value: null } }
```
