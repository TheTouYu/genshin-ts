# 21 — 图谱缺口 G1–G5：五个"B站语料答不上来"的设计问题

**What to build:** 把 T12 设计书登记的五项图谱缺口从"知道缺"推进到"有数字"。

**Blocked by:** **需要输入源**——这五项**不是查不到，是语料里本来就没有**。
两条可选路径（由用户裁）：① 用户指出 2–3 个真实优质奇域，我们做对照测量；② 在游戏内做受控实测。

**Status:** ⬜ 待开工（等输入源裁决）

---

## 五个缺口（T12 设计书登记，逐条说明为什么语料答不上来）

| # | 问题 | 为什么语料里没有 |
|---|---|---|
| G1 | **迷宫规模**：多大格阵体验最好？ | 创作者只讲"我做了多大"，不讲"多大最好"——没有对照组 |
| G2 | **造景密度**：多少格一处造景不显空也不挤？ | 同上，属手感量 |
| G3 | **手累坑阈值**：连续几个左转才让键鼠玩家不适？ | 源作者只说"一大堆连续向左转"，没给数 |
| G4 | **隐藏物数量**：几个合适？ | 源讲"明晃晃放一个+其余藏起来"，没给总数依据 |
| G5 | **出口引导强度**：路标给到什么程度不破坏探索感？ | 源自身就在两者间取舍（原话「难度让位于体验」），给的是判断而非刻度 |

**这五项的共同点**：它们是**刻度问题**，不是**有无问题**。B站教程的体裁决定了创作者讲"我怎么做的"，
不讲"多少最优"——所以**再检索也答不上来**，只能靠测量。（这条本身是图谱的一条元结论，值得入 MAP。）

## 验收项

- [ ] 与用户确认输入源路径（真实作品对照 / 游戏内实测 / 两者）
- [ ] 为每个缺口定义**可测的量**（如 G3 = 连续同向转数 vs 玩家转向率）
- [ ] 收集 ≥3 个样本点（不同作品或不同配置）
- [ ] 产出刻度建议，**每条标注样本量与不确定性**（3 个样本不给"最优值"，只给区间）
- [ ] 回写 `docs/knowledge-graph/reproduction/T12-design.md` 的 G1-G5 条目（从"缺口"改为"结论+区间"）
- [ ] 把"刻度问题 vs 有无问题"这条元结论写进 `docs/knowledge-graph/MAP.md` 的覆盖缺口节
- [ ] 收轮三件套

## 备注

**不要用检索冒充答案**——本票的诚实边界是：如果最终只有 3 个样本，就写"3 个样本下的区间"，
不写"最佳值"。这是 T12 复盘里「核验必须读回可比较的数字」的延伸：**数字不够时如实说不够**。
