## 🎉 里程碑 3：CLI 写入真实地图成功（2026-10-17 04:03）

**链路全通**：`maps:init` 补骨架 → `assets:entities import` 出候选 → 回读 → `apply-candidate` 哈希门控写回 → Temp 同步。

| 步骤 | 读数 |
|---|---|
| 编辑新建的地图 | 仅 **89 字节**（**无引擎骨架** root 3-49）→ 直接 import 报 `root 6 section not found` |
| `maps:init --write` | 89B → **21277B**；replacedRoots 3..49；备份落 `.gsts/backups/` |
| 实体候选 | `assets:entities import --map-id N --entities <json> --output <cand.gil>`（**动作名必须在选项前**） |
| **实体 JSON schema** | `{schemaVersion:1, entities:[{name, definitionId, position, rotation, scale, color}]}`<br>⚠️ `color` 必须是 **`'#RRGGBB'` 字符串**（不是 structure.json 的 `{enabled,rgb:0x…}` 对象）；**JSON 不支持 `0x` 字面量** |
| 写回 | `assets:entities apply-candidate --map-id N --candidate F --expect-source-hash S` |
| 结果 | sourceSha `1b33524b…` 匹配 → `writePerformed=true`；写后 = Temp = `b2d42624…` |

### 🔑 编辑器 vs 磁盘（实测，重要）

**编辑器不会自动保存**——`maps:init` 之后我写入的 SHA，在编辑器全程开着的情况下**原封不动**保留到写回时。
⇒ CLI 写入安全，**只要不在编辑器里主动保存**，磁盘版就是权威版。
⇒ 但反过来：编辑器内存里仍是旧地图，**CLI 写入后必须让编辑器/游戏重新载入才可见**（待验证是否 试玩 自动重载）。

1. 我第一次点侧栏图标 `(34,182)` 时**就生效了**——但那一次经 `ys-gui-slot` 抓图**没有先抬升窗口**，

**⇒ 教训（写进纪律）**：
- **陈旧帧会把"生效"判成"没反应"，并且诱导出完全相反的行动（再点一次 = 撤销）**。
  任何「动作 → 判读」必须先 `ys-kwin-raise` 真抬升（工具 `ys-peek`/`ys-act` 已固化）。

## 🔴 里程碑 11：重载的正确顺序（2026-10-17 05:15）——"切走再切回"会亲手抹掉改动

**铁证**：
```
CLI 写入新布局 → 磁盘 SHA d94f733d（坡道 x=-6，P0..P4 在 x=3/13/23/34/46）
执行"切走再切回"重载 → 磁盘 SHA 249af5c7（坡道 x=8，P0..P4 在 x=18/28/38/49/61 = 旧值）
试玩报错仍说 "布设位置超出场景生效范围: [61.0,3.8,0.0]"（旧位置）
全程零报错
```

**根因**：编辑器把地图常驻内存，且**离开一张图时先把内存版写回磁盘**。于是：
```
① 内存=旧  ② CLI 写盘=新  ③ 切走 → 编辑器把【旧】写回盘（新被抹）  ④ 切回 → 载入【旧】
```

**✅ 正确顺序（顺序本身是资产）**：
```bash
tools/ys-editor/ys-switch-save     # ① 先离开我的图（写回的是旧内存，无所谓）
<CLI 改 .gil / 注入 / 挂载>          # ② 此刻磁盘是我的新内容，编辑器不在我的图上 ⇒ 不会被覆盖
tools/ys-editor/ys-switch-save     # ③ 再切回我的图 → 从磁盘载入【新】内容
tools/ys-editor/ys-playtest-start  # ④ 然后才允许试玩
```

**为什么同一个动作能用两次**：存档列表 = 「当前打开」置顶 + 其余按时间倒序，而我的图是最新的 ⇒
- 编辑器在**我的图**上 → 第 2 位 = 别的图 ⇒ 点它 = **离开**
- 编辑器在**别图**上 → 第 2 位 = 我的图 ⇒ 点它 = **回来**

工具：`tools/ys-editor/ys-switch-save`（单次切换 + 前后证据图）。
