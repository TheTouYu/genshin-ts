### 🔑 三条硬教训（**都是本轮实测踩出来的，此前记录不全或错误**）

1. **点击必须长按 ≥500ms**：`ydotool click 0x40; sleep 0.6; click 0x80`。
   游戏仅 **6~11 FPS**（DXVK 软渲染），**130ms 的按放会被整帧吞掉** ⇒ 表现为"点了没反应"。
   （旧记录写"≥120ms 即可"——那是对 **Wine 菜单**成立，对**游戏 UI 不成立**。）
2. **模态外点击 = 关闭模态**：`新建存档` 弹窗出现后，若在同一坐标再点一次，
   会点在模态外的按钮上 → **弹窗被关掉、前一步白做**。
   ⇒ **一次点击一张截图，确认后再点下一步；禁止连点。**
3. **`import -window` 在窗口被遮挡时返回陈旧帧**（实测：两次抓图 MD5 完全相同，而画面其实已变）。
   ⇒ **取真值用全屏 `spectacle -b -n -f -o <file>`**；`ys-shot <win>` 仅适用于窗口在前台的场合。

### ⚠️ 编辑器占用内存的写回纪律（**先读再写，血泪教训**）

编辑器开着时，存档在**编辑器内存**里。**CLI 写回 `.gil` 后若编辑器再保存，会覆盖掉 CLI 的写入**
（历史事故源，见 `genshin-ts-asset-operations`「通用安全写回流程」step 6）。
⇒ 纪律：**CLI 写回 → 编辑器必须重新加载存档 → 才允许继续**；不确定时先比对 SHA。

### 🔴 架构修正（推翻此前认知，务必记住）

**千星编辑器 UI 渲染在「原神」窗口内**，不是独立进程窗口。

因此：
- `ys-editor-guard` / `xdotool search --class beyondeditor` 找"编辑器窗口" → **找不到是正常的**（编辑器页在游戏窗内）。
- `ys-editor-guard status` 的「编辑器进程」读数**有假阳性 bug**：`editors() { pgrep -f '[B]eyondEditor' }`
  会匹配到**任何命令行含该字样的进程**（含我自己跑的 bash 命令）。
  **修法（待做）**：改为 `pgrep -f '/BeyondEditor\.exe'` 或校验 `/proc/<pid>/exe` 真身。
- 坐标模型：游戏内 UI 与窗口 1:1（`device-playtest-loop` 已录），窗口在 (0,0) ⇒ **窗口坐标 = 屏幕坐标**。
