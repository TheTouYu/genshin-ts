## 一、三大多人问题拍板（SKILLS-4V4 §5 遗留）

### Q1 谁算物理 → **维持单客户端权威**（listen-server 形态）

- 证据：D5 双人实测 `kit-dup=0`，服务端按 tick 单调去重天然单权威，已验证。
- 多人不变：跑 kitLoop(20008) 的客户端算唯一的球物理；所有玩家输入经服务端槽汇聚给它。
- **新风险（D5 未覆盖）**：D5 是"单人施放技能"场景。「只有一个客户端在执行」可能是因为
  只有一个人施放过技能链。若 A、B 都施放 → 两客户端各跑一份 kitLoop → **双份物理打架**
  （服务端去重只防重复计票，不防两份物理各算各的）。
- **对策：物理执行权显式锁**。服务端变量 `fb_phys_owner`（playerId）：首个施放者持有，
  其余客户端 kitLoop 读到 owner≠自己 时只发心跳不施力。掉线接管=owner 心跳超时
  （服务端已有心跳链）→ 清 owner，下一个施放者接管。**锁的成本 ≈ 10 节点，远低于换架构。**
- 备选（否决理由）：球权持有者算——切权威瞬间球状态撕裂；服务端算——服务端图无 15Hz
  稳定拍（D5 实测 15Hz 上限来自 AI 客户端），且运动器下发延迟 +1 跳。

### Q2 输入身份 → **三候选通道，M0 实验 10 分钟裁决**

现状：`fb_input(key,state)` 信号**不带玩家标识**（fb-input.lua:89-99）；D5 双人实测
508~790 票混流，服务端分不出谁按的。

| 候选 | 做法 | 已有证据 | 风险 |
|---|---|---|---|
| a) Lua 带身份 | Lua 端取本地玩家 id 塞信号 `fb_input(pid,key,state)` | 未查 Lua API 面 | Lua 可能无此 API |
| b) 信号来源 | 服务端信号监听节点若输出 fromEntity/fromPlayer 引脚 | 未查节点定义 | 引脚可能不存在 |
| c) PlayerSelf 变量 | 每客户端 Lua **写**自己 PlayerSelf 变量（键位走变量不走信号） | D708：Lua 能**读** PlayerSelf；**写**未验证 | 写权限/时延未知 |

- 裁决原则（AGENTS.md「官方文档功能=候选可支持面」）：先查 miliastra 文档面
  （`docs/docs/*/doc/cli/` + 千星知识库），三通道都不是"判死"是"待验证"。
- M0 实验设计（需用户两客户端配合，10 分钟）：fb-input.lua 加探针打印
  `game.*` 全可见字段 + 服务端信号节点引脚回读，一轮真机日志定通道。

### Q3 球权仲裁 → **物理派：最近者优先 + 滞回 + 显式动作覆盖**

- 带球模型已是触碰式（2026-11-03 用户裁决：TOUCH_R=1.2m 内周期性小踢 TV_K=+1.3m/s，
  连续助力已删）⇒ **没有"持续牵引归属"问题**，只剩三个判据：
  1. **踢球资格**（已有）：distBP<DRIBBLE_R(2.4) 且球速<KICK_GATE_SPD(8)。
  2. **同拍多人触碰合并**：权威端逐玩家判 touchHit，同拍多命中 ⇒ **距离最近者优先**
     （并列按玩家序号稳定排序），只执行一次小踢。防球速叠加。
  3. **抢断**（已有 D1 形态）：显式键 → 球踢离 + 被抢者 `S_COOLDOWN` 带球抑制
     （deadline 拍数，变量已存在 kit-loop.ts:54）+ 抢断者自身冷却 0.8s。
- **滞回**（新增，网页验证定参）：归属仅用于 HUD/抢断目标选择，不用于物理；
  候选=当前 lastTouch 者享有 0.3m 距离优惠或 2 拍保持，防两人贴身时 HUD 闪烁。
- lastTouch：权威端每踢/触/抢断后写服务端（进球归属+回放）。

## 二、数据通道与预算（服务端=汇聚点）

```
Lua×N（各自客户端） → [身份通道 M0 裁决] → 服务端 kitListen
    写 8 玩家槽：fb_pN_key / fb_pN_seq（输入）
    读 8 玩家位置（getPlayerGuidByPlayerId 链，已有正解）→ 差分速度 → fb_pN_vx/vz
→ 权威客户端 kitLoop：读全部槽 → 六态物理 + 多人 touch 仲裁 + 技能
→ 服务端 kitRender：运动器渲染（B 方案自主节拍，不动）
→ HUD：比分/球权色（lastTouch）→ fb_score_a/b（fb-input.lua 已留通道）
```

- **槽变量规模**：8 玩家 × {key,seq,x,z,vx,vz} ≈ 48 个实体变量（丘丘人载体）。
  先例：球实体 31 变量在役、v2 时代 72 变量可行 ⇒ 规模可行，但**写入拍频要分频**
  （位置差分每拍必须，key/seq 事件式；kitListen 节点预算 +64 估计，现 36n 图有余量）。
- **节点预算**：kitListen +8×读位链(≈8×8n)；kitLoop +多人 touch 仲裁循环(≈30~50n，
  用单实例 for 循环 + 数组槽，禁 8 份复制)。kitLoop 现 979n < 2000 红线，余量够但要精算。
- **玩家枚举**：`getPlayerGuidByPlayerId(0..7)` 死槽判据（离线玩家位置不变/无效 GUID）待验，
  查文档面有无 getAllPlayerCount 类节点。
