## 0. 现状与差距（一句话）

球会算、技能能踢，但**没有"一场比赛"**：没有计时、没有比分累加、进球不重置成开球、
没有结束/再开一局。这三样补齐，"能踢一场"的最小闭环才成立。

| 层 | 现状 | 差距 |
|---|---|---|
| 物理 | 客户端 kitLoop 六态积分 + 服务端 kitRender 施运动器（结构层已核，行为层待验） | 无 |
| 进球判定 | 越门线+门洞内+低于横梁 ⇒ 球回中圈 + 发 `tag='G'` + 服务端 `fb-goal` | 比分不累加、不广播 |
| 输入 | Lua 6 键双态（有球/无球）→ fb_input → 服务端写 fb_key | 无（待真机验） |
| HUD | 记分牌/计时/横幅/技能条 11 控件（结构层已核） | 比分与事件没有数据源 |
| 比赛 | 无 | 计时、比分、开球、结束、重开 |

## 1. M1 目标（单人最小可玩，一周内）

**一句话验收**：进图 3 分钟内，你能踢进 2 个球，比分从 0:0 变成 2:0，每次进球后球回到中圈、
计时从 00:00 走到 03:00 后弹出「比赛结束」，按 ⑥ 可重开。

### 1.1 规则（M1 只做单人练习模式）

| 规则 | 取值 | 依据 |
|---|---|---|
| 模式 | 单人练习（1 球员 1 球，无对手 AI） | 先闭环再上 4v4 |
| 时长 | 3 分钟（180s） | 短到可反复测，长到能进 2+ 球 |
| 比分 | 进球 +1（当前只有"我方"一门） | 双门/两队属 M2 |
| 开球 | 进球后 1.5s 冷帧 → 球回中圈 → 2s 倒计时横幅 → 继续 | 给玩家反应时间 |
| 结束 | 180s 到 → 横幅「比赛结束 比分 a:b」→ 冻结球 → 按 ⑥ 重开 | 重开=清零比分/计时/球位 |
| 出界 | M1 不做（场地有围挡，球会被弹回） | 边线/底线规则留 M2 |

### 1.2 状态机（服务端权威，客户端只报事件）

```
Idle --(进图/按⑥)--> Kickoff(2.0s 倒计时) --(到点)--> Playing
Playing --(kit_state tag='G')--> Goal(1.5s 冻结) --(回中圈)--> Kickoff
Playing --(t≥180s)--> End --(按⑥)--> Kickoff
```

- 权威在**服务端**（防作弊、防客户端掉线导致比分丢）：客户端 kitLoop 只报"进球发生"。
- 服务端状态用**节点图变量**（图内），比分/时钟要跨图给 HUD 读 ⇒ 用自定义变量（见 §2）。

## 2. 数据通道（M1 的硬骨头，先做 10 分钟可行性实验）

| 需求 | 候选通道 | 判据 |
|---|---|---|
| 服务端算比分/计时 → 客户端 HUD | **玩家实体自定义变量** `fb_score_a` / `fb_secs`：服务端「设置自定义变量」写，Lua 用 `game.GetGlobalCustomVariableValue(Enum.CustomVariableEntityType.PlayerSelf, name)` + `RegisterCustomVariableChangedHandler` 读 | Lua 侧代码**已写好**（pcall 兜底）。**未验证**：①玩家实体上未声明的变量能不能直接 set ②`PlayerSelf` 作用域是否就是玩家实体变量 |
| 兜底 A | 关卡变量（`Enum.CustomVariableEntityType.Level`）：Lua 能读；服务端要能写关卡变量（`设置自定义变量` 节点只认实体 ⇒ 需确认是否有"设置关卡变量"节点） | 需查节点面 |
| 兜底 B | 第四份信号 def「发送客户端脚本信号」（0x60000001）：DSL 无节点，要 wire 编辑 `gil-node-graph-editing` | 成本高，作最后手段 |

**实验（10 分钟，编辑器 + 一张测试图）**：给玩家实体加自定义变量 `probe_int=int` → 服务端图
`设置自定义变量(target=玩家1, probe_int=42)` → 客户端 Lua 打印
`game.GetGlobalCustomVariableValue(Enum.CustomVariableEntityType.PlayerSelf,'probe_int')`。
读到 42 即通道成立，M1 直接落地；读不到转兜底 A。

## 3. 服务端比赛图（新图 kitMatch，20000）

- 触发：进图（OnStart）/ 收 `kit_state`（tag='G'）/ 定时器（1s 心跳）
- 职责：状态机 + 比分 + 计时 + 开球重置 + 写自定义变量给 HUD
- 复用：`kitRender` 保持"只演"，不塞比赛逻辑（一张图一个职责，2000 节点上限的纪律）
- 与 kitRender 的接口：进球事件已由 kitLoop 发 `tag='G'`，kitRender 已 print `fb-goal`；
  kitMatch 直接监听同一信号（`kit_state` 的 monitor 用途），或由 kitRender 转发
