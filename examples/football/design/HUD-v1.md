## 0. 为什么样式放在 Lua，不放在 .gil

`assets:ui update --font-size/--align` 只支持 `kind=textbox/input-box/message-queue`；`client-textbox` 的
文本样式在记录深层 `f505(501=64/f502=84)→f503→f74→f75`（f501 字号、f505 颜色、f510 文本字节），
CLI 没有这条命令面。而 `update --position/--size` 对 client-textbox 有效。

⇒ 分工：**.gil 只负责"控件存在 + 初始位置尺寸"，字号/颜色/对齐/文案全部由 Lua 运行时赋值**
（`c.text` / `c.fontSize` / `c.fontColor` / `c.horizontalAlignment='Middle'`；真机形态来自
`workspace/hmlt-qixia`（霜华纪）已跑通的写法）。改样式 = 改 `examples/football/lua/fb-input.lua` +
`assets:scripts update`，不动地图二进制。

## 2. 层级与配色（按 `08-art` 五条规则）

- **容器隐喻**：球场记分牌 + 转播字幕条。顶部一簇 = 记分牌（标题+比分+计时），中央 = 字幕，右侧 = 键位条。
- **层级**：比分 46 号白字（主）> 标题 24 号描金（次）> 计时/状态 22~24 号灰（弱）> 技能条 20 号浅灰（弱）。
- **克制**：唯一"动"的是横幅出现 1.2s 后自动清空；不做循环动效。
- **语义**：每个控件都回答"它代表什么"（比分/时间/事件/按键/状态），无装饰件。

## 3. 数据通道（现状与缺口）

| 方向 | 通道 | 状态 |
|---|---|---|
| 客户端 Lua → 服务端 | `game.ServerSignal('fb_input')` → 服务端 `kitListen` 写 `fb_seq/fb_key` | ✅ 已在用（本次保留原链路） |
| 服务端 → 客户端 Lua | 全局自定义变量 `fb_score_a`/`fb_score_b`（`Enum.CustomVariableEntityType.PlayerSelf`）+ `RegisterCustomVariableChangedHandler` | 🟡 代码已在 Lua 里（pcall 兜底，缺变量就不生效）；**服务端写入侧尚未接** |
| 服务端 → 客户端 Lua（定向信号） | 「发送客户端脚本信号」第四份 def（0x60000001） | ❌ DSL 无该节点；要 wire 编辑或补 DSL |

比分当前显示 `0 : 0`（本地占位）；接上服务端写入后无需改 Lua。
