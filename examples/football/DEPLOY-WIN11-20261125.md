### Win11 上提交

`.git/hooks/pre-commit` 是 bash 脚本，调 `python3 scripts/doc_health.py --staged`；Win11 的 PATH（含 PortableGit 自带的 bash）里
没有 `python3`，钩子以 127 失败并把提交拦下。做法是**让门禁照常执行**：给钩子进程一个 `python3` shell 函数
（非交互 bash 启动时 source `$BASH_ENV`；仅该次提交的进程树生效，不改系统设置、不改钩子文件）。不要 `--no-verify`。

```powershell
$py = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
$env:PYTHONUTF8 = '1'                                # UTF-8 模式：见下方"编码"一段，别只设 PYTHONIOENCODING
function ConvertTo-Posix([string] $p) { '/' + $p.Substring(0, 1).ToLower() + '/' + $p.Substring(3).Replace('\', '/') }

& $py scripts/doc_health.py --staged                 # 预检：与钩子里同一条命令

$shim = "$env:TEMP\genshin-ts-win-deploy\bash-env-python3.sh"
"python3() { PYTHONUTF8=1 `"$(ConvertTo-Posix $py)`" `"`$@`"; }`n" | Set-Content -LiteralPath $shim -Encoding Ascii   # 无 BOM，bash 才认
$env:BASH_ENV = ConvertTo-Posix $shim
git commit -m "<message>"                            # 钩子内 python3 -> DSH Python 3.12
Remove-Item Env:\BASH_ENV
```

实测（2026-11-25）：不注入时钩子环境里 `python3 --version` → `command not found`，rc=127；注入后 → `Python 3.12.14`，rc=0；
本轮三次提交（`99774abd` / `929bec4d` / `b80a16a0`）钩子均真实执行并放行。

**编码**：只设 `PYTHONIOENCODING=utf-8` 时，`doc_health.py` 拉起的子进程（`longtask_check.py` 等）按 UTF-8 输出，而它自己用
`subprocess.run(text=True)` 仍按系统 GBK 解码 ⇒ 读取线程抛 `UnicodeDecodeError`（实测 3 次）。判定按退出码走、不会假 PASS，但真 FAIL 时的具体文本会丢。
**用 `PYTHONUTF8=1`**（UTF-8 模式，父子进程一致）。四种组合实测：仅 `PYTHONIOENCODING` 3 次异常 / 都不设 0 / 仅 `PYTHONUTF8` 0 / 两者都设 0；
真 bash + 内置 `PYTHONUTF8=1` 的 shim 走一遍门禁：0 次异常、rc=0。

⚠ 别写 `git status … | Select-Object -First N` 这类「取满即掐断管道」的命令：`git status` 会在后台刷新索引，被中途掐断会留下 0 字节的
`.git/index.lock`，之后所有写索引的 git 命令都报 `Unable to create '.git/index.lock'`（2026-11-25 21:03 实发，来源为推断——时间窗对得上本会话的
一条此类命令）。要看前几行先落变量再截取：`$s = git status --short; $s | Select-Object -First 50`。
陈旧锁的判据＝0 字节 + 无 `git` 进程 + 时间戳对得上一条已结束的命令；**删除锁文件前先向用户确认**。
