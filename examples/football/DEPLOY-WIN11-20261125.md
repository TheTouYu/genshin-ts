### Win11 上提交（2026-11-25 晚按用户裁决固化——现在什么都不用设）

钩子不再写死 `python3`：`scripts/git-hooks/pre-commit` 经 **`scripts/py.mjs`** 找 Python——`GSTS_PYTHON`（显式指定；坏了直接报错，不静默换人）
→ PATH 里的 `python3` / `python` / `py -3` → DSH 运行时；每个候选都用 `--version` 实测（Windows 应用商店的假桩会被淘汰）；子进程固定 `PYTHONUTF8=1`。
新机器 / 新克隆先装一次钩子（Win11 用 PortableGit 自带的 bash 跑同一条；脚本末尾自检「钩子可运行」，并在 Windows 上关掉 `core.filemode` 噪音）：

```bash
bash scripts/install-git-hooks.sh
```

手动跑任何仓库 Python 件走同一个入口：`node scripts/py.mjs scripts/doc_health.py --staged`。
看它选中了谁：`node scripts/py.mjs --print`；自测（含「无候选必须 127 并给指引」的负例）：`node scripts/py.mjs --selftest`。

实测（2026-11-25 22:2x，全程不设任何环境变量）：自测 PASS；安装脚本自检通过；`.git/hooks/pre-commit` 与源文件哈希一致；
固化后的真实提交见本文件所在提交之后的 `git log`。固化前的做法（给钩子进程注入 `BASH_ENV` 的 `python3` 函数，127 → rc=0）只作历史：
它依赖每次提交都记得注入，换个人就会重踩，所以被固化件取代。

环境事实：Windows 会给子进程自动补回 `USERPROFILE` / `PATH` / `HOMEDRIVE` 等 7 个用户级变量（只传 6 个系统变量，子进程里却有 13 个）——
想在子进程里「拿掉」它们只能显式给值；`--selftest` 的负例就是踩了这个才第一次假红。

**编码**：只设 `PYTHONIOENCODING=utf-8` 时，`doc_health.py` 拉起的子进程（`longtask_check.py` 等）按 UTF-8 输出，而它自己用
`subprocess.run(text=True)` 仍按系统 GBK 解码 ⇒ 读取线程抛 `UnicodeDecodeError`（实测 3 次）。判定按退出码走、不会假 PASS，但真 FAIL 时的具体文本会丢。
**用 `PYTHONUTF8=1`**（UTF-8 模式，父子进程一致）。四种组合实测：仅 `PYTHONIOENCODING` 3 次异常 / 都不设 0 / 仅 `PYTHONUTF8` 0 / 两者都设 0；
真 bash + 内置 `PYTHONUTF8=1` 的 shim 走一遍门禁：0 次异常、rc=0。

⚠ 别写 `git status … | Select-Object -First N` 这类「取满即掐断管道」的命令：`git status` 会在后台刷新索引，被中途掐断会留下 0 字节的
`.git/index.lock`，之后所有写索引的 git 命令都报 `Unable to create '.git/index.lock'`（2026-11-25 21:03 实发，来源为推断——时间窗对得上本会话的
一条此类命令）。要看前几行先落变量再截取：`$s = git status --short; $s | Select-Object -First 50`。
陈旧锁的判据＝0 字节 + 无 `git` 进程 + 时间戳对得上一条已结束的命令；**删除锁文件前先向用户确认**。
