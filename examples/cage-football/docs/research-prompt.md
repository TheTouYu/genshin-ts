# 任务：实况足球 & FIFA/FC 机制细节联网调研（为笼式足球还原真实度服务）

> 使用方式：本提示词整体复制给一个**有联网搜索能力**的新会话或子代理执行。
> 执行者不需要访问游戏，只需要 web_search + 读写本仓库文档。

## 一、任务目标

- 联网完整收集两大真实足球游戏系列的**玩法机制细节**：
  - **实况系**：PES（Pro Evolution Soccer / Winning Eleven）→ eFootball（免费化转型）
  - **FIFA 系**：FIFA 系列 → EA Sports FC（FC24/FC25/FC26）
- 收集目的：为本项目 `examples/cage-football/`（笼式足球，千星沙盒引擎上的 4v4 笼式足球）
  提供"真实足球机制参照库"——**每条机制都要回答：这个引擎能不能还原/怎么简化/还原不了**。
- 成功长什么样：`examples/cage-football/docs/research/` 下按机制域分篇的结构化中文 Markdown，
  每条关键机制带来源 URL，带引擎映射三分类标注，后续设计迭代可直接引用
  （例如"蓄力条满格时长参照 FIFA 射门力量条约 1s"这种粒度的可用结论）。

## 二、铁律

- 纯研究任务：**只联网搜索 + 写文档**，不改地图、不注入、不动 examples 下任何现有设计文件
  （research/ 目录除外）。
- **来源可信度分层**：官方文档/官方 Patch Notes > 数据站与深度机制解析
  （如 Operation Sports、FUTBIN 类、机制逆向长文）> Reddit/论坛讨论 > 泛攻略。
  每条关键机制与数值标注来源 URL。
- **不得编造数值**：查不到就写"未查到公开数据"，宁缺毋滥；社区实测数据标"社区实测"。
- **区分系列共性与版本特性**：每条机制标注适用版本（如 FIFA23 / FC24 / PES2021 /
  eFootball 2024）。FIFA→FC 改名与 PES→eFootball 转型是机制断代点，禁止混写。
- 版本范围：**近作为主**（FC24/FC25 + eFootball 2024/2025 + PES2021 末期），经典机制
  （如 PES 传奇手感类讨论）可追溯但不考古。
- 搜索以**英文为主**（机制解析深度远超中文社区），产出**中文**。

## 三、核验标准

- 模型侧（提交前自检全过）：
  1. 机制域清单（§四 R1~R8）全部成文，无空域；
  2. 每域 ≥5 条具体机制条目，关键数值（速度/力度/时长/概率类）有来源；
  3. 每条机制都有引擎映射标注，三选一：**可还原**（引擎有直接能力）/
     **可简化**（无直接能力但可近似——注明近似通道）/**不可还原**（引擎无通道，注明缺什么）；
  4. `INDEX.md` 汇总表：机制 → 所在文档 → 映射分类，一页可查。
- 用户侧（每轮/终审）：抽查来源链接有效性；审映射分类是否越界
  （映射判断的唯一依据是 DESIGN.md §3 证据表——**不要映射出引擎不存在的能力**，
  例如引擎无刚体物理、无原生蓄力 UI）。
- 最终验收：笼式足球 DESIGN.md 的下一次迭代能直接引用本库结论支撑参数选择。

## 四、多轮迭代与会话拆分

每轮 = 搜索 → 整理落盘 → 更新进度 → `git commit`（只提交 research/ 下本轮文件）。
轮次按机制域划分（顺序可按搜索发现调整/合并，域不可缺）：

- **R1 操控与输入**：移动/转向/加减速/冲刺与体力/变向与惯性/护球（Shielding）/
  停球与第一脚触球（first touch）/花式动作与技能招式表
- **R2 球物理**：球速量级/弧线与旋转（马格努斯）/弹地与滚动衰减/门柱横梁反弹/
  球网表现/球与球员身体的碰撞交互
- **R3 射门/传球/带球**：射门力量条机制（蓄力时长/满格值/松开判定）/射门准度影响因素/
  辅助等级（辅助/半辅助/手动传球射门差异）/传球类型全表（短传/长传/直塞/过顶直塞/
  传中/贴地传中）/带球节奏（触球频率与速度的关系）
- **R4 防守与守门员**：站立抢断/铲球（正面铲/侧铲）/拉拽与身体对抗/卡位；
  门将 AI 行为（站位/出击/扑救判定）/门将手动操作模式/门将属性对扑救的影响
- **R5 规则与裁判**：越位判定细则/犯规判定与有利原则/红黄牌/定位球全表
  （点球/任意球（直接间接）/角球/界外球/球门球的操作与判定）
- **R6 球员属性**：属性表全项与作用机制（PAC/SHO/PAS/DRI/DEF/PHY 六维+细分属性+隐藏属性）/
  弱脚与花式星级/位置适配与化学（若属 PES 则是能力值体系与位置 rating）
- **R7 AI 与战术**：难度等级对 AI 的影响（AI 作弊争议类结论也要）/战术板与队伍指令/
  队友跑位 AI（前插/接应/拉开）/教练模式
- **R8 呈现与反馈**：镜头系统/力度条等辅助 UI/雷达小地图/播报与音效反馈/回放系统

**会话衔接**：每轮结束把进度追加到 `examples/cage-football/docs/research/PROGRESS.md`
（已完成域/每域条目数/未查到清单/下轮计划）；新会话（或续接会话）先读该文件再干活。

## 五、复用清单（先查再用，不要重新发明）

- **research 全局技能**：联网调研+高信任源+落盘 Markdown 的流程规范，直接按它执行
- **web_search 工具**：联网搜索（英文查询为主，一次 1~4 条查询）
- 用途上下文（第 0 轮必读）：
  - `examples/cage-football/DESIGN.md`——当前设计 v2.1 与 D1~D9 裁决、**§3 证据表=引擎能力边界**
  - `examples/cage-football/CONTEXT.md`——领域术语表（产出文档用词与它对齐）
- 引擎能力侧参照（映射时查证，不是必读全文）：
  - `.agents/skills/game-from-scratch/references/engine-rules.md`——运动器/事件/坐标系速查
  - `docs/game-engine-knowledge/`——分域权威文档（motion-devices.md / components.md /
    camera-system.md 等）
- 落盘位置：`examples/cage-football/docs/research/`：
  `mechanics-<域>.md` 分篇 + `INDEX.md` 汇总 + `PROGRESS.md` 进度

## 六、已知局限与风险

- 两系列内部数值（射门力量公式/精确帧数据）多数**未官方公开**，社区逆向为主——
  一律标"社区实测"，注明争议
- eFootball 免费化后机制与 PES 末期差异大（道具收费/手感争议），引用时防串代
- 英文机制解析站质量分布：Operation Sports 论坛/官方 Patch Notes/深度长文 >
  Reddit 碎片讨论——碎片结论要交叉验证
- 引擎映射的最大坑：把"引擎做不到的"标成"可简化"（如 11v11 全场 AI、网络同步层）——
  拿不准就归"不可还原"，笼式足球本来就有意收窄（4v4/笼式/无越位）
- 本仓库 PKC 知识树无任何 FIFA/PES 沉淀（2026-09-01 查证），不存在重复收集问题
