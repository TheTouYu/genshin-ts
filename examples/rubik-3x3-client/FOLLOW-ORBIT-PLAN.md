## 一、已闭合结论（铁证）

1. 官方机制 = 中心球自转 + 块是球的装饰物（用户编辑器查证，2026-08-31）：
   直接给中心圆球施加旋转，块的视觉位置/旋转由装饰物关系自动传导；官方不使用跟随运动器。
2. 帧级证据（3030）：中心球 = Create Prefab 1077936170（Entity=31，位置=(2,5,2)=
   玩家锚点(0,3,4)+(2,2,-2)）；26 块的 Create Prefab 位置恒定 (0,3,4)、IN5:Integer=1
   （装饰物挂接语义）。每块 per-block 图加一个「旋转」Target-Oriented 设备 0.5s
   euler(0,270,0)，信号带 Float=0.5 时长 + Vector(0,-90,0) 角度向量；设备停 → Remove Unit
   Status → 选中状态图 +1 计数。全程无跟随操作码、无 per-block 位置设备。
3. B1 判定 B：Target-Oriented = 纯转向（块原地自转）——在非装饰物实体上是转向；
   在装饰物实体上旋转围绕宿主锚点，才产生公转视觉。两者不矛盾。
4. 用户情报 H1b：跟随运动器需自行配置、与基础运动器组件互斥（不配置保持基础运动器）。

## 二、三路线对比

| 路线 | 机制 | 单次面转设备数 | 定时器 | 风险 | 评价 |
|---|---|---|---|---|---|
| 1 我们现状 | 每块 spin+orbit 双设备 + 折线数学 + 错峰定时器群 | 18+9 | 0.01~0.24s 九槽群 | —— | 待替换（负载铁律违例） |
| 2 官方式 | 块改装饰物挂到中心球，球单设备自转，全部自动传导 | 1 | 无 | 资产层大改（26 块挂接重排，逻辑/视觉分离未验证） | 已实证、但改造大 |
| 3 跟随运动器（用户推荐） | 26 块预配 followMotion(9)；每转用 API 给需转的 9 块动态指定跟随目标+相对旋转，只转中心球 | 1（球） | 无 | 相对旋转合成关系必须实验 | 理论负载最低、不重构资产 |

用户方向 = 路线③：所有块配置跟随运动器 → 每次给需要转动的块用 API 配置跟随运动器 →
只旋转中心的球。相对旋转关系待实验验证（跟随坐标系/旋转偏移与球自转如何合成成
「公转+自转」）。

## 三、路线③实验计划（第 1 轮最小切片）

目标：在 1073741914 上用最小样本确认相对旋转关系——1 个中心球 + 1~2 块，
球自转 90°，块通过跟随运动器是否得到正确公转+自转。

- 样本 A（2 块对角线）：块 A 偏 (1,1,0)、块 B 偏 (0,0,1) 相对球；预配 followMotion(9)；
  用 switchFollowMotionDeviceTargetByGuid 分别指定世界坐标系偏移(1,1,0)/(0,0,1)；
  球加匀速旋转设备绕 Y 90°（时长 0.5s）→ 期望：A 到一个新格点、B 原位自转
  （偏移符号按引擎实测）。
- 样本 B（相对坐标系+旋转偏移）：偏移在相对坐标系下是否随球旋转传导（旋转偏移=块初始
  朝向差）。
- 判定表：块位置弧线+朝向变化正确 = 相对旋转关系闭合；块不动/飞走 = 按日志逐帧归因
  （跟随激活帧/球设备帧/操作码）。

先决工程（组件层，地图一次性，可 CLI 做）：
- 26 块定义/实例 basicMotion(4) → followMotion(9)（组件互斥，替换非并存）。
- 中心球：空模型 10005018 实体 + 保留 basicMotion(4)（供设备自转）+ 默认隐藏。

节点层（每转，事件驱动）：
- 信号入口 → 算层内 9 块（重用现有 logic_apply_face 的列表）→
  switchFollowMotionDeviceTargetByGuid×9（完全跟随/跟随位置+旋转偏移）→
  球加单设备（匀速旋转，轴=层轴向）→ 设备停 → busy 解锁 → 逻辑位置写回。
- 错峰定时器下线清单不变（turn.ts 全槽 + visual.ts turnblock/orbit2 群全删）。
