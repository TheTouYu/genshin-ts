## GAP-01 · 结构体（Struct）类型无法从代码创建 🔴

**视频知识点**（P3 · 37:53~40:16）
结构体在编辑器「左上角菜单 → **高级数据管理** → **创建结构体**」中定义；参数上限 50；不能递归套娃（"非法结构，不能保存"）；定义时带默认值，自定义变量创建结构体时套用该默认值。

**官方出处**
- `docs/ui-tutorial/official-guide-concepts.md:10564` 局内存档结构体与基础结构体使用方式基本一致
- `docs/ui-tutorial/official-guide-auxiliary-appendix.md:2144` 结构体数量上限 999

**我方现状（证据）**
- `src/cli/gil_level_variables.ts:505-526` —— 变量类型联合 `UiVarType` 全部成员为：
  `entity / guid / int / bool / float / str / vec3 / guid_list / int_list / bool_list / float_list / str_list / entity_list / vec3_list / faction / config_id / prefab_id / config_id_list / prefab_id_list / faction_list / dict`
  → **有 `dict`，没有 `struct` / `struct_list`**。
- `grep -rn "struct\|Struct" src/cli/gil_custom_variables.ts src/cli/gil_level_variables.ts` → **0 命中**。
- `grep -rn "局内存档" docs/ src/ tools/`（排除 ui-tutorial）→ 仅 `docs/capability-coverage-map.md:50` 把它登记在 D 体系"其它：…未覆盖"。

**影响**
- `assets:custom-variables` / `assets:level-variables` **无法创建结构体类型变量** → 无法在实体/关卡上落结构体数据。
- 直接堵死 GAP-04（局内存档）与 GAP-08（UI 绑定结构体成员）。
- 视频里两个"必须用结构体"的场景（局内存档、消息队列）**一个都做不了**。

**待裁决选项**
- (A) 走 `editor-incremental-gia-investigator` 最小差分：编辑器新建 1 个结构体类型 + 1 个结构体变量，差分出 wire 格式，再扩 `UiVarType`。
- (B) 先只做**只读**：能解析地图里已存在的结构体定义/变量（不新增）。
- (C) 暂不支持，登记 open-items。

## GAP-02 · DSL 无结构体拼装/拆分 API 🔴

**视频知识点**（P3 · 40:16~43:28）
三种结构体节点：**拼装结构体**（每次调用创建新对象）、**拆分结构体**（一次拆出所有成员）、**修改结构体**（只改指定成员）。讲师的标准用法：`拆分结构体` → 成员存节点图变量缓存 → 循环里读缓存（否则 5 段伤害会拆 5 次，负载高）。

**官方出处**
- `docs/ui-tutorial/official-guide-nodes-server.md` / `src/definitions/nodes.ts` 已含三节点定义

**我方现状（证据）**
- 节点定义**存在**：`src/definitions/nodes.ts:11911 splitStructure()`、`src/definitions/nodes.ts:11925 assembleStructure()`、`src/definitions/nodes.ts:8260 modifyStructure()`。
- 运行时封装**不存在**：`grep -rn "assembleStructure\|splitStructure\|modifyStructure" src/runtime/*.ts` → **0 命中**。
- `src/runtime/value.ts:458-467` 的 `struct` 类是**空占位**：
  ```ts
  export class struct extends value {
    declare private readonly __brandStruct: 'struct'
    constructor() { super() }
    override toIRLiteral(): Argument {
      return { type: 'struct', value: null }
    }
  }
  ```
  无字段参数、无成员访问 → **即使地图里已有结构体变量，DSL 也取不到成员**。

**影响**
- "用结构体存关卡表 / 50 把弓的数值表"这类玩法**无法用 TS 写出来**。
- 该节点定义在 definitions 里是自动生成的，属"知识在、API 缺"的典型——按项目口径属**候选可支持面**，不是"不支持"。

**待裁决选项**
- (A) 补运行时封装（`f.assembleStructure` / `f.splitStructure` / `f.modifyStructure`）+ 结构体类型在 DSL 里的表示（需先有 GAP-01 的类型定义读取能力）。
- (B) 等 GAP-01 落地后一并做（**建议**：两者是同一链路的上下游）。
- (C) 暂缓。

## GAP-03 · 单位状态 / 职业 / 道具节点图无法创建 🔴

**视频知识点**（P5 · 35:10~39:20）
- **状态节点图**可**动态附着**：捡到所有钥匙前门没有开门逻辑，捡到后才施加该状态 → 动态增删一个节点图。状态节点图还能接收"单位状态结束"事件，天然处理成对逻辑。
- **道具节点图**：消耗品（RPG 血瓶/治疗苹果）**只能挂在道具上**，"不能从实体节点图挂上去"。

**官方出处**
- `docs/ui-tutorial/official-guide-concepts.md:6424-6426`
  - 状态节点图 = 挂载于**单位状态**，生命周期跟随单位状态
  - 职业节点图 = 挂载于**职业配置**，可挂玩家或角色实体，职业切换即失效/生效
  - 道具节点图 = 挂载于**道具配置**
- `docs/ui-tutorial/official-guide-concepts.md:6414-6416` 三者与实体节点图统称**服务端节点图**

**我方现状（证据）**
- **缺口在"建图"这一环**：`src/cli/assets_node_graphs.ts:143`
  > `// 未采样自动节点结构的类型：20003 状态 / 20004 ClassNode / 20005 ItemNode → fail closed`
  `src/cli/assets_node_graphs.ts:155` 对应分支直接抛错。`--type` 帮助文本（:230-231）也只列到 20000/20001/20002/20006/20007/20008/20009/20010。
- **但上下游其实已在位**（说明这是样本缺口，不是设计缺口）：
  - `src/runtime/IR.d.ts:37` `export type ServerGraphSubType = 'entity' | 'status' | 'class' | 'item'` —— **DSL 已声明四种服务端子类型**（`g.server({ type: 'status' | 'class' | 'item' })`）。
  - `src/injector/folder.ts:5-15` `DEFAULT_GRAPH_TYPE_VALUES` 已含 `[20003, 2300] / [20004, 2400] / [20005, 4300]` —— **注入侧类型映射已在位**。
  - `tests/eslint_rules_showcase.ts:706/714/723` 有 `type: 'status' / 'class' / 'item'` 的编译用例（声明层）。

**影响**

- 视频 P4 的"组合式行为"（怪物能力写成单位状态图）与 P5 的"道具自身逻辑"两条主推路线都落不了地。

**待裁决选项**
- (A) 走 `editor-incremental-gia-investigator`：编辑器各建 1 张该类型空图，差分出**自动节点结构**（参考技能类的 `节点图开始 200042/2001 + f8={1:6}` 模式，见 `src/cli/assets_node_graphs.ts:521-526`），补进 `assets:node-graphs create`。
- (B) 只补最常用的 **道具节点图（20005）** 一类先验证。
- (C) 暂缓。

## GAP-05 · 实体通用组件无法新增 🟠

**视频知识点**（P5 · 21:20）
"任何一个你需要用的在实体上面用的，比如说包括**运动器**呀、包括一些**物件镜头**、或**自定义变量**它的状态什么的，**你都需要添加通用组件**，不添加的话你会在日志当中看到他报错的。"

  `--color / --position / --rotation / --scale / --attach-aux / --detach-aux / --remove-component / --tab-options`
  → **无 `--add-component`**；`grep -rn "addComponent\|add-component\|setComponent" src/cli/*.ts` → **0 命中**。
  ⚠️ **2026-09-16 定性更正（GAP-05 大幅缩小）**：以上判据**不足以支持「组件不能加」的结论**——我搜的是一个**命令名**，而真实入口是**配置项** `components:`。
  `src/cli/gil_static_assemblies.ts:487 componentSnapshot()` 实际支持 **7 种**组件：
  `followMotion`(9) / `basicMotion`(4) / `nameplate`(27) / `textBubble`(28) / `lightSource`(38) / `hitDetection`(12) / **`tabBar`(17)**（配置位 `staticAssemblies[].components` / `staticPrefabUpdates[].components`，`src/compiler/gsts_config.ts:286/:475/:531`）。
  **真正缺的只是场景实体侧**：`EntityImport`（`src/cli/gil_entities.ts:42-54`）无 `components` 字段。
  **教训**：「grep 不到」≠「不存在」——能力类断言必须先查文档面 `docs/docs/*/doc/cli/`，再查代码面。
- **反证（单项可行）**：`src/cli/assets_global_timers.ts` 有 `attach` 子命令，「给场景实体(root5)挂全局计时器组件并引用计时器名」，`COMPONENT_TYPE_GLOBAL_TIMER = 16`（root5 实体记录 f7 组件槽）→ **挂通用组件的 wire 路径已被走过一次，只是没做成通用框架**。

**影响**
- 无法用代码给实体挂**运动器 / 物件镜头 / 单位状态**等组件 → 很多玩法第一步就卡住。
- 因为缺口是"没有通用框架"而非"不知道 wire"，补齐成本相对可控。

**待裁决选项**
