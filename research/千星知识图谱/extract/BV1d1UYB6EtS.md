## 做法与技巧

- **【开工前置·三表先行】打开节点图之前先用表格列出三张清单：①卡牌表（表头＝元件 id / 所在格子 / 出现概率，一行＝一张卡）；②棋盘表（每个格子的信息＝我是谁、我在第几层、第几行、第几列、是否会被挡住；格子里填的是卡牌 id 而不是把卡牌贴上去）；③生成规则表（三条约束逐条写成逻辑）**
  - 出处：`[00:00:46]` "第一行写表头原件id所在格子出现概率每一行就代表着一张卡牌"
  - 证据等级：个人经验（本图为开源实现，可直接对照文件）
  - 维度：数据导向⊕

- **初始化流程四步（照抄即可复现棋盘生成）：①读配置（当前模式是不是教学关、会用到哪些类型的卡牌）；②准备牌堆（按规则从卡牌表挑可用卡 id 洗牌进一个列表）；③遍历棋盘每个格子（判断当前层/列能不能放卡，能就抽一张放进去）；④规则检查（补非 3 倍数的卡、用卡牌 id + 卡牌字典确定上下层遮挡关系）**
  - 出处：`[00:02:18]` "第三步遍历棋盘的每个格子当前在第几层第几列这行能不能放卡可以的话就从牌堆抽一张放进去"
  - 证据等级：个人经验
  - 维度：D3 逻辑编写

- **【邪修·定时器分批】把"一次性处理 100 个格子"拆成"每秒处理 20 个格子"，绕开沙箱掐断：开启一个循环定时器每 0.05 秒触发一次，第几次触发就是第几次循环（读格子→判断→抽卡→填上去→立即完成循环），处理完全部格子后停止定时器**
  - 出处：`[00:03:53]` "我们开启一个循环的定时器每0.05秒触发一次第几次触发就是第几次循环"
  - 证据等级：个人经验（讲师给出的正是绕过保护机制的标准解法）
  - 维度：负载与开发机⊕

- **初始化流程要配一个"卡牌生成定时器"做分帧推进（卡牌生成→层/行捕捉→逐行生成→一层完成再进入第二层→全部生成完才进入检查步骤）**
  - 出处：`[00:02:18]` "第四步规则检查顺序总览卡牌生成定时器陈行捕捉生成层为生成行做准备"
  - 证据等级：个人经验（字幕此处有误识别，需对照开源节点图）
  - 维度：D3 逻辑编写

## 设计经验与教训

- **数据导向方法论：先把"会变的东西"写成数据（表），再让逻辑去读表，实现会更快更稳——开局要用到的信息在拉节点图之前就已经被拆解完成**
  - 出处：`[00:01:31]` "这就是数据导向先把会变的东西写成数据再让逻辑去读表就会更加的快捷"
  - 证据等级：个人经验
  - 维度：数据导向⊕

- **循环中途停住的第一嫌疑是沙箱保护而不是自己写错——先按"每次处理量太大"去排查（改成分批定时器），不要盲目改逻辑**
  - 出处：`[00:03:07]` "为什么循环跑到一半突然停了明明我没写错啊"
  - 证据等级：经验共识
  - 维度：负载与开发机⊕

- **整套思路可迁移：卡牌表/格子表/规则表 + 定时器分批，换个玩法照样能拆开做（讲师结论"各种玩法都可以拆开做"）**
  - 出处：`[00:03:53]` "原来是一口气数到100现在改成每秒数20个"
  - 证据等级：个人经验
  - 维度：数据导向⊕
