## 规则与机制

- **千星奇域的音效是定死的**，创作者不需要额外设计音效——所以团队分工表里没有独立音效岗（其他游戏才需要）。
  - 出处：`[00:07:53]` "因为铅芯里的音效是定死的不需要你去额外设计设计音效"
  - 证据等级：硬规则
  - 维度：项目管理⊕

- **结算共四种结果：未完成 / 完成 / 胜利 / 失败；只有「未完成」不算结算**——所以把玩家的结算判定给成「完成」同样算速通漏洞。
  - 出处：`[00:25:34]` "结算过程有有四种一个叫未完成它是澜这就是一个叫未完成一个叫做完成一个叫做胜利一个叫失败"
  - 证据等级：硬规则
  - 维度：D4 玩法系统

- **跨端执行链会被算力截断**：手机端算力不够时，本来要循环 20 次的执行链可能只循环 10 次就被引擎掐断（服务器负载过高直接卡掉），表现为系统不工作、事件紊乱。
  - 出处：`[00:25:34]` "本来循环要循环20次他可能循环十次说不行服务器负载太大了还是什么负载太大了然后直接给卡掉了"
  - 证据等级：实测
  - 维度：多端适配⊕

- **手游端算力低 = 创作者必须显式测多设备**：原千星奇遇是多设备平台，创作者只摸得到电脑键鼠，手机触屏与电脑手柄的基本操作要靠测试者额外关注。
  - 出处：`[00:10:10]` "因为原千心奇遇它是个多设备的平台然后创作者的话是更多的是接触到电脑键鼠那么对于一些手机触屏啊对于一些电脑电脑的手柄啊这些的基本操作的话可能需要测试者去额额外关注一下"
  - 证据等级：硬规则
  - 维度：多端适配⊕

- **手柄多按钮映射同一按键会直接让游戏不可玩**（实测案例：开始 / 教程 / 退出三个按钮对应同一个手柄键）。
  - 出处：`[00:24:49]` "所以手柄端这三个按钮的对应的都是一样的你只能按你只能按一个按钮"
  - 证据等级：实测
  - 维度：多端适配⊕

- **平台自带的「匹配游玩」在作品不火时匹配不到人**：想做多人玩法会连玩的人都没有，直接决定项目形态（该团队因此从类似太空狼人杀改成单机解谜）。
  - 出处：`[00:05:28]` "在你的作品不火的情况下你去点那个匹配游玩然后是匹配不到人的"
  - 证据等级：实测
  - 维度：曝光机制⊕

- **千星奇遇对玩家只有「一次性机会」**：进去体验差直接退出来就不会给第二次，直接打差评——引导缺失的代价被这个机制放大。
  - 出处：`[00:22:30]` "尤其是在千星千星因为他一旦退出来就不会给你第二次起飞就直接给你打差评了对不对"
  - 证据等级：经验共识
  - 维度：引导设计⊕

- **上架后的曝光结构**：发布页给玩家的第一印象是「奇域名字 + 封面」，点开后是详情介绍 + 可滑动查看的**五图**，然后才是实机宣发视频。
  - 出处：`[00:07:05]` "然后封面还有接下来的你可以接下来点开之后的话他有个详情介绍然后后面可以拉了几个图它叫做五图"
  - 证据等级：硬规则
  - 维度：曝光机制⊕

## 做法与技巧

- **游戏制作四阶段**：①预制作（写策划案、市场调研、定位玩法）→ ②制作（程序实现 / 美术 / 音效 / 文案）→ ③测试 → ④发布与运营。每个阶段都有对应工种，不是一条直线写代码。
  - 出处：`[00:01:33]` "我我更倾向于把它分为四个流程然后第一个流程的话叫做怎么点不动对叫做预制作阶段"
  - 证据等级：经验共识
  - 维度：项目管理⊕

- **千星特化的团队分工**：策划（含数值策划，兼运营）、程序、美术（最基础的是**地编**：负责地图设计与搭建；要搓 UI 另算）、测试/质量保障、音效（千星不需要）。人多时另设一个「催进度」的负责人保证按时发布。
  - 出处：`[00:08:39]` "美术的话最基本的美术的话就是底边如果你要搓UI的话那另说"
  - 证据等级：经验共识
  - 维度：项目管理⊕

- **烟雾测试（smoke test）四件事，一条一条过**：①游戏能否正常启动 ②基本操作是否正常（移动/射击/装弹，多设备 + 多语言）③基本关卡逻辑是否跑通（敌人能否出现、能否被击杀、敌人能否击杀玩家 = 基本玩法循环）④基本指标反馈是否正常显示（生命值、饱食度等——「有的时候你真的可能自变量就装错了」）。
  - 出处：`[00:13:17]` "然后最后一步的话就是基本指标的反馈特别正常比如说像原神的话生命值就是放了下面一个生命值向当要存量而这类东西能不能被正常显示"
  - 证据等级：经验共识
  - 维度：测试与QA⊕

- **烟雾测试的分工**：电脑端由创作者自己跑完，其他设备端交给测试者过一遍；烟雾测试都过不了的图「绝对会有差评，那玩家就来帮你测了」。
  - 出处：`[00:14:02]` "然后接下来烟雾测试呃一般来说我们说了电脑端的会由创作者完成那么其他设备端的然后你们测一测就好了"
  - 证据等级：经验共识
  - 维度：测试与QA⊕

- **逻辑测试用 checklist**：按策划案/程序实现给出的目标列成表格一条条打勾——每个 UI 打开一遍、UI 同时打开会不会出 bug、有没有连招能把角色卡出地图。
  - 出处：`[00:14:02]` "然后你就一条条测试看这个UI能不能正常打开同时打开U和AIQ会出现bug然后或者有没有一些四法场连招可以不小心卡出地图"
  - 证据等级：经验共识
  - 维度：测试与QA⊕

- **回归测试（retest）流程**：作者发更新日志说修了哪些 bug → 拿到最新版本按原路径再走一遍（例：速通 bug 声明修了，就一进游戏直接点结算，看是不是给「未完成」），各设备单测一遍。
  - 出处：`[00:27:07]` "然后第三个回归测试比如说就是作者说速通bug修了然后我过来看然后我拿到最新版本我一开一进来就点结算然后看能不能给出一个未完成"
  - 证据等级：经验共识
  - 维度：测试与QA⊕

- **bug 提单五字段模板**：①标题概括 ②复现步骤（最正式要从「启动游戏 → 60 秒流程 → 打开 UI → 点放大镜格子 → 背包点不亮」这样写全）③预期情况（按策划案应该发生什么）④实际情况 ⑤严重性/优先级。表单另加：测试者名字（便于统计发福利）、测试日期、设备端、语言。
  - 出处：`[00:17:54]` "然后对于一个对于我们对于呃我在暑假里面干过一件事情叫做我们写给了个bug提单"
  - 证据等级：经验共识
  - 维度：测试与QA⊕

- **严重性分级判据（可直接照用）**：**P-1 = 能速通**（严重性与优先级都最高）；**P0 = 不修不能玩**（如手柄按键完全冲突、引导缺失导致卡关）；**P1 = 能玩但有恶劣影响**（如 UI 重叠但错开的地方还能按到）；**P2 = 修不修影响不大**（如没子弹时短暂显示 -1）。
  - 出处：`[00:17:09]` "最后一个就是严重性和优先级那比如说像现金曲遇如果发现你可以速通那就是p-1"
  - 证据等级：经验共识
  - 维度：测试与QA⊕

- **野路子：简单 bug 跳过提单，直接录屏/截屏甩给程序或作者**——不用填表，作者一看就懂，是最高效的反馈通道。
  - 出处：`[00:20:13]` "那你可以直接录屏录屏最好如果如果你的如果你不知道你的手机怎么录屏的话你可以截屏或者截多个屏然后直接发给对应的程序"
  - 证据等级：经验共识
  - 维度：测试与QA⊕

- **极限情况测试清单（创作者自己绝对测不出来，必须由测试者专门跑）**：跳到物体上飞着下不来、掉进两个物体的缝里、贴墙穿墙、碰撞触发器范围延伸到不该存在的地方（门后要操作的设备，人还在门前就能触发操作选项卡）。
  - 出处：`[00:21:00]` "还有这里举例的碰撞触发器的范围边界有没有延伸到不该存在的地方"
  - 证据等级：实测
  - 维度：测试与QA⊕

- **引导的四条参考标准**：①简洁——用最少的文字传达最多的信息，必要时用图标（原神第一次登录时顶部一个标黄的 W 键提示，按了即消失）②循序渐进——不短时间内教大量操作，逐步接收信息 ③潜移默化——用机制逼玩家学会，而不是弹窗打断 ④代入感——新手教程不脱离世界观。
  - 出处：`[00:32:30]` "我们这里这次给出四个参考标准第一个叫做以简洁啊对于玩家来说的话"
  - 证据等级：经验共识
  - 维度：引导设计⊕

- **潜移默化的教科书做法（植物大战僵尸）**：开局只给 50 阳光 → 只有向日葵是亮的可种 → 玩家自己就把向日葵种下来；后期再用提示强化「开局先种三排一排向日葵」防后期植物不够用。先机制限制、后文字提示，两段式。
  - 出处：`[00:34:49]` "那么它的根方法就是开局我只给你50阳光那开局的时候那就只有向日葵亮着"
  - 证据等级：实测
  - 维度：引导设计⊕

- **「笨拙但有效」的手把手引导可用**：崩坏三前 22 分钟从 1-1 做到 1-4，一步步打断玩家的攻击、强制点进每个 UI 讲用途——缺点是破坏手感、强制性强，但优点是绝对讲清了操作和世界观，「比完全没有引导好」；差劲（什么都没讲清）才是贬义。
  - 出处：`[00:30:56]` "然后你学会了之后冒出来一个僵尸这时候你刚准备打的时候我先打断你然后再打断你"
  - 证据等级：经验共识
  - 维度：引导设计⊕

- **四件套操作引导组合（案例：积木小车大冒险）**：①全程用任务 + 任务点引导，「至少会让玩家知道我接下来该干什么」②教程系统（原神同款，玩家自己点开看）③出现新操作时给一个醒目的大按钮提示可用，并马上安排对应玩法让玩家熟练 ④用长镜头和随处可见的箭头指方向（跳三个蹦床，蹦床旁两个箭头）。
  - 出处：`[00:38:36]` "然后第二个就是他有一个教程系统原神自己也有个教程系统"
  - 证据等级：实测
  - 维度：引导设计⊕

- **引导要先讲基本操作再讲目标**：引导的基本功能 = 告诉操作 + 给出任务目标（开门见山，开局就说「任务目标是救出小月，同时调查真相」）。原神玩家天然会移动，但独立发布的游戏必须写清 WASD/手柄前后左右，否则玩家进去完全动不了。
  - 出处：`[00:40:53]` "引导的基本功能是告诉操作还有给出任务目标那开门见山然后开局就告诉你"
  - 证据等级：经验共识
  - 维度：引导设计⊕

- **文字类（galgame 型）奇域的信息密度**：单句 10~20 字，不要每段弹 100 字——玩家点一下就能读完才会乐此不疲地点下去，一次弹 100 字会觉得疲惫。
  - 出处：`[00:40:53]` "然后他每句话的人物说话并不长那甚至有的时候他甚至不会到20个字然后可能甚至有的时候就是十个字左右"
  - 证据等级：经验共识
  - 维度：D5 表现层

- **状态变化必须外显，不能只藏在日志里**：物品丢失/清晰度升高等变化要用不同颜色的文字提示；饥饿、脱水、受伤等状态优先做成血量条或原神自带状态栏的额外提示，而不是让玩家点开日志才看得见。
  - 出处：`[00:43:59]` "然后所以的话就需要不一样的颜色去告诉玩家里的状态变化"
  - 证据等级：个人经验
  - 维度：D5 表现层

- **无角色限制时必须给默认角色**：经典模式里玩家没有选到角色就进不了游戏，正常做法是给旅行者/奇偶/安柏（解锁千星时必定持有安柏）三个之一；或者把模式改成超限（工作量大）。
  - 出处：`[00:48:45]` "首先他作为一些经典模式然后刚刚已经有人说过了就是他的这个角色性质在没有角色限制的时候他根本进进不了游戏"
  - 证据等级：实测
  - 维度：D4 玩法系统

- **角色技能说明要前置到选人界面或更新日志**：玩家在局内看完技能再退出来重进太繁琐（想搭技能搭配的玩家尤其痛苦），把技能列表摆在外面即可。
  - 出处：`[00:49:31]` "那他是要先进去一趟然后看一看有什么有什么角色的技能然后考虑综合考虑一下然后再出来然后再重新进去这样的这样的情况的话可能就是对玩家来说操作还是太繁琐了"
  - 证据等级：个人经验
  - 维度：引导设计⊕

- **移动端 UI 必须支持纵向滑动**：屏幕小的设备信息显示不全，一开始不能下滑就等于玩家根本看不到完整信息。
  - 出处：`[00:24:49]` "那可能我们刚刚还说到UI你如果你作为手机的话你刚刚你们在玩的时候可能就是信息不全你们需要下滑对不对一开始的时候他是没有办法下滑的"
  - 证据等级：实测
  - 维度：多端适配⊕

- **实战优化建议（可当通用改法）**：元素选择改成悬浮交互页而不是逐个点星；退出按钮点一次不生效的 bug 要在过程中的任何时候都能退出；能量/结算类按钮位置不要依赖左上角小叉。
  - 出处：`[00:46:24]` "我我建议把它都做成悬浮交互页那每个元素选元素就不用除标准星这么麻烦的方式"
  - 证据等级：个人经验
  - 维度：D5 表现层

## 设计经验与教训

- **四个阶段里预制作最重要**：玩法与创新奠定整个游戏的灵魂、世界观构建也在这一步——「你游戏能够打破常规开发新玩法那相信你的热度是不会太差的」，创新要在预制作阶段就定下来。
  - 出处：`[00:51:03]` "那么就像我刚刚说的你的游戏能够打破出打破常规开发新玩法那相信你的热度是不会太差的对"
  - 证据等级：个人经验
  - 维度：项目管理⊕

- **零宣发爆火是特例，不是默认路径**：心跳通讯录质量特别高，作者只发了一个实机 PV 就爆火；其他作品（神圣传说、积木小说大冒险等）都需要投入宣发——做宣发视频、花钱找专业 up 主推流。
  - 出处：`[00:04:42]` "都需要投入你的宣发比如说做宣发视频然后花钱然后花可能花一部分的钱然后找一些专业的up主然后给他推流"
  - 证据等级：实测
  - 维度：项目管理⊕

- **发布后必须做运营闭环**：千星里没有 100% 好评率的作品，要根据差评与好评里的建议持续优化并做热更新（类比原神本体 bug 反馈后的热更）。
  - 出处：`[00:03:55]` "然后最后一部分的话叫做发布与运营就是你游戏做出来之后你得让别人知道吧"
  - 证据等级：经验共识
  - 维度：项目管理⊕

- **测试者除了 bug 还必须给出主观感受**：第一遍玩的直观体验——哪里好、哪里不好、哪个 UI 该更明显、引导好不好、每个 part 是否过长过短。每个玩家的意见（尤其测试阶段）都很宝贵。
  - 出处：`[00:03:55]` "然后每一个玩家的意见尤其是测试阶段的意见都很宝贵"
  - 证据等级：经验共识
  - 维度：测试与QA⊕

- **引导缺失可以判到 P0**：案例中开局 60 秒玩家完全无所适从、不知道物资在哪、无物资开局——程序本身没错（照着步骤走能通关），但引导有问题且受影响玩家多，直接按 P0 处理。
  - 出处：`[00:27:53]` "然后进去刚开始60秒完全无所适从然后无物资开局"
  - 证据等级：实测
  - 维度：引导设计⊕

- **成熟作品的 bug 会变少，但引导问题长期存在**：心跳通讯录早期无法查阅过往记录，玩家只能靠回溯重做一遍，后续版本才补了查看记录的功能——这类「玩家觉得别扭」的问题不修不会自己消失。
  - 出处：`[00:27:53]` "比如说心跳通讯录它一开始的话是没有办法去查阅过往的记录的"
  - 证据等级：实测
  - 维度：引导设计⊕

- **「还有事情没做完」式的提示 = 死档错觉**：案例中玩家第一天不知道有日志，直接点睡觉被提示「还有事情没做完」，以为死档直接给差评——模糊提示要在后面加括号写清「进行什么操作」。
  - 出处：`[00:42:26]` "很多人就之前给出的测试的时候很多人就是第一天就是不知道有日志这个东西然后在那点睡觉然后告诉你还有事情没做完然后就觉得死档了然后直接跳出来给差评"
  - 证据等级：实测
  - 维度：引导设计⊕

- **信息要「先讲清楚，再变简洁、变不强制」**：优化顺序不能颠倒——先把话说清楚（基本操作 + 阶段目标），再删字、去强制；否则只是把玩家搞晕。案例：远古版本任务图标看不出变量在哪，玩家只能乱找，改进方式是在那里放个光点或优化美术让玩家一眼认出是避难所。
  - 出处：`[00:43:13]` "那接下来就是第二步那在保证你做抢清楚之后再强制显得不变得很简洁变得不强制"

  - 维度：引导设计⊕

- **文案功底不能在文案上敷衍**：剧情类/文本占比高的奇域，文案是核心体验的一部分（该案例剧本被点名表扬）。
  - 出处：`[00:02:19]` "如果你是剧情类或者是里面文本占比很重要的一部分的话你的文案功就是这写文案的人文案功底这这这功底还是也是需要的"

  - 维度：D5 表现层

- **测试者遇到「不符合习惯」先别怀疑自己**：玩家觉得别扭往往就是创作者的问题，直接反馈就行（案例：千星右上角抽卡入口从非原石形状改成类似原石形状后，大世界玩家一看就懂）。
