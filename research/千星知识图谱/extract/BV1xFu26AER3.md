## 规则与机制

- **UI 图片格可以引用"动态文本域"，动态文本域只取列表里的某一个值——所以只要更新列表对应位置的值，对应区域的图片表现就变；作者的整张棋盘 UI 就是 1 个 70 格列表驱动的 70 格图片。**
  - 出处：`[00:01:40]` "它的地图总共用是一个七是70格的一个列表然后他引用的是一个动态文本域动态文本域就是说我列引用的是列表里的某一个值"
  - 证据等级：实测
  - 维度：D5 表现层

- **空白的格子必须占位：没图的位置也要往列表里填一个 0 把位置占住，否则后面的元素会往下排导致错位。**
  - 出处：`[00:03:13]` "我就是也要给他列表一个零的值啊然后把那个位置占住不然的话你不占住它就会往下排就会出问题"
  - 证据等级：实测
  - 维度：D1 概念模型

- **UI 必须分层（底层机关层 + 角色移动层，另有三层技能层）：只做一层时，角色走到机关格上会把那一格的机关刷新掉。**
  - 出处：`[00:02:27]` "如果一层的话我移动过去就我移动过去我底下那层会被它刷新掉就我角色走到那个机关上然后我的机关会被刷新走"
  - 证据等级：实测
  - 维度：UI框架⊕

- **状态层级数不能为 0：用状态传位置这类整数参数时要先 +1 再传，取值时 -1 还原。**
  - 出处：`[00:11:01]` "因为它的因为我的这个值不能为零嘛所以我那边传的时候我会把那个位置进行一个加一然后在这边解的时候在这边拿的时候我进行一个减一"
  - 证据等级：实测
  - 维度：D3 逻辑编写

- **添加状态与"是否能读到这个状态"之间有延迟（作者说有几秒）：所以高频按四个方向键时位置会拿串、角色乱窜，这个高频交互问题无法靠状态完全解决。**
  - 出处：`[00:13:22]` "我虽然执行了添加状态但是我下一个拿的时候它他大概有个几秒的延迟我才能去判断这个状态是不是添加了"
  - 证据等级：实测
  - 维度：D3 逻辑编写

- **永久持续的状态必须手动移除：一旦漏移，它会一直重复添加，添加两三次之后"添加状态"事件就不再触发了。**
  - 出处：`[00:14:57]` "那么我如果移除的状态是一个移除错了啊没有移除掉这个状态那么它就会一直添加那么添加两三次之后他这个添加状态就不会触发这个事件了"
  - 证据等级：实测
  - 维度：D3 逻辑编写

- **在客户端移除单位状态，服务端侧的"单位状态结束"是 100% 不触发的。**
  - 出处：`[00:14:57]` "我们在客户端移除这个单位状态它的服务端的单位状态移除是百分之百不触发的"
  - 证据等级：硬规则
  - 维度：D3 逻辑编写

- **技能变量是纯客户端的：本端一改，对应客户端马上就能判断到（跟服务端没有关系），适合做客户端本地 CD。**
  - 出处：`[00:13:22]` "因为技能变量他是我这边改了我那边就是马上就拿到的因为跟客户都没有关系"
  - 证据等级：实测
  - 维度：D3 逻辑编写

- **高频刷新 + 事件全部写在服务端会"炸"：不仅负载高，响应也差、手感也差——这类 UI 游戏要转到客户端节点图。**
  - 出处：`[00:03:13]` "你们如果全写在服务端它是会炸弹的不仅炸弹的响应也差手感也差那么这个时候我们就需要用到它的客户端了"
  - 证据等级：实测
  - 维度：性能与负载⊕

## 做法与技巧

- **【邪修】用"添加状态"代替"发送信号"来传整数参数：发送信号太频繁会一直堆积、会炸；而状态可以携带一个整数参数（用状态的层数当参数），把位置 +1 塞进去、取出来再 -1。**
  - 出处：`[00:10:14]` "如果我是用一个发送信号那发送信号太频繁了就一直发送一直发送一直发送那么它他的堆积会很多就它里面堆积会很多会炸"
  - 证据等级：实测
  - 维度：D3 逻辑编写

- **【邪修】用"特效播放器"播一个空特效来放音效：这个特效本质上只是一个音效，播特效就等于播音效——顺手在客户端就播掉了，不需要再走服务端。**
  - 出处：`[00:20:29]` "我的这个特效它本质上只是一个音效而已就是说我只要掉我只要播这个特效就等于是播音效啊唉这也是一个呃好用的方法"
  - 证据等级：实测
  - 维度：D5 表现层

- **【技巧】做"信号分发中心"（二次分发）：移动等事件先统一丢给一个"中转站"技能，再由它按机关/技能类型查表把信号二次分发到各功能技能。不要把事件和信号全堆在一张节点图里——那样会堆得很多、很难阅读。**
  - 出处：`[00:06:22]` "我不可能把所有的事件所有的信号写到一一个技能里面那样子他会堆的很多而且很很难很难理解很难阅读"
  - 证据等级：个人经验
  - 维度：UI框架⊕

- **【技巧】分发用查表法：循环遍历信号列表 → 用移动后的位置查这个位置的机关类型/事件 → 命中后把该值当键去查技能 id → 释放指定技能 → 跳出循环。**
  - 出处：`[00:07:08]` "循环就是说我有几个信号每个信号去查一下我这个信号是否包含因为我移动之后它有个位置嘛然后我去查了他这个机关的类型"
  - 证据等级：个人经验
  - 维度：D3 逻辑编写

- **【技巧】移动 CD = 技能变量 + 状态回调：添加技能变量（CD 标记）的同时添加一个状态；状态被调用（走完）时把技能变量置空，就代表冷却结束、完成一次消解重置。**
  - 出处：`[00:14:08]` "我在添加这个技能变量的时候我同时添加了一个状态看到没有他如添加这个时候同时添加了一个状态然后然后当那个状态被调用的时候就状态被调用的时候就那个状态被调用的时候我就是会执行这个技能"
  - 证据等级：实测
  - 维度：D3 逻辑编写

- **【技巧】用"职业"做多玩法隔离：每个职业挂各自的节点图（例：扫雷玩法一个职业，走的是生成地图+扫雷规则+多端适配的逻辑），切职业即切玩法，互不干涉；要加新玩法就新建一个职业。**
  - 出处：`[00:16:29]` "我会进行一个职业的切换它职业一切换那么它里面走的节点图就是我这个职业里面的节点图就是不会跟其他的有所干涉"
  - 证据等级：实测
  - 维度：D4 玩法系统

- **【技巧】用列表做局内存档：只要列表里的信息不动就保存住了；玩家 ESC 退出后再继续游戏不需要重新加载地图，只要把列表里的值重新赋给他/整体换掉这个列表。**
  - 出处：`[00:18:55]` "因为我们是用列表保存的那么我们继续游戏他不需要重新加载不需要重新加载地图他只需要重新把你的列表里的那个值赋给他"
  - 证据等级：实测
  - 维度：D4 玩法系统

- **【技巧】把高频重复的节点封装成复合节点（例：对列表设置值）：不封复合节点时标识不易辨识、看多了看花眼，封装后一眼能识别、后期好改。**
  - 出处：`[00:12:33]` "我为什么分个复合节点呢因为是队列表直射者不封复合节点的话它的标识不一样嘛但我一看就能看到"
  - 证据等级：个人经验
  - 维度：D7 工程化工具链

- **【技巧】地图生成用列表配置驱动：每个关卡在初始化信息列表里存好配置，元件被创建时读这个列表来生成地图（游玩时表现为加载进度条的地图生成）。**
  - 出处：`[00:17:15]` "我这个上面它每一关他是有很多变量的比如说初始化信息啊大家可以看到我的列表一个配置初始化的信息就是说我这个被创建的时候我会拿到这里面的信息进行一个地图的生成"
  - 证据等级：实测
  - 维度：D4 玩法系统

- **【技巧】多端适配：给手机端玩家补一套方向键（手机点屏幕不好点），再用信号转发把操作转给主逻辑。**
  - 出处：`[00:16:29]` "还有一个多装适配就是手机端的那个按键嘛因为他点那个可能不太好点然后给了他一个移动方向键"
  - 证据等级：个人经验
  - 维度：D5 表现层

## 设计经验与教训

- **UI 游戏有结构优势：玩家没有操作（不能移动角色、没什么技能），正好把这些算力让给客户端高频刷新和事件处理。**
  - 出处：`[00:03:13]` "发挥我们UI的一个前线我们UI游戏它是没有他是没有玩就玩家是没有什么操作的就玩家不能移动这个角色啊没有什么技能发挥我们的强项"
  - 证据等级：个人经验
  - 维度：UI框架⊕

- **框架化的收益要提前想到：一套做对的基础框架可以复用给扫雷，之后还能接着做 2048、蜘蛛纸牌这类 2D 小游戏。**
  - 出处：`[00:15:43]` "还有一个就是说其他的玩法就是扫雷或者之后可能会做2048蜘蛛子牌子这些奥迪的游戏"
  - 证据等级：个人经验
  - 维度：UI框架⊕

- **踩雷复盘：状态传参是高负载场景下的权宜之计，不能根治高频交互——高频按方向键仍会位置拿串，作者最终是用客户端技能变量做 CD 兜底。**
  - 出处：`[00:12:33]` "移动玩家四个按键如果高频按的话它是会有一个就乱窜的因为位置会拿串掉他无法完全解决这个高频交互的问题啊"
  - 证据等级：实测
  - 维度：性能与负载⊕

- **音频要做成玩家可调：每个人对音效的需求不一样，所以作者专门做了音频调整（机关、音效分类）；不需要区分时就直接在客户端播特效解决。**
  - 出处：`[00:19:42]` "我感觉我觉得嗯有音频可能大家每个人需要都不一样所以做了一个音频调整这机关音效每个区分的音效"
  - 证据等级：个人经验
  - 维度：D5 表现层
