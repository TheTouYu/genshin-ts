## 0. 一句话结论

**180 条可上屏文案**（四角色 44 / 45 / 44 / 46），最长一句 **21 字**（规范上限 24），
四角色口吻零重复（cast 首条、首条标签、全部 cast 句集合三查全过），
机检 `224/224` 全绿；另每人备 **10~12 句台词**（原版角色页只渲染 2 句，见 §5）。

改动前的问题（用户视角）：「台词只有 2 句 + 被动读起来像系统说明 + 四个角色一个味」。
v6.0 对症三处：**每人 10~12 句台词池**、**说明改成角色在说话**、**声线卡量化到句法层**（见 §3）。

实测读数（2026-10-29）：

```
luac -p                                  → exit 0（无输出）
dofile                                   → v6.0  纳西妲  少女
tests-lua/copy_audit.lua                 → ALL GREEN  224/224 assertions passed
M.audit()                                → total=180 maxLen=21 over=0 ok=true
                                           perRole = 44 / 45 / 44 / 47（girl 含 holdN）
```

`copy_audit.lua` 分了 10 组断言，逐组对应一条判据（不是笼统「能跑」）：

| 组 | 核什么 |
| --- | --- |
| A | 模块能装载、版本、别名（columbina/少女/哥伦比娅 → 同一张表）、元素与称号事实 |
| B | 导出契约 23 个字段一个不缺（main 在读） |
| C | 条数达标（cast/hold/settle/level ≥3、help/tips ≥3、idle ≥2、fail 三因各 ≥3、quotes ≥8） |
| D | 每条 ≤24 字（含标签——标签会进标题栏） |
| E | 无开发词（系统/玩家/数值/策划/程序） |
| F | 角色区分度：cast 首条、首条标签、全体 cast 句集合，三项零重复 |
| G | 角色口吻：每人 ≥6 句台词带第一/第二人称 |
| H | 运行时：轮播不连出同句、fail 数字向上取整且无残留 `{n}`、hold 收尾句、settle 三分支、sayList 撑满 8 句 |
| I | 模块内置 `M.audit()` 自身可信（真机 `print` 的就是这组数） |
| J | **main.lua 消费路径冒烟**：照 main 的 7 处真实调用形态逐个跑（主题色/名字/技能名、技能反馈五 kind、持续期 left 8→0、charData 的 blocks 循环、help/tips、详情页 element·title） |

> 注：G 组是这一轮真起作用的判据——首版有 3 个角色只有 4~5 句带人称，被它拦下后
> 改了 13 句（例如纳西妲「天空在说：睡觉时间到了哦。」→「听见了吗？天空说：该睡觉了。」，
> 用的是她官方口癖）。**判据写得具体，才拦得住「像说明文」这种退化。**

## 5. 未闭合项（谁该接手）

1. **角色页台词区目前只显示 2 句 —— 病根在 main.lua，不在文案库。**
   证据（行号级）：
   - `lua/main.lua:4272-4277`：`charData` 只从 `cast / hold / settle` 三块各取
     `math.min(2, #t)` 条塞进 `says`（最多 6 条）；
   - `lua/main.lua:4421-4422`：`R.pSay` 只渲染 `d.says[1]`、`R.pSay2` 只渲染 `d.says[2]`。
   ⇒ 即便文案库每人有 10~12 句，页面上仍然只有 2 句。**文案侧已备好接入点**：
   ```lua
   -- main.lua 里把 charData 的 says 改成读台词池（n = 页面上想放几句）
   d.says = {} ; for _, it in ipairs(CP.sayList(role, 8)) do d.says[#d.says+1] = it.body end
   ```
   改 `main.lua` 不在本次写权限内（边界：只写 copy.lua / copy_audit.lua / 本文件）。
2. **天赋（被动）文案尚未落库**：`docs/v6-talent-design.md` 在本轮交付时还不存在
   （`talent-designer` 未产出）。落地方式建议：设计定稿后按
   `passive = { {key, name, desc, quotes?}, ... }` 追加到对应角色块，**不新增全局函数**；
   文案库这边预留的就是「字段只增不删」这条契约，加 `passive` 不会破任何调用方。
3. **help/tips 里的数字是快照**，出处 `lua/tetris/skills.lua` 的 `M.NUM`
   （CD 25 / 7.5→4.5 / 12 / 17，TAKE_DUR 6~10，LAYERS 2~4，COST 60，ENERGY_REGEN 6）。
   平衡一改，这两组要同步改——机检 D 组只核字数，核不到数字对不对，**这一项靠人**。
