**不要做的事**（这些坑都踩过，见 `docs/v2-feedback-retro.md` C13/F4/G5）：

### 1.2 容量怎么算出来的（公式 + 官方字号规范）

**横向**：`容量 = floor((控件宽 - 4) / fontSize)`，CJK 字宽**恰好 = fontSize**（实测 `measureText('国')@13px = 13.00`）。
控件宽来自 `lua/main.lua:4068-4112` 的 `layout()`：左栏 `panelW=420`（hint 420 / best 420 / keyA-C 420）、
`hud` 460、右栏 `hudNext` 200、两个横幅 `W-180`（1280 画布 = 1100）、结算面板 `cw-60`。

**纵向**：`框高 ≥ fontSize × 1.45 + 4`，否则整行静默不画（`lineHeight=1.2×size` + `blockInset=0.25×size+4`）。
这条决定了「横幅只能放一行」：下横幅框高 48，22 号单行需 35.9 ✓，两行需 62.2 ✗。

### 1.3 三个渲染通道 + 层序铁律（写文案前必须知道）

| 通道 | 能放什么 | 硬约束 |
| --- | --- | --- |
| **服务端 textbox**（`hud/best/hint/keyA-C/hudNext/topBanner/botBanner`） | 1 行短句 + 数字 | 层级**永远低于**运行时实例 ⇒ 落在棋盘区域会被吃掉；框高/宽不满足就静默丢字 |
| **运行时实例文字**（`MS.addText` / `HUD_INST.txt` / `settleExtra` / `CNT`） | 长句、轮播、大字 | 标题屏**只能**走这条（服务端 textbox 被 `MS.addCell('menuWall*')` 展台墙压住）；`SetVisible` 隐藏**不生效**，只能销毁 |
| **结算层**（整棵实例化的容器） | 结算标题/分数/明细/旁白 | 颜色必须走 `g.settleNoteRGB` + `settleSetColors`，否则每帧被统一色刷掉 |

**三条判据**（任一不满足 = 用户看到的是空白，不是报错）：
1. 框高 `h ≥ size×1.45+4`；
2. 文案显示宽 ≤ 控件宽 − 4；
3. 常驻位同一时刻只有一条 —— 上/下横幅各 1 条，`bannerTimer > 0` 时新提示必须让位（局内）/ 排队（结算）。

## 2. 文案总表

> `文案` 列可直接塞进 Lua 双引号字符串：**无引号、无换行、无颜色符**；需要变色时按 §8 另设 `color` 字段。

> 超容量的行**在备注列给短版**（本文已全部压到容量内：脚本核验 **0 条超容**，见 §9.1）。
> `重复`：`一次` = 整个存档只出一次；`冷却N` = 距上次 ≥N 秒才能再出；`局1` = 同一局只出一次。
> `优先级`：数字越小越优先；同一时刻只显示一条时，**小的赢**。

## 7. 不重复原则（一次性 vs 可重复）

### 7.1 三档语义（表里 `重复` 列就是这三档）

| 档 | 语义 | 存活范围 | 例子 | 落地要求 |
| --- | --- | --- | --- | --- |
| `一次` | **整个存档只出一次**（跨局、跨重开、跨回标题） | 永久（存盘可选） | 首次消行提示、首次触屏引导、首块锁定 | 必须持久化，否则每次开局都重播 = 玩家最烦的那种「新手提示」 |
| `局1` | **同一局只出一次**（重开或换模式即重置） | 单局 | 新纪录、顶死旁白、满级台词 | 挂在「开局初始化」里清 |
| `冷却N` | 距上次显示 ≥ N 秒才能再出 | 滑动窗口 | 消行台词 6s、危险预警 8~12s | 与**同条**冷却，不与其他条共享 |

### 7.2 实现建议（一个 used 表 + 一个冷却表；伪代码，供工程师改写）

```
-- 状态（挂在局表 g 上，别新增文件级 local：main.lua 的 200 local 上限已满）
g.copyUsed  = {}        -- ["guide_clear"] = true        （一次 / 局1 共用；"局1" 的键在 newGame 时清空）
g.copyCool  = {}        -- ["clear_1"] = elapsed + 6     （到点前不再显示）

-- 取文案前先过闸：三道闸按顺序短路
function copyPick(key, kind, cool)
  if kind == 'once' and saveUsed[key] then return nil end   -- 永久档
  if kind == 'round' and g.copyUsed[key] then return nil end -- 单局档
  if g.copyCool[key] and g.elapsed < g.copyCool[key] then return nil end
  g.copyUsed[key] = true
  if cool and cool > 0 then g.copyCool[key] = g.elapsed + cool end
  return CFG.COPY[key]
end
```

**三条纪律**：
1. **一个 used 表、一个冷却表**，不要每条文案各写一个 `local taughtXxx`（现有代码已有
   `g.taughtLock` / `g.taughtClear` 两个先例，再添 20 个就把命名空间吃光了）；
2. **冷却用游戏内 `g.elapsed`，不用 `os.time`**（暂停时 `g.elapsed` 不走，玩家开帮助页回来不会被「冷却已过」突袭）；
3. **同场景多条文案的轮换用 `idx = (idx % #list) + 1`**，写在 `showGameOver` 旁白轮播已经用过的那个模式上
   （`g.settleNoteIdx`），别新造轮播器。

## 8. 颜色与「不要用行内标签」的说明

**重要纠正**：本引擎**不支持** `<color=#XXXXXX>` 这类行内富文本标签。颜色是**控件属性**：
`trySet(ctl,'fontColor', C(a,r,g,b))`，config 里写 `color = C(255,127,207,106)`。
所以本文所有文案**不含任何颜色符**；需要一句话里两种颜色时，只能**拆成两个控件**（例：`settleExtra` 旁白 +
`settleOpts` 选项）。若上游要求写成 `<color=…>` 形式，请先确认引擎是否新增该支持；目前没有（`main.lua` 里
全部颜色注入都是 `fontColor` 属性赋值，0 处标签解析）。

| 角色/语义 | 现成常量 | 值 | 用在 |
| --- | --- | --- | --- |
| 纳西妲（草） | `D_LEAF` | `#7FCF6A` | 她的台词、casual 主题强调 |
| 刻晴（雷） | `D_BOLT` | `#B39BEA` | 她的台词、ai-battle 主题 |
| 甘雨（冰） | `D_ICE` | `#8FD8F0` | 她的台词、coop 主题 |
| 少女（樱） | `D_PETAL` | `#FFA8C8` | 她的台词、pvp 主题 |
| 旁白/说明 | `THEME.textSub` | 墨色次字 | `title.note`、结算旁白 |
| 数值/成就 | `THEME.gold` / `goldDeep` | 描金两档 | 新纪录、满级、B2B |
| 警告 | `THEME.hint` + 自定义红 | — | 危险预警用**上横幅 + 红**（现有 `showGameOver` 兜底横幅就是这么干的） |
| 系统 | `C_TEXT` | 主字色 | HUD、按钮、系统状态 |

**结算层特例**：`settleExtra` 的颜色每帧被 `settleSetColors(a)` 统一刷，必须**先**写
`g.settleNoteRGB = {r,g,b}` 再让 `settleSetColors` 读它（v3.2 已修，新条目沿用同一通道，不要另开）。
