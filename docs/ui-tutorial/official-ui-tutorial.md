##### 一、界面控件是什么

界面控件是指设计和实现[界面布局](https://act.mihoyo.com/ys/ugc/tutorial//detail/mhozt0r74ng6)的各种文本框、图标或特殊功能的基础资产

##### 二、界面控件的特点

每一种界面控件都有其特定的功能，可在后续介绍中查看。

界面控件可以直接配置在界面布局默认生效，也可以编辑为界面控件组模板使用。

界面控件的运行显示依赖界面布局。

##### 三、界面控件的分类

界面控件分为_固有界面控件_和_预制界面控件_

固有界面控件是关卡运行时不可缺少的流程型控件，或与业务关联的功能型控件

预制界面控件提供原子化的界面资产，可以进行编辑修改和自定义组合，来构成更加定制的界面控件组

###### 1.固有界面控件

###### (1)固有界面控件的概述

固有界面控件是界面布局的默认包含的控件，大部分和业务逻辑相关，例如选项卡控件，需要通过选项卡组件进行调用。

不支持移除，不可移动，不可调节尺寸，仅支持少量编辑配置。

部分固有控件支持调整可见性。

###### (2)固有界面控件的引用

在界面布局中会默认存在的控件，无需主动添加

部分固有界面控件会在关卡运行时默认存在，部分固有界面会通过业务按需调用

##### 四、界面控件的渲染模式

在月之五及之前的版本中，界面控件的渲染仅和创建时序有关，层级参数并未生效。在月之六版本我们对其进行了修复，并提供了两种渲染模式，分别为【时序渲染(旧)】和【层级渲染(新)】，可以在界面控件组管理中图示位置点击进行切换

[图]

**时序渲染(旧)**：原有的渲染逻辑，该模式下将按照“界面控件”创建时序进行渲染。月之六版本更新前创建的关卡存档、已发布的关卡均默认为该模式。如果需要对控件进行修改，那么新增的控件可能会出现层级显示的问题，建议切换到【层级渲染(新)】模式；如果不需要对控件进行修改，可以保持该模式

**层级渲染(新)**：月之六版本新增的渲染逻辑，该模式下“界面控件”将会按照层级配置顺序进行渲染，支持对界面控件层级进行调整。月之六版本更新后新创建的关卡存档将默认为该模式。如果需要对旧存档的控件进行修改，或者需要创建新的存档，建议选择该模式

此外，请注意后续版本将不再维护新增控件在【时序渲染(旧)】模式的表现，建议奇匠们在月之六版本更新后均使用【层级渲染(新)】模式进行制作

【时序渲染(旧)】模式切换到【层级渲染(新)】模式后，推荐的修复方式



检查层级配置，层级越大越靠上；同层级的会按照创建时序排列，后创建的在上



层级渲染模式下，界面布局中的控件层级低于界面控件库中激活的控件层级，若原先是通过节点的创建时序实现主屏控件显示在控件模板上层的话，推荐都转为控件模板，然后通过层级配置实现

#### ★ 界面控件组

##### 一、界面控件组的定义

_界面控件组_是创作者(奇匠)对界面控件的自定义数据。

界面控件组是对单个/多个预制_界面控件_，进行组合、编辑参数后保存的数据。

界面控件组包括单个界面控件组，组合界面控件组两种。

[界面控件](https://act.mihoyo.com/ys/ugc/tutorial//detail/mhnapxrumtzy)指用于设计和实现[界面布局](https://act.mihoyo.com/ys/ugc/tutorial//detail/mhozt0r74ng6)的各种资产

##### 二、界面控件组的编辑

界面控件组模板可以直接引用于_界面布局_的配置，也可以通过节点图管理。

组合界面控件组可以通过界面控件组组合统一管理，也可以对包含的单个界面控件做状态管理。

###### 1.命名和索引

在_界面控件组库管理工具_中，每个界面控件组都有其索引，作为节点图的入参

界面控件组模板的组合、组合内控件，都有自己的索引进行标识

###### 2.界面控件组状态

(1)界面控件组_状态_： **激活、未激活**



激活 存在于界面布局，可通过节点图管理表现状态



未激活 不存在于界面布局，不可操作表现状态

(2)已经激活的界面控件组_表现状态_： **开启、关闭、隐藏**



开启，界面控件组可见性开启。

隐藏状态到开启状态，将界面控件组可见性开启。

关闭状态到开启状态，将界面控件组重新初始化，并开启可见性



关闭，界面控件组可见性关闭，并且不保留动态改动的信息

关闭后开启的界面控件组，表现和数据都会初始化



隐藏，界面控件组可见性关闭，并且保留动态改动的信息

隐藏后开启的界面控件组，表现和数据都和隐藏前的一致

##### 三、界面控件组的管理

###### 1.以界面布局引用

在界面布局中引用的界面控件组模板，默认随界面布局一同激活。不可对状态修改，仅可对表现状态做调整。

###### 2.以节点图管理

### 3.1 UI 制作全景图

**能做什么（官方原文）**：
- 用**界面布局**承载玩家运行时的信息获取与交互操作界面；每个玩家有且仅有一个生效的界面布局。
- 用**界面控件**（文本框、图片、按钮、进度条、计时器、计分板、弹窗、卡牌选择器、动效、悬浮交互页、特殊数字、状态显示区、消息队列、自定义小地图等）搭建 UI。
- 用**界面控件组**把单个/多个控件组合、编辑参数后保存为可复用模板；可被界面布局引用，也可由节点图运行时激活/移除。
- 用**节点图**按玩家维度控制布局切换、控件组激活/移除、控件表现状态，并接收按钮类交互事件。

**前置/资源（官方原文）**：
1. 在编辑器左上角系统菜单打开【界面控件组管理】（`mhewyi0fjfvs`）。
2. 界面布局库不可为空，最少有一个“默认布局”。
3. 预制控件通过【添加界面控件】引用到界面布局，或在界面控件组库中组合成模板；保存为模板后获得**索引**（节点图入参）。
4. 玩家默认使用的界面布局通过**职业 → 选择布局**配置（经典模式无“职业”时如何配置待核验）。
5. 控件 ID / 索引：界面布局与控件组中的每个控件/组合都有唯一**索引**，节点图用整数索引引用。
6. 素材库：自定义按钮/开关/悬浮交互页/页签/单选项视窗/图片控件可引用素材库资源；素材组支持遮罩。

**节点/组件速览（官方原文 + 知识库）**：

| 类型 | 名称 | 归属端 | 关键参数 |
| --- | --- | --- | --- |
| 执行 | 切换当前界面布局 | 服务端 | 目标玩家（实体）、布局索引（整数） |
| 执行 | 激活控件组库内界面控件组 | 服务端 | 目标玩家（实体）、界面控件组索引（整数） |
| 执行 | 移除控件组库内界面控件组 | 服务端 | 目标玩家（实体）、界面控件组索引（整数） |
| 执行 | 设置界面控件(组)状态 | 服务端 | 目标玩家（实体）、界面控件(组)索引（整数）、显示状态（枚举：关闭/开启/隐藏） |
| 查询 | 获取玩家当前界面布局 | 服务端 | 入参：玩家实体；出参：布局索引（整数） |
| 事件 | 界面控件组触发时 | 服务端 | 出参：事件源实体、事件源GUID、界面控件组组合索引、界面控件组索引 |

**事件（官方原文）**：
- 只有 **交互按钮、道具展示、自定义按钮、自定义开关** 的界面控件会触发「界面控件组触发时」。
- 该事件只有触发交互的**玩家**节点图可以获取；节点图需挂载在**玩家**身上（FAQ 明确）。
- 目前没有弹窗/其他控件单独“开启/关闭”事件（FAQ）。

**常见流程（官方原文）**：
1. 信息类 UI：界面布局 → 【添加界面控件】→ 文本框/图片/进度条/计时器/计分板 → 配置文本或变量 → 玩家运行即显示。
2. 交互类 UI：添加交互按钮/道具展示/自定义按钮/自定义开关 → 保存为界面控件组模板（获得索引）→ 玩家节点图监听「界面控件组触发时」→ 通过出参索引区分控件 → 执行后续逻辑。
3. 运行时显隐/激活：节点图用「激活控件组库内界面控件组 / 移除控件组库内界面控件组 / 设置界面控件(组)状态 / 切换当前界面布局」控制。
4. 多设备适配：界面布局与控件均按设备（PC/移动/主机/手柄）分别设置位置、大小、锚点；移动端 16:9 作为死区基准。

**注意事项（官方原文 + FAQ）**：
- 固有界面控件不可移除、不可移动/调尺寸，部分仅支持可见性。
- 界面布局中引用的控件组默认随布局激活，只可调表现状态，不可改状态。
- 关闭 = 可见性关闭且不保留动态改动（重开会初始化）；隐藏 = 可见性关闭但保留动态改动（重开恢复原样）。
- 计时器控件只能读取关卡实体（LevelEntity）与玩家身上的计时器组件，读不到其他实体上的全局计时器。
- 文本框支持 `\n` 换行与 `<color=颜色>文本</color>` 改色。
- 渲染模式：官方推荐使用【层级渲染(新)】；旧存档默认【时序渲染(旧)】，后续版本不再维护新增控件在旧模式下的表现。

### 3.2 UI 相关服务端节点速查（官方节点文档原文）

> 来源：`miliastra-knowledge get_node_info`，节点出处分别为《执行节点》《查询节点》《事件节点》官方章节。

- **切换当前界面布局**（执行，服务端）：通过布局索引切换目标玩家当前的界面布局。参数：`目标玩家`（实体）、`布局索引`（整数）。
- **激活控件组库内界面控件组**（执行，服务端）：在目标玩家的界面布局上激活界面控件组库内以自定义模板形式存在的界面控件组。参数：`目标玩家`（实体）、`界面控件组索引`（整数）。
- **设置界面控件(组)状态**（执行，服务端）：通过界面控件索引修改目标玩家界面布局内对应界面控件的状态。参数：`目标玩家`（实体）、`界面控件(组)索引`（整数）、`显示状态`（枚举：关闭=不可见且逻辑不运行；开启=可见+逻辑正常运行；隐藏=不可见+逻辑正常运行）。
- **移除控件组库内界面控件组**（执行，服务端）：移除已通过「激活控件组库内界面控件组」激活的界面控件组。参数：`目标玩家`（实体）、`界面控件组索引`（整数）。
- **获取玩家当前界面布局**（查询，服务端）：获取指定玩家实体当前生效的界面布局索引。参数：入参 `玩家实体`（实体），出参 `布局索引`（整数）。
- **界面控件组触发时**（事件，服务端）：只有交互按钮、道具展示、自定义按钮、自定义开关触发；只有触发交互的玩家节点图可获取。出参：`事件源实体`、`事件源GUID`、`界面控件组组合索引`（多控件组合时才有值）、`界面控件组索引`（单控件组=该组索引；多控件组=组合内该控件的索引）。

### 3.3 官方 FAQ 要点（界面控件组编辑）

> 来源：官方 FAQ `mhuj5600xfhk`（知识库镜像）。

1. 文本框支持 `\n` 换行；支持 `<color=颜色英文>正文</color>` 换色。
2. 目前没有弹窗/其他控件被开启/关闭的单独事件。
3. 计时器控件只能读取关卡实体（LevelEntity）以及玩家身上的计时器组件信息；要读全局计时器，请挂到关卡实体或玩家身上。
4. 「界面控件组触发时」只监听特定玩家的点击；节点图需挂载在【玩家】身上且应用给目标玩家。
5. 卡牌选择器的“重置”按钮需要挂载节点图来实现功能；没有对应节点图时默认直接关闭卡牌选择器弹窗。
6. 卡牌选择器目前只可添加到界面控件组库，不支持直接添加到界面布局。

创作者手柄适配引导

在千星沙箱界面控件组管理中，开放了四种界面布局适配方案供奇匠配置，根据不同平台和设备，交互方式和特点也有所不同：

|     |     |     |
| --- | --- | --- |
| 平台 | 交互方式 | 限制与特点 |
| 触屏（移动端） | 触屏交互 | 可以直接点击屏幕内任意位置的界面控件，相较键鼠没有悬停交互，没有快捷键，相较PC端屏幕空间较小 |
| 键鼠（PC） | 鼠标指针点击/拖拽+键盘快捷键交互 | 可以直接点击屏幕内任意位置的界面控件 |
| 手柄（主机） | 焦点导航+快捷键交互，指针交互模式可用但操作不便，不推荐使用 | 只能与手柄导航焦点所在的控件，或配置了手柄快捷键的界面控件进行交互，快捷键相较键鼠更少 |
| 手柄（移动端） | 焦点导航+快捷键交互，指针交互模式可用但操作不便，不推荐使用 | 只能与手柄导航焦点所在的控件，或配置了手柄快捷键的界面控件进行交互，快捷键相较键鼠更少，屏幕空间更小 |

可以看到，手柄与其他端交互方式的差异决定了在设计手柄界面交互时，需要采取一套不同的设计方法，本文将为奇匠简单介绍手柄端适配设计的思路和常用方法。

##### 一.认识手柄导航

###### 1.支持手柄导航的控件

_交互按钮，道具展示，自定义按钮，自定义开关_ 这类可交互的界面控件被添加至悬浮交互页内时，会额外提供【手柄导航】的配置，此外： _页签，单选项视窗，文本视窗_ 这些仅能在悬浮交互页中使用的控件，也支持【手柄导航】的配置。

[图]

###### 2.手柄导航提示

如图所示，在交互悬浮页控件中，左下框内类型的控件可以被设置为手柄导航的对象，若希望控件能够被手柄摇杆导航选中，可开启“可被手柄导航选中”开关。

控件在成为手柄导航对象后，会以图中的箭头提示，可以选择导航提示箭头的样式，朝向以及位置偏移。

[图]

###### 3.手柄导航的规则

可以通过图示中 向左/向右/向上/向下 的参数，指定当手柄导航焦点位于当前控件时，玩家向左/向右/向上/向下推动摇杆后，希望焦点移动到的目标控件对象。

默认导航规则为：移动到当前摇杆方向上中心点距离最近的控件。

可通过控件列表指定希望跳转到的控件对象，或者不进行跳转。[图]

###### 4.导航焦点与按键

除页签，文本视窗外的控件在成为手柄导航的对象时，均能够响应固定确认按键[图]或[图]（取决于玩家的系统按键设置），若控件自身额外配置了快捷键，则还能同时响应手柄快捷键。

##### 二.手柄端适配设计准则

奇匠在进行手柄端的界面交互设计时，可以按照以下几条准则进行设计

**焦点导航为主，手柄快捷键为辅：**

手柄的快捷键数量有限，在界面控件较多的界面中，为每一个控件设置一个单独的快捷键是不现实的。

推荐奇匠将手柄快捷键分配给界面中的重要功能，其他控件的交互则主要通过配置手柄焦点导航实现。

**推荐对功能进行分区和收纳：**

由于手柄端玩家无法直接点击到屏幕内的界面控件，因此推荐玩家对功能定位相同/相似的控件进行分区，将次要功能控件收纳到弹窗/次级界面内，已确保玩家能快速理解界面功能，同时专注于界面的核心功能和玩法。

**非必要不使用指针交互：**

在月之八版本我们为奇匠开放了常驻指针功能，推荐在键鼠布局下使用该功能。

在手柄布局下，该功能虽然可用，但在手柄端的操作效率低，体验较差，也不符合手柄玩家的操作习惯，若使用指针作为手柄端的主要交互方式，可能降低手柄玩家的游玩意愿，因此推荐在手柄端设计时，非必要情况不使用指针交互。

### 3.5 本地已确认规则与待验证点（证据分级）

> 来源：`docs/game-engine-knowledge/ui-controls.md`（本地框架草案）与本次整理。

**本地已记录（`[本地]`，多为待验证）**：
- 屏幕控件位于固定屏幕空间，不属于 3D 世界；实体铭牌属于 3D 世界（见 `components.md`）。
- 每个控件拥有控件 ID，运行时按 ID 操作。
- 按钮事件先发给该玩家对应的角色，再由角色节点图处理（官方事件实际为“玩家节点图可获取”，二者关系待核验）。
- 按钮可通过角色节点图转发到其他实体。
- 多人模式下 UI 显示/事件是否按玩家隔离，是待验证核心规则（官方文档已确认“界面控件组触发时只有触发玩家节点图可获取”，多人其他状态待核验）。

**与官方原文的对照结论**：
- 官方已明确：状态语义 = **开启/关闭/隐藏**，不是“启用/禁用”；关闭不保留动态信息，隐藏保留。
- 官方已明确：控件/控件组用**索引（整数）**作为节点图入参。
- 官方已明确：界面布局每个玩家有且仅有一个生效；事件仅触发玩家节点图获取。
- 本地 `ui-controls.md` 中“隐藏/关闭/禁用是否保留内部状态”的疑问，官方文档已给出部分答案（关闭不保留、隐藏保留），但“是否继续接收输入/逻辑运行”仍需游戏核验（官方节点参数说明：关闭=不可见且逻辑不运行，隐藏=不可见+逻辑正常运行，已给出官方口径）。

**待验证项（`[待验证]`）**：
1. 经典模式（无职业）下如何配置玩家默认界面布局。
2. 节点「设置界面控件(组)状态」对“悬浮交互页内控件”是否有效（社区 FAQ 称交互页内控件只能由页内方法控制，待官方/游戏核验）。
3. UI 状态/事件在多人场景下的完整隔离语义。
4. 控件 ID（索引）在 `.gil`/`.gia` 中的存储与引用形式（需真实地图证据，本轮未做）。
5. 交互按钮“技能”类型在经典/超限模式下的可用性差异。

### 3.6 下一步“正式解析 UI”最值得优先处理的 3 个点

1. **建立“界面控件 → 索引/状态 → 节点图事件”的最小可运行闭环**：在编辑器做一个最小差分实验（一个文本框 + 一个交互按钮 → 控件组 → 玩家节点图监听「界面控件组触发时」→ 修改控件状态），同时抓取保存前后的 `.gil` 对照，确认索引、状态枚举（开启/关闭/隐藏）与事件出参在真实文件里的 wire 形态。
2. **解析“界面布局 / 界面控件组”的资源结构**：用真实地图的 `.gil` 与编辑器快照对比，确认界面布局、控件组模板、控件资产、素材库遮罩在关卡文件中的存储位置和引用关系（这是后续用 Genshin-TS 生成/操作 UI 的前置）。
3. **多人与设备适配边界**：优先验证“每个玩家一个生效布局 / 事件仅触发玩家 / 状态是否按玩家隔离”以及 PC/移动/主机/手柄多套变换的配置是否独立落盘，避免把单玩家 UI 结论误推广到多人。

> 这三项都遵循项目纪律：先查本地 docs/知识树 → 最小编辑器差分 → 真实 `.gil`/GIA 证据 → 游戏核验，不做猜测性 wire 结论。
