## 05-实体和元件

## 实体与元件
千星奇域编辑器核心概念 -- 单位体系、实体摆放与元件编辑

### 一、核心概念：单位、实体与元件
概念层级
单 位
编辑与运行中集成了数据的个体
实 体
单位在游戏中的具象化体现
运行时可作为变量类型记录与传递
动态实体
可编辑属性、组件、节点图
静态实体
仅模型布设与是否在场，用于装饰
元 件
预设的实体数据，所有实体均由元件创建
标识与分类
实体 GUID
每个可编辑实体的全局唯一标识符
即使同一元件创建，GUID也不同
元件 ID
元件的全局唯一标识
仅动态/敌人元件可通过节点图生成运行时实体
预制元件
系统提供的动态、静态、敌人元件
自定义元件
基于预制元件修改后另存为的元件
临时实体
运行时由节点图创建，无编辑时GUID

### 二、单位的六种类型
玩家
抽象实体，描述角色从属
角色
玩家实际控制的物理实体
造物
自主反应的敌对/NPC实体
物件
静态/动态场景实体
本地投射物
本地计算的投射物实体
关卡
承载关卡逻辑的特殊实体

### 七、静态实体特殊说明
静态实体限制
- 无法编辑额外的属性、组件与节点图功能
- 不可供玩家在运行时获取
- 仅用于装饰与场景布设
- 无GUID，不可被节点图操作
- 不可通过节点图【创建元件】创建临时静态实体
- 仅可通过拖动元件到实体摆放页签场景创建
运行时实体与临时实体
运行时实体
关卡运行时，根据可编辑实体数据生成
或使用节点图通过预设元件即时生成
临时实体
通过节点图【创建元件】在运行时由元件创建
无编辑时GUID，其他与普通实体一致

### 八、实体与元件的覆写和还原机制
覆写规则
实体的数据引用元件数据，在实体上单独修改会覆写引用数据
未被覆写的数据
接收元件推送的数据修改（元件点击覆盖保存后）
被覆写的数据
不接收推送修改（详情面板中标蓝显示）
修改元件：
元件库中直接编辑 / 实体右键菜单 > 覆盖保存元件（反向推送） / 另存为元件（创建新元件）
还原到元件数据：
整体还原：顶部栏物件图标 > 还原为元件数据（除移动、旋转外回退为元件状态）

### 九、重要注意事项
删除元件后，所有由该元件创建的实体会一同被删除
将元件拖入场景创建实体后，对实体的改动完全与创建其的元件无关

## 06-元件组

## 元件组
多元件引用与批量布设工具

### 一、元件组的功能
核心定义
元件组可以引用多个元件，其中包含各元件的位置、旋转（相对于元件组中心）等信息。
元件组可以直接创建，也可以在关卡运行中通过节点图创建，效果等同于同时创建多个元件。
元件组可以比较方便地对实体进行布设，改动元件组的位置信息，其内部包含的元件会随之移动。
核心优势：批量管理
一次操作即可创建/移动/旋转多个元件，元件组中心位置自动计算确定

### 二、元件组的编辑方式
元件库编辑

### 1
在元件库中同时选中多个元件

### 2
右键菜单选择"创建元件组"或"合并元件组"

### 3
元件组中心位置会自动计算确定
适用场景：在元件库中预先组合多个元件
实体布设场景编辑

### 1
在场景中布设好实体后，同时选中多个实体

### 2
右键菜单选择"创建元件组"或"合并元件组"

### 3
元件组中心位置会自动计算确定
适用场景：在场景中已摆放好的实体组合成组

### 三、修改元件组信息
元件组内部编辑
选中元件组后，可以调整其中每一个元件相对元件组中心的位置和旋转。
每个元件的位置和旋转信息都是相对于元件组中心定义的。
移动元件组整体位置时，内部所有元件随之移动，保持相对位置不变

### 四、节点图创建元件组
运行时动态创建
通过节点图节点直接创建元件组，效果等同于分别创建其中的每个元件。
适用于需要在关卡运行时动态生成一组实体的场景。
节点图创建元件组 = 分别创建元件组内每个元件的效果

### 五、元件组使用流程总结
典型工作流

### 1
准备元件
在元件库中准备好需要组合的多个元件

### 2
创建元件组
选中多个元件/实体，右键创建或合并元件组

### 3
调整内部布局
调整每个元件相对于元件组中心的位置和旋转

### 4
布设或运行时创建
拖入场景布设，或通过节点图在运行时动态创建

## 07-造物

## 造物
自主反应的敌对/NPC实体 -- 行为模式、战斗配置与组件功能

### 一、造物的定义与特点
定义
造物是对人型生物、元素生物、深渊魔物、
异种魔兽、小动物、机械战斗单位等的统称。
造物可以自主对敌对阵营的实体做出反应，
包含但不限于入战、追踪。
造物遵循实体的一切通用规则
阵营关系决定敌对/友善判定
核心特点
行为模式
编辑时配置，运行时不可动态替换
仅生效一种行为模式，整个生命周期内严格执行
受击盒
默认携带与自身模型等大受击盒
可正确接收战斗信息
通用规则
遵循实体一切通用规则
行为模式来自预先提供的行为池，不支持运行时动态切换

### 二、造物的行为模式
非入战状态
造物创建后，默认处于非入战状态。
当造物入战后，通过各种原因脱战，
会重新回到非入战状态。
未入战行为（部分可编辑）：
待机
游荡
巡逻
不同行为模式包含不同的未入战行为池
游荡参数：
移动区域(球体) / 区域半径(m) / 移动间隔时间(s) / 单次移动距离(m)
以造物创建坐标为中心，在领地符合范围的区域内随机选点运动
入战状态
当造物通过范围感知或视野检测获取到
敌对关系的实体时，以对应实体为目标，
从非入战状态切换为入战状态。
入战区域检测方式：
范围感知
敌对实体处于范围内即入战
视野检测
全视野(球体) / 视锥(扇形)
脱战规则：
脱战距离(m) / 寻路失败脱战 / 脱战延时(s)
领地：无/球体/圆柱体，以创建坐标为中心
玩家离开区域后脱战 + 脱战延时(s)

### 三、常规设置（造物专有特化配置）
行为模式 / 未入战行为 / 入战区域
行为模式
从枚举项中选择，每种模式对未入战/入战提供不同可选行为
未入战行为
选择行为模式后可配置，不同模式包含不同未入战行为池
入战区域
范围感知 / 视野检测，所有行为模式都包含这两种规则
巡逻配置（部分造物支持）：
初始生效巡逻模板 / 循环类型(单程/往返/循环) / 巡逻起始位置(最近点/起点)
巡逻路径：引用路径管理工具中配置好的路径
路点信息：前往速度(走/跑) / 抵达判定半径(m) / 停留时间(s) / 到达后转向 / 到达通知节点图
技能设置（部分造物支持）：
技能名称 / 启用该技能 / 初始冷却区间(s) / 默认冷却区间(s)
部分造物支持配置自身逻辑参数（如深渊法师的元素护罩强效）

## 08-复杂造物

## 复杂造物
可自定义逻辑与技能的造物 -- 造物状态决策、技能管理与自主逻辑参数

### 一、复杂造物的定义与创建
定义
为满足奇匠对造物模型和行为进行更自由化定制的需求，投放了部分造物可以对其自主逻辑进行编辑，
以及可以像角色一样编辑自定义技能，这部分造物称为复杂造物。
创建方式：
在实体摆放界面，在复杂造物页签中选择具体项，选中或拖入场景内即可创建。

### 二、复杂造物与基础造物的区别
基础信息差异
变换
支持缩放调整，缩放调整率为0.5-3.0
模型
可调整预设状态，影响一系列表现（含初始动作）
其他参数含义参考基础造物文档
基础造物的通用组件、节点图等功能同样适用于复杂造物
特化配置差异（核心）
造物状态决策节点图
持续访问，按条件进入不同自主逻辑状态
造物技能管理
自定义技能，类似角色技能编辑方式
自主逻辑参数设置
定义战斗行为基础需求参数
复杂造物独有：状态决策 + 自定义技能 + 自主逻辑参数模板

### 三、造物技能管理
技能基础设置
复杂造物可使用自定义技能，需预先定义后才能在造物状态节点图中使用。
技能编辑方式类似角色技能。
技能引用：
序号
状态节点图中引用，用于实际执行的调用
引用技能
只能引用支持自身使用的技能
技能释放受三重冷却限制：
技能公共冷却时间 + 技能冷却时间 + 技能冷却组时间，全部满足才可释放
造物技能通用配置：
可打断其他技能 / 自动面向目标 / 击败目标是否继续释放
目标可达时释放技能 / 目标不可达时释放技能
技能类型：
瞬发技能（瞬间触发，不可编辑动画） / 普通技能（可编辑动画时间轴）
冷却时间配置
每个技能的冷却参数：
初始冷却开始时点
入战时 / 脱战时
初始冷却区间(s)
区间随机，创生后经过此时间才可使用
默认冷却区间(s)
区间随机，使用后在此时间内不可再用
所属冷却时间组
需同时满足自身+公共+组冷却
冷却时间触发时机
技能结束时 / 技能开始时
触发/忽略公共冷却
是否影响/无视公共冷却时间
公共冷却时间(s)：
所有技能都受此公共冷却影响
冷却时间组：
组序号(节点引用) / 组名称(编辑选取) / 冷却区间(s)

### 四、自主逻辑参数设置
参数模板概述
复杂造物需要定义自主逻辑参数模板，可在造物状态节点图中使用。这些参数是战斗行为的基础需求参数。
初始生效自主逻辑参数模板
运行时默认生效，至多1个
入战设置
范围感知：
范围感知距离 -- 敌对实体处于该范围内即入战
视野检测：
视野类型：视锥(配置视锥距离) / 全视野(配置球体半径)
连锁入战距离(m)：
造物入战时，范围内未入战的造物也一同入战
所有范围均可在编辑界面开启预览查看
脱战设置与领地设置
脱战设置：
脱战距离(m) -- 与目标距离大于配置距离时脱战
寻路失败脱战 -- 与目标间无合法路径时脱战
脱战延时(s) -- 满足脱战条件后延时脱战

## 13-阵营

## 阵营
对抗性玩法的群体划分 -- 阵营定义、关系配置与经典模式限制

### 一、阵营的定义
核心概念
为构建对抗性玩法而将实体划分为不同的群体，归属于同一群体内的玩家有着相同的游戏目标，这个群体被称为阵营。
在组队竞技类型的游戏中，阵营可以作为结算目标或得分的判断依据。
阵营是实体的属性，可在基础信息面板中设置

### 二、阵营的全局定义
关卡设置 > 阵营页签
在基础信息上选择阵营之前，需要先在关卡设置的阵营页签定义玩法所需的阵营。
阵营名称
该阵营的命名
默认阵营对象
新创建的玩家/物件/造物将被归类到对应的默认阵营中
包含的玩家
玩家列表，代表初始有哪些玩家归属于该阵营
包含的实体
物件和造物的列表，代表初始有哪些归属于该阵营
默认阵营对象：当实体创建时阵营值为0（默认），会被分配至该实体类型的默认阵营

### 三、阵营关系
关系配置（关卡设置 > 阵营关系）
任意两个阵营之间都一定存在敌对和友善两种关系。
阵营关系是单向的！
阵营1对阵营2敌对，不代表阵营2对阵营1也敌对。可能阵营2对阵营1友善，此时仅阵营1可攻击阵营2
其他系统中，阵营相关的配置均以关卡配置的阵营关系生效。
例如：能力单元会正确命中敌对阵营的目标。
示例：初始玩家阵营与初始物件阵营和初始造物阵营均为敌对
因此可以直接攻击阵营为这两个阵营的实体（角色、造物或物件）

### 五、经典模式中的阵营限制
经典模式限制条件
1. 所有玩家和角色为【玩家阵营】，不可修改
2. 所有造物为【造物阵营】，不可修改
3. 物件可配置为：玩家阵营 / 造物阵营 / 物件阵营1 / 物件阵营2 / 物件阵营3
