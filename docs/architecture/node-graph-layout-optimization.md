## 1. 用户视觉核验结论（2026-08-14，唯一权威基线）

1. **存在大量拥挤现象**——部分区域节点密集堆叠。
2. **整体布局有骨架，但细节处很拥挤**——大结构（事件组/列）有框架，细节（分支内/数据节点/包裹区）拥挤。
3. **连线设计需要更合理**——不仅布局算法升级，连线布线（交叉、走线、数据/执行线分离）也要优化。

## 2. 编译器布局现状（只读盘点）

### 2.1 布局算法（src/compiler/ir_to_gia_transform/layout.ts）

- 网格化：`columnWidth=800`、`rowHeight=600`、`maxColumns=50`（列满换行）；
- 事件组间隙 `eventGap`、分支间隙 `branchGap = rowHeight×0.6`、包裹偏移 `baseX = maxX + columnWidth`；
- 输出按执行深度（depth）定位：x = (depth % maxColumns) × columnWidth，y = 列内占用游标（occupyNextFreeY）；
- GIA 写入时缩放：`setPos(layoutPos[0] / 300, layoutPos[1] / 200)`（index.ts 475/547 行）。

### 2.2 当前 GIA 实际坐标（game.gia，290 节点）

- **稀疏不规则**：290 个节点 290 个不同 x（跨度 1.39~18406），列距无规律（0.01~8 不等）；
- 与"网格化"预期不符——需定位来源：事件组偏移？branchGap？包裹 baseX？缩放？
- **未决问题**：布局代码是网格的，GIA 输出却稀疏——疑似某个坐标写入路径（如复合/捕获/特殊节点）绕过了 layoutPositions。

## 4. 优化方向（候选，按实验逐项验证）

### 4.1 布局算法

- 网格对齐复核：找出绕过 layoutPositions 的写入路径（L4 定位）。
- 拥挤缓解：列宽/行高按节点尺寸自适应？分支内子布局？包裹策略调优？
- 事件组间距与组内密集度的平衡（骨架已有，细节优化）。

### 4.2 连线布线

- 数据连线与执行连线分离布局（数据节点侧向/独立列）。
- 长连线优化（中间节点路由/减少交叉）——先量化当前交叉数，再定策略。

### 4.3 结构优化（配合）

- 复合节点抽取：重复逻辑（罗德里格斯链/层筛选/速度计算）抽 defineComposite，宿主图节点数下降 → 间接缓解拥挤。
- 多图拆分：初始化/分派/执行拆图（跨图通信验证）。

## 5. 验证方式

- **量化**：GIA 解码统计（节点数/坐标分布/列数/交叉估计）；对比优化前后。
- **视觉**：用户编辑器打开图核验（拥挤度/对齐/连线可读性）——每轮一个可归因变量。
- **回归**：编译 → 注入 → 游戏核验（布局改动不得破坏逻辑）。
