## 二、不变量丢失审计（v4→v5 重写丢了什么）

方法：对 v5 交付 commit `7927753` 逐文件 git show，比对 v4 时代已修复的工程纪律是否在位。

### 铁证 1：物化快照纪律——被"架构理论"主动退役，16 小时后重学

- **v4 修复链**（同一陷阱修了三遍）：`e463c1c`(8/27 physSlideTick 二次求值翻倍→tmp* 快照) → `73b0ca6`(8/27 kickApply 同族) → `43a5fe1`(8/28 负载+物化) → `4ec9343`(8/31 00:46 spin 读 tmpDribbleVel，注释原文："消费点一律读物化快照 tmpDribbleVel，避免 newVelX/Z 多消费重算")
- **v5 交付**（16 小时后）：`7927753:dribble-v5.ts:50` 直接 `f.getCustomVariable(e,'vel')` 参与 Δv 运算，无任何物化；**第 107 行注释亲口宣布退役**："v4 的 ballVx/Vz/spinW/lostTicks/tmpDribbleVel 全部退役（真相在逻辑层黑板）"
- **代价**：决策图与物理层双 loop 相位交错 → Δv 基于被 drain 更新过的未来值重算 → 冲量反向放大 → 用户第 3、4 轮复测"问题依旧" → `3fb7098`(8/31 20:12) 重新引入 vel 物化，AI 自述"v4 tmpDribbleVel 纪律继承——**我重写时只物化了位置漏了速度**"
- **复发**：9/1 铁球问题（`0312e388` T9）= 同一陷阱换位置再咬一次（决策与脱手判定读两个不同次求值的玩家位置）

**判定：不是遗忘，是置信错位。** 重写者相信新架构（单一黑板真相源）使旧纪律不再必要，用注释把纪律"合法退役"。架构文档预判过竞态"概率低"，实测推翻。知识在周度复盘 R1 族卡片里（10 案例）、在 PKC 树里——**知识在场，但没有任何载体在重写时刻强制它出场。**

### 铁证 2：clamp 抄写笔误——max 公式顶替 min，潜伏七轮

- v4 `kick.v4.ts:152` 是正确的 min 写法；v5 重写时 `ball-phys.ts:75` 写成 `(a+b+|a−b|)/2`（=max），配 `MAX_SPEED=24`，**每个 <24m/s 的速度每拍被"钳制"吹到 24**
- 潜伏期：8/31 17:32 交付 → 9/1 10:01 `b2370a5` 修复。期间它解释了第 2-4 轮"vel 模恒 24"现象但未被识别（handoff durable_candidates 原文自认"也解释第 2-4 轮 vel 恒 24 历史现象"）
- 当前代码 `ball-phys.ts:174-180/541-544` 已修并留注释

### 铁证 3：单一真相源 state——v4 修过的跨图分歧以新形态复活

- v4：`560ac4e`(8/30) 修"图变量与实体位置跨会话分歧"（获得判定量幽灵球）；`784a93d`(8/30) 状态机唯一仲裁重构
- v5：拆成 825/826/828/829 四图后，`ballStateTransition`/`ballPhysTick` 读写**图变量** state——图变量每图独立 → 826 踢球写 FLY，825 读到自己图内的残留值 → Stop Timer 冻结球（`0312e388` T3-T4，9/1 10:30 修复：改读实体自定义变量）

### 审计小结

| v4 已修复纪律 | 在 v5 交付时的状态 | 后果 |
|---|---|---|
| 物化快照（4 次修复，3 天内） | **主动退役**（注释宣布） | 第 3-4 轮复测失败 + 重学 + 9/1 复发 |
| clamp min 公式 | **抄写成 max** | 潜伏 7 轮复测才定位 |
| 单一真相源 state | **架构性弱化**（图变量分裂） | 9/1 第 8 轮复测失败 |
| 单 outflow 声明（`f612e0e` 8/28） | **部分丢失**（ballDribbleDecideAtomic 含 exec 未声明 outflows） | 第 6 轮"足球完全不动"（`e348612` 裁边） |

**审计结论（供 R2 归因）**：六天七代里，每代重写都在"功能正确"维度重新出发，而"已修复纪律"维度从零开始。纪律存在于 commit message、PROGRESS、族卡片、PKC claim 四处，但没有一处与"改 examples/football 代码"这个动作绑定。examples/football 零 AGENTS.md（R0 实测）意味着重写时刻系统性地没有任何机制提醒"先读本模块不变量清单"。

## 四、headless sim PASS 31/0/1 与游戏连败的分叉点

`02a53f5`(8/30 16:33) 交付确定性物理引擎+验收 harness，报告 `sim/reports/verification-report.md` 总判定 PASS（31/0/1）。次日游戏内连败 7+ 轮。分叉不是"sim 错了"，是**模型边界**：

| sim 覆盖（数学层） | sim 不覆盖（全部失败层） |
|---|---|
| 弹道/反弹/滚动/旋转闭式解（A/B 门） | 双 loop 相位竞态（两图独立定时器，sim 单线程无此维度） |
| 摩擦/表面参数（PORTING-MAP 对齐） | 注入层裁边（outflow 声明→注入器行为） |
| 确定性逐位复现 | 节点预算拒载（2465>2000） |
| — | 设备/渲染语义（运动器吃 vy、同名顶替 0.15s） |
| — | 图变量 vs 实体变量可见性（引擎语义） |

**读数**：sim 验证的是"物理数学对"，游戏失败全在"工程装配层"。sim PASS 给了重写者（和汇报对象）过强的信心底座——它不在失败层上，却在报告语气里与游戏可用性并列。这正是三栏门禁（9/1）要切断的混层，但 sim 报告本身从未被要求声明"我不覆盖什么"。
