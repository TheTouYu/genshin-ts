## 一、这是什么任务（三句话）

1. **目标**：让 AI 具备**自主开发完整游戏**的能力——先用本项目已有 70% 的能力 + computer-use，交付**三个完整 3D demo 游戏**，每个都要"有玩法、没有 bug、自己玩通关"。
2. **但**：2026-10-17 实跑第一天就暴露，**GUI 操作占掉一轮 426s 里的 92%**（仪器开销），看错一次就要整轮返工——所以用户裁决：**先只做 GUI 模块的 AGI 实现，过了验收门槛再回到三个游戏**。
3. **所以**：现在的"当前任务"是 GUI AGI 模块（感知/动作/验收），"总目标"仍是三个游戏 + 递归自进化到 AGI 门槛。**GUI 不是终点，是先行条件。**
4. **并且（2026-10-24 用户纠正）**：这些任务**不是串行的一条线**，而是**几条线并行推进**（足球 / 模拟器 2D / GUI）。哪几条线、各自断点、谁在推 —— 全在 [`LINES.md`](LINES.md)。**本文件不主张"现在只做 X"**——那种写法会让接手的人只拿到一条任务。

## 五、四条硬规矩（违反会直接丢上下文）

1. **落盘先于压缩**：任何要被压缩的进展，先写进本目录或 `.scratch/gui-stack/STATE.md`，再压缩。
2. **交接落仓库**：handoff / 交接 / 恢复报告写在仓库路径（`docs/longtask/`、`.scratch/gui-stack/`），写 `/tmp` 等于没写。
3. **用户原话优先**：本目录所有结论都能追到"哪天哪句原话"，转述会把指令变成传闻。
4. **多线并行：一轮一条线，只改本线**：进门先看 `LINES.md`（线由用户指定，不按时间戳猜）；收尾只改本线那一行 + 本线 dossier + `03-state.md` 本线分节；**一次提交只含一条线的文件**。
