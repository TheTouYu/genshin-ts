## 一、进门协议（三条；违反就会又"只拿到一条任务"）

1. **线由用户指定，不由时间戳猜**：用户首句点明线（"回到足球"/"走 2D 线"）→ 只读那条线；**没点明就问一句**，不按 mtime / 最新提交自动挑（那会挑到别的会话正在推的线，2026-10-19 已踩过）。
2. **一轮一条线**：本会话只推进 §二 里状态为「活跃」的那一条。要临时碰第二条：先在 §二 登记（谁、做什么、多久），并确认 §三 的独占资源不在别人手上。
3. **收尾只改本线**：只改 §二 自己那一行 + 本线 dossier + `03-state.md` 里标了本线 id 的分节。**改写别线的行 = 覆盖别人的断点**，这是多线并行最容易造成的破坏。

## 三、共享资源与仲裁（多线真正会撞的地方）

两条线在同一台机器上，**共用的不只是仓库**。下表是本机实测的独占面（读数见 `03-state.md`）：

| 资源 | 独占性 | 获取 | 释放判据（可机检） |
|---|---|---|---|
| 真机试玩（编辑器 + 沙箱，用户的手） | **独占** | 用户在场且同意；`ys-screen-grant grant` | 交还回执：`activeWindow` = 用户窗且堆叠在其上；失败回落 firefox 并 rc≠0 |
| 编辑器窗口 / 焦点 | **独占** | `ys-gui-slot`（无凭据 exit 6 `NO_GRANT`） | `ys-gui-slot release`，判据同上行 |
| 存档地图 `<mapId>.gil` | **按图可并行，同图独占** | gsts 安全写回（SHA+备份+双址） | Save_Level 与 Temp 同 sha；**CLI 写完必须重载才试玩**（否则编辑器内存版回写抹掉改动） |
| 游戏进程 / Wine prefix | 共享（重试玩会回写内存版存档） | 无需申请 | 不主动杀；要杀先问 |
| 模拟器 web `127.0.0.1:4173` + `/home/h/qxqy-workspace` | `sim-2d` 线独占 | 该线启动 | 改源码后必须重启才生效 |
| git 工作树 / 提交 | 共享 | 常规 | **一次提交只含一条线的文件**（`git status --short` 核对） |
| GPU（6 GB，OCR/检测常驻会挤兑） | 共享但会挤兑 | 起常驻服务前先看余量 | 用完停靠 |

**判据**：任何"要占屏幕 / 要用户的手"的动作，先看本表有没有别的线持有；持有方不是本线 → 停下来问用户，不抢（D308 事故：用户在场时抢桌面 8+ 次、零结果）。

## 四、收尾怎么更新（多线版三件套）

1. **本线在 §二 的那一行**：状态 / 断点 / 上次读数——只改自己那一行。
2. **本线 dossier**：§现状读数（带测量时间）+ §断点。
3. **`03-state.md`**：只改共享段（机器、常驻服务、门禁）与**标了本线 id** 的分线读数节；新增读数要带线 id。
- `04-timeline.md`：只在出现**跨线决策**（切线、并线、开线、仲裁）时 append 一行，日常进展不写。
- `05-open.md`：每条开头标线 id（`[football]` / `[sim-2d]` / `[gui-agi]` / `[global]`），否则没人知道该谁关。

## 五、开线 / 关线

新增一条线要过三问：① 它有自己的**判据**吗（不是"顺手做点"）？② 它的**断点**能一句话说清、别人能接手吗？③ 它会不会和现有线**抢 §三 的独占资源**？
三问全过 → §二 加一行 + 建 `dossiers/<line>.md` + 跑体检；否则并进现有线。
关线（已闭环）保留行与 dossier，状态改 `已闭环`，证据写 dossier §证据，**不删行**。
