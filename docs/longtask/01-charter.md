## 三、AGI 基准的四条口径（不可降标）

| # | 口径 | 用户原话 | 落地判据 |
|---|---|---|---|
| A1 | **单次执行 ms 级** | 「一个简单的单次执行，我们应该控制在 **ms 级别**…已经存在了失控的风险了」 | 单次默认 ≤50ms、缓存 ≤5ms、检测 ≤10ms（AGI-BAR 预算表） |
| A2 | **对象检测走学习型** | 「这个叫做**对象检测**。在我们的 gpu 上跑应该**很轻松**」 | D2 检测器 ≥0.6 micro；GPU 通道为默认，CPU 兜底 |
| A3 | **主动补全** | 「不仅能做出这个推断，还能**自动下滑，补全全部信息**」 | 列表类信息一次给全（滚动+结构化），不要求模型逐行扫 |
| A4 | **验收上限=用户在环** | 「这个验收标准太低了…最稳的**把我加入到反馈轮**」 | 机器门禁只是下限；上限是用户亲测反馈 |
| A5 | 人类基准对照 | 「通用的操作，给我只需要 **5s** 就完成了」 | 同类操作端到端 ≤5s（2026-10-21） |

## 四、形态与边界（已拍板，不要再改主意）

- **形态 A（用户拍板「A，这就是我要的」）**：常驻世界状态服务 + **单一 schema** + **三动词** `look / act / wait_until`；返回**回执**不返回像素；预算写进契约，超预算**降级并说出来**。
- **通用性**：「agi 是通用的，不是针对原神这个游戏设计的」（2026-10-21 22:22）⇒ 任何"先判是不是某个游戏/编辑器窗口"的分流都是倒退，走**开集识别**（NOVEL 也是合法结果）。
- **不抬窗取数**：`act` 默认 dry-run；为了取一个读数而去抢用户屏幕，永远不做。
- **不做上传发布**（用户明确）；不碰需要用户确认的破坏性操作。

> 「我现在想恢复：给我们的项目融合大佬开发的千星2d lua脚本模拟器的能力。简单来说就是：大佬开发的功能，局限在2d的lua脚本。实际上，我们项目做的是真正的游戏。」

> —— 2026-10-23 17:0x，本会话首条（逐字）

- **定位**：模拟器是**产线**不是终点。它给的是「无 GUI 抖动 + `runCase` 批量回归」的开发环境，用来把 2D 游戏先做对；交付物必须是**真游戏里能玩通的产物**（GIA 导入真机 / 将来走 `gsts` 直写 GIL）。
- **不改变 §一 总目标**（三个 3D 游戏）；它是"把游戏真正送进游戏"的第二条路径，也是对 GUI 线的**绕行**（2D 线不依赖窗口自动化）。
- **本分支判据**：① 真机导入后开局不黑屏（模板 guid 已校准）② 六关从选人跑到通关 ③ 用户亲自试玩认可（§六 用户层）④ 素材"看得下去"（图元拟合或真图，用户判）。
- **载体**：虹猫蓝兔 `workspace/hmlt-qixia`（Lua 重写完成、17/17 离线用例绿；缺口=素材 + 真机打通）。细节见 [`dossiers/simulator-2d.md`](dossiers/simulator-2d.md)。

## 六、判"做完了"的三层证据（不能混报）

1. **结构层**：代码/编译/注入/回读 —— 能说明"在位"。
2. **行为层**：日志帧值、真机读数 —— 能说明"真的在动"。
3. **用户层**：用户亲自试过并说好用 —— 唯一能说"验收通过"的。
