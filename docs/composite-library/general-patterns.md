## 通用方法论（提炼）

1. **空模型当结构体**：作者提出「在场景里放置一个空模型用于归纳需要的自定义变量；可替代结构体使用，减少负载」。**节点图没有结构体类型，用「空实体 + 多个自定义变量」模拟结构体**——这是「数据聚合」的通用技巧。
2. **跨实体读写变量 = Query Entity by GUID + Get/Set Custom Variable**：要操作别的实体的变量，先 `Query Entity by GUID` 定位实体，再读写它的自定义变量。**这是「跨实体数据访问」的标准模板**。
3. **「事件 + 动作」是最简单的复合形态**：隐藏模型、碰撞触发、UI 触发传送，都是「监听事件 → 执行动作」两段式。**这是纯事件流复合的教科书**。
4. **「位置 + 生成」是生成类玩法的通用模板**：实体周围生成、随机点生成，都是「算位置 → Create Prefab」。**位置来源可配置（实体/预设点/随机）**。
5. **「累加 + 封顶」用 Take Smaller Value**：资源变量累加时用 `Take Smaller Value` 限制上限。**这是「数值封顶」的通用技巧**。
6. **「数量控制」是开放式节点**：作者标注「该节点为开放式节点，需要根据作者需要进行调整」——**上下限控制类逻辑要按业务定制**，但「查询数量 → 判断上下限 → 创建/销毁」的骨架是通用的。

## 复用提示

- 「空模型当结构体」是**最有价值的思路**——节点图没有结构体，这个技巧解决了「多字段数据聚合」的痛点。
- 「跨实体读写变量」模板是**跨图/跨实体数据共享**的基础。
- 「事件+动作」「位置+生成」「累加+封顶」都是高频骨架，直接套用。
