# 资源包 6：玩家/角色工具包（player-tools）

> 状态：当前推荐
> 来源：真实 GIA 资源包「常用复合节点大全 v1.7」逆向整理
> 最近校验：2026-08-22
> 适用范围：千星沙箱服务端节点图；多人玩法必备

## 用途

玩家序号↔实体转换、随机玩家、玩家退出检测、玩家数量获取。

## 节点清单

| 复合 ID | 功能 | 内部节点 | 关键点 |
|---|---|---|---|
| 1073741845 | 玩家序号→玩家/角色实体 | 玩家列表 + 角色列表 + 取值 | 序号从 1 开始，列表从 0 开始 |
| 1610612742 | 玩家序号→玩家+角色（同时输出） | 减法 + 取值 + Assembly List | 减一是序号转索引 |

## 通用方法论（提炼）

1. **玩家序号 -1 = 列表索引**：作者在两个节点里都强调「玩家序号从 1 开始，玩家实体列表从 0 开始」，所以「减一是将玩家序号转变为列表序号」。**这是多人玩法的头号坑**。
2. **玩家退出检测有两种实现，按频率选**：
   - **轮询法**（1610612739）：全局计时器定时对比「当前玩家数量 vs 上次记录数量」，数量变了说明有人退出。**负载取决于检测间隔**（1s 约 50ms，0.06s 约 800ms）。
   - **事件法**（1610612740）：监听 `When Entity Is Removed/Destroyed`，判断被移除的是否是玩家。**负载取决于实体创建/销毁频率**。
   - 作者结论：「频率较低则推荐事件法；非常高建议用轮询法」。
3. **玩家实体 vs 角色实体是两级**：`Get List of Player Entities` 拿玩家，`Get All Character Entities of Specified Player` 拿角色。**很多玩法要同时拿到两者**（1610612742 用 Assembly List 同时输出）。
4. **玩家退出后无法获得玩家实体**（作者注释）——退出检测要在玩家还在场时记录信息，退出后只能靠「数量对比」或「移除事件」感知。

## 复用提示

- 玩家序号 -1 的坑要写进任何涉及「按序号取玩家」的代码注释里。
- 退出检测的「轮询 vs 事件」权衡是通用决策模式：**持续状态用轮询，离散事件用事件监听**，按负载选。
