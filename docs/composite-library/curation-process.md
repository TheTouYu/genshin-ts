# 复合节点资源库策展流程（curation-process）

> 状态：当前推荐
> 来源：2026-08-22 学习「常用复合节点大全 v1.7」资源包时沉淀
> 最近校验：2026-08-22
> 适用范围：把外部资源包 / 自己项目的节点图，抽象成通用复合节点资源库的固定流程

## 目的

把「学习外部资源包 → 提炼通用知识 → 回灌技能」这套流程固化下来，让后续
（包括把 2x2/3x3 魔方等项目的复合节点抽象成资源包）能复用同一套方法，少走弯路。

## 流程（5 步）

### 第 1 步：读资源包，提取复合节点 + 注释

用只读工具解码 `.gia`，提取每个复合节点的：ID、内部节点列表、`compositePins`（接口）、
`comments`（作者注释）。

```bash
# 解码 .gia 到 JSON（.gia 是「复合节点资源包」格式：主图 CompositeDef + N 个 which==9 的 impl 图）
npx tsx tools/decode-gia.ts <file.gia> 2>/dev/null > /tmp/decoded.json

# 提取每个 impl 图的：id / 节点类型 / 注释 / compositePins 数量
# 节点类型 ID → 名字：查 src/thirdparty/.../node_data/node_pin_records.ts
```

**关键认知**：`.gia` 资源包里，复合节点的**名字在 `comments` 字段里**（作者写的中文注释），
`name` 字段是空的。**注释是资源包的核心价值**——没有注释的复合节点无法复用。

### 第 2 步：按功能分类，判断「通用价值」

把复合节点按功能归类（变量运算 / 随机 / 定时器 / 实体查询 / 销毁 / 玩家 / 逻辑 / 枚举转换 /
矩阵 / 排名 / 语音 / 特权玩家 / 通用思路……）。

判断「通用价值」的标准（用户定义）：
- **复用型**：真正多处调用，跨玩法可复用（如「变量+1」「随机玩家」「延时执行」）；
- **封装型**：把「一件事」的范围拆清楚（如「顺序发言」）；
- **思路型**：提供一种「写法思路」而非具体功能（如「枚举转整数」「空模型当结构体」）——
  这类**最值钱**，因为具体实现要按业务改，但思路可推广。

### 第 3 步：提炼「通用方法论」

对每个资源包，提炼**跨资源包、真正通用**的经验：
- 标准形态（如「读-算-写」三段式、「查列表→遍历→取值」三段式）；
- 关键技巧（如「动态列表转静态」「哨兵值 -1 + 自增」）；
- 负载意识（如「重操作拆帧/间隔」「向量形式 vs 列表形式负载差 100 倍」）；
- 前置条件（如「依赖关卡实体挂全局计时器」「依赖玩家实体挂排名变量」）。

### 第 4 步：落盘到资源库 + 回灌技能

- 落盘到 `docs/composite-library/` 对应资源包文档（用途 / 节点清单 / 通用方法论 / 复用提示）；
- 回灌到 `dsl-nodegraph-development` 技能（通用方法论、惯用法、负载经验）；
- 回灌到 `docs/game-engine-knowledge/composite-usage-guide.md`（通用模式）；
- 更新 `docs/composite-library/README.md` 的资源包总览表。

### 第 5 步：知识落盘到 PKC

把「可复用、可行动」的规则录入 PKC 知识树（`pkc-project-operator` 技能），
让后续任务能通过 `python tools/pkc.py query ... --level 2` 检索到。

## 复用现有工具（少走弯路）

| 需求 | 工具/技能 |
|---|---|
| 解码 .gia 资源包 | `tools/decode-gia.ts`（配 jq） |
| 读真实 .gil 节点图 | `gil-node-graph-reading` 技能（explain/parse/scan） |
| 节点类型 ID → 名字 | `src/thirdparty/.../node_pin_records.ts` |
| 复合节点编写方法论 | `dsl-nodegraph-development` 技能 + `composite-usage-guide.md` |
| 知识落盘 | `pkc-project-operator` 技能 |
