# rubik 2×2 → 3×3 写法演进比对

> 状态：当前推荐
> 来源：完整精读 rubik-2x2（40 复合）与 rubik-3x3（约 50 复合）源码（2026-08-22）
> 最近校验：2026-08-22
> 适用范围：作为「同一玩法从简单版演进到复杂版」的写法演进参考，抽象通用设计模式

## 为什么读这场演进

rubik-2x2 → rubik-3x3 是**同一玩法从 8 块到 26 块**的扩展。扩展过程踩了节点预算、帧数、跨图同步、
循环物化等一系列坑，并沉淀了更成熟的写法。这场演进是「节点图玩法怎么规模化」的宝贵样本。

## 六大演进（按价值排序）

### 1. 命名前缀化（gsts_* → 分层前缀）

| 版本 | 命名 | 问题 |
|---|---|---|
| 2x2 | 全部 `gsts_*`（gsts_rotate_vec、gsts_logic_apply_move、gsts_orbit_scheduler…） | 50 个复合堆在一起，无法一眼看出分层 |
| 3x3 | `math_*` / `logic_*` / `flow_*` / `motion_*` / `view_*` / `long_list_*` | 前缀即分层，一目了然 |

**经验**：复合节点按「职责层」命名前缀 + 按文件拆分，比「全写一个文件 + 统一前缀」可维护得多。

### 2. 逻辑状态：字典 → 列表 + finiteLoop

| 版本 | 状态容器 | 读写方式 |
|---|---|---|
| 2x2 | 字典（`dict([{k,v}])`） | `set_or_add_key_value_pairs_to_dictionary` + `queryDictionaryValueByKey` |
| 3x3 | 列表（`int_list`） | `set_list_value` + `getCorrespondingValueFromList` + `finiteLoop` |

**原因**：字典是 exec 操作（读写都要 exec 链），列表是「data 读 + exec 写」，配合 `finiteLoop`
物化循环体（循环体只 1 份），节点数从 142 降到 ~30。**列表 + finiteLoop 是大量状态读写的推荐形态**。

### 3. 定时器调度：N 分支 → handlerMode 变量化

| 版本 | 分派方式 | 节点代价 |
|---|---|---|
| 2x2 | `multipleBranches(timerName, {'0'~'7': 每块一个分支})` | 8 分支 × 每分支「设变量 + 调复合」= 节点爆炸 |
| 3x3 | `multipleBranches(mode, {0: turn, 1: orbit})` + `base`/`seq` 传入 | 2 分支，单次调处理器复合 |

**经验**：`multipleBranches` 的分支里**只 set 变量参数，join 后单次调用统一处理器**，
把「N 分支 × 复合展开」降为「N 分支 × set 变量 + 1 次复合调用」（详见 timer-scheduling 资源包）。

### 4. 视觉图拆分：单图 → 主图 + 视觉图 + 跨图同步

| 版本 | 图结构 | 共享状态 |
|---|---|---|
| 2x2 | 单图（逻辑 + 视觉混在一起） | 节点图变量直接读 |
| 3x3 | 主图（逻辑/流程）+ 视觉图（表现） | 自定义变量桥接（`setCustomVariable` → `view_sync_*` → `setNodeGraphVariable`） |

**原因**：26 块 + 26 视觉 + 流程，单图节点超 3000。拆图后主图/视觉图各自 <3000。
**经验**：单图接近 3000 且职责边界清晰时拆图，共享状态用自定义变量桥接（详见 cross-graph-sync 资源包）。

### 5. 循环物化：build 展开 vs 运行时循环的权衡

3x3 的 `logic_apply_whole`（整体转 26 块）反复在「节点预算」和「帧数」两个硬限之间权衡：

| 方案 | 节点 | 帧 | 结果 |
|---|---|---|---|
| 全 finiteLoop | 少 | 978f 控制帧（36%）| 单记录 3002 帧截断 |
| 全 build 展开 | 512 节点 | 少 | 游戏拒载（预测 3657 > 3000） |
| **折中（temp 展开 + 写回循环）** | ≈216 | ≈2513 | ✅ 达标 |

**经验**：节点预算 <3000 和单记录帧 <3000 是**两个独立的硬限**，要同时算。循环不变量提升、
两阶段读写等技巧见 loop-node-budget 资源包。

### 6. 随机相位差：运行时随机 → 预生成常量表

| 版本 | 错峰方式 | 代价 |
|---|---|---|
| 2x2 | `getRandomFloatingPointNumber` 运行时随机 + 物化到列表 | 每次转动都要算随机 + 写列表 |
| 3x3 | `faceTurnTimes`/`wholeTurnTimes0..3` 预生成常量表 | 直接查表，零计算 |

**经验**：错峰时间序列如果**每次转动都相同**，就预生成常量表（图变量字面量），不要每次运行时随机。
