# 资源包 16：输入锁/防重入包（input-lock）

> 状态：当前推荐
> 来源：从 rubik-2x2 / rubik-3x3 项目抽象（2026-08-22）
> 最近校验：2026-08-22
> 适用范围：千星沙箱服务端节点图；调用流复合，防重入

## 用途

「输入锁」——在动作执行期间锁住输入，防止重入（如魔方转动期间忽略新的转动指令）。

## 节点清单（1 个，调用流复合）

| 复合名 | 功能 | 接口 | 逻辑 |
|---|---|---|---|
| `flow_tab_lock` | 输入锁 | 无输入，outflow=done | 检查 lock 变量，空闲则置 lock=true 并继续，忙则直接返回 |

## 通用方法论（提炼）

1. **「busy 锁」是防重入的标准模式**：动作开始前置 `lock=true`，动作结束（如运动设备停止）后置
   `lock=false`。**任何「执行期间禁止重复触发」的场景都要用**（转动、动画、结算、传送）。
2. **锁的检查用 `doubleBranch`**：`isFree = (lock == false)`，`doubleBranch(isFree, 空闲分支, 忙分支)`。
   空闲分支置锁并继续，忙分支空操作（直接返回）。**这是「条件门」的标准写法**。
3. **锁变量用节点图变量**：`lock` 是图变量（bool），跨复合共享。**锁状态要全局可见**，所以用图变量
   而不是局部变量。
4. **锁的释放要可靠**：锁必须在动作真正结束时释放（如运动设备停止事件里），否则会永久卡死。
   魔方里用「定时器序列最后一个 slot 触发 unlock」保证释放（见 timer-delay 资源包）。

## 复用提示

- 这是**跨玩法通用的机制模式**（B 类），任何「有状态动作」的玩法都要用。
- 锁变量名、锁的释放时机要按项目调整，但「检查锁 → 置锁 → 执行 → 释放锁」的骨架是通用的。
- 与「定时器序列调度」配合使用：锁的释放挂在定时器序列的最后一个触发上。
