## 通用方法论（提炼）

1. **「顺序发言」= 定时器 + 发言序号 + 开/闭麦**：作者用「定时器定时修改发言序号，根据发言序号解锁指定玩家麦」实现顺序发言。**这是「状态机 + 定时器」的完整案例**——发言序号是状态，定时器驱动状态流转。
2. **发言序号默认值 -1 的巧妙设计**：作者注释「建议把发言序号默认值设置为 -1，这样第一个发言的是列表序号 0 的玩家」——**用 -1 作为「未开始」哨兵值，+1 后正好是第一个玩家**。这是「哨兵值 + 自增」的经典技巧。
3. **「变量变化时」触发是状态机流转的关键**：`When Node Graph Variable Changes` 监听发言序号变化，触发开/闭麦。**用变量变化事件驱动状态机，而不是轮询**。
4. **语音节点需要测试**（作者反复标注）：语音权限这类**涉及真实玩家交互的节点，编译/注入成功 ≠ 行为正确**，必须游戏内实测。
5. **「切人」用定时器延时**：作者注释「由于使用定时器触发节点，所以会延时一个切人时间」——**状态切换用定时器做延时，避免瞬时冲突**。

## 复用提示

- 这是**「状态机玩法」的完整参考**：状态（发言序号）+ 驱动（定时器）+ 触发（变量变化）+ 动作（开/闭麦）。
- 「哨兵值 -1 + 自增」技巧可推广到任何「从 0 开始遍历」的场景。
- 「变量变化事件驱动状态机」比轮询更优雅、负载更低。
