## 用途

销毁实体：延时销毁、批量销毁、迭代销毁。含一个跨领域的关键技巧——「动态列表转静态」。

## 通用方法论（提炼）

1. **「动态列表转静态」是销毁实体的关键技巧**：作者在 1610612737 注释里点破——「销毁实体会使获取实体的列表变化，从而导致无法完全销毁」。**遍历一个列表的同时销毁列表里的元素，会导致列表长度变化、索引错乱**。解法：先把动态列表复制到局部变量（静态快照），再遍历静态快照销毁。
2. **大批量销毁要间隔执行**：作者在 1610612753 注释里明确「列表迭代销毁实体会产生巨量负载导致炸图」，所以「间隔 0.1s 执行」。**重操作要拆帧/间隔，不能一次性全做**。
3. **销毁方式按数量选**：少于 20 个用简单迭代销毁（1610612737/1610612749），大批量用间隔销毁（1610612753）。**没有银弹，按规模选实现**。
4. **延时销毁 = 定时器 + 销毁**：`1073741833` 用定时器封装实现「指定时间后销毁」，本质是「延时执行」的一个特例。

## 复用提示

- 「动态列表转静态」是**跨领域通用技巧**，不只用于销毁——任何「遍历列表时修改列表」的场景（删除、移动、替换）都要先转静态快照。
- 「重操作拆帧/间隔」也是通用原则，矩阵运算、批量创建、批量销毁都适用。
- 延时销毁建议「优先应用于需要销毁的物体自身」（作者注释），这样销毁逻辑跟着物体走，不用在关卡实体上集中管理。
