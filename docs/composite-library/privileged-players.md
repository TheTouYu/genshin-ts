## 用途

按玩家昵称标记特权玩家/黑名单，做特殊处理（铭牌、特效、结算状态）。

## 通用方法论（提炼）

1. **「昵称列表匹配」是标记玩家的通用手段**：`Get Player Nickname` 拿昵称，`List Includes This Value` 判断是否在标记列表里。**这是「白名单/黑名单」的通用实现**。
2. **作者明确警告昵称重名问题**：「由于玩家昵称存在重名现象，所以尽量不要进行有损游戏体验的调用」——**昵称不是唯一标识，重名会导致误判**。更可靠的是用玩家存档里的唯一 ID。
3. **「思路型」节点**：作者反复强调「该节点为特权玩家示例」「通过该思路可以实现局内拉黑/关注玩家」「气泡文本、小地图标识等同理」——**学的是「标记玩家 → 特殊处理」的思路，不是照抄昵称匹配**。
4. **特效要本地过滤**：作者提示「需要注意对特效进行本地过滤防止影响正常游玩」——**特权特效只对目标玩家可见，不能影响其他玩家**。
5. **黑名单在多人游戏中的局限**：作者注明「由于奇域只有全局结算关卡，所以不建议多人游戏中使用」——**功能要结合游戏模式评估适用性**。

## 复用提示

- 「标记玩家 → 特殊处理」是社交/运营向玩法的通用框架，可推广到「VIP 玩家」「关注玩家」「内购玩家」等。
- 昵称重名是重要陷阱，生产环境应改用唯一 ID。
- 这些节点价值在「思路」，具体实现要按自己的需求改。
