## 一、官方定义与命名

- **节点图 = 无代码编程方式**：通过创建、拖拽、连接节点实现数据运算、事件触发、逻辑判断。
  - 出处：`BV1uUJCzMEfs` `[00:01:46]` "你可以把节点图理解为是一种无代码的编程方式"
  - 证据等级：硬规则
- **官方分类（5 类节点）**：`docs/ui-tutorial/official-guide-nodes-server.md:21`
  "服务器节点包含了执行节点、事件节点、流程控制节点、查询节点、运算节点"
  - 证据等级：硬规则
- **颜色即语义（编辑器视觉约定）**：黄绿色 = 执行节点（做什么）、红色 = 事件节点（什么时候做）、蓝紫色 = 查询节点（对谁做）。
  - 出处：`BV1UCxWzhEcx` `[00:07:40]` "黄绿色的是执行节点就是我们要做什么红色是事件节点就是什么时候做蓝紫色的是查询节点就是我们要对谁做"
  - 证据等级：硬规则
- **它在「做优质游戏」里的位置**：节点图是**玩法逻辑的唯一落点**——所有可玩行为都必须从事件节点出发、经执行/流程控制节点收敛为可观测的关卡状态变更。判定一个玩法能不能做出来，先看它能否被拆成「事件 → 数据 → 执行」三段的节点图。这也是我方 TS DSL 的目标编译产物（`docs/knowledge-graph/d/d3a-节点图基础与执行流.md`，见第五节）。
- **口语别名对照**（讲师口述 vs 官方名）：执行线 = 「蓝线」（`BV1t8xPzzE4b` `[00:00:00]`）；通用双分支 = 「if 语句」（`BV1uUJCzMEfs` `[00:45:56]`）；局部过滤器节点图被讲师误读为"布尔攻击器/布尔功率/布尔控制器"（`BV1K4tH6GE4k` `[P5 00:41:05]`）。

### C. 执行流语义（本专题核心）

| # | 硬规则 | 出处 |
|---|---|---|
| C1 | **执行线每被下游经过一次，就把上游节点整条重新执行一次**。同一个「获取随机整数」供两个打印节点使用 → 两次生成两个不同随机数 | `BV1t8xPzzE4b` `[00:00:00]` "到这个打印字符串节点的时候他会把这条蓝线蓝线执行一次……到这一步啊他又要把这条蓝线执行一次"（硬规则） |
| C2 | 推论：**数据源类节点（随机/查询/时间）在多处被引用就会被多次求值**。凡要求"同一个值贯穿全程"，必须先落进局部变量再分发 | `BV1t8xPzzE4b` `[00:00:46]`、"除非它生成两侧生成一样的"（硬规则） |
| C3 | **「获取局部变量」的初始值在一次工作流运行中只会被赋值一次**；之后再从上游给它赋值不再生效，读到的仍是第一次写入的值 | `G-S:5084`、`BV1t8xPzzE4b` `[00:01:31]` "他的初始值在这一次的这个工作流里运行的过程中只会被复制一次"（硬规则） |
| C4 | 「设置局部变量」必须把「获取局部变量」的执行线接到它之后；它把该局部变量的值设成自己的**第二个入参**（不是新建变量）。覆写后再次使用「获取局部变量」，出参【值】为覆写后的值 | `G-S:5088`、`BV1t8xPzzE4b` `[00:02:16]`（硬规则） |
| C5 | **列表迭代循环内所有迭代共享同一个局部变量** → 可用它做跨迭代累加（每轮读旧值 + 本次 each → 写回） | `BV1t8xPzzE4b` `[00:03:05]` "那么第一次它的初始值是零所以是6+0=6"（实测） |
| C6 | 「变量变化时」对容器类型**只在整体赋值时触发**（`设置自定义变量`）；用列表插入/设置值等节点改列表内部元素**不会**触发 | `BV1K4tH6GE4k` `[P3 00:55:08]`（硬规则）；官方同口径：`G-A:1743`、`G-A:1745`、`G-A:1905`、`G-A:1907` |
| C7 | 设置变量时**可显式关闭事件**：`是否触发事件` 默认为"是"，选"否"则这次修改不触发变量变化事件 | `G-S:245`、`G-S:262` |
| C8 | **空值陷阱**：未在编辑时预定义的实体自定义变量、不存在的局部变量，读出的**不是默认值而是空值**；空值参与运算可当默认值用，但**直接作为信号参数会导致信号无法发出**，极难排查 | `BV1oaDrBuE11` `[00:11:34]`（硬规则）；`learn/BV1oaDrBuE11/ALL.md:51` "信号的参数里不能有空集不存在的局部变量否则完全无法发出" |
| C9 | **引擎有执行保护上限**：一次循环处理太多会被自动掐断（表现为"循环跑到一半突然停了"，明明没写错） | `BV1d1UYB6EtS` `[00:03:07]` "这不是bug是千辛沙箱的保护机制"（硬规则） |
| C10 | 「有限循环」包含起止值：**循环起始值/循环终止值本身都在遍历范围内**，每次整数加一 | `G-S:51`、`G-S:60`、`G-S:61` |
| C11 | 「跳出循环」的出引脚必须与【有限循环】或【列表迭代循环】的【跳出循环】入引脚相连；跳出后**仍会执行【循环完成】** | `G-S:70`、`G-S:53` |

### S1 · 执行流与局部变量

- **「读一次、用多次」标准写法（锁值模式）**：随机整数 → 接到「获取局部变量」的初始值 → 各处下游统一从「获取局部变量」取值。改完后每次输出的字符都一样。
  - 出处：`BV1t8xPzzE4b` `[00:00:46]` "在获取随机整数以后我们把这个结果放到一个局部变量的初始值里面"｜证据等级：实测
- **改「初始值」不生效是高频困惑点**：第二次把 8 赋给「获取局部变量」的初始值没有效果（值仍是上一次的 2）——这就是为什么累加必须走「设置局部变量」而不是重连初始值。
  - 出处：`BV1t8xPzzE4b` `[00:02:16]` "虽然给它赋值成八但是他负的是初始值所以相当于没有效果那么这个局部变量值依然是上一个这里生成的二"｜证据等级：实测
- **列表求和（累加器）写法**：选项卡选中时触发 → 对整数列表做迭代循环 → 循环体内「设置局部变量」= each + 获取局部变量 → 循环结束后读「获取局部变量」打印总和。initial 先置 0（第一次 6+0=6）。
  - 出处：`BV1t8xPzzE4b` `[00:02:16]` "这是一个简单的对列表求和的一个流程就会用到这个设置局部变量"｜证据等级：实测
