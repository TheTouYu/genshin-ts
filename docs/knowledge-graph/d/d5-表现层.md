## 一、官方定义与命名

### 1.1 表现层在官方体系里的位置

官方把「表现」拆在两个地方：**资产四类**（跨 UI 与实体）与**界面布局**（纯 UI）。

> **资产**指的是构成游戏体验的所有数字内容和资源文件，分为**特效、预设状态、技能动画、界面控件**几部分
> —— `official-guide-concepts.md:7015`

这四类就是 D5 的官方命名边界。其中「界面控件」的**结构配置**属 D2b，其**表现行为**（动效/层级/显隐/自适应）属本文。

### 1.3 一句话定位

**表现层是「玩法大家都见过，但作品能被记住」的那一半。** 点评者的判断是：一个五万热度、99.1% 推荐的作品，
玩法本身「就还好」，是 **UI 动效 + 动画过渡 + 场景美术 + 操作手感** 把它拉到「能放进应用商店」的水平
（`BV1L6416oER1` `[00:04:41]`/`[00:08:38]`，证据等级：经验共识）。
反过来说，表现层塌陷会直接杀死留存：`BV11d6rB4Ejc` `[00:16:57]` 复盘 S 级《夜访积木屋》——玩法新鲜（过传送门切大小人、
微观宏观解谜融合），但「美术相对来说还是比较单调了就是一些呃木盒子楼梯啊阶梯还有传送门还有一些小人啊你乍一眼看上去确实没有什么太大的亮点」，热度上不去（实测）。

## 四、实操细节（来自视频语料）

> 官方文档写「有哪些参数」，视频写「怎么用才不出事」。以下按主题组织。

### 4.1 镜头：官方只说「能切模板」，实操要自己算

**R34 明确禁止动态改模板参数**，所以所有非模板化的镜头表现都要靠节点图算。`BV1CL3d6fEZJ` 给出三条可复制的算术流程（证据等级：实测）：

- **取镜头旋转**：`[00:00:45]`「使用视口坐标0.5获取屏幕中央再转成世界坐标深度值零就是镜头位置深度值移就是镜头朝向一单位距离这个随便填大于零就行获取这两个就可以计算镜头旋转」
  → 即：视口坐标 (0.5, 0.5) 转世界坐标；**深度值 0 的点 = 镜头位置**，**深度值 1 的点 = 镜头朝向 1 单位距离**（深度填任意 >0 值）。
- **镜头回正解算式**：`[00:00:45]`「通过获取镜头初始旋转中的X与角色旋转YX对应重置镜头时的XY就是角色朝向然后就可以回到重置镜头时的镜头画面」
  → 取 **镜头初始旋转的 X** + **角色旋转的 Y**，X 给回正镜头的 X、Y 用角色朝向，即可回到重置镜头时的画面。
- **偏移镜头的回正（到偏移视点）**：`[00:02:19]`「先获取实体向前向量并往试点方向旋转90度再按试点偏移的直缩放这个距离再提取原来镜头的高度并计算就可以了」
- **物件镜头创建位置**：`[00:00:45]`「再获取一个深度值等于视距的世界坐标这个就是物件镜头的创建位置了」。

**剧情演出用触发器强制切镜头**（`BV1ehYGzxEJe` `[P7 00:13:06]`，证据等级：个人经验）：
「强制所有到达某个节点之后所有的呃玩家一自动会把这个镜头切到这里播放诸葛亮的这段话」——玩家到剧情节点 → 自动切机位 + 播台词 → 播完交还控制权。

**用单位状态层数当跨端整数信道做镜头动画**（`BV1h1qeBgEnt` `[00:00:46]`–`[00:04:01]`，证据等级：实测）：
讲师的核心 hack 是「目前客户端是很难向服务器端发送数字的只能靠全局变量或写一套字典之类的…**我突然想到单位状态层数这么个整数变量读取不就能发送一个整数了吗**」，
`[00:01:31]`「就成功实现了在**不修改服务器节点图**的情况下实现任意想要的镜头效果」。
落地形态：`[00:03:14]`「第一个节点的字符串二和字符串三填上两个切换用的镜头模板之后持续时间内就会在这两个镜头之间来回切换」，层数 = 持续时间 × 系数（层数下限 50）；后两个参数可填可选，_延期时间_ 要与_续期时间_ 加同样层数；_影响范围半径_「不填不会生效」，填了则对以自身为中心半径内所有角色单位生效；`[00:04:01]`「目前还有一点bug**不能在0.1秒内多次触发**」。
效果示例 `[00:00:46]`：抬视角 0.5 秒后回正 = 两个节点；立刻轻微震屏一次、延迟 0.3 秒后持续渐平 0.4 秒 = 几个节点。

### 4.3 动效与显隐：一个硬伤 + 两个绕过方案

**硬伤（必须开工前规避）**：`BV1s6LB6WEF4` `[00:00:00]`（证据等级：实测）：
「由于目前**无法通过节点图控制悬浮交互页里控件的显影**每次重新打开界面都会变回默认的样子所以**有些细节还没法优化**」。
→ 与 R19/R21 对照可知：R21 的 `修改界面布局内界面控件状态` 管的是**界面布局内的控件组**，**不覆盖悬浮交互页内部的控件**。这是本轴最重要的一条实操教训。

**绕过方案 A —— 页签序号承载状态**（`BV1s6LB6WEF4` `[00:00:00]`，实测）：
「每个章节结束后可以查看已经完成过的剧情都是提前预设好的**只要控制页签显示的序号就能实现**」。
讲师在切片中的提炼：「界面重开后要保留状态，状态必须挂在**页签序号**上而不是控件属性上」，因此「涉及悬浮交互页动态显隐的需求要在**开工前先按页签粒度切分界面**」。

**绕过方案 B —— 页签当多路开关**（`BV1MVYj65EoV` `[00:01:34]`，证据等级：实测）：
「定时器启动后呢就要用到**更新悬浮交互页列表数据**节点图这里**列表索引就填叶签的索引显示项就是叶签的序号**」。
→ 用 `更新悬浮交互页列表数据`（DSL：`updateFloatingInteractionPageListData`）一次调用完成「第 N 颗星点亮」的整套显隐切换，末尾再补一个音效。

**动效的信息密度**：`BV1L6416oER1` `[00:02:02]`（实测）：「**派蒙的表情代表着不同的行为模式**」——用角色表演承载「当前行为模式」的可视化提示，等于把教学做进表演而不是纯文字教程。

### 4.4 布局自适应：三种做法的取舍

- **锚点当「布局保险」**（`BV1mLMr6QESr` `[00:01:38]`，证据等级：经验共识 + 硬规则佐证）：
  「空间就会随屏幕拉宽而拉宽」／「对于特殊数字控件功能也有一些优化」。
  同源给出的**机制**（证据等级：**硬规则**）`[00:00:47]`：「其实这四个箭头是代表锚点在题目中多少比例的位置实际切换比例的时候则是保持空间的四个角落相对锚点的绝对距离」——
  即**四角相对锚点的绝对距离不变**。默认锚点 = 四角相对屏幕中心（不同比例下控件看起来不动）；拉到屏幕两侧 → 随屏幕拉宽而拉宽；拉到控件四角 → 等于规定「屏幕的多少比例到多少比例是这个控件」，布局稳定。这与 R5/R6/R7 完全对齐。
- **预设多套尺寸 + 设置里切显示模式**（`BV1s6LB6WEF4` `[00:01:38]`，证据等级：实测）：
  「目前只为**对话回顾界面**做了不同尺寸的适配点击设置修改显示模式即可**可以看到分隔符的长度变了**」
  → 关键结论：适配是**按元素尺寸成套替换，不是等比缩放**。
- **移动端误触的野路子**（`BV1s6LB6WEF4` `[00:00:47]`，证据等级：实测）：
  「为了防止移动端点击选项卡时**误触下一句对话**所以就把**交互范围设置到了屏幕下方**」——把对话触发区压到屏幕下方，避开选项卡区域。
- **多端补方向键**（`BV1xFu26AER3` `[00:16:29]`，证据等级：个人经验）：
  「还有一个多装适配就是手机端的那个按键嘛因为他点那个可能不太好点然后给了他一个移动方向键」，再用信号转发把操作转给主逻辑。
