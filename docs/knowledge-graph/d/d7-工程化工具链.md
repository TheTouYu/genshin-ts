## 四、实操细节（视频语料 + 我方实测）

### 4.1 负载从哪来（先定位主因，再谈优化）

- **超载的两个主因：有限循环次数太多、设置自定义变量次数过多**
  - 出处：`BV1K4tH6GE4k` `[P5 00:31:49]` "负债问题基本上是第一第一个问题就是你用的太你的循环次数太多了你的有限循环次数太多了"
  - 证据等级：实测
- **变量写入的负载三级排序：设置局部变量最小 < 设置节点图变量中等 < 设置自定义变量（写实体变量）最大**
  - 出处：`BV1K4tH6GE4k` `[P5 00:32:36]` "设置局部变量它是负载最小的然后设置节点图变量它是附带中的设置自定义变量就是你必须要写入一个实体"；`[P5 00:45:18]` "你要设置自定义变量设置实体里面的自定义变量这个写入过程当中负载会比前面大很多"
  - 证据等级：实测
- **写实体变量的优化**：把循环里的写入"拆到不同定时器里分批做"，或尽量改用节点图变量与局部变量
  - 出处：`BV1K4tH6GE4k` `[P5 00:32:36]` "但两个解决办法是一个是你开一个定时器把不同的把它循环拆到不同的定时器去处理这个写入操作"
  - 证据等级：个人经验
- **逻辑操作替代多个双分支**：逻辑非/逻辑运算"比加法运算减法运算乘法运算它更快的其它负载是更小的"
  - 出处：`BV1K4tH6GE4k` `[P5 00:31:02]` "我是非常推荐大家用逻辑操作去代替一些双分支判断的"；`[P5 00:31:49]`（同上引文）
  - 证据等级：实测
- **模型数量失控会把地图做成"炸弹"**：讲师早年图"主要是我这些模型它是啊同时加载的"，自己都进不去（"所以说进这个图的可能会呃给我电脑爆破掉哈"）

### 4.2 拆 tick / 分批（本域最常用的手法）

- **【邪修·定时器分批】把"一次性处理 100 个格子"拆成"每秒处理 20 个格子"，绕开沙箱掐断**：开循环定时器每 0.05 秒触发一次，"第几次触发就是第几次循环"，处理完全部格子后停止定时器
  - 出处：`BV1d1UYB6EtS` `[00:03:53]` "我们开启一个循环的定时器每0.05秒触发一次第几次触发就是第几次循环"
  - 证据等级：**个人经验**（0.05s 属高频；我方红线口径见 §五——只可**短时分批**，禁止长期高频轮询）
- **循环中途停住的第一嫌疑是沙箱保护而不是自己写错**：先按"每次处理量太大"排查（改分批定时器），不要盲目改逻辑
  - 出处：`BV1d1UYB6EtS` `[00:03:07]` "为什么循环跑到一半突然停了明明我没写错啊"

- **大批量销毁必须间隔执行**：迭代销毁实体会产生巨量负载，"间隔 0.1s 执行"
  - 出处：`docs/composite-library/entity-destroy.md:24`（来自真实 GIA 资源包注释）
  - 证据等级：我方实测（真实 GIA 逆向）
- **现成的分片调度模板**：大任务 = `pStep` 状态机 + `shardStartTick` 定时器（`interval 0.5`），每个 tick 只做一类小工作，做完不再续 timer

### 4.3 降低单点负载的写法（省节点与省计算是两件事）

- **字典"遍历"的替代方案**：`获取键列表` → 列表迭代循环 → 迭代值 + `一键查询字典值`；**键列表必须先存变量**（"你如果直接去查它的话它的负载会比较高的"），建议打成复合节点
  - 出处：`BV1K4tH6GE4k` `[P3 00:31:41]`

- **结构体嵌套多/成员多时获取负载高**：拆出来的值先缓存到节点图变量再复用（局部变量不支持存结构体和字典）
  - 出处：`BV1K4tH6GE4k` `[P3 00:50:22]`
  - 证据等级：实测
- **结构体越用越绕 = 负载与可读性双输**：拆多次结构体的累计负载只有 80，整体优化版 500 多，而"每次都要把这些东西全部拆出来它的负载就会就高的很多了"
  - 出处：`BV1K4tH6GE4k` `[P3 00:52:47]`
  - 证据等级：实测
- **拆字典绕开"单节点过长"**：同一张映射表拆成多个字典再拼起来，"避免单个节点太长"
  - 出处：`BV1dNkDBgEUn` `[00:02:17]`
  - 证据等级：个人经验
- **列表元素上限用"分块 + 乘法选择器"突破**：官方编辑时列表内元素最大 100（A/B3），长列表包把 3 段 ≤100 的 chunk 用 `chunk=i/chunkSize`、`offset=i%chunkSize` 选择，sel 为 0 的 chunk 贡献 0
  - 出处：`docs/composite-library/long-list.md:20-30`（复合 `long_list_get_vec3` / `long_list_get_int`）
  - 证据等级：我方实测
- **循环不变量提升 + 两阶段读写/复位**：循环体内不变的表达式提到循环外只建一次；置换类操作必须先读入 temp 再写回（原地改会互相覆盖）；全 0 int_list 先写非 0 哨兵撑满长度再写 0
  - 出处：`docs/composite-library/loop-node-budget.md:37-92`（3x3 魔方实证）
  - 证据等级：我方实测
- **build 期展开 vs 运行时循环的决策口诀**：迭代体小（~6 节点/迭代）+ 次数少（8）→ build 期展开（帧收益 ~3.1f/节点）；迭代体大（~13 节点/迭代）+ 次数多（26）→ 运行时循环（展开会推到 512 节点、游戏拒载 3657）
  - 出处：`docs/composite-library/loop-node-budget.md:21-33`
  - 证据等级：我方实测

## 七、缺口与待验证

### 7.1 口径冲突（**本域最需要澄清的一条**）

- 副作用：`docs/composite-library/loop-node-budget.md:18` 仍写"节点预算 单图 <3000"，与 `AGENTS.md:44` 冲突（该文档的实证数字——拒载 3657、3x3 折中 216 节点/2513 帧——仍然有效，只是标题口径需同步）。
