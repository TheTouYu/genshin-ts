## 三、硬规则清单（官方）

> 全部 82 条来自官方指南原文，行号对该镜像 11,124 行版本。这是本域**可被实现直接依赖**的资产。

### A. 单位 / 实体 / 元件（基础层级，20 条）

1. **单位定义**："_单位_是编辑过程中与关卡运行中集成了数据的个体"。— `official-guide-concepts.md:21`
2. **实体定义**："单位在游戏中具象化的体现称为_实体_"。— `official-guide-concepts.md:23`
3. **两分法**：能承载复杂逻辑、有属性/组件/节点图的是**动态实体**；只能模型布设 + 设置是否在场的是**静态实体**。— `official-guide-concepts.md:25`、`:27`
4. **实体必来自元件**："每个实体必须基于一份已编辑的基础数据进行创建，该基础数据称为_元件_"；动态/静态实体分别由对应类型的元件构成。— `official-guide-concepts.md:29`、`:31`
5. **实体的两条创建路径**：编辑阶段直接创建明确的实体数据；或运行中基于指定元件即时创建。— `official-guide-concepts.md:35`
6. **实体可作变量类型**："在游戏运行时，实体可以作为_变量类型_，进行记录与传递"。— `official-guide-concepts.md:43`
7. **编辑面差异**："除_静态实体_外，实体可以编辑额外的特化配置、通用组件与节点图功能"。— `official-guide-concepts.md:45`
8. **GUID 全局唯一**：每个编辑场景下的可编辑实体都有唯一 GUID，**同一个元件创建出的多个实体也各有唯一 GUID**。— `official-guide-concepts.md:49`、`:51`
9. **元件是预设的实体数据**：所有可编辑实体都由元件创建。— `official-guide-concepts.md:55`、`:57`
10. **只有两类元件能运行时生成实体**："元件均具有全局唯一的元件ID，但**仅有动态元件与敌人元件**可通过节点图节点来生成运行时实体"。— `official-guide-concepts.md:67`
11. **单位共六种类型**：玩家 / 角色 / 造物 / 物件 / 本地投射物 / 关卡。— `official-guide-concepts.md:71-83`
12. **名称与 GUID 双唯一**：实体摆放页签下的可编辑实体具有全局唯一的实体名称与 GUID。— `official-guide-concepts.md:89`
13. **动静态类型不可事后切换**："你不可以通过实体面板切换实体的动静态类型"。— `official-guide-concepts.md:113`
14. **静态实体只有基础信息面板可编辑**："静态实体仅可以编辑基础信息面板，想切换到其他面板则会提示无法编辑"。— `official-guide-concepts.md:115`
15. **运行时创建的两条通道**：通过节点图节点【创建元件】可在运行时创建动态实体或敌人实体；特别地，**动态物件元件与造物元件**可直接由元件创建运行时实体。— `official-guide-concepts.md:189`、`:193`
16. **元件保存需全局唯一名称**，保存后生成**全局唯一的元件ID**。— `official-guide-concepts.md:151`、`:153`
17. **覆盖保存 vs 另存为**：改预制元件后可保存为自定义元件；改自定义元件则可**覆盖保存元件**或**另存为元件**。— `official-guide-concepts.md:179-181`
18. **实体与元件解耦**："对实体的改动将完全与创建其的元件无关"。— `official-guide-concepts.md:201`
19. **临时实体没有编辑时 GUID**。— `official-guide-concepts.md:207`
20. **静态实体无法用【创建元件】创建**，只能由静态元件拖入场景。— `official-guide-concepts.md:213`

### B. 玩家与角色（12 条）

21. **玩家是抽象实体类型**，描述"角色的从属概念"：提瓦特上玩家队伍可编入多个角色；**超限模式中每个玩家只对应一个角色**。— `official-guide-concepts.md:220`、`:224`
22. **玩家模板基础信息项**：生效目标（模板对哪些玩家生效）、等级（覆写职业初始等级）、出生点、初始职业、复苏规则、特殊被击倒损伤（溺水/摔伤时扣除的生命百分比）。— `official-guide-concepts.md:240-250`
23. **玩家可用组件只有 3 种**：自定义变量、全局计时器、单位状态。— `official-guide-concepts.md:258-264`
24. **玩家是纯逻辑实体**，不直接布设在场景上，因此**没有布设信息**。— `official-guide-concepts.md:276`、`:280`
25. **玩家生命周期**：随关卡初始化创建，随关卡销毁而移除；**用户主动退出返回大厅时玩家实体被移除**。— `official-guide-concepts.md:284-286`
26. **常驻光标四配置**：光标常驻、可点击层级（场景/受击盒/物件碰撞/光标碰撞）、光标最多可选目标数、点击可穿透 UI 控件（关闭时光标点击穿过 UI 后不再打到场景）。— `official-guide-concepts.md:300-306`
27. **移动端硬要求**："在移动端使用常驻光标功能时，必须要使用单位状态效果【光标点击释放技能】来补充PC端鼠标点击选中的额外逻辑"。— `official-guide-concepts.md:310`
28. **角色实体有物理实体**，指代玩家实际控制的走跑爬飞单位；**角色模板作为玩家模板的一部分**存在（入口在玩家模板的角色编辑页签）。— `official-guide-concepts.md:649`、`:653`
29. **角色实体不具有对应的 GUID**（按模板配置动态初始化）。— `official-guide-concepts.md:703`
30. **角色死亡的事件归属**：角色生命值归零时，**角色实体上的节点图**可收到【实体销毁时】与【实体移除/销毁时】事件；而**物件销毁时事件会被推送到关卡实体上**。— `official-guide-concepts.md:707`
31. **联机返回大厅**：玩家主动返回大厅时，关卡会收到角色的移除事件。— `official-guide-concepts.md:711`
32. **仅角色可加的组件**：除通用组件清单外，还有仅角色可以添加的**装备栏组件**。— `official-guide-concepts.md:695-697`

### C. 复苏（9 条）

33. **触发条件**：玩家的所有角色实体被击倒时（玩家所有角色倒下状态）进入复苏相关流程。— `official-guide-concepts.md:319`
34. **玩家实体不可被击倒**："玩家实体自身不可被击倒，但存在玩家所有角色倒下的概念"；因此**也不存在"复苏玩家实体"的概念**。— `official-guide-concepts.md:327`、`:329`
35. **复苏即解除倒下**："当玩家所有角色均处于倒下状态时，任一角色的复苏都会导致该玩家解除倒下状态"。— `official-guide-concepts.md:325`
36. **复苏配置挂在玩家模板上**，玩家实体由模板生成 → **不同玩家可以有不同复苏配置**（例：1 号玩家 3 次复活限制，2 号玩家无次数限制但每次等待 30 秒）。— `official-guide-concepts.md:353`
37. **【显示复苏界面】=否的后果**：该玩家倒下后不弹复苏界面，**无法通过游戏内置逻辑复苏，必须自制自定义逻辑**（如其他角色协助复苏），否则只能退出当前关卡。— `official-guide-concepts.md:363`
38. **【复苏后生命比例（%）】该值不可为 0**。— `official-guide-concepts.md:369`
39. **特殊被击倒损伤**（溺水、坠入深渊）扣除最大生命比例，此类复苏**不是常规复苏流程，也不会扣除复苏次数**。— `official-guide-concepts.md:370`
40. **复苏点选取规则 4 种**：最近的复苏点 / 最新激活的复苏点（可通过再次激活刷新激活时间）/ 优先级最高的复苏点（同优先级随机）/ 随机复苏点。— `official-guide-concepts.md:368`
41. **复苏相关节点共 14 个**：执行 6 ——【复苏角色】`:374`、【复苏玩家所有角色】`:395`、【击倒玩家所有角色】`:417`、【设置玩家复苏耗时】`:434`、【设置玩家剩余复苏次数】`:456`、【允许/禁止玩家复苏】`:478`；事件 5 ——【玩家所有角色复苏时】`:496`、【玩家所有角色倒下时】`:517`、【玩家异常倒下并复苏时】`:535`、【角色倒下时】`:552`、【角色复苏时】`:575`；查询 3 ——【查询玩家角色是否全部倒下】`:592`、【获取玩家复苏耗时】`:610`、【获取玩家剩余复苏次数】`:628`。
    - 关键语义：【复苏角色】在超限模式中与【复苏玩家所有角色】功能相似且**不扣除复苏次数**（`:386`）；【复苏玩家所有角色】可选是否扣次数，**次数不足 1 次则节点无法执行**（`:415`）；【设置玩家复苏耗时】改的是**下次**复苏耗时，**当前正在计时中不修改**（`:442-446`）；【设置玩家剩余复苏次数】设为 0 会使该玩家**无法复苏**（`:468`）；【玩家所有角色倒下时】的**原因**枚举 = 节点图导致 / 正常击倒 / 非正常击倒（`:533`）。

### D. 造物与复杂造物（13 条）

42. **造物统称**：人型生物、元素生物、深渊魔物、异种魔兽、小动物、机械战斗单位等；可自主对敌对**阵营**实体做出反应（入战、追踪等）。— `official-guide-concepts.md:718`、`:720`
43. **行为模式编辑时定死**："造物实体依赖编辑时配置的_行为模式_决定其行为逻辑，**不可在运行时动态替换**"；运行时**仅生效一种**行为模式，整个生命周期严格依据该模式执行。— `official-guide-concepts.md:726`、`:728`
44. **行为模式来自预设行为池**，不同造物支持配置的数量与内容不同，**不支持运行时动态切换**。— `official-guide-concepts.md:736`
45. **默认受击盒**："造物实体运行时，默认携带和自身模型相等大小的_受击盒_"。— `official-guide-concepts.md:730`
46. **未入战 / 入战两段逻辑**：造物创建后默认非入战；通过**范围感知**或**视野检测**获取到敌对实体时切换为入战；脱战后回到非入战。— `official-guide-concepts.md:742-748`
47. **造物变换轴向受限**："不支持空间X、Z轴的旋转，仅支持Y轴（水平朝向）的编辑"。— `official-guide-concepts.md:760`
48. **组件唯一性**："每一种组件最多挂载一次"。— `official-guide-concepts.md:784`
49. **复杂造物的差异化能力**：支持缩放调整（**0.5–3.0**）；可调整预设状态（影响初始动作等一系列表现）。— `official-guide-concepts.md:877-881`
50. **造物状态决策节点图会持续访问**，按配置条件进入不同的自主逻辑状态；**在其中可以引用造物状态节点图，由状态节点图让造物执行实际技能、战术**。— `official-guide-concepts.md:887`、`:889`
51. **技能三重冷却限制**：复杂造物技能释放受 **技能公共冷却时间 + 技能冷却时间 + 技能冷却组时间** 三重限制，"当三种时间限制全部满足时，技能才可以释放"。— `official-guide-concepts.md:897`
52. **自主逻辑参数模板**：需要先定义模板才能在状态节点图中使用；**初始生效的模板至多 1 个**。— `official-guide-concepts.md:956`、`:963`
53. **决策图的执行语义**：以【按顺序唯一执行】起始，每个出引脚连【切换自身执行状态】；**前置状态不满足则优先走失败执行**，仍不满足才尝试下一引脚；决策图持续执行，**前置顺序的状态一旦满足条件会立刻切换**（正在执行 C 时 A 条件满足 → 立即切到 A）。— `official-guide-concepts.md:1045`、`:1047`、`:1053`
54. **状态节点图引脚限制**："造物状态节点图的出入引脚，**仅支持单线连接**"；它代表持续性行为，未被决策图切换时会持续执行。— `official-guide-concepts.md:1061`、`:1063`

> 附带（同章规则，供查询）：**领地**支持无/球体/圆柱体，**以造物的创建坐标为中心、不随造物运动改变位置**，造物运动范围被限制在领地内（`:1032`）；**连锁入战距离**：造物入战时该范围内未入战的造物也会一同入战（`:1011`）；**寻路失败脱战**与**脱战延时**（`:1024-1025`）；**玩家离开区域后脱战**（`:1034`）。

### E. 物件 / 水物件 / 白盒物件 / 本地投射物（12 条）

55. **物件定义与三条边界**：地貌/植被/建筑/人造装饰/机关的统称；**无法对角色做出自主反应**；**无法自主移动**（可挂运动器组件按规则移动）。— `official-guide-concepts.md:1072`、`:1074`、`:1076`
56. **静态物件 = 纯表现向**：主要为环境、氛围表现使用，**不支持组件、节点图等任何功能**。— `official-guide-concepts.md:1082`、`:1084`
57. **动态物件**：运行时可根据配置的**预设状态**呈现不同动画表现；遵循实体的一切通用规则。— `official-guide-concepts.md:1088`、`:1090`
58. **基础信息可改不可增删**："在游戏过程中，基础信息可以被动态读取或修改，**但不能被动态添加或删除**"。— `official-guide-concepts.md:1098`
59. **水物件 = 环境类特殊物件**：多种预设形态、支持自由拼接；**所有水物件均具备水体交互属性，角色一旦进入水体范围自动切换至游泳状态**（获得对应移动方式与行为逻辑）。— `official-guide-concepts.md:1131-1133`
60. **水物件三种类型**：水体（圆柱形 = 水井/圆形水潭/喷泉基座；立方形 = 水道/水槽/方形水池/护城河，**均支持缩放调整**，可从侧面走入或上方跳入触发游泳，浅水/深水颜色可选）、圆形水体（轻量化**平面水体**，厚度极薄不占纵向空间，适合贴地铺设的水坑/水洼/积水）、瀑布（**3 个独立部件**：顶端=水流源头、侧面=垂直水流段**可叠加不限数量**、中端=转折或底部冲击段）。— `official-guide-concepts.md:1143-1180`
61. **白盒物件 = 基础几何体集合**，用于编辑阶段的空间验证与原型搭建，**可正常当模型资产使用**（支持缩放、换色、换材质、挂载逻辑组件、挂载节点图）。— `official-guide-concepts.md:1191`、`:1193`
62. **白盒物件 11 种几何体**：长方体、球体、平面、三棱柱、五棱柱、三棱锥、五棱锥、圆柱、圆锥、线框长方体（常用于区域标注）、线框圆柱（常用于区域标注）；**网格线每格标准 1 米**；**线框长方体、线框圆柱体无法更换材质**。— `official-guide-concepts.md:1203-1225`、`:1231`、`:1235`
63. **本地投射物必须编辑时预定义**："本地投射物需要在编辑时预先定义，**才能被技能节点图引用创建**"。— `official-guide-concepts.md:1246`
64. **本地投射物的运行时依赖**：依赖**投射运动器**决定运行时规则、依赖**命中检测**决定碰撞触发判定与效果；遵循"生命周期"配置。— `official-guide-concepts.md:1248`、`:1250`
65. **命名与索引**：每个预定义的本地投射物命名需全局唯一，并会自动生成**全局唯一的元件ID**。— `official-guide-concepts.md:1262`
66. **战斗参数与销毁优先级**：属性设置二选一——**继承自创建者**（生命/攻击/防御与创建者相同）或**独立设置**；"后续是否受创建者影响"开启后**仅有影响生命值、攻击力、防御力的单位状态会同步给投射物**；**X/Z 轴销毁距离是除能力单元外优先级最高的销毁判定**；生命周期结束时**按配置顺序从上到下执行能力单元**。— `official-guide-concepts.md:1279-1280`、`:1289`、`:1294`

### F. 关卡（5 条）

67. **关卡实体在新建关卡后自动创建**在场景中，用特殊图标表示；编辑入口在实体编辑页签。— `official-guide-concepts.md:1331-1335`
68. **关卡可接收特殊事件**：**物件和造物类型的实体在移除/销毁时，实体本身无法收到对应事件，事件会转发到关卡实体上**并由关卡处理后续逻辑。— `official-guide-concepts.md:1363-1367`

### G. 功能与通用组件（5 条）

72. **功能的四要素**：基础信息、特化配置、通用组件和节点图；**玩家和角色也拥有其中的部分功能**。— `official-guide-concepts.md:1386`、`:1388`、`:1390`
73. **基础信息覆写**：元件布设成实体时自动应用元件上的基础信息值，**支持在实体上重新改写，改写实体时元件的基础信息不会变化**。— `official-guide-concepts.md:1412`

> 附带：**创建设置**指实体布设在场上后关卡初始化时是否创建，关闭则需后续通过节点图动态创建（**实体被销毁或移除后也可以使用该节点再次创建**）。— `official-guide-concepts.md:1473`、`:1477`
> 附带：**可见性只影响模型**，不影响碰撞、触发器、节点图等其他逻辑，推荐用于制作隐藏实体相关功能。— `official-guide-concepts.md:1463`、`:1465`

### H. 技能（6 条）

77. **技能定义与三个基本功能**：接收游玩时的用户输入、让角色执行预设行为的封装（经典模式中普攻/元素战技/元素爆发都是技能）；三功能 = **角色动画调用**、**触发客户端节点图**（通过动画的_节点图事件轨道_）、**配置技能状态**（时间窗口附加持续性逻辑）。— `official-guide-concepts.md:8589`、`:8595-8603`
78. **配置ID 是技能的唯一标识**，节点图修改技能配置时引用该 ID。— `official-guide-concepts.md:8619`
79. **技能类型共五种**：瞬发（无法编辑动画，输入瞬间立即触发逻辑）、长按（循环动画，长按进入）、普通、连段（配置连续动作，接受特定时点输入后在动作间跳转）、瞄准（成套瞄准动作 + 进入瞄准状态）。— `official-guide-concepts.md:8621-8631`
80. **技能槽位五个**：普通攻击 = PC 鼠标左键、技能1 = E、技能2 = Q、技能3 = R、技能4 = T。— `official-guide-concepts.md:8845-8865`
81. **技能添加两条途径**：职业的默认配置；或通过节点图进行添加。— `official-guide-concepts.md:8869-8871`
82. **技能资源**：特定技能释放时需要扣除的资源（经典模式的"元素能量"即一种）；创作者可自定义资源类型；入口在**系统菜单栏 → 技能资源管理**；_配置ID_ 是技能资源的唯一标识，节点图调用时依赖它。— `official-guide-concepts.md:8883`、`:8889`、`:8901`

## 四、实操细节（来自视频语料）

> 官方文档给规则，视频给**踩坑**。本节按主题重组，不按来源。

### 4.1 元件 / 实体 的心智模型（官方不教学的类比）

- **元件 = 菜谱 / 样板菜，实体 = 实际吃到的菜**：元件决定"配料比例、重量、口味、价格、摆盘"，实体是元件的复制品，"每一份菜都是和之前的样板一模一样的"。**官方素材其实也都是元件**，拖进场景自动生成一模一样的实体。— 出处：`BV1UCxWzhEcx` `[00:03:48]`/`[00:04:34]`"原件就像是菜谱…而我们在餐厅里实际吃到的菜呢就是实体它是原件的复制品"；证据等级：硬规则（与官方 `:29`/`:55` 一致，类比属讲师原创）
- **为什么要区分**（视频给出的动机，官方只给定义）：① 大规模复制——先做一个"戴帽子的史莱姆元件"，之后摆的都是戴帽子的，不用一个个加；② 批量改——改元件设计 → **保存覆盖** → "场景里所有由这个元件复制出来的实体都会跟着改变"。— 出处：`BV1UCxWzhEcx` `[00:04:34]`/`[00:05:19]`"我想让场上这12个史莱姆…有了尸体之后我可以先制作一个戴帽子的史莱姆原件"；证据等级：实测（与官方 `:181` 覆盖保存语义一致）
- ⚠️ **讲师原话与官方口径的差异**：视频把"覆盖保存"说成无条件全局生效，官方只定义"覆盖保存元件 = 更新原本的自定义元件"（`official-guide-concepts.md:181`），而实体已被改动过的部分**不会**被元件回冲（`official-guide-concepts.md:201`）。**实现时以官方为准**：批量回冲只对"未在实体上被改写过"的字段成立。

### 4.2 从元件库到运行时：一条完整链路

- **元件编辑入口**：实体摆放 → 左侧素材库/元件库 → 选"造物/物件"等基础模块 → 拖出后才可逐项编辑（变换/阵营/单位标签/负载优化/音效/备注）。— 出处：`BV1uUJCzMEfs` `[00:08:44]`"我们点击这个基础模块旁边有造物…使用丘丘人我们把这个丘丘人点击一下诶拖出来拖出来之后呢就可以看到这个丘丘人的模型呢就被加载出来了"；证据等级：实测
- **"原魔本质上就是一个元件"**：木牌点击对话 → 创建原魔，用的就是节点图【创建元件】；**元件ID 在主界面可复制，直接粘贴到节点图**。— 出处：`BV1ZAnGzhEVS` `[00:01:32]`"这里原文本质上就是一个元件所以把两个节点连接起来…在这里可以提醒你需要召唤的原件idIE在主界面可以找到直接复制下来即可"；证据等级：实测
- **GUID 的实操用法**（把官方 `:51`"GUID 可精确标识实体"落成动作）：选中实体 → 复制其 GUID → 粘贴进节点图的实体入参 → 创建出来的就是这一个实体。— 出处：`BV1uUJCzMEfs` `[00:28:55]`"你会看到这个实体旁边呢有一个GUID…我们可以点击这个复制按钮把它复制过来我们直接诶复制粘贴过来那你可以看到创建的就是这一个火元素方碑的这一个对应的j u id这么一个实体"；证据等级：实测
- **关卡的实操定位**：关卡实体"你可以理解为是一个这个关卡的挂载点，它本身所在的位置并不是特别的重要，它更多的是需要可以在这个关卡实体这个挂载点上呢去挂载（逻辑）"。— 出处：`BV1uUJCzMEfs` `[00:19:36]`；证据等级：实测（与官方 `:1327`"被推荐用于承载关卡逻辑"一致）

### 4.3 静态 vs 动态：视频给出的判据

- **判据 = 能不能配战斗/组件/节点图**："对于这个静态单位来说呢它就无法去设置这个战斗部分通用组件部分以及去挂载这个节点图，那么它呢只能是把它进行比如说位移呀然后放大缩小啊调整一下位置"，所以**要实现功能的单位就不能用静态单位**。— 出处：`BV1uUJCzMEfs` `[00:21:08]`；证据等级：实测（与官方 `:45`/`:115` 完全一致）

### 4.4 组件：官方不写的互斥与冲突

- **组件之间会互斥（官方文档未声明）**："在目前的系统中一些组件会相互冲突，比如**移动组件和跟踪组件就不能同时存在**——所以要旋转就不能跟踪，要跟踪就不能旋转"。— 出处：`BV1UCxWzhEcx` `[00:06:06]`；证据等级：实测（⚠️ 个人实测口径，未在官方文档中找到声明，见第七节待验证）
- **绕法**：不能加跟踪组件就用节点图手写跟随逻辑。— 同上；证据等级：个人经验
- **元件 → 组件 → 实体生命周期**的完整用法：新建"镜头元件"→ 加基础运动器 → 创建实体 → 创建/移除实体由节点图控制。— 出处：`BV1CL3d6fEZJ` `[00:00:45]`/`[00:01:33]`"在节点图中设置开始运镜时创建元件并激活操控运动器…最后运镜结束时直接移除实体"；证据等级：实测

### 4.6 数据容器：D1 里唯一被视频讲透的一块（切片主源）

> 列表/字典/结构体属于"数据模型"层，本域切片 28 条中 21 条来自 `BV1K4tH6GE4k` P3（列表、字典，结构体入门 · 小猪之最老师授）。

- **列表只能存单一类型**："一个列表里面是不能存两种或者更多种不同类型的数据的"；每种基本数据类型都有对应列表类型；创建入口 = **自定义变量组件里先选列表类型再点新增变量**。— `BV1K4tH6GE4k` `[P3 00:03:08]`；证据等级：硬规则
- **序号从 0 开始**：长度 8 的列表序号是 0~7；`对列表插入值` 的序号**可取 0~N（N=长度）**，取 N 即末尾新增。— `[P3 00:06:13]`、`[P3 00:11:02]`；证据等级：硬规则
- **`拼装列表` ≠ `拼接列表`**：拼装列表**创建新列表**（泛型引脚可选任意类型、可一直加引脚、也可连引脚进来）；拼接列表把第二个列表接在第一个后面，**只改第一个、不改第二个**。— `[P3 00:08:42]`/`[P3 00:12:32]`"一个是拼接列表一个是拼装列表这是两个不同的节点"；证据等级：硬规则
- **末尾追加用 `拼接列表` 更省事**："你就不用算它的序号了"。— `[P3 00:13:19]`；证据等级：个人经验
- **排序与清除**：列表排序只有两种——顺序=从小到大、逆序=从大到小；`清除列表` 只清内容、**类型不变**。— `[P3 00:14:10]`/`[P3 00:14:56]`；证据等级：硬规则
- **"多少个"输入框 = 一次性新增 N 个列表元素**（当初讲师也一个个点过加号）。— `[P3 00:03:54]`；证据等级：硬规则
- **列表迭代循环每次迭代都会重新获取被迭代列表的值** → 必须先把列表存进变量（自定义变量/节点图变量/局部变量任选其一）再迭代，否则值会变；多人场景推荐先存局部变量"保险一点"。— `[P3 00:48:49]`、`[P3 00:15:42]`；证据等级：实测
- **字典键 7 类，值不限**：键只能是**字符串 / 整数 / GUID / 配置id / 原件id / 阵营 / 实体**；**浮点数**因精度误差、**列表**因是容器都不能做键。— `[P3 00:18:00]`/`[P3 00:18:46]`；证据等级：硬规则（⚠️ 我方实测与官方逐项一致，见第五节）
- **字典无序**：不能按序号取键/值，只能按键查；转成键列表/值列表之后才有顺序。— `[P3 00:21:52]`/`[P3 00:25:30]`；证据等级：硬规则
- **字典键不能重复**（写重复键会提示并**改回原值**），值可重复；所有字典操作都围绕键——移除只要给键、不必管值。— `[P3 00:19:32]`、`[P3 00:28:32]`；证据等级：硬规则
- **泛型引脚先定好**：字典的键类型/值类型必须先全部定义好，否则引脚很容易断；自定义变量的字典类型也必须先选字典再填键值类型，**不能留泛型（会报错）**。— `[P3 00:22:42]`；证据等级：实测
- **`建立字典` vs `拼装字典`**：建立字典传两个列表，**长度不一致取短的那一个**（多余截掉）；拼装字典手填键值对/连引脚，**两个列表长度必须一致**。— `[P3 00:25:30]`/`[P3 00:27:01]`；证据等级：硬规则
- **字典排序限制**：按键排序时键只能是整数；按值排序时值只能是整数或浮点数；输出为键列表 + 值列表。— `[P3 00:29:18]`；证据等级：硬规则
- **实体不能设初始值**，只能节点图里动态写 → "玩家实体 → 分数"的字典类用法必须靠逻辑写入。— `[P3 00:20:20]`；证据等级：硬规则
- **结构体入口与上限**：左上角菜单 →「高级数据管理」→ 创建结构体；**参数上限 50 个**；**不能无限递归**（套娃会变成非法结构、无法保存）；改完必须点按钮**应用修改**。— `[P3 00:37:53]`/`[P3 00:39:30]`/`[P3 00:40:16]`；证据等级：硬规则
- **结构体默认值**：定义时填的值即默认值；节点图里 `设置自定义变量` 选结构体且什么都不连，**等同于写入这份默认值**。— `[P3 00:39:30]`；证据等级：硬规则
- **`拼装结构体` 每次调用都创建新对象**；空引脚给该类型的默认值（空字符串/0/否）。— `[P3 00:40:16]`；证据等级：硬规则
- **`拆分结构体` vs `修改结构体`**：拆分一次性拆出全部成员；修改只指定要改的成员（可只改名称，也可同时改多个）。— `[P3 00:42:43]`；证据等级：硬规则
- **结构体的实战价值**（讲师自己的项目）：关卡数据（15 个关卡全存成结构体）、Roguelike 武器数值（49/50 把弓"每把弓都有很多参数"，用列表存会"要连很多自定义变量"）；**结构体可外部导入导出（JSON 文件，样例 228K）**；**绝对存档与消息队列必须用结构体**（绝对存档需 LV4 以上，消息队列无等级限制）。— `[P3 00:33:16]`/`[P3 00:34:47]`/`[P3 00:37:06]`；证据等级：实测 / 个人经验
- **局部变量节点既是创建也是获取**，可设初始值（类型必须匹配），没设置过时读到的就是初始值。— `[P3 00:31:41]`；证据等级：硬规则
- **⭐节点图变量作用域坑**：一个实体模板挂上节点图后在地图里摆两份，**两个实例的节点图变量不互通**。— `[P5 00:33:26]`；证据等级：硬规则
