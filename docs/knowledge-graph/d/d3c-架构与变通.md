## 一、官方定义与命名

本节只给**能落到 `文件:行` 的名词定义**——后面所有规则和变通都挂在这些名词上。

### 1.1 架构三件套：复合节点 / 节点图变量 / 自定义变量

| 名词 | 官方定义 | 出处 |
| --- | --- | --- |
| **复合节点** | 创作者可自定义节点结构的节点类型：把部分节点图实现的功能封装在内部，自行决定对外暴露的参数和逻辑引脚；**只能在服务端节点图使用，无法在客户端节点图中使用** | `docs/ui-tutorial/official-guide-auxiliary-appendix.md:1293-1295` |
| **虚拟引脚** | 复合节点内部子节点图上"对外暴露"的引脚，序号与外部引脚序号相同；同类型的两根引脚可**合并**，合并后相当于同时连接在两个引脚上 | `official-guide-auxiliary-appendix.md:1317-1321`, `:1425-1441` |
| **节点图变量** | 生命周期**跟随节点图**的变量，**仅服务端节点图可用**；仅在定义它的节点图内可访问（设置/获取/监听事件） | `official-guide-auxiliary-appendix.md:1140-1148` |
| **自定义变量** | 生命周期**跟随实体**、全局可访问（需指明实体）；同组件内不可重名 | `official-guide-auxiliary-appendix.md:1152-1162` |

官方给出的**分工推荐**（这是"架构"在官方口径里的唯一正面表述）：

- **自定义变量** ← 隶属实体、全局可访问的通用性数据（例：机关的受击次数，可能被别的实体/节点图读写）— `:1186-1188`
- **节点图变量** ← 隶属节点图的局部性、临时性数据（例：某物件节点图内部暂存玩家列表）— `:1190-1192`
- 官方明确节点图变量的架构价值：**"避免将专属于节点图功能的变量暴露到外部，降低节点图逻辑的阅读难度…可以更专注于节点图功能的封装，不需要关心这个节点图会被挂载在哪个实体上，可以实现更模块化的设计"** — `:1178-1182`

### 1.2 服务端图 / 客户端图的分型（插件的物理边界）

官方口径：**实体节点图、单位状态节点图、职业节点图、道具节点图**的逻辑在服务端运行，统称**服务端节点图** — `docs/ui-tutorial/official-guide-concepts.md:6414`

其余可运行的客户端节点图分型与入口（`official-guide-concepts.md`）：

| 图类型 | 入口 / 说明 | 行号 |
| --- | --- | --- |
| 角色技能节点图 | 角色自定义技能编辑页-动画编辑-时间轴；**仅支持超限模式** | `:6485-6497` |
| 造物技能节点图 | 造物自定义技能编辑页-动画编辑-时间轴；**超限 + 经典模式** | `:6499-6511` |
| 布尔过滤器节点图 | 最终输出布尔值，TRUE 则引用它的业务生效 | `:6517-6521` |
| 整数过滤器节点图 | 最终输出整数，输出值落在业务配置的整数列表内则业务生效 | `:6529-6535` |
| 造物状态决策节点图 | 按条件/优先级切换造物自主逻辑状态 | `:6541-6543` |
| 造物状态节点图 | 造物处于某状态时具体执行的行为；**出入引脚仅支持单线连接** | `:6549-6551`, `:1061` |
| 角色操控技能节点图 | 操控状态下才可使用，释放期间**无技能动画表现** | `:6557-6559` |

### 1.3 技能与"插件化"的官方地基

- **复杂造物**＝官方投放的一部分可自主编辑逻辑、可像角色一样编辑自定义技能的造物 — `official-guide-concepts.md:861-863`
- 复杂造物特化配置三件套：**造物状态决策节点图**（持续访问、按条件进入不同自主逻辑状态）、**造物状态节点图**（执行实际技能、战术）、**造物技能管理**（技能需先定义才能在状态节点图中使用）— `:885-895`
- **决策节点图**以【按顺序唯一执行】节点起始，每个出引脚接【切换自身执行状态】节点；前置状态条件满足则**立刻切换执行状态**，不满足优先走「失败执行」，再尝试下一引脚；条件都不满足时**可能不执行任何状态节点图** — `:1045-1053`
- 复杂造物技能释放受**三重时间限制**：技能公共冷却时间 × 技能冷却时间 × 技能冷却组时间，三者全部满足才能释放 — `:897`
- **技能动画**是实体战斗动作的动画资产；角色技能动画必须依赖角色实体、播放依赖自定义技能释放，按使用特色分**普通攻击 / 持续引导 / 位移**三类；造物技能动画分**普通 / 持续**两类 — `:7142-7170`

## 三、硬规则清单

> 逐条给 `文件:行` 或 `BV + 时间戳`。**规则按"拆架构 / 找替代 / 抓物理"分组**。

### 3.1 拆架构（程序架构⊕ / 架构设计⊕）

1. **复合节点只能在服务端节点图使用，客户端节点图不能创建、也不能使用复合节点。** — `official-guide-auxiliary-appendix.md:1295`；客户端侧同口径实测 "不能创建复合节点" — `BV1oaDrBuE11 [00:03:02]`
2. **节点图变量仅服务端节点图可用，且仅在其所在节点图内可访问。** — `official-guide-auxiliary-appendix.md:1140-1148`
3. **节点图变量对外暴露后可在关卡编辑时覆写其值**（覆写按实体实例分别填）。 — `official-guide-auxiliary-appendix.md:1226-1252`
4. **造物状态决策节点图按"顺序优先 + 唯一执行"选择状态**；正在执行的状态一旦被更高优先级条件命中会**立即切换**；全不满足时可能什么状态都不执行。 — `official-guide-concepts.md:1045-1053`
5. **造物状态节点图的出入引脚仅支持单线连接**（不能一进多出扇出）。 — `official-guide-concepts.md:1061`
6. **造物技能的释放受三重时间限制共同约束**（公共 CD × 技能 CD × 冷却组），三者全满足才放。 — `official-guide-concepts.md:897`
7. **函数调用要能"非阻塞"只需 2 个节点；要做"阻塞调用"额外再加初始化 / 调用 / 返回 / 监听 4 个节点。** — `BV164CEBfE1L [00:00:46]`
8. **阻塞函数的被调用者必须在函数结束处显式调用「函数返回」节点，且返回节点的目标实体必须是调用者实体。** — `BV164CEBfE1L [00:01:33]`
9. **同一实体上阻塞函数嵌套调用可能同时等待 2 个以上断点 → 断点必须做"入站/出站"以维护返回后的断点环境。** — `BV164CEBfE1L [00:03:54]`
10. **从外部调用自身阻塞函数、且该函数会回调自身其他函数时，必须"调用者入站"保存调用者信息，返回时"出站"还原。** — `BV164CEBfE1L [00:03:54]`
11. **信号是广播（一对多）且有 99 个上限**；需要一对一时改用「设置自定义变量」——它可同时指定实体与"信号名"。 — `BV1K4tH6GE4k [P4 00:17:13]` / `[P4 00:17:58]`
12. **监听信号必须放在关卡实体节点图里**，放玩家/角色实体图内会导致多人游戏下多个实体重复收到同一信号（服务端拆逻辑时同样成立）。 — `BV1oaDrBuE11 [00:10:46]`
13. **引擎循环节点开销高**：作者实测后放弃循环，改用"展开循环版本"的广播接口（固定支持最多 8 个对象）。 — `BV164CEBfE1L [00:03:08]`
14. **反例规则（官方未写、讲师实测的坑）**：逻辑与数据耦合——把文本写死在节点图里、一堆重复的 `设置自定义变量`，文案或变量名一改就得全图重来。 — `BV1K4tH6GE4k [P4 00:03:06]`

### 3.2 找替代（打表映射⊕ + 变通）

15. **字符串没有拼接节点**——这不是"没找到"，是可验证的缺失：官方服务端节点文档中**唯一的"拼接"节点是【拼接列表】**（`official-guide-nodes-server.md:112-118`），没有任何字符串拼接/格式化节点；我方 `src/definitions/nodes.ts` 中 `拼接列表` → `concatenateList` 亦为列表专用（`src/definitions/zh_aliases.ts:219,647`）。 → 定长槽位 + 打表是**当前唯一路**。
16. **客户端节点图的硬性限制**：不能创建复合节点、**不能修改自定义变量的值**、**不能修改引用类型（列表、结构体等）的值**。 — `BV1oaDrBuE11 [00:03:02]`
17. **技能实例不能直接携带参数**——要传任何参量或状态量，都必须通过实体的自定义变量传递（代价=引入数据同步问题）。 — `BV1oaDrBuE11 [00:03:02]`
18. **技能变量（月之六）是对角色共享的值，服务端无法读写，目前只支持浮点类型，是客户端节点图唯一的数据持久化手段。** — `BV1oaDrBuE11 [00:06:08]`
19. **客户端运算与动画技能完全互斥**：一个角色同时只能放一个技能；玩家动画技能期间服务端释放的瞬发技能**完全无法执行**；若新技能也是动画技能，则由原技能的"允许打断"配置决定谁留下。 — `BV1oaDrBuE11 [00:03:48]`
20. **调用客户端是纯异步（完全基于回调）**：服务端释放技能实例后逻辑就地中断，要等客户端发出若干信号、在对应信号的监听事件里流程才继续；服务端对客户端状态完全无能为力（可能延迟很久，多人下玩家可能刚好退出），**永远无法保证结果及时返回甚至能否返回**。 — `BV1oaDrBuE11 [00:04:36]`
21. **单位状态定时触发技能的 tick 间隔最小 0.1 秒**（在客户端唤起定时器释放指定槽位技能）。 — `BV1oaDrBuE11 [00:06:08]`
22. **客户端节点图允许发信号给服务端，信号可携带任意数据**（这是原始的单向通道，能双向的前提是有技能实例）。 — `BV1oaDrBuE11 [00:01:31]`
23. **服务器节点图资源管理器与客户端节点图资源管理器是两个入口**——选项卡的本地过滤器放在客户端节点图管理器里。 — `BV1uUJCzMEfs [00:25:02]`

### 3.3 抓物理（物理约束⊕）

24. **力场器的逻辑生效范围是同心球**，可分别配置内球半径、外球半径、球心相对实体的偏移、内径以内/外径以外的朝向与速率。 — `official-guide-concepts.md:4286-4329`
25. **力场器在角色处于生效范围内时持续检测**，结果变化立刻生效（弹射器/牵引器只在进入范围时检测一次）。 — `official-guide-concepts.md:4195`, `:4333`
26. **基础运动器组件只能赋予"物件实体"运动能力**，不能直接驱动角色；多个运动器可叠加、部分互斥。 — `official-guide-concepts.md:3192-3198`
27. **"卡住角色"的实测参数**：长宽 **0.2** 的正方形空间刚好把角色卡得几乎无法位移；**再小 0.01 角色就进不去**。 — `BV1FksrzAEo7 [00:00:00]`
28. **"拉回原点"的实测参数**：力场向中心吸引，**内球半径 0.25、内径速率 0**，角色正好停在力场中心；**再小 0.01 角色就开始鬼畜**。 — `BV1FksrzAEo7 [00:00:00]`
29. **调参步长就是 0.01**——把 0.2 / 0.25 当基准，上下各试 0.01 就是"刚好/失效"的分界。 — `BV1FksrzAEo7 [00:00:00]`

### 3.4 技能插件化的事实边界

30. **插件系统规格（案例实测）**：每个技能可同时装 **3 个插件**，每个插件可改技能形态或加全新效果 → 任何技能释放时都能触发别的花式效果。 — `BV1RESoBgEoA [00:00:00]`
31. **技能之间可以互相联动**，组合出的效果会超出作者预设。 — `BV1RESoBgEoA [00:00:45]`

## 四、实操细节（视频语料）

### 4.1 拆架构：五问 + 三段拆分法（`BV1K4tH6GE4k` P4）

**拆任何一个功能，先答五个问题**（讲师原话，等价于冯诺依曼架构的输入/控制器/存储器/输出）：

> "我们需要是呃**谁触发**、**谁处理逻辑**、**谁保存数据**、**谁来执行**、还有**谁需要知道**" — `BV1K4tH6GE4k [P4 00:03:52]`
> "其实我想应该挺多人会知道这个叫嗯**冯诺依曼架构**的" — `[P4 00:11:43]`

**对话系统 = 可复制的最小范例**（三段拆开）：

1. **输入**（按钮 / 碰撞箱）——只负责"推进下一句"这个请求，**不知道内容**：
   > "他们并不需要知道下一句话是什么或者说呃我们下一句话的序号是什么内容是什么" — `[P4 00:07:51]`
2. **控制器**（单独实体的对话管理器）——序号自增、溢出反馈、接收强制关闭、确认数据：
   > "我们把它拆分成了一个呃逻辑器跟渲染器在我这里…写了叫呃流程的控制器以及这个对话渲染器" — `[P4 00:06:18]`
3. **渲染器**（单独实体按信号渲染样式与文本）；**对话数据存在触发对话的实体（如树桩）身上**，讲完通过回调事件通知它 — `[P4 00:05:32]`, `[P4 00:07:05]`

### 4.2 架构设计：用变量监听当日志/函数总线（`BV164CEBfE1L`）

**前提事实（作者实测）**：「自定义变量变化事件」在**重复设置相同的变量值时也能重复触发** — `[00:00:00]` → 这是"把实体变量当函数表用"的全部根据。

| 概念 | 映射 |
| --- | --- |
| 函数名 | 实体变量名 |
| 函数调用 | 对该变量**设置值**（重复设同值也触发） |
| 实参 | 随设置值一起传入的**调用者实体** |

- **非阻塞调用**：初始化时"传入接口列表 → 对每个函数创建一个同名实体变量"；调用时对相应函数名变量传入调用者实体即可 — `[00:00:46]`
- **调用者取回**：把调用者实体随函数名变量送进去，用自封装的「缓存函数调用者」/「读取函数调用者」两个节点取回，变量名统一叫"函数调用者" — `[00:01:33]`
- **阻塞调用侧契约**：被调用者结束时显式调「函数返回」（目标实体=调用者）；调用者监听返回事件，按**断点名**把事件流导入对应函数节点 — `[00:01:33]`
- **面向对象的最省事做法**：一个实体监听自身变量变化并做出响应，本身就是面向对象；类封装只需三步「定义接口 + 初始化变量 + 监听变量响应调用」 — `[00:02:20]`
- **多态**：先按需要定义接口函数，再在各"实现类"里实现同名函数，调用方直接把实现类当接口对象用（类比 Go 的隐式接口） — `[00:02:20]`
- **接口约束的野路子**：沙箱里做不到也不必要做接口定义约束 → 干脆**新建一张"不用的节点图"**，在里面随手把接口定义一遍，用于规范开发、避免忘记接口 — `[00:03:08]`
- **入站/出站的触发条件**：只在"自调用 / 回调 / 循环依赖"时才需要开；嵌套调用适用场景 = 同一实体上的嵌套，或调用实体之间存在循环依赖 — `[00:03:08]`
- **作者自测结论**：同函数重复调用、多物体多态调用、非阻塞与阻塞函数的多波调用、嵌套调用**四类场景均能正常工作** — `[00:04:43]`

### 4.3 打表映射：字符串拼接的完整管线（`BV1dNkDBgEUn`，4 分钟全片）

**约束**：节点图不提供字符串操作节点，又需要动态字符串展示。

**骨架**：
- ASCII 码表存放在**关卡实体**上（方便读取） — `[00:00:00]`
- 玩家实体上**预留足够多的槽位**存放字符串片段 — `[00:01:10]`
- **槽位数就是字符串长度上限**（不足补空白），槽位越多节点越多 — `[00:01:10]`

**五步管线（照抄可复现）**：
1. 初始化映射表——"虚线就是**打表出奇迹**了"：把大写字母、小写字母、数字分成三个字典再拼成一个（避免单个节点太长），返回创建完成的映射表存到关卡实体 — `[00:02:17]`
2. 触发链：选项卡交互记录点击事件 → 发送"生成名称"事件；**每点击十次**才触发抓取一个预制变量名称 — `[00:01:10]`
3. 关卡创建时执行映射表初始化并**监听生成事件，区分"随机名称"与"预制名称"两条路径** — `[00:01:10]`
4. 生成逻辑五步：返回字符编码列表 → 把字符编码列表转为字符串列表 → 映射表里找不到就返回**占位字符** → 循环遍历字符串片段插入变量槽位 → 列表长度小于槽位数量则**补齐空白** — `[00:03:04]`
5. 拼装收尾：由于字符串不能拼接，**只能写一个巨无霸 switch 语句**把对应变量设置进去（继续用字典打表也可以），最后把全部变量槽位拼到文本组件里 — `[00:03:53]`

> 作者吐槽点（可当"官方后续会不会给字符串节点"的观察指标）："虽然我一直不理解老米连自定义结构体都提供了却不给字符串操作这么基础的功能" — `[00:03:53]`

### 4.4 变通：客户端算力什么时候值得用（`BV1oaDrBuE11`）

**适合拆去客户端的四类场景** — `[00:13:07]`：
1. 各种复杂的 **AI 决策逻辑**（实时性要求不高或可容忍延迟）
2. 略复杂的**界面逻辑**（字符串拼接、素材 id 更改等；容忍较大延迟但**要处理数据同步**）
3. **随机事件**（准确性要求低，甚至可容忍调用失败）
4. 其他复杂而可容忍延迟的逻辑（**统计类运算**等）

**经验数据**：客户端算力充足且**永远不会导致关卡崩溃**；单次运算节点数的个人体感极限在 **数万**左右，太多会导致客户端明显卡顿甚至无响应 — `[00:14:38]`

**典型实战拆分（俄罗斯方块复刻）** — `[00:08:28]`：消行连锁（遍历所有行判消除条件、记录状态、剩余行下落）、维护每列最高方块位置做落点预测（预览方块落点多达 15 行）、分数计算（含 5 个可自由加点乘积）、界面"消球倍率"的复杂字符串拼接——**全部客户端算，服务端直接取用或只做合法性校验**。

**sequence 匹配法**（解决"客户端读到旧值"）— `[00:10:46]`：客户端侧配"异步调用客户端 sequence"**技能变量**；玩家身上配"异步调用服务端 sequence"**自定义变量**（初始值 1）；每次调用客户端运算前服务端先 +1；客户端开始逻辑时**比对两个 sequence 是否相等，相等才算并返回**、同时把客户端 sequence +1；不相等说明版本过期，发回一个特别信号要求服务端重新释放技能实例。
> 局限（作者自陈）— `[00:13:53]`：sequence 匹配法**不一定能保证全局数据同步**，最多保证该玩家身上的自定义变量数据最新，其他实体不一定。

**多重精度技巧**：用技能编辑器的**循环轨道**把定时精度抬到 2.5ms 级——0.01 秒间隔放 4 个节点图调用、循环 25 次 = 一次动画技能里调用输入检测节点图 100 次；实测该动画技能（开启功能后全息覆盖）**不干扰**用瞬发技能做客户端运算的策略 — `[00:06:08]`、`[00:06:54]`

**多人选客户端的握手**：定期让全部在场玩家发回"获取当前客户端时间"（高精度毫秒），服务端收到后再发起一次相同调用，比较时间差得到延迟定性值——等价两次握手 — `[00:07:40]`

**规避动画技能互斥的空子**：错开"调用客户端算力"与"玩家可释放技能"的时段；单个动画技能时长 **<0.5 秒**时实测瞬发技能大部分时候也能正常释放 — `[00:03:48]`

**客户端不允许改列表的替代**：用"多分支 + 局部变量"模拟（操作时要大量重复，是当前设计所限）；**多发信号不会产生很大负载**，唯一决定负载的是服务端收到信号后做的处理逻辑 — `[00:12:20]`

**三条经验纪律** — `[00:11:34]`：①监听信号最好放关卡实体节点图（见硬规则 12）；②**不要在玩家/角色实体的"实体创建时"事件里调用释放指定技能实例**（不生效，可等 1 秒再试）；③养成在节点图最开始初始化全部局部变量的习惯——未预定义的变量读出来是空值，**把空值直接当信号参数会导致信号发不出去，极难排查**。

### 4.6 物理约束：无输入接口时用物理拼出"输入"（`BV1FksrzAEo7`）

## 六、诊断路径

按"症状 → 先查什么 → 常见归因"组织。

### 6.1 "图能跑但改一处就崩一片" → 先查耦合

1. 用**五问**过一遍：谁触发 / 谁处理逻辑 / 谁保存数据 / 谁执行 / 谁需要知道 — `BV1K4tH6GE4k [P4 00:03:52]`
2. 若答案是"都在同一张图里"→ 检查是否犯了**逻辑与数据耦合**（文本写死在图里、一堆重复 `设置自定义变量`）— `[P4 00:03:06]`
3. 修法优先级：改数据不改逻辑（把文本/变量名抽成实体上的数据）> 抽复合节点 > 拆实体。
4. 客户端图**不能用复合节点**（硬规则 1）——想在客户端复用逻辑，只能拆成"多分支 + 局部变量"或换页签式结构。

### 6.2 "信号没收到 / 收到多次" → 查监听位置与广播语义

1. 监听是否放在**关卡实体**节点图里？放在玩家/角色图内在多人下会**重复收到** — `BV1oaDrBuE11 [00:10:46]`
2. 是否超过 **99 个信号**上限？考虑改用「设置自定义变量」做一对一触发（同时指定实体 + 信号名）— `BV1K4tH6GE4k [P4 00:17:13]`
3. 收到"信号发不出去"：**信号参数里不能有空值**（未预定义的局部变量读到的是空值）→ 检查是否在节点图最开始初始化了全部局部变量 — `BV1oaDrBuE11 [00:11:34]`
4. 想用"变量监听"当函数调用：确认接收侧监听的正是那个变量名，且**初始化时已为每个"函数"创建了同名实体变量** — `BV164CEBfE1L [00:00:46]`

### 6.3 "复制过来的技能/状态图不触发" → 查泛型与事件节点

1. **事件节点的泛型引脚未确定会导致节点无法被正常触发**（典型：自定义变量变化时节点的"变化后值/变化前值"没连线就上传）— `official-guide-auxiliary-appendix.md:1127-1131`
2. **保持泛型状态进入试玩 = 节点不合法，运行时不会正常执行** — `official-guide-auxiliary-appendix.md:1073`
3. 造物状态相关：确认决策图用【按顺序唯一执行】起手、每个出引脚接【切换自身执行状态】；状态图**出入引脚仅单线连接** — `official-guide-concepts.md:1045-1061`
4. 造物"脱战后还在放技能"：**只配技能不配交战判定**是实测踩过的坑——必须判断自身是否处于交战，未交战则顺位执行下一个状态（讲师补了一个"静止不动"状态后问题消失）— `BV1SgqPBQEpM [00:03:41]` / `[00:04:27]`

### 6.4 "客户端算完结果不对 / 拿到旧值" → 查同步与限制

1. 是否在**同一事件处理程序内**改完自定义变量立刻调用客户端？客户端读不到最新值 — `BV1oaDrBuE11 [00:10:46]`
2. 上 **sequence 匹配法**（见 4.4）；注意它只保证玩家身上的自定义变量最新 — `[00:13:53]`
3. 是否踩了客户端三禁：建复合节点 / 改自定义变量 / 改引用类型 — `[00:03:02]`
4. 浮点精度：传递数据尽量用浮点数本身，**取整统一用服务端的正规节点做四舍五入** — `[00:13:53]`
5. 全局暂停（stop the world）是否可行？多人下玩家掉线/中退会让全局暂停卡死 → 优先"服务端先评估确实需要，再调用客户端" — `[00:09:15]` / `[00:15:24]`

### 6.5 "角色/物件不按物理预期动" → 查载体与参数步长

1. 要动**角色** → 只能用**角色扰动装置（力场器/弹射器/牵引器）**；**基础运动器组件只能作用物件实体** — `official-guide-concepts.md:3194`
2. 力场方向/范围不对：核对**内外球半径 + 内径朝向 + 内径速率**四项（力场以同心球为核心）— `:4286-4329`
3. 参数微调一律按 **0.01** 步长试边界（0.2 卡位 / 0.25 回中）— `BV1FksrzAEo7 [00:00:00]`
4. 需要"看不见的墙"：用空气墙（静态几何，编辑器摆放）而不是节点图——**我方 `assets:terrain` 能写静态几何，但围合尺寸仍要手摆实测**
5. 决策节点图/状态节点图的"物理感"不对时，先确认造物的**自主逻辑参数模板**（范围感知距离、视野类型、脱战距离、领地）是否配了 — `official-guide-concepts.md:954-1035`

### 6.6 "预算不够了" → 查官方编辑项范围限制

先查表（`official-guide-auxiliary-appendix.md:2002-2055`）再动刀：**运行时实体 1000 / 运行时列表 1000 / 编辑时列表 100 / 单实体自定义变量 500 / 单实体组件 100 / 全局计时器 50 / 单实体定时器 100 / 能力单元 20**。
另：循环太多会被**沙箱执行保护自动掐断**（表现为"循环跑到一半突然停了"，明明没写错）— `BV1d1UYB6EtS [00:03:07]`；客户端侧体感极限是**单次数万节点**— `BV1oaDrBuE11 [00:14:38]`。
