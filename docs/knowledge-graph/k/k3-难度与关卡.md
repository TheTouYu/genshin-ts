## 一、这是什么（定义与官方命名）

### 官方命名

千星奇域官方文档里**没有"难度"这个独立概念**（可复现核验：`grep -rn "难度" docs/ui-tutorial/*.md` 仅 1 命中，
且是无关义——`docs/ui-tutorial/official-guide-auxiliary-appendix.md:1178` "可以降低节点图逻辑的阅读难度"）。
官方把这一层拆成**一组编辑器管理项**（硬规则，官方原文整理稿）：

> `docs/ui-tutorial/official-guide-editor-interface.md:39`
> "…计时器管理、**关卡变量管理**、**预设点管理**、…**局内存档管理**、试玩临时数据管理、
> **实体布设组管理**、**单位标签管理**、…**路径管理**…"

即：官方侧「难度与关卡」= 关卡变量 + 预设点/复苏点/出生点 + 实体布设组 + 局内存档 + 计时器。
视频口语里叫 **"难度平衡" / "难度设计" / "难度节奏"**（切片原始维度：难度平衡⊕ / 关卡设计⊕ /
可重玩性⊕ / 对抗平衡⊕ / 难度节奏⊕）。

### 它在一句话里的位置

**玩法创意决定玩家会不会点进来；难度与关卡决定他玩不玩得下去、玩不玩得完、还想不想再玩第二遍。**
切片 32 条里，"引导不足/难度错位/可重玩性缺失"是唯一一类能**直接杀死已完成作品**的问题——
它不是加分项，是保命项（玩家原声见 §三·U1、§三·U2）。

## 三、规则与做法

### A. 先定难度框架，再填内容（顺序纪律）

**A1. 难度必须在设计具体内容（单位/技能/剧情/按键）之前定下来。**
在还没算清难度时就写几千字文案、编几个技能的数值，做到一半就会因工作量失控而放弃。

- 出处：`BV1ehYGzxEJe` `[00:06:59]` "你要考虑的是难度因为你如果你提前去考虑低一点每个事件的剧情啊、单位啊是内容、细节、放技能按哪个键啊哪个单位在哪个位置"
- 出处：`BV1ehYGzxEJe` `[00:12:25]` "规定好你的这个难度再去做这个内容细节这样的话，你的游戏制作流程才有可行性"
- 证据等级：个人经验（作者自述其魔兽地图做法）
- 落地写法：先写一页「难度框架」（档位数、每档数值系数、每档解锁/奖励），再去 `assets:` 里建内容。

### B. 起步把可控变量压到最少（降平衡难度的第一版配方）

**B1. 第一版只放少量"双方完全一样"的单位/英雄/塔，把可控变量压到最少。**
两边 20+ 个不同角色时平衡难度"非常非常高"；只调少量相同单位和机制时"很相对容易调"。

- 出处：`BV1ehYGzxEJe` `[00:10:53]` "你只调这少量的一样的单位和角色和塔和机制那就很相对容易调"
- 出处：`BV1ehYGzxEJe` `[00:10:06]` "你要是一开始你就给他设计了20几个角色可以选…那这个时候他的平衡性难度就非常非常高"
- 证据等级：个人经验

**B2. 角色数量靠后续版本慢慢加，每加一个就按本版本反馈调一次强弱。**

- 出处：`BV1ehYGzxEJe` `[00:13:11]` "我的角色也是一开始没有那么多的是慢慢的加的啊…每更新一个单位每更新一个角色再去根据这个版本的反馈去调加强或者削弱"
- 证据等级：个人经验

### C. 难度区间的两条红线

**C1. 太易 = 没有可重玩性。**"只要把装备/钱花完就能过"的难度，一次 20 分钟通关后再没人玩。

- 出处：`BV1ehYGzxEJe` `[00:08:33]` "你只要把装备把这钱花完就能过的那这种就属于呃，没有可重复性的"
- 出处：`BV1ehYGzxEJe` `[00:09:18]` "并且难度极低一次20分钟通关了之后就再也没人玩了"
- 证据等级：经验共识

**C2. 太难 = 门槛劝退。**"怎么玩都打不过"时只有几个硬核玩家还在挑战，大部分人不想再玩。

- 出处：`BV1ehYGzxEJe` `[00:09:18]` "你这个游戏如果太难的话门槛太高是太难了怎么玩都打不过的人家也不想玩了可能就几个硬核的玩玩家还在挑战但大部分人不想再玩了"
- 证据等级：经验共识

**C3. 正确答案不是"中间值"，是"上限低 + 可精通"：保证有难度且可精通，让玩家重复玩时能感到自己实力/胜率提升。**

- 出处：`BV1ehYGzxEJe` `[00:04:35]` "但是你又要保证你的游戏可精通精通有一定难度而且可以精通这个是为了提供你的游戏有重复游玩的价值能够为玩家重复游还能感受到自己实力提升操作提升胜率提升以及成就有成就感"
- 证据等级：经验共识（作者列为「合格 UGC 玩法六条件」之一）

### D. PVE 难度档位化：房主开局可选 + 高难度必须挂专属内容

**D1. 让房主在开局选择游戏难度**，这是 PV1 平衡难测的标准解法（PVE 自己测不出真实难度）。

- 出处：`BV1ehYGzxEJe` `[00:22:32]` "可以其中一种方法就是在游戏开始时选择游戏难度啊让房主来选择游戏难度让这个游戏有挑战性同时你在设计难度的时候你要设置高难度有特殊奖励低难度也不缺失内容"
- 证据等级：个人经验

**D2. 高难度不能只是"怪物数值变强"，必须附带专属内容**：特殊成就 / 特殊段位经验 / 特殊装备 / 额外经验（不必多，但要在普通模式之外"拉开差距"）。

- 出处：`BV1ehYGzxEJe` `[00:23:18]` "不能不能让高难度就纯粹高难度啊比如说高难度的时候可以获得特殊的成就啊特殊的段位经验或者特殊的装备或者说打怪有额外的经验"
- 证据等级：个人经验

**D3. 低难度不得缺失内容**（不能把剧情/关卡砍掉只留数值差）。

- 出处：`BV1ehYGzxEJe` `[00:22:32]` "低难度也不缺失内容啊等等"
- 证据等级：个人经验

### E. PVP 平衡必须用真实数据测，不许脑内推演

**E1. PVP 地图可以直接从对局数据看哪边更容易赢 / 哪些英雄更容易赢 / 哪些玩法更容易赢；非对称图就看逃亡者与追杀者哪边难赢，据此快速调平衡。**

- 出处：`BV1ehYGzxEJe` `[00:07:51]` "你可以直接通过数据来看一下哪边更容易胜利哪些英雄更容易胜利"
- 证据等级：经验共识

**E2. PVE 无法这样测**：作者自己太了解自己的图，"肯定能过"，所以必须另找测试者（作者原话："你自己去测试你觉得有太多价值吗没有太多价值"）。

- 出处：`BV1ehYGzxEJe` `[00:08:36]` "你想要一个单机闯关游戏来测试出平衡性那是非常困难的"
- 证据等级：经验共识

**E3. 数值细节不能靠一个人在脑子里推演改出来**，只能靠玩家人数上来后按数据持续更新（作者以英雄联盟的持续更新类比）。

- 出处：`BV1ehYGzxEJe` `[00:11:40]` "并不是你一个人在脑子里面去想游戏的数值细节就能改解决的啊这是不可能的啊"
- 证据等级：经验共识

### F. 非对称对抗：强度红线 + 四件套配方

**F1. 反方英雄的强度红线（可直接抄的量化口径）：一个反派英雄单位能打 2~3 个小兵，但 4~5 个小兵围殴就能打赢他。**
上限作用是"保证反方英雄不能单人通关"，下限作用是"让正方小兵看到他得赶紧跑"。

- 出处：`BV1ehYGzxEJe` `[00:16:14]` "他一个人他的实力平衡度是他一个人能打两个小兵或者三个小兵但是小兵可以四五个人来过来围殴他"
- 证据等级：个人经验

**F2. 9v1 平衡四设定（配方）：①双方英雄给复活次数（禁止"死了就退游"）；②反方每击杀一个正方真人英雄获得特殊资源，自行选择强化后续波次单位/建筑/自己英雄；③拆掉正方基地或大将即获胜（正方英雄还活着也算输）；④正方死亡过多则敌方普通小兵与将领大幅变强，正方只能点投降。**

- 出处：`BV1ehYGzxEJe` `[P9 00:10:03]` "每打死一个正方英雄就是真人的啊真人都能获得特殊资源自行选择强化后续波次的单位"
- 证据等级：个人经验

**F3. 非对称图的平衡前提是"大家都有翻盘手段"。**非对称本来就可以不一样、不完全平衡玩家也能理解，"你只要保证不要太离谱就好了然后大家都有翻盘的手段"。

- 出处：`BV1ehYGzxEJe` `[00:13:13]` "它不一定好做平衡性但在我看来其实这个也平衡性也也还是算比较好做因为毕竟它不是对称的东西…你只要保证不要太离谱就好了然后大家都有翻盘的手段"
- 证据等级：经验共识

**F4. 不对称对抗是"优先级很高"的选型**，因为它天然允许不平衡，比对称竞技好调。

- 出处：`BV1ehYGzxEJe` `[00:13:13]` "然后大家都有翻盘的手段啊或者有一些特殊的手段去逆转形势啊然后再经过一段数据观察可以去加强哪一方的一些阵营等等反正这个游戏这这一类我是非常推荐的我到时候做的时候优先会考虑这一类游戏"
- 证据等级：个人经验

### G. 人数适配 = 难度要素

**G1. 同一张图必须给 2 人局和 4 人局不同难度：怪物血量不同或机制不同。**
官方有自动匹配系统（独狼可匹配陌生人），所以不必担心"没人联机玩不了"，但联机程度越高越好。

- 出处：`BV1ehYGzxEJe` `[00:06:09]` "你可以在游戏机制上设计难度要素啊就是两个人开局四个人开局他的怪物的血量是不一样的或者说其他的一些机制不一样来保证不同人数的游玩啊都有合适的难度"
- 证据等级：经验共识

### H. 可重玩性三抓手（按作者给出的有效性排序）

**H1. ①随机要素要多**（敌人的随机性、难度的随机性）；**②持续更新加新内容**；**③人数适配**（见 G1）。

- 出处：`BV1ehYGzxEJe` `[00:06:12]` "如何提升这个可重复性第一个就是首先你这个游戏本身的随机要素一定要多啊随机的机制一定要多然后敌人的随机性难度的随机性或者难度的合理性一定要够第二个就是持续更新啊持续更新有新的内容"
- 证据等级：经验共识

**H2. 随机要素越少，地图越依赖"持续更新"续命**——两者至少得占一样，否则玩通即流失。
（PVE 劣势三连：一次性地图问题、平衡性难以测试、制作周期更长。）

- 出处：`BV1ehYGzxEJe` `[00:20:57]` "第一点就容易面临一次性地图问题开通啊玩通后玩家又迅速流失"
- 证据等级：经验共识

**H3. 内容量是硬指标。**只有一张图、玩一两轮就结束会被直接判内容量不足，评审建议是"多做几个图"。

- 出处：`BV1WXY96GETB` `[00:07:52]` "但是内容量比较少啊你这个游戏就玩一两轮就结束了啧希望那个啥啊希望可以做多一点啊"
- 证据等级：经验共识

### I. 关卡骨架：目标物 + 单向推进 + 卡关兜底

**I1. 给整关卡套一个明确的目标物当叙事骨架，让所有子任务围绕它收束。**
（样本：全部光点收集都围绕"重建星空"——散落星光 = 原料，最后蓄力发射星空收束全流程。）

- 出处：`BV16mJH6EEBE` `[00:00:52]` "散落的星光是重建星空的原料" ／ `[00:08:41]` "这需要一点改造蓄力发射绚烂的星空"
- 证据等级：实测

**I2. 单向推进：越过挡板就无法回头（一次性通过型通道），配合剧情推进（收缩阵加速、重创目标）制造不可逆的节奏压力。**

- 出处：`BV16mJH6EEBE` `[00:02:48]` "越过当向板就无法回头" ／ `[00:09:34]` "这意味着收缩增在加速看来我们成功重创了他"
- 证据等级：实测

**I3. 必须留一条显式的卡关兜底捷径，而不是硬要求所有人解完。**
（样本：谜题解不开时直接走同色门"自动通关"。）

- 出处：`BV16mJH6EEBE` `[00:13:16]` "你解解不开了就直接蓝色的踏开蓝色的门"

**S1. "融入景观会给大量路标、必然降低迷宫难度"这个取舍值得做。**
理由：不会让玩家因为"在哪都看起来一样的墙体"心情变差；且**能用玩家的操作惯性做视觉引导**，
反过来创造小难点（造景引导视线朝某方向，就在反面藏路）。

- 出处：`BV1Gj1jB1EQf` `[00:01:33]` "虽然从迷宫探索的角度来看这样的做法肯定会给你们提供大量的路标降低一定的难度但我觉得这一点还是挺重要的"
- 出处：`BV1Gj1jB1EQf` `[00:02:20]` "利用玩家的操作惯性来进行视觉引导反而可以用这个来创造一些小的难点"
- 证据等级：个人经验
- 进阶样本（同源）：为键鼠玩家量身定制坑——"一大堆连续向左转的路让你的手感到不舒服之后肯定会导致你接下来在可行的情况下向右走"。

### T. 其他可重玩性/热度机制（与难度间接相关，含冲突性结论）

**T1. 数值膨胀本身就是爽点**：即使经营数值不平衡，玩家快速攒钱、看钱变多、经营规模变大就会觉得有成就感。

- 出处：`BV18Ken6bEwT` `[00:18:29]` "你就算做到不平衡但是你可以快速把钱攒起来玩家看到数值膨胀啊也是很爽的"
- 证据等级：个人经验（与 C1「太易 = 没有可重玩性」形成张力，作者未消解，两个都保留）

**T2. 联机竞技要素会拖低推荐率**：输了的玩家会归因到"作者设计不合理"，推荐率必然低于无竞技压力的跑酷类。

- 出处：`BV18Ken6bEwT` `[00:09:15]` "避免不了有些玩家还是会存在嗯觉得这个作者设计的不合理导致他输了这种一个感觉所以推荐率肯定是不如前几个那种那么高的"
- 证据等级：经验共识

**T3. 模拟经营的可重玩性来源：每局重开都能有不同的攻略方法与体验**（且属休闲类里最"好玩"、不需要战斗、无平衡压力）。

- 出处：`BV18Ken6bEwT` `[00:20:02]` "每一局啊重新开局你又可以重新有不一样的一个感觉或者你有不一样的攻略方法不一样的一个体验"
- 证据等级：经验共识

**T4. "每张图都要重学"的玩法类型引导成本爆炸**：塔防的每张地图系统/建筑全新建，没有统一数值模型，
所以"每一把都要去做一个上手的一个教学"，对玩家非常耗时间精力——作者据此把塔防判为最不推荐。

- 出处：`BV1NWYE6LEDz` `[00:07:47]` "你每一把都要去做一个上手的一个教学啊引导然后每一把都要去学东西记东西啊对于玩家来说也非常耗费的时间精力"
- 证据等级：经验共识

### U. 玩家视角的验收线（K 轴指定输入）

**U1. 引导 + UI 清晰度是"能玩"与"玩不下去"的第一道门，优先于玩法深度。**

### Z. 硬规则：官方范围限制（设计关卡前必须核对的数值上限）

来源：`docs/ui-tutorial/official-guide-auxiliary-appendix.md:2011-2018`（官方教程原文整理稿，**硬规则**）。
与本轴直接相关项：

| 名称 | 限制范围 | 对难度/关卡设计的含义 |
|---|---|---|
| 运行时实体最大数量 | **1000** | 波次总量 + 同屏单位数的真实天花板（不是 3000） |
| 编辑时实体最大数量 | 3000 | 编辑期可铺垫的实体总量 |
| 编辑时实体布设组最大数量 | **500** | 用布设组切难度档/波次时的组数上限 |
| 单个实体布设组内动态物件最大数量 | **100** | 单个波次最多 100 个动态物件 |
| 编辑时复苏点最大数量 | 200 | 高难度"死亡惩罚"设计空间 |
| 编辑时出生点最大数量 | 200 | 多分场景/多路线关卡的出生点预算 |
| 编辑时预设点最大数量 | 2000 | 巡逻/演出/触发点位预算 |
| 单个预设点的单位标签最大数量 | 20 | 用标签分组控制难度时的粒度上限 |
| 全局计时器最大数量 | **50** | 关卡节奏/限时挑战的计时器预算 |
| 编辑时玩家列表最大长度 | 8 | 人数适配（G1）的上限口径 |

> 同表另有与本轴弱相关项：地块数量上限 1200、物件编辑缩放上限 50、运行时列表内元素最大数量 1000、
> 编辑时列表内元素最大数量 100、单个实体运行时自定义变量最大数量 500、自定义变量最大成员数量 500。
> 完整表见 `docs/ui-tutorial/official-guide-auxiliary-appendix.md:1998-2040`。

**Z2. 碰撞触发器范围内的实体数量上限 = 100**，且"达上限后不会触发进入碰撞触发器时的事件"
——用"范围内实体列表"做难度判定时，超过 100 个实体后事件直接不触发，是**静默失效**类陷阱。

- 出处：`docs/ui-tutorial/official-guide-auxiliary-appendix.md`（"碰撞触发器范围内的实体数量上限 | 100 | 使用获取范围内实体列表的时候只能拿到最早进入的 100 个实体，另外达上限后不会触发进入碰撞触发器时的事件"）
- 证据等级：硬规则
