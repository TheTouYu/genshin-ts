## 一、这是什么（定义与官方命名）

**千星官方把这个轴叫「协作模式」**——2026 年新版本上线的官方功能，原名口径：

> `BV1qkYa6zEVP` `[00:00:00]`「新版本将会上线协作模式功能起匠们可以邀请伙伴一起编辑存档分工协作各展所长」

（「起匠/漆匠/奇将」均为字幕对**奇匠**的错字；该 UP 的标题解读是「协作模式倒是好理解，从个人开发升级到团队开发嘛」。）

**它解决什么问题**：千星奇遇的分工不是「一条直线写代码」，而是四个阶段各自带工种——**预制作（策划案/市场调研/定位）→ 制作（程序/美术/音效/文案）→ 测试 → 发布与运营**。不按这条线组织，典型失血点是「上一秒写的功能，下一秒就找不到了」。

> `BV11d6rB4Ejc` 首条热评（29 赞，《方神2》作者自述）「整个项目管理一塌糊涂，上一秒写的功能，下一秒就找不到了」（证据等级：**实测**，见 `COMMENTS-INSIGHTS.md:24`）

**本轴的两条主线**：
1. **组织线**——人怎么分工（含官方的协作模式）、成本怎么算、进度怎么不失控；
2. **交付线**——四阶段怎么排、测试怎么做、发布后怎么运营、版本怎么迭代。

**与其他轴的分界**：玩法怎么选型属 K1，引导属 K2；K7 只管「把这件事组织起来做完并持续维护」。单个 bug 的排查方法属 K8。

## 三、规则与做法

### ① 千人千面之前：先确定你是「一个人」还是「一个团队」

**一个人的队伍 = 全岗位叠加**，这是基线而不是例外：

> `BV1ehYGzxEJe` `[P2 00:00:47]`「如果以一个人的视角来做游戏的话那你就要兼游戏制作人的还有游戏整个团队的角色啊包括策划研发程序美术设计然后销售运营全都是你啊」
> 证据等级：**经验共识**（1809 赞评论同口径：「要是一个人能统一实现美术、演出、设计、功能实现，那真的是神人」，`COMMENTS-INSIGHTS.md:15`）

**单人不要许愿请 CV 配音**（个人/小团队不可能请 CV，AI 配音合法性待商榷）；因此做剧情类必须把力气放在**演出和分镜**上：

> `BV1ehYGzxEJe` `[P2 00:10:49]`「不能只会写文案」
> 证据等级：**个人经验**

**协作模式之前的过渡态**：官方上线 `协作模式` 前，多人项目靠「一个人交一块」——`BV19ab76LE6c` `[00:06:16]` 的神圣传说实例：大白兔做地编 + 解密逻辑，基金霜做一部分元件与解谜，主讲自己做文案/时装剧情/测试/对接官方/热更新（证据等级：**实测**）。

### ② 千星特化分工表（五岗 + 一个「催进度」）

| 岗位 | 千星里的边界 | 出处 |
|---|---|---|
| 策划 | 含数值策划；**兼任运营**（千星删去独立运营岗） | `BV19ab76LE6c` `[00:08:39]` |
| 程序 | 玩法实现 | 同上 `[00:07:53]` |
| 美术 | **最基础的美术 = 地编**（负责游戏地图的设计与搭建）；要搓 UI 另算 | 同上 `[00:08:39]`「美术的话最基本的美术的话就是底边如果你要搓UI的话那另说…最基础的美术的话就是地编就是负责游戏地图的设计」 |
| 测试 / 质量保障 | 反复测试保质量 | 同上 `[00:07:53]` |
| 音效 | **不需要**（见下方硬规则） | 同上 `[00:07:53]` |
| 进度负责人 | 人一多就另设一个「去催进度」的人，**保证作品按时发布** | 同上 `[00:08:39]`「另外一个说法呢就是去催进度的…保证你的作品能够按时按时发布」 |

**硬规则（可直接依赖）——千星音效定死，不要排音效岗**：

> `BV19ab76LE6c` `[00:07:53]`「因为铅芯里的音效是定死的不需要你去额外设计设计音效」
> 证据等级：**硬规则**

**四角色的行业侧印证**：1809 赞评论总结优质作品的四个角色 = **美术 / 演出 / 策划 / 实现**（`COMMENTS-INSIGHTS.md:15`，证据等级：**实测**）。与上表一致，只是把「地编」上提到「美术」、把「文案+分镜」显化为「演出」。

### ③ 立团队前先算三笔成本账

这是 `BV1ehYGzxEJe` 整期的主干（证据等级：**经验共识**，多处以「劝退」口径给出）：

**账一 · 时间成本**
> `[P2 00:07:39]`「你如果想做出这样一个地图你得半年起步啊半年起步一个人来说…你如果是技艺不精啊那半年可能都说快了」
> `[00:03:48]` 简单地图（解谜/塔防随便摆单位）成不了：「你如果按这种水平去做的话其实是你这个地图是成不了的」+ **维护时间成本**：上线后还要持续更新内容或平衡性调整

**账二 · 人力成本**
> `[00:08:24]`「招人就是要钱的啊比如说你再招一个人每个月你要给他发几千块」
> `[00:09:10]`「如果是一个人几千块那十个人几万块…还要提供办公室」；降低成本的唯一现实做法 =「除非是你自己本身就是大牛你让他们做到完成之后让他们退出啊后面更新你自己一个人来完成」；且「这个就属于你真的去招人的话就真的属于创业阶段了这种创业全是风险」

**账三 · 管理成本**（最容易被低估）
> `[00:10:42]`「有了固定收入你没有你的完整的一个绩效这个考核…管理制度那你怎么样去管理这个效率问题」；「你让他在家里干人家告诉你他在家里干了八个小时很辛苦其实他只是干了一个小时其他时间都在玩游戏啊在摸鱼」；「你这个地图因为这个人的拖延或者某些人的拖延某个模块一直出不来」+ 请假理由（母亲生病/亲戚结婚）

**找人凑队之前先想清楚的三件事**：
> `[00:09:57]`「很多人在评论区说想找个合作伙伴…不要工资的想法…谈钱伤感情你觉得这种可能吗」→「你将面临的是多人协作效率问题」
> `[00:11:28]` **保密与抄袭**：「人家把你的这个工程文件拷走啊如果你这个工程文件很有价值的话」；`[00:12:13]`「拿去自己改或者发给别人…偷偷挂上咸鱼去卖」「别人有一个好的团队两下把你的地图升级变成他的东西」
> `[00:12:13]` **分工要按能力配**：「你怎么样去管理谁负责什么…把有能力的人用在刀刃上啊然后能力弱的人也有他的用处你这都是都是管理的问题」

**收益账（决定你要不要立团队）**：
> `[00:14:31]` 两条路径对比：「如果你是填了这个团队问卷你是被米哈游吃掉啊进去线下驻点去创作地图的那种啊那确实有收益」vs 普通网友找人凑队 = **不知道收益、无法计算投入**
> `[00:15:17]`「第一天就几十个人玩第二天几个人玩…你觉得米哈游会给你分钱吗可能像B站的这个视频板块类似…一点点播放量给你一几分钱」；「你自己去干就可以忽略这一点…你是为了提升技能你是不给自己发工资」
> `BV18ARnBVEZP` `[00:00:46]`（日语源调侃口径）线下驻点/签约化的代价是「被电话找上门、IP 落到上海、离开家乡」——证据等级：**个人经验**，仅供风险意识，不是规则。

**入坑时机（可逆决策，影响成本）**：
> `BV1ehYGzxEJe` `[00:16:29]` 建议晚点入坑等公测后：「第一时间参与的话他的这个千星沙箱这个系统肯定有很多 bug 或者说没有完善的一些模块啊这个时候是需要参与内测的一些创作者去跟米哈游共同去完善的」；但「你晚的话可能就吃不到第一波流量了就可能说每个玩法类型都已经有大佬已经做了很成熟的地图了」
> `BV1UCxWzhEcx` `[00:14:51]` 同一现象的编辑器侧口径：「目前我体验到新形奇遇还是处于测试阶段有一些功能和素材还没有完全开放…官方在前阵中已经表示揭阳奇遇会是一个长期项目会持续的更新迭代」
> 证据等级：**个人经验**（取舍类结论，两个方向都保留）

### ④ 四阶段里，预制作的权重最高

> `BV19ab76LE6c` `[00:50:17]`「我会跟你说就是…每个阶段其实都挺重要的…但是呢我会觉得话它最重要的部分应该是一直做的阶段」（指预制作）
> `[00:51:03]`「一个游戏的玩法和创新是奠定了整个游戏的一玩法…整个游戏的世界观的构建是奠定了整个游戏的灵魂」；「你的游戏能够打破出打破常规开发新玩法那相信你的热度是不会太差的」
> `[00:51:03]`「制作的人要考虑只要照着策划案做就好了那写策划案的人考虑的就要很多了」
> 证据等级：**个人经验**（单一讲师的主观权重判断，但两个源同向：`BV11d6rB4Ejc` `[00:00:00]`「我将最重要的三个点放到了最上面了其中啊越靠上的越重要」）

**预制作的产物 = 一份可以被执行的策划案**，后面 ⑤ 的 checklist 测试直接以它为准。

### ⑤ 测试 = 三层 + 反馈单 + 严重性分级（可直接照抄的流程）

**层级一 · 烟雾测试（smoke test）**——基本操作与基本指标：
> `BV19ab76LE6c` `[00:10:56]` 第一层「测游戏的基本操作比如说呃在原神里面你会不会按WASD在键位正确的定位下这个角色动不了了或者你按E或者你按Q」
> `[00:13:17]` 最后一步是**基本指标的反馈**：「生命值…像你的饱食度…能不能被正常显示因为有的时候你真的可能自变量就装错了」
> `[00:14:02]` 分工：「烟雾测试一般来说电脑端的会由创作者完成…其他设备端的然后你们测一测就好了」；「如果烟雾测试都过不了的话那绝对会有差评那玩家就来帮你测了」
> 证据等级：**经验共识**

**层级二 · 逻辑测试（最理想 = 按策划案列 checklist 一条条测）**：
> `[00:14:48]`「我们会一般来说你可以列个表杆然后对着这个目标然后一条条测试然后checklist那比如说…这个UI能不能正常打开同时打开U和AIQ会出现bug然后或者有没有一些四法场连招可以不小心卡出地图」
> 现实折扣（主讲自己也承认）：「实际情况就是很多的创作者的话不程序他并不写…如果程序自己都不想管的话那其实你花再多心思他可能后面连改都不会改」
> 证据等级：**经验共识**

**层级三 · 回归测试（retest）**——「声称已修的 bug 是否真的修了」：
> `[00:10:56]`「创作者说我这个bug修了然后你上号一看我去这个bug怎么还在然后这这种的话测试的话就是声称和被修复的bug是否被修复」
> `[00:15:36]`「我们会建议的话及时写一下更新日志」；回归 = 看更新日志列出的条目逐条复测 + 各设备端单测一遍
> 证据等级：**经验共识**

**不能漏的两条红线（测试阶段）**：
> `[00:21:45]`「一个不能给速通不能给速通不能给速通然后第二个就是…观察有没有多设备的适配然后多语言的适配」
> `[00:25:34]` 结算四态 **未完成 / 完成 / 胜利 / 失败**——只有「未完成」不算结算（速通 bug 的判据就在这）
> 证据等级：**实测**

**除 bug 外还要测「你自己的直观感受」**（引导/交互是否给够）：
> `[00:22:30]`「除了你作为一个测试那除了bug之外你还得测点其他东西比如说你自己的直观感受…而对于作者来说每个游戏的每个玩家第一次接触游戏后的反应是非常宝贵」
> 实例：千星右上角 UI 一开始**不是原石形状**，玩家不知道哪个是哪个，后来改成原石形状
> 证据等级：**实测**

**反馈单（bug 提单）的字段——照抄即可**：
> `[00:15:36]` 正式反馈至少五项（主讲说其实六项）：「第一点就是说给这个给你这个问题起个总数…然后这个标题概括那接下来是给出我们的复线步骤」，加**预期情况 / 实际情况 / 严重性**，第六项**优先级**（主讲认为与严重性区别不大）
> `[00:17:54]` 实际做过的提单还含：**测试者名字**（「方便我们后面统计的时候然后发福利的」）、测试日期（用来标明测的是哪个 version）、**设备端**（原神多设备）、**多语言**、**建议修改方式**
> 轻量替代：`[00:20:13]`「你可以直接录屏录屏最好…直接发给对应的程序或者发给一般来说的话测试或者或发给作者」
> 证据等级：**实测**

**严重性分级（只有两档，口径明确）**：
> `[00:18:39]` **P0 = 不修不能玩**的 bug（例：手柄按键完全冲突——一个 UI 三个按钮都绑手柄同一个键，游戏玩不了）；**P1 = 能玩但有恶劣影响**（例：UI 重叠）
