## 一、玩法定义

**一句话**：玩家在带造景的迷宫中探索，走出去即通关；沿途藏着若干隐藏收集物，集齐可换取场景上的额外回馈。

**核心循环**：探索 → 遇见路标/造景 → 判断路线 → 收集隐藏 → 走出迷宫 → 结算（集齐则解锁回馈）

## 二、设计决策与依据（**每条都引图谱**）

### 决策 1：造景即路标——难度让位于体验

- **做什么**：在迷宫路径沿线放置差异化造景元素（灯柱/树/钟/花坛等），使任何一段路都不会"看起来和别处一样"。
- **依据**：源 `[00:01:33]`「我首先第一点考虑的就是在迷宫的搭建及设计过程中融入景观的元素，以至于大家呢在探索迷宫的时候不会被这个在哪都看起来一样的墙体整的心情很不好」；同源 `[00:01:33]`「虽然从迷宫探索的角度来看这样的做法肯定会给你们提供大量的路标降低一定的难度，但我觉得这一点还是挺重要的」
- **图谱佐证**：`docs/knowledge-graph/k/k2-引导与上手.md`（引导优先于玩法深度）；`k3-难度与关卡.md`（难度节奏要"舒服"）
- **玩家侧判据**：`COMMENTS-INSIGHTS.md` 378 赞「没有清晰的引导和UI，奇遇本身再牛逼，我都玩不下去」
- **反例**（必须避免）：源 `[00:00:46]`「高难度 + 尘歌壶没负荷做装饰，导致作品玩着晕而且非常压抑」→ 作者因此搁置整个作品。

### 决策 2：邪修·用操作惯性做视觉引导，再反向造难点

- **做什么**：在某个方向放一小块吸引视线的造景；在它的**反面**藏一条可选路径。
- **依据**：源 `[00:01:33]`「我学到了利用玩家的操作惯性来进行视觉引导，反而可以用这个来创造一些小的难点」
- **图谱归位**：`k3-难度与关卡.md` / `d2a-模型与实体资产.md`（造景与摆位）
- **注意**：这是**双向**工具——正向用于引导、反向用于设伏，设计时要明确当前是哪一种。

### 决策 3：邪修·"手累坑"——用身体疲劳替代视觉提示

- **做什么**：安排一段连续向左转的路径，让操作手感累积不适；其后在可自由选择处，玩家会**自然倾向向右**。
- **依据**：源 `[00:02:20]`「有好几个坑就是专门为键盘鼠标量身定制的，就比如说一大堆连续向左转的路，让你的手感到不舒服之后，肯定会导致你接下来在可行的情况下向右走」
- **前提**：源 `[00:02:20]`「有好多人说 up 主你是用手柄玩的，操作习惯和我们这些用键盘鼠标的不太一样，你放心这次做迷宫的时候我可考虑到这一点了」→ **操作习惯差异必须专门适配**（经验共识级）。
- **我方约束**：本复现按**键鼠操作**设计；若日后要兼用手柄需重新评估。

### 决策 4：隐藏收集物的双层结算

- **规则**：正常走出 = 正常通关；拿齐全部收集物 = 额外回馈（隐藏成就 / 场景惊喜）。
- **依据**：源 `[00:03:07]`「如果你正常走出去就是正常通关，如果你拿到了这些收集物就可以获得一个隐藏成就」
- **可重玩性**：这是「一次通关后还有理由再走一遍」的来源，见 `k3-难度与关卡.md`（可重玩性）。

### 决策 5：邪修·没有自定义文字时，用**空间布局**传达"有隐藏，且有几个"

- **做什么**：把其中一个隐藏**明晃晃地放在路中间**，并让它**对准对面的钟**——玩家由此推断"有隐藏"与"大概几个"。
- **依据**：源 `[00:04:40]`「很简单，只需要把其中一个隐藏明晃晃的放在路中间，并对准对面的钟，好了，游戏第二阶段开始」
- **背景**：源 `[00:03:53]`「当时没有自定义文字功能，所以无法用文字直接告诉玩家：这个游戏有隐藏，而且一共有几个」
- **我方能力对照**：`_CAPABILITY.md` D3 条目「无字符串拼接」→ 即便今天，动态文字仍要走打表映射（成本高）。
  **本复现沿用空间布局方案**（更优雅，且规避打表成本）。

### 决策 6：隐藏成就的门槛前置检查（**踩过的坑**）

- **事实**：源 `[00:03:53]`「你目前有这么一个叫做奇想等级的东西，达到四级的时候你才可以做这种的隐藏成就」；同源 `[00:03:53]`「结果呢接下来就被官方背刺了一下」
- **处置**：本复现**不依赖官方隐藏成就能力**（等级门槛 + 我方无此 CLI）。
  回馈改为**节点图可达的场景变化**——这正是源作者的替代方案：源 `[00:03:53]`「直到我学会了连线，感觉上又瞬间解锁了一大堆新的创意，我就想啊，如果让找齐隐藏的玩家能获得一些场景上的小惊喜也还不错吧」
- **图谱佐证**：`k6-平台与生态.md`（等级门槛硬规则）；`ATOMIC-RULES.md` R8。

### 决策 7：不依赖局内存档

- **依据**：`ATOMIC-RULES.md` R8——局内存档需结构体列表，我方结构体类型创建与 DSL 拼装均 🔴，且官方有 LV4 门槛 → **长流程养成类不可落地**。
- **处置**：本复现为**单局玩法**，进度不跨局保存。这正是把能力约束转成设计约束的例子。

### 决策 8：难度节奏——必须给回头路

- **依据**：玩家评论 `COMMENTS-INSIGHTS.md:757赞`「这次可能是为了休闲目的**没有防回头路**，总之整体难度控制得很舒服」→ 作者是**有意**不防回头路的。
- **处置**：不设置单向门/不可逆落差，允许玩家回退重走。

### 决策 9：多人友好（可选加分项）

- **依据**：源 `[00:03:07]`「因为找隐藏这件事大家一起上可能会更轻松，所以后面补了多人相关内容」
- **处置**：本复现预留不阻碍多人同时游玩的设计（不锁门、不做单人独占判定），但**不实现**多人专属玩法，登记为后续项。

## 三、实现拆解

| 层 | 内容 | 我方手段 | 状态 |
|---|---|---|---|
| 几何 | 迷宫墙体、地面、造景元素 | `assets:entities` **import（root 5 场景实体批量创建）** + `assets:static-assemblies` | 需实做验证 |
| 判定 | 进入隐藏物范围 → 计数；走出迷宫 → 结算 | 服务端节点图（`g.server({ type: 'entity' })`） | 可做 |
| 回馈 | 集齐后场景变化（灯亮/门开/造景变化） | 节点图 + 实体组件操作 | 可做 |
| 引导 | 造景路标 + 空间布局 | 设计层面，非代码 | 可做 |
| UI | 收集进度提示 | **不用动态文字**（规避打表映射）→ 用图标/亮度/实体状态 | 可做 |
| 存档 | —— | 明确不做 | 规避（R8） |
