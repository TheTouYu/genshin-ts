## 背景与动机

`lights-out` 现有 v4.1 版本只有 **3 关**（3×3 → 4×4 → 5×5），对新玩家而言入口门槛偏高，且在 **点击反馈、通关动画、管理台交互** 三方面缺少强化。

本升级方案的目标是：

1. 将关卡数量扩展为 **7 级**（其中 6 级已实现，第 7 级挑战关待后续批次）；
2. 引入 **参数化关卡配置表**（`levels.ts`），把所有关卡的尺寸、间距、起源坐标、胜利条件、预置掩码等常量集中管理；
3. 通过 **统一的灯柱玩法图模板**（`lamp-graph.ts`）将 **即时点击反馈**（短暂旋转）、**波浪式通关动画**（顺序点亮）以及 **预置灯阵**（位掩码）抽象为一次可复用的实现；
4. 同步改进 **管理图**（`game-manager.ts`），实现 **动态关卡创建 → 波浪动画触发 → 延迟清理 → 下一关创建** 的完整闭环；
5. 预留后续批次：管理台交互扩展（重开 / 返回 / 提示）、文本气泡 / 光源组件接入。

### 3. 管理图（`src/game-manager.ts`）

| 步骤 | 触发 | 行为 |
|------|------|------|
| ① | `whenEntityIsCreated` | 打印 `manager-ready`，等待玩家交互 |
| ② | `whenTabIsSelected` | 调用 `buildLevelBlock(f, self, LEVELS[0])` 创建 **第一关**，打印 `level1-ready` |
| ③ | `onSignal(level_clear)` | 控制台旋转庆祝、广播 `win_wave(level)`、计时 `wipe{level}`（灯柱清理）、计时 `build{next}`（下一关创建）、打印 `level{n}-complete` |
| ④ | `whenTimerIsTriggered` | 6 关构建链 + 6 关灯柱清理链 + `win30` 结算链 |

## 风险与缓解

| 风险 | 触发条件 | 缓解措施 |
|------|----------|----------|
| `for (let k = 0n; k < n; k++)` 在 DSL 内部是否支持运行时上限 | 若 stage1 编译器将 `k < n` (n 为编译期常量) 视为 `finite_loop` 而不展开为多层节点，则可能导致编译失败 | 通过 `npm run build` 已确认 lights‑out 示例无 TS 错误；编译后 `gsts assets:node-graphs nodes` 将进一步验证节点数（若超 3000，需改回手写 createPrefab 列表） |
| `presetMask` 位运算 `for (let i = 0n; i < indexInit; i++) { maskShift = f.division(maskShift, 2n) }` | 同样可能编译失败 | 同上 |
| `lamp_wipe` 未注册导致游戏拒载 | 注入时缺信号注册 | 注入前先 `gsts assets:signals register lamp_wipe --write` |
| 新增 prefab 实体未配置 `tabBar` | 编辑器缺组件 | 在编辑器中为 1077936200‑6202 手动添加 tabBar 选项（半径 1.0/球心 y1.2），参考 v4.1 配置 |

## 关键实现发现（可复用经验）

1. **编译器入口检测要求内联 `.on()` 链**：`hasNodeGraphEntryCall`（`src/compiler/ts_to_gs_transform/index.ts`）只在源文件里检测到直接的 `g.server(...).on(...)` 调用时才标记 `@gsts:entry`。通过 helper 函数（如 `makeLampGraph(LEVELS[i])`）返回的图**不会被识别为入口**，导致 Stage 2/3 静默跳过该文件（`.gs.ts` 生成但 `.json`/`.gia` 不生成）。**结论**：关卡图必须内联 `g.server().on()` 链，或由生成器（`tools/gen-levels.mjs`）产出内联文件。

2. **int×float 乘法需显式转换**：`f.multiplication(int, float)` 会报 `Generic parameter not matched`。需先 `f.dataTypeConversion(int, 'float')` 再乘。`f.float()` 不是 `f` 对象的方法（是全局工厂），不可用。

3. **位掩码取位避免 `let` 重赋值循环**：`let maskShift = 0n; for(...) { maskShift = f.division(...) }` 会报 `cannot store value of type any in LocalVariable`。改用 `f.exponentiation(2n, index)` 求 `2^index`，再 `f.division(mask, pow2)` + `f.moduloOperation(..., 2n)` 一步到位，无循环、无重赋值。

4. **handler 内禁用 JS 数组下标**：`LEVELS[i]` 在 handler 闭包内会被 Stage 2 当作图节点解析而失败。需在模块顶层用 `const L1 = LEVELS[0]` 等解析期常量，handler 内引用 `L1`。
