# ADR-0006: 元件继承模型与批量更新 / 差异化保留

把 CLI 的元件操作从"各命令各自为政"收敛为统一的**三层继承模型**，支持"改一个元件定义 → 同步元件实例 + 所有引用实体"，并保留实体独属修改（transform / 颜色 / 额外组件）不被覆盖。

**Status**: accepted（五轮编辑器差分闭合 wire 规律，2026-08-22）

## 背景与问题

GIL 里"元件"实际是三层，CLI 各命令对它们的处理不一致：

| 层 | 用户概念 | 位置 | 语义 |
|----|---------|------|------|
| 元件定义 | **"元件"（本体）** | root4（f8 组件槽） | 元件的真正结构，删除实例后仍存在 |
| 元件实例 | "元件页面模型" | root8（f7 组件槽） | 所见即所得的编辑辅助，可删 |
| 场景实体 | "实体" | root5（f7 组件槽，f2 引用 prefabId） | 游戏实际读取的摆放实例 |

现状问题（2026-08-22 魔方"改了元件但游戏没生效"实证）：

- `convertPrefabStatic`（静态/动态切换）**已做** root5 实体联动（`gil_prefabs.ts` line 353-375）。
- `applyStaticPrefabUpdate`（通用组件写回，`assets:static-assemblies` 的 updates 入口）**漏了** root5。
- `applyTabOptionsUpdate`（选项卡）曾漏 root5，已补但逻辑与 convert 重复。

根因：**没有统一的"三层联动"抽象**，每个命令各自判断是否联动 root5，导致漏写或重复写。

## 游戏概念（用户定义，2026-08-22）

1. **继承链**：官方预制定义（resID）→ 自定义定义（root4，引用官方）→ 场景实体（root5，引用定义）。
   玩家引用官方定义创建实体，或引用官方定义创建新定义（形成元件），再基于元件保存为新定义，形成继承。
2. **"元件" = 定义（root4）**：日常说"元件"指的就是定义；元件实例（root8）只是编辑辅助，
   删除实例后定义仍在（第 5 轮差分实证）。
3. **批量更新**：改一个元件定义，同步到元件实例（方便玩家观察）+ 所有引用它的实体。
4. **差异化保留**：实体可保留独属修改（坐标 / 颜色 / 额外组件）。批量更新时：
   - 未改动的属性 → 同步更新；
   - 额外增加或修改的部分 → 不受影响。

## 五轮差分闭合的 wire 规律（2026-08-22）

| 轮 | 编辑器操作 | wire 变化 |
|----|-----------|----------|
| 1 | 移动实体位置 | 只改 root5 实体 f6 槽1.f1（稀疏编码，0 分量省略）；不碰 root4/root8 |
| 2 | 实体加"铭牌"组件 | root5 实体 f7 新增 type 27；root4/root8 不变 |
| 3 | 改实体 tabBar 选项 | 只改 root5 实体 f7 tabBar 内容；root4/root8 不变 |
| 4 | 改"元件面板" tabBar | 只改 root8 实例 f7；root4/root5 不变 |
| 5 | 删除元件实例 | root8 移除；root4 定义 + root5 实体保留 |

**核心结论**：

1. **三层完全独立**，编辑器操作只改目标层，**不自动同步**。
2. **编辑器操作映射**：改"元件面板"→ 写 root8 实例 f7；改"场景实体"→ 写 root5 实体 f7/f6；
   root4 定义 f8 在编辑器里不被直接编辑（"保存元件"时由 root8 同步写入）。
3. **游戏实际读取** root5 实体 f7。
4. **差异化保留 = 假设 A（字段级差异）**：实体独属修改 = 实体 f7/f6 与定义 f8 的字段级差异，
   **无显式 override 标记**。加组件 = 实体 f7 多一个组件槽；改属性 = 实体 f7 内容变；移动 = 实体 f6 变。

## 核心设计

### 1. 统一三层联动抽象

抽一个共享函数，所有"组件槽写回"命令复用：

```text
syncComponentSlots(bytes, { prefabId, components | removeComponents | tabOptions })
  → 写 root4 定义 f8 + root8 实例 f7 + root5 场景实体 f7（按 f2 引用 prefabId 定位）
```

- **组件槽**（components / removeComponents / tabBar options）→ 三层联动。
- **transform**（position / scale）→ 只改 root8 实例，不联动 root5（场景实体 transform 是独立坐标层）。

`applyStaticPrefabUpdate`、`applyTabOptionsUpdate`、`convertPrefabStatic` 都走这一套，不再各自判断。

### 2. 批量更新命令

新增 `assets:prefabs update`：

```text
gsts assets:prefabs update <definitionId> [--prop ...] [--force] [--write]
```

- 默认（无 `--force`）：**差异化保留**——同步时跳过实体独属修改的部分。
- `--force`：**强制覆盖**——实体所有属性完全同步到定义（丢弃实体独属修改）。

同步范围（按用户确认）：
- 改 root4 定义（元件本体）→ 同步 root8 实例（方便玩家观察）+ 所有引用 root5 实体。
- 差异化保留：实体 f7 里"独属新增/修改"的组件槽保留，定义 f8 的"继承部分"同步。

### 3. 差异化保留的判定（已闭合）

实体独属修改 = 实体 f7 组件槽与定义 f8 的**字段级差异**（无 override 标记）：

- 实体 f7 里**定义 f8 没有的组件槽**（如 type 27 铭牌）= 独属新增，保留。
- 实体 f7 里**与定义 f8 同 type 但内容不同**的组件槽 = 独属修改，保留（除非 `--force`）。
- 实体 f7 里**与定义 f8 完全一致**的组件槽 = 继承，同步更新。
- 实体 f6 transform = 天然独属，永不参与同步。

## Considered Options

- **每个命令各自判断 root5 联动**（现状）：漏写/重复写，已否决。
- **统一三层联动抽象 + 批量更新命令**：复用 convert 已验证的联动逻辑，新增差异化保留，被采纳。
- **只做三层联动、不做差异化保留**：能解决"改了没生效"，但无法满足"实体独属修改不被覆盖"，不完整。

## Consequences

- `applyStaticPrefabUpdate` 补 root5 联动后，需回归验证不破坏现有 `assets:static-assemblies` 的 preview/plan 行为。
- 批量更新命令需明确"哪些属性参与同步"（组件槽 / transform / 颜色 / 变量），边界要清晰。
- 现有 `convertPrefabStatic` 的联动逻辑应迁移到统一抽象，避免三份实现。
- 差异化保留的"同 type 组件内容对比"需要精确的字段级 diff 算法（组件槽逐字节对比）。
