# ADR-0005: 魔方完整游戏关卡架构 = 五层分离 + 逻辑状态单一事实源

把 2×2 魔方 demo 升级为完整游戏关卡（胜利判定/结算/打乱/自动复原/重置），并为 2×2→3×3 自动求解铺路。设计约束：保留已验证的转动表现机制；受限环境（节点/列表/字典/运算上限）作为一等公民核算。

**核心架构（五层分离）**：

```text
输入层(选项事件) → 流程层(状态机/锁/模式) → 逻辑状态层(单一事实源)
                 ↘ 表现层(自旋+分段公转，纯视觉)
结算层(胜利判定 → setPlayerSettlementSuccessStatus)
```

关键决策：

1. **逻辑状态与表现完全解耦**：`applyMove(moveId)` 先更新逻辑状态（位置+朝向 int 编码），再驱动视觉。胜利判定、求解输入、复原进度只读逻辑状态，**不读实体位置/rotation**——组合旋转后实体 rotation 的欧拉表示有环绕歧义，不能作事实源（替代 v5.4 的"按物理坐标筛层"用于判定的角色）。
2. **逻辑状态编码**：`cornerPos[8]` + `cornerOrient[8]`（dict<int,int>，初始还原态），move 应用走离线算好的静态置换表（工具脚本 + CubeLib 交叉验证），3×3 扩展 corner+edge 共 40 int。
3. **自动复原 = 统一队列播放**：打乱（随机队列）与自动复原（求解器队列）共用同一套"队列 → 逐动应用 → 完成解锁 → 取下一动"机制；求解器本轮占位，2×2 轮实装。
4. **胜利判定时机**：每次转动完成解锁时（afterTurn 钩子）检查 `isSolved()`，未结算过则结算。
5. **数据驱动、禁止分支展开**：转动/表查询/队列一律循环+表（2400→240 节点实证）。

**Status**: proposed（待代码编译/注入回读/用户游戏核验后 accepted）

**Considered Options**

- 逻辑状态 = 复用实体物理坐标/rotation：组合旋转后层成员变化、欧拉环绕歧义，判定不可靠，被否决。
- 逻辑状态 = 独立 int 编码（pos+orient）：与 3×3 准备基线状态模型一致、是求解器直接输入、可离线验证表，被采纳。
- 胜利判定 = 转动结束后比对实体位置+朝向：float 精度 + 欧拉歧义 + 求解器无法回写，被否决。
- 打乱/复原各写一套播放：逻辑重复，被否决；统一队列播放被采纳。
- 表数据运行时计算：每次转动算 sin/cos 更新 8 块状态，节点贵；离线静态表（24×3 int）被采纳。

**Consequences**: 逻辑状态表正确性需离线工具 + 游戏核验双重保障；tabBar 需扩展 7-9 选项（资产更新，先以现有 6 选项临时映射测流程）；基础设施新增节点估算 ~420-510（2000 预算内）；求解器实装后节点/时间预算在 2×2 轮实测。
