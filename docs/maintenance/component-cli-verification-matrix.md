## 目的

添加 → 回读断言 → 游戏核验 → 移除 → 回读确认 → 游戏再核验。

  （components.md exp16 时代"删除组件仍未实测"的结论已过时，见该文件更新。）
- **模板自带组件 18/1/3/19/6/14 保护**：模板默认槽（UI 不可见系统组件 + 自定义变量/
  单位状态/特效播放），游戏可能依赖，**不纳入移除行**；矩阵只验证实验性添加的组件。
- 验证地图：1073741888（现有实体 1077936151 挂 5 图，**不动**；每行新建专用实体）。

## 执行步骤（每行一轮，一个可归因变量）

1. **建实体**：验证地图 1073741888 上 static-assemblies 建专用实体（模板 10005018 空模型，
   命名 `verify-comp-<type>`），记录 ID 与写回前 SHA。
2. **添加**（4/9/17/27/28/38）：`staticPrefabUpdates` 配 components → preview 候选 → 差分确认
   只动目标记录 → 用户确认 → `--write`（自动备份）。
3. **回读断言**：probe 脚本列槽（type + hex）+ component-diff 与编辑器样本对照。
4. **游戏核验**（用户）：按上表核验点操作；Beyond_Debug_Log 佐证（debug-log-investigator）。
5. **移除**：`removeComponents` 同上流程；回读确认槽数恢复。
6. **游戏再核验**（用户）：实体行为正常、无残留影响。
7. **沉淀**：每行结论登记 components.md（区分已验证/待验证层级）+ open-items 关闭。

## 验收标准

- 每行：CLI 回读与预期字节一致（自动证据）+ 差分只动目标记录 + 用户游戏核验通过（双方向：
  添加生效、移除恢复）。
- 全部行完成后：components.md 增补"CLI 操作矩阵"章节（含 12 类型操作能力表）。
- 证据分层报告：CLI 自动回归 / 差分回读 / 用户游戏核验 分开陈述。

## 风险

- 部分类型游戏核验点需要节点图配合（命中检测触发等）——核验点降级为"实体存在且地图正常"。
- 验证地图实体 1077936151 保持不动（现有 5 图实验），新建实体避免互相干扰。
- 写回后需用户重新加载地图/游戏（编辑器旧内存覆盖，B4）。
