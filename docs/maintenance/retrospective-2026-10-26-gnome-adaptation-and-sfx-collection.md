## 三、系统性根因（三条）

1. **观测先行缺失**：不先证明"我看的是当前屏幕 / 当前窗口 / 当前状态"，后面所有判据都建在流沙上。
   本轮最贵的一次（X11 读回陈旧 99.6%）污染了从 19:24 到 21:0x 的**全部**轮次——污染半径 = 所有信任过它的轮次。
2. **判据选可被伪造的代理**：`crc 变化`（被 MangoHud 计时器伪造）、`固定 y`（被滚动/展开移位伪造）、
   `像素差`（被悬停高亮伪造 5.42%）。凡"代理指标"必须先用**真值通道**对账一次再启用。
3. **"机制当文档"**：`ys-doc`、`list-collect.py` 等既有工具躺在仓库里，我却凭记忆重造残缺版本，
   于是把已被解决过的问题（坐标空间、位移估计、闭环纠正）重新踩了一遍。

## 四、方法论教训（用户原话逐字）

| 用户原话 | 落成的规则 |
|---|---|
| 「窗口都不对」「你截图的一直都是固定的」（另一会话 19:35/19:48） | 抓帧前先证"这是当前屏幕"：与 portal 真值比像素，>阈值即陈旧 |
| 「不要一直空分析，是需要自己尝试点击和切换窗口的啦」 | 真机任务先动手跑最小闭环，再做静态推断 |
| 「你直接 ocr 不太能发现问题，知道吗？」 | 看界面必须**自己看图**；OCR 只能当索引，不能当眼睛 |
| 「拖动不要太快，会触发加速移动导致不稳的。按住时间 1s 中消耗不了我们太多时间的」 | 慢拖定标：按住 0.8–1.0s → 分步 20–30px；168px≈4–5 行 |
| 「思路应该是：快速 ocr 识别这个列表对象，然后用 ocr 给出的每行的位置数据，用算法计算每行应该要移动多少…移动多了少了都可以自动纠正」 | 位移闭环 = OCR 框位 + 匹配估位移 + 残差回补（已落 `ys-doc`） |
| 「这个强制要求有键盘，你没抓住重点」 | 键盘导航只是特例；通用机制是"框位 + 位移估计" |
| 「翻页没有做好，需要单独验证翻页之后的 id」「还是从最上面开始吧」 | 翻页验收 = 索引序列核对；回顶判据 = 首行索引等于该类首号 |
| 「没检查列表当时的状态，它初始就不是在最上面」 | 任何列表操作前先取状态（首行索引 + 折叠态），不假设初始态 |
| 「为什么之前不用呢？明明是同一个东西」 | 动手前先查仓库有无现成工具（`ls tools/`、`--help`），再造轮子算返工 |
| 「你尽情发挥，上下文管够」 | 不以"上下文预算"为由跳过验证；预算不是降级借口 |
