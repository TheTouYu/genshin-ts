## 1. 这一轮实际做了什么

起点是「GUI 能力层没过完验收（门槛 ③④ 缺真实流程，本体状态未建模）」，终点是**一次架构级重新定义**。

| 类别 | 代表产出 | 关键数字 |
|---|---|---|
| **性能治理** | `ys-state` 模板匹配改走常驻；`failure-ledger` 注入用例去重；OCR 常驻 CUDA；新建 `tools/ys-perf` | 判态 3301→450ms；账本检查 523→328s；OCR 3673→**489~552ms**（5.5×）；容器层 113~149ms |
| **能力建设** | 本体三态（GAME_WORLD / GAME_PAIMON / GAME_ACTIVITY）；首个任务级意图；`ys-scroll-scan`；结构层；`containers[]` 容器层 | 真机 ESC 开合派蒙菜单 **8/8**；`paimon-to-activity` **3/3 rc=0**；派蒙网格 **19/19 tile** |
| **认知纠正** | 用户反馈轮 14 帧语料；两份设计文档；AGI 系统规格 | 容器级命中率 **1/124 = 0.8%** |

## 2. 错误谱系（我这轮犯的错）

### 2.1 六类错误

| # | 错误类型 | 次数 | 最重的一次 |
|---|---|---|---|
| 1 | **跳过结构，直接算指标** | 2 | ①盲滚：区域设成整屏 `0,180,2560,1100`、指针压在右侧详情图上，滚错容器 ②用「平坦度」解释 f09 漏检，被数据打脸——漏检行 std 23.2，比检出行的 28.7 **更平坦** |
| 2 | **阈值先写后回填** | 3 | `native-state` 阈值设 9000ms（实测 810ms，等于没检查）；性能目标 `<10ms`（`import numpy+cv2` 就 230ms）；结构缓存 `<10ms`（CLI 启动 70ms） |
| 3 | **不重新取帧就下结论** | 1 | 用户换了活动详情页，我拿上一张帧的分析继续讲 |
| 4 | **把「不存在」当结论** | 1 | 断言「派蒙菜单九宫格里没有千星奇域入口」——**实际在首屏之下，滚动后可见**（f06 顶 vs f07 滚后） |
| 5 | **把上限降级成下限** | 1 | 验收写成「场景 A / 场景 B」脚本用例；用户纠正：最稳的是**把用户在环的反馈轮**作为验收上限 |
| 6 | **自己写错的规范没验证** | 2 | ①gitignore 写成 `pattern  # 注释`（不支持行尾注释）⇒ 规则**完全没生效**，`git check-ignore` 零命中 ②模式带尾斜杠只匹配目录，目标是 PNG **文件** |

### 2.2 根因归并（两条）

**A. 用便宜的代理指标代替真实判据。**
四条同型：旧帧（替当前帧）、文本集合差异比例（替条目进出）、像素平坦度（替对象边界）、脚本用例（替用户在环）。
共同特征：**拿得到、算得快、但不是那个东西本身**。

**B. 先定阈值再测。**
三条同型，全部是「我觉得应该多快」而不是「物理地板是多少」。

## 3. 核心发现：工具输出的是文本行，不是界面结构

用户亲手操作 8→14 帧真实界面，我逐帧标注人眼可交互单元 **124 个**，`ys-screen` 只对 **1 个**给出 IoU≥0.40 的对象（一个巧合的头像）。

**117 个只能靠「某一行有文字」间接指到，6 个完全没有对象。**

### 3.1 检出率与底板特征强相关（14 帧）

| 底板特征 | 帧 | 检出率 |
|---|---|---|
| 不透明纯色 | f06/f07/f08 派蒙网格 | **95~100%** |
| 半透明 / 有装饰 / 有渐变 | f09 (5/10)、f10 (5/13)、f11 (8/12)、f12 (0/3)、f13 (~2/24) | **0~67%** |

⇒ **现行判据（flat+rect）只在最简单的那类界面上有效。这是判据假设的问题，不是阈值问题。**

### 3.2 六条缺口（跨四种界面形态都成立）

1. **图形元素不可见**：角色头像（f00 五个带✓、零文字）、左侧纯图标列（f06/f07）、红点角标、道具图标、角色立绘
2. **容器本体不可见**：f04 卡片只框住文字列，真实边界更大
3. **层级不足**：只有「面板→行」，缺「分区→卡片→行」中间两层；`parent` **实测全为 None**
4. **可点性不可判**：f05「前往纪游/前往颂愿」按钮与正文同为 `kind=content`；`affordance.clickable` 恒 `unknown`
5. **可滚判据**：单帧特征**全部证伪**（详见 §4）；唯一可靠 = **跨帧条目进出 + 整体位移**
6. **`state` 字段不存在**：f12「语言」高亮 0 检出；绝对亮度判据失效（背景自上而下 96→189 单调递增，语言 168 < 账户 173）

## 4. 被证伪的路线（留给后来者别重走）

| 路线 | 证伪证据 |
|---|---|
| 长直边投影找面板边框 | 活动页竖直长边候选列 = **`[]`**（面板是半透明+圆角+软边，没有 1px 硬边框） |
| 均匀面连通域 | 连成整屏一块（游戏背景本身平滑） |
| 同色块连通域 | 抓到的是天空/地面条带 |
| 颜色区域生长 | 从容器内空白起步仍漏到背景（`[0,48,1928,956]`） |
| OCR 抓 W/S 小图标判可滚 | 同一界面两帧一正一反 |
| 容器边缘纹理判裁切 | 真实被裁切时只有 **15.5%**（阈值 25% 判「没裁切」） |
| 末行距容器下沿判可滚 | 世界页队伍栏（**真不可滚**）也满足 |
| 同行尺寸离群判裁切 | 规则方向对（f01 右端 32px 残块），但**元素分割不稳**（16px 间距 + 8-邻接会连通合并） |
| 像素平坦度解释漏检 | f09 实测：漏检行 std 23.2 < 检出 28.7 |

## 5. 用户定义的架构（本轮最大的认知转折）

用户原话要点：

> 「我们这里 gui 模型的 agi 实现，应该提供，**所见所得，点击即达**的能力。」

> 「比如模型看到这一帧之后，选择加载编辑云阶的存档，那么会直接进入加载，**最终达到稳态，载入成功**。
> 我们**提高模型下一个状态**。并且**告知，中间还经历了加载状态过程**（比如多少秒，加载状态大致内容）」

> 「模型想关注某个局部细节，我们可以把**切割好的内容直接呈现**。（……在完成解析状态的时候，
> 我们已经完成了切割，并对每个局部执行 ocr，这样可以**并行**，并且**单个图片非常小，速度快，准度高**）」

> 「模型可能选择下一个动作，或者**增加一个加载判断条件**，设定什么情况算加载完成了。」

⇒ **这是对象检测（object detection）问题，不是图像处理问题。** 而本机算力实测过剩：
`9.3 GFLOP U-Net@640 fp16 = 5.3 ms`，比现有经典 CV（113~149ms）快 20~30 倍。
缺的不是算力，是**权重与标注**——而 14 帧语料正是标注起点。

### 5.1 融合而非重做

六个补充**没有一条需要新建子系统**，全是在既有接口背后换实现或加字段：

| 用户的补充 | 接到现有哪里 | 接口变不变 |
|---|---|---|
| 对象检测 | `ys-screen` 的 `containers[]` 内部引擎 | 不变 |
| 切块 + 并行 OCR | `ys-screen` 的 `run_ocr()` 内部 | 不变 |
| 返回下一稳态 | `ys-state`（稳态）+ `ys-do` 的 `post`（后置断言） | 不变 |
| 过渡态报告 | `ys-state` 补 `LOADING` + `ys-do` 账本（已在逐步记录） | 加字段 |
| 切片按需返回 | `ys-screen` 新增 `slices[]` + `ys-lookd` 缓存 | 加字段 |
| 判据注入 | `ys-do` 的 `post`：固定 `wait` 秒 → 可注入判据 | 加字段 |

### 5.2 验收体系（用户纠正）

| 层 | 判据 | 作用 |
|---|---|---|
| **下限（机器自动）** | 回归不退化 / 性能不超阈 / 判据单一源 / 失败账本每笔有防线 | 防止倒退 |
| **上限（用户在环，每轮）** | 用户实操 → 系统读 → 差异暴露 → 修 → 再实操 | **驱动进化** |

下限只能证明「没变坏」，定义「够好」的是**用户遇到的第一个不顺**。
脚本用例的位置是：**用户先发现 → 固化成脚本 → 防退化**，不是脚本先行。

## 6. 未闭合（诚实清单）

| # | 未闭合项 | 现状 |
|---|---|---|
| 1 | 卡片贴在彩色插画上检不出（f04 五张白卡、f05 任务卡） | 内部有花纹 E 中位 17.9~66.5、边界 ΔE 仅 5.5；**不输出，也无「未闭合探测器」** |
| 2 | `clipped` 恒空 | f08 顶部 174×64 vs 完整 174×156 是白给的数字 |
| 3 | 无 `LOADING` 态、无过渡态报告 | 模型看不到「正在加载」，只能从静到静跳变 |
| 4 | 无切片索引、无按需局部返回 | 每次调用重处理整帧 |
| 5 | 无判据注入 | `ys-do` 只有固定 `wait` 秒 |
| 6 | `state` 字段不存在；`parent` 恒 None | 状态是「组内相对属性」，没有组判不出选中 |
| 7 | 角标只认红色 | f08 皇冠角标漏检 |
| 8 | 退化整屏 panel | f09/f10/f12 均产出 `[0,0,2560,1440]`，会把所有文字吸走 |
| 9 | 粘连 | f13 `panel [520,826,1144,1122]` 把卡片和编辑按钮合成一个 |
| 10 | 「不存在」类结论无安全闸门 | 已被 §2.1 第 4 条实证踩过 |

## 7. 可复用的教训（写成触发条件）

| 触发条件 | 动作 |
|---|---|
| 要下「界面里没有 X」的结论 | **先滚全可滚区域**；单帧只能支持「这一屏没看到」 |
| 要设一个性能阈值 | 先测物理地板（导入/解码/启动），**由地板倒推**，不许先写后回填 |
| 要解释一个「为什么检不出」 | 先把候选判据逐条对着失败样本算一遍，**不许用直觉归因**（本轮被「平坦度」打脸） |
| 用户说「看」 | **必须重新取帧**；上一帧的结论不能当这一帧的事实 |
| 要写一个自动化验收 | 先问「这是下限还是上限」；上限只能是**用户在环**，脚本是下限补充 |
| 要写 gitignore 规则 | 用 `git check-ignore -v <path>` 验证真的命中；**行尾注释不支持、尾斜杠只匹配目录** |
| 看到「工具报了字段」 | 先确认它是**读数**还是**截断**（`controls` 恒 40 = `MAX_CONTROLS` 截断，不是「界面有 40 个控件」） |
