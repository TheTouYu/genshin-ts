# GUI「屏幕结构」识别：现状实测、结构输出设计、路线裁决

> **状态**：待验证（设计 + 实测；检测原型在 `.scratch/gui-arch-probe/`，未进仓，未接入 `tools/ys-screen`）
> **来源**：本轮在 `.scratch/gui-corpus/` 8 帧语料上的直接测量（命令见附录）；未涉及的结论一律标未闭合
> **读者**：接手 GUI 能力层的下一个代理；以及要决定"要不要上学习模型"的用户
> **语料**：`.scratch/gui-corpus/f00..f07.png`（2560×1440，7 个界面形态 / 两个 App / 滚动前后对照）
> **实测时间**：2026-10-18，仓库 `/home/h/genshin-ts`，GPU RTX 3060 Laptop（游戏占用 4.4/6 GB）

## 结论先行（全部为本轮实测读数）

1. **现有工具对「可交互单元」的容器级命中率 = 1/124（0.8%）**。我把 8 帧里人眼可点/可操作的 124 个单元逐个标了 bbox，`ys-screen` 只对其中 **1 个**给出了 IoU≥0.4 的对象（一个头像，且是巧合）；117 个只能靠"某一行有文字"间接指到，6 个完全没有任何对象。**工具现在输出的是"文本行"，不是"界面结构"。**
2. **容器检测的经典 CV 路线在"平坦皮肤"类界面上已经可用**：`flat+rect`（Lab 边缘能量 + 形态学闭 + 连通域 + 矩形度）在 f06/f07 派蒙菜单上 **20/20 与 18/18 个网格格子全部命中**（bbox 误差 <8px），对世界的平坦区假阳性（f06 3 个 + f07 4 个，共 7 个）用两条判据（同皮肤色兄弟 / 内含 OCR 文本）**全清**；仅剩的屏边条 `[0,0,120,1440]` 因内含 HUD 文本而存活，接 `ys-screen` 已有的 `_known_hud` 掩膜即可消掉。耗时 **33~41 ms**（0.5 缩放）。
3. **它在"卡片贴在彩色插画上"这一类上完全失效**（f04 的 5 张白卡、f05 的任务卡/药丸按钮）。实测原因不是阈值没调，而是前提不成立：卡片内部**不是平坦区**（卡内有波浪花纹与大图标，内部 Lab 边缘能量中位数 17.9~66.5），边界台阶只有 ΔE 5.5。LSD 线段检测在同一帧给出 **4578 条**线段，无法直接配对。
4. **滚动是"跨帧问题"，而且已经有干净解法**：按"同名文本的位移聚类"判，3 组对照帧全对——f02→f03 = **dy −120**（行吸附，活动列表步长 121px）、f06→f07 = **dy −688**（像素级平滑滚动，非行吸附）、f00→f01 = **只有 dy=0 簇**（列表没动）。成本 ≈ 0（复用 OCR 结果）。**单帧只能给 `unknown`**，这条现有设计是对的，本次实测支持它。
5. **<10 ms 在进程内不可达，且不必追**：`import numpy+cv2` 已 230 ms、`cv2.imread` 一张 2.5 MB PNG 78 ms——单次 CLI 的**地板就 >300 ms**。真实可达目标是 **常驻服务里 ≤200 ms/帧**（像素管线实测 155~165 ms + OCR 缓存命中 2 ms），相对现状 900~1638 ms 是 **6~10 倍**。
6. **学习型路线在本机不是算力问题，是资产问题**：一个 9.3 GFLOP 的 U-Net 在 640² 上实测 **5.3 ms fp16 / 7.3 ms fp32**（≈1762 GFLOP/s），算力绰绰有余；但**本机没有 ultralytics、没有任何权重、没有该游戏 UI 的标注数据**，且 GPU 已被游戏占用。→ 学习模型只能做"离线标注器 / 商品图标检测器"，不能当在线闭环的第一层。

## 一、交付 A：8 帧 × 人类可交互单元 vs 现有工具输出

### 1.1 我的数法

- 逐帧看图（不是看 OCR 列表），把**人眼可以点/可以拖/可以选**的矩形单元逐个记下来，判据：有可见的独立可点外观（格子/卡片/按钮/行高亮/头像/图标），装饰性立绘、★、缎带、"W/S"提示**不算**。
- "可机械 bbox 化"一列 = 我能给出稳定 bbox 的单元数（其余如"角色预览"图标与文字混排，边界主观）。

## 二、交付 B：结构输出设计（`ys-screen/2`）

### 2.1 分层与对象

```
L0  frame        2560×1440 帧 + sha256（缓存键）
L1  regions[]    屏幕分区（标题栏/导航/列表/详情/底部），**只用于粗定位，不当判据**
L2  containers[] 面板 / 卡片 / 网格组（**带皮肤色与层级**）
L3  containers[] 行 / 格子 / 按钮 / 芯片（可点单元的实体）
L4  text[] glyphs[] badges[]   文本、纯图形、角标（叶子，必须能归属到 L2/L3）
```

一个容器对象（键全部可机读，不带叙述）：

```json
{ "id": "c7", "parent": "c1",
  "bbox": [174, 738, 348, 894],
  "kind": "tile|card|button|row|panel|chip",
  "skin": {"lab": [96, 129, 117], "fill": 0.72, "rect": 0.87},
  "text": ["特典活动"],
  "glyphs": [{"bbox": [...], "role": "icon"}],
  "badges": [{"bbox": [...], "corner": "tr", "kind": "alert"}],
  "affordance": {"clickable": "yes|no|unknown", "evidence": ["skin_siblings:18", "text_in:1", "hover:none"]},
  "clipped": {"edges": ["top"], "cut_by": "panel", "px": 104},
  "confidence": 0.82 }
```

### 2.2 每个字段的判据、成本、失败行为

| 字段 | 判据（本轮实测的依据） | 成本 | 失败时 |
|---|---|---|---|
| `containers[].bbox`（L3 平坦皮肤类） | Lab 三通道 Sobel 合能量 E<6 ⇒ 平坦；5×5 闭；8-连通；矩形度≥0.55；**且（同皮肤色兄弟≥1 或 内含 OCR 文本≥1）**；世界假阳性 7/7 被这条清掉 | 33~41 ms | 漏检（不出假对象） |
| `containers[].kind` | 皮肤色 + 面积 + 长宽比 + 是否成网格（同行同列等距） | ~0 ms | `unknown` |
| `containers[]`（L2 卡片贴插画） | **未闭合**：内部不平坦（E 中位 17.9~66.5）、边界 ΔE 5.5、LSD 4578 条无法配对 | — | 不输出，`degraded` 标记 |
| `skin` | 容器内平坦像素的 Lab 中位数 + 填充比 | 含在上面 | — |
| `text[] → 归属` | OCR 框中心落在哪个容器内（最小面积优先） | ~0 ms | 落到 `free_text[]` |
| `glyphs[]` | 局部对比显著性：`|Lab − medianBlur(31)|` 三通道和 >45，闭 5×5，16~140px，填充≥0.25 | 87~92 ms | 漏检 |
| `badges[]` | R>140 且 R−G>55 且 R−B>40，面积 90~8100，长宽比 0.6~1.7；**必须归属到某容器角** | 27~34 ms | 漏检 |
| `affordance.clickable` | 目前只给 `unknown`；`yes` 需要 hover/按下态证据（工具还没做） | 0 | `unknown`（不假装） |
| `scroll.status` | **单帧恒 `unknown`**；有前帧时给 `{status, dy, dx, n_matched}`，判据=同名文本位移簇 n≥2 且 |dy|≥8 | `unknown` |
| `clipped` | 容器 bbox 越过父容器/屏边即标裁切方向 + 像素数 | ~0 ms | — |

### 2.3 三条硬约定

1. **结构不猜语义**：`kind` 只描述形状角色（tile/card/row/button），不说"这是活动入口"。语义解释留给上层（VLM 或规则库），因为它是会变的那层。
2. **每个对象必须带 `evidence`**：下游要能问"你凭什么说它是按钮"，答案是可复算的数字，不是我的判断。
3. **fail-closed**：OCR 后端缺失 → 现有 exit 4；像素管线异常 → 输出 `containers: []` + `degraded: true` + `error`，**绝不编造结构**。宁可下游说"看不见"，也不要它按假结构乱点。

## 三、交付 C：算法论战（三条路线，用读数裁）

### 3.1 路线 1：纯经典 CV（本轮已实测）

- **能做的**：①平坦皮肤容器（格子/深色面板/药丸按钮）20/20 与 18/18；②网格行列分组（pitch 实测 208×190、格子 174×156）；③纯图形元素（f00 的 5 头像 + 3 奖励格 + 已达成 ✓ + 搜索放大镜 + 红色 ! 全部检出）；④跨帧滚动（3/3 对正确）。
- **不能做的**：①卡片贴在彩色插画上（f04 5 张全漏）；②面板级边界（派蒙菜单米色面板：skin-CC 会经"同色通道"把 6 个格子并成一块 `[374,1022,980,1392]`）。
- **成本**：像素管线 **155~165 ms/帧**（leaf 33~41 + badge 27~32 + glyph 87~92），零外部依赖（numpy/cv2 已在）、零训练数据、可逐字段解释。

### 3.2 路线 2：学习型检测/分割（OmniParser 类）

- **算力实测**（本机，torch 2.14 + CUDA）：9.3 GFLOP U-Net @640² = **5.3 ms fp16 / 7.3 ms fp32**，≈1762 GFLOP/s ⇒ 即使 100 GFLOP 的模型也只是 ~60 ms 级。
- **真实阻塞不是算力**：本机 **未装 ultralytics**、`~/.cache/torch/hub/checkpoints` 为空、HF 上 `microsoft/OmniParser-v2.0` 只提供 `.pt`（需 ultralytics）**没有 ONNX**；**没有该游戏 UI 的标注数据**；GPU 已被游戏占 4.4/6 GB（在线推理会与游戏抢显存）。
- **能用在哪**：离线批量标注（把 124 个手标单元变成训练集）、或作为"商品图标检测"补在经典 CV 之上（需走 CPU ONNX 跑道，本机未测）。

### 3.3 路线 3：VLM 看全图（当前"模型主动看图"）

- 信息最全，但每帧一次多模态调用 ⇒ 秒级、不可复现、不可解释、不可回归（同一帧两次结果可能不同）。**只能当离线裁判/标注器，不能进在线闭环**。

### 3.4 裁决

**在线闭环 = 经典 CV + 结构化先验；离线 = 学习模型 / VLM 生产标注。** 依据是这张表：

| | 经典 CV | 学习模型 | VLM |
|---|---|---|---|
| 本机可得性 | ✅ 依赖已在 | ❌ 无权重/无数据/GPU 被占 | ⚠️ 需调用 |
| 延迟 | 155~165 ms | 理论 5~60 ms，实际待测 | 秒级 |
| 可解释 | ✅ 每个 bbox 有判据 | ⚠️ | ❌ |
| 可回归 | ✅ 同帧同结果 | ✅ | ❌ |
| 现在能覆盖的单元 | 124/124 的 bbox 我都手工给出了 ⇒ **"看见"不是瓶颈** | 同 | 同 |

**这张表最关键的一行**：我之所以能给出 124 个单元的 bbox，是因为**"看见"本身不难**——难的是"分类与归属"（这块是卡片还是面板、这行属于哪个容器）。而分类与归属恰好是几何 + 文本绑定能吃掉大部分、且必须可解释的那部分。

## 五、未闭合清单（不虚构，登记待办）

1. **卡片贴在彩色插画上**（f04 的 5 张卡、f05 的任务卡/药丸按钮）：三条路都失败，实测数字见 §1/§3.1。候选下一步：①线段配对（需先把 4578 条线段按长/轴/共线聚到 <50 条）②用经典 CV 的"卡通"先验（卡片=低饱和高亮 + 4 条长直线）③学习模型。
2. **面板级边界**（派蒙菜单米色面板、活动页整页内容区）：skin-CC 会被同色通道粘连，需要"网格切分"后处理（先用 L3 的格子反推 panel，再用 panel 反推 region，两层互为约束）。
3. **横向可滚**：f01/f02 的奖励行两帧都是两端被裁（左端切、右端切），说明存在横向容器，但**没有"横滚前后"的对照帧** ⇒ 无法确证，需要补样本。
4. **`affordance.clickable`**：目前只能给 `unknown`。要 `yes` 必须有 hover/按下态证据（需要两帧：静止 + hover），工具链还没有这个采集通道。
5. **f03 的异常读数**：OCR 在 f03 抓到 `O`、`min: 6.2 ns`、`max‡ 27,2 ms`（其余帧是 `ms`、`6.2 ms`）⇒ OCR 在低对比/半透明上有噪声，会污染"位移簇"的样本，需要在跨帧匹配时按置信度过滤。

## 六、需要用户裁决的三件事

1. **要不要把 `containers[]` 落进 `ys-screen`**（它是共享工具，改前必须确认）：实测成本 +33~41 ms，收益 0.8% → 约 85% 的单元获得容器级对象（f06/f07 的 38 个格子），世界假阳性 0。
2. **卡片检测投多少**：补样本继续做经典 CV（推荐先做，成本 = 多拍 3~5 帧不同 App 的卡片界面），还是装 ultralytics + 权重走学习路线（需下载 + CPU ONNX 跑道实测，且 GPU 与游戏抢显存）。
3. **性能目标口径**：`<10 ms` 建议改为 **"常驻服务 ≤200 ms/帧、命中缓存 ≤5 ms"**——理由见 §四末段的三条实测地板。
