# 文档治理与长期维护方案（足球启动优化补充细则）

> 状态：当前推荐
> 来源：足球项目文档审计（2026-09-05，40 份文件逐文档体检）
> 最近校验：2026-09-05
> 适用范围：仓库注入文档 + examples/football 文档/票档案 + 源码注释
> 补充说明：本文件是根 [`documentation-governance.md`](../documentation-governance.md) 的**操作补充**，不取代根规则；根规则负责状态标签/来源分级/归档原则，本文件补充“文档类型模型、启动读取协议、足球项目 P0-P2 执行路线”。

## 目标

降低 AI 代理每次启动/继续任务时的上下文开销；消除文档“当前事实”与“历史过程”混排；让文档状态可被机器检查。

## 1. 文档类型模型

| 类型 | 代号 | 职责 | 启动是否必读 |
|---|---|---|---|
| 注入规则 | R | 每次会话自动读入的行为/知识 | 是（应最小化） |
| 当前状态入口 | S | 定位“现在在哪/下一步” | 是（只读顶部） |
| 设计/权威 | A | 当前实现依据 | 否，按需 |
| 历史/归档 | H | 已退役但保留决策证据 | 否 |
| 票/执行档案 | T | 某票过程与结论 | 否，按票 |
| 源码内注释 | C | 代码旁当前契约/红线 | 只读当前在飞文件 |

## 2. 文档状态头规范

每份文档顶部使用：

```markdown
> doc-type: R | S | A | H | T | C
> status: active | historical | archived
> updated: YYYY-MM-DD
> owner: core | football-v2
> current-source: <path>       # 当前事实权威入口
> superseded-by: <path>        # historical 必填
> derived-from: <path>         # 派生源码/文档
> read-when: startup | ticket | archive-only
```

规则：
- active = 当前可执行/当前权威
- historical = 已不执行，保留原位供追溯
- archived = 已移入归档目录
- read-when 用于 agent 启动时判断是否读取

## 3. 文档结构通用原则

1. 当前事实在前，历史在后。
2. 单一事实源：同一事实只在一个权威文件维护，其它文件用指针。
3. 禁止整段复制旧头；派生文件只写差异 + `derived-from`。
4. 计数/枚举/ID 不手写多处；尽量指向权威源或由脚本核对。
5. 收口即更新：BOARD 顶部、issue 状态行、PROGRESS 当前摘要、受影响文档 `updated` 同步。
6. 启动必读最小化：R + S + 当前在飞文件的 C。

## 4. 分类型治理细则

### R（注入规则）
- 每条规则：现行动作一句话 + 出处链接。
- 历史日期/踩坑叙事迁移技能/PKC/复盘。
- 同一命令/路由/规则在 AGENTS/CLAUDE 之间只保留一份。
- 路由表按高频/按需分组。

### S（当前状态入口）
- BOARD 顶部固定“当前前沿快照”：HEAD、工作区、在飞票、下一步、阻塞、最小必读。
- 票文件顶部固定“本票状态行”：最后一轮日期、结论、下一步。
- 状态变更只改顶部快照，历史往下追加。

### A/H（设计/历史）
- H 必须加 `historical` + `superseded-by`。
- A 中已被推翻的方案折叠为“历史裁决（已废止）”。
- A 部分章节仍权威时，头部标明仍有效/已历史。

### T（票档案）
- 每票顶部状态行 = 当前结论 + 下一步。
- 执行轮次统一表格行；设计讨论/备选方案不留在当前状态区。

### C（源码注释）
- 文件头统一：`@status`、图类型/ID、职责、数据契约、编译前置、`@derived-from`。
- 历史证据/踩坑推导移 issue/复盘；源码只留防回归红线。
- 同源多图共享契约放单一文件，派生图只写差异。

## 5. 生命周期与维护流程

```text
新建 -> active -> historical -> archived
```

- 新建文档：先写状态头；判断类型；启动会读的必须极简。
- 修改当前事实：更新 `updated`，检查其它文件同一事实引用。
- 收口轮次：三同步清单（BOARD 顶部 / issue 顶部 / PROGRESS 当前摘要）。
- 退役实现：旧文档加 historical + superseded-by；确认无引用后移归档。
- 定期健康检查：跑 `doc_health.py`，修复断链/过期状态头。

## 6. 文档健康检查（doc_health.py）

检查项：

| 检查 | 说明 |
|---|---|
| 状态头缺失 | 活跃区文档缺 doc-type/status/updated |
| 占位残留 | “占位/候选/预期/待办”无日期或已回填说明 |
| 断链引用 | 引用文件/行号不存在 |
| 复制头检测 | fb-phys2 头部大段出现在派生文件 |
| 计数漂移 | 注释“参数 N/镜像 N”与真实变量清单不一致 |
| 状态行滞后 | 票顶部状态与 BOARD 顶部不一致提示 |

## 7. 分阶段路线

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 修误导性矛盾：历史 banner、BOARD/issue 状态同步、源码注释 ID/复制头、挂载目标核对 | 高优先级矛盾归零；启动不再被旧 v5 误导 |
| P1 | 瘦身去重：PROGRESS 拆分、根 AGENTS/CLAUDE 压缩、源码注释头瘦身、@status 标记 | 启动必读字节下降；重复段落减少 |
| P2 | 机制化：治理方案落盘、状态头模板、doc_health.py、收口 checklist 纳入 AGENTS | 健康检查可重复运行；状态头覆盖率 100% |

## 8. 启动上下文预算（度量目标）

- 启动必读 ≈ R（已压缩后）+ football/AGENTS 3KB + BOARD 顶部 2KB + git log/status 2KB。
- 活跃/历史文档状态头覆盖率 100%。
- doc_health 高优先级矛盾输出 0。
- 派生文件无整段旧头。

## 9. 强制门禁（2026-09-05 起，不靠自觉）

- `scripts/doc_health.py` 已支持自动目录扫描与 `--staged` 模式。
- 仓库安装 `scripts/git-hooks/pre-commit` 后，**每次 git commit 都会自动运行 `doc_health.py --staged`**；范围文件有问题时提交被拒绝。
- 安装命令：`bash scripts/install-git-hooks.sh`。
- 新 clone/新环境必须先安装 hook；未安装时全量体检命令仍可手动运行：`python3 scripts/doc_health.py`。
- 禁止用 `git commit --no-verify` 绕过文档门禁。
