# 票据驱动工作流（Ticket-Driven Workflow）—— 执行类任务的工程化规范

> 状态标签：**当前推荐**（2026-09-03 用户定调；来源=用户工作方式裁定+足球 v2 首个应用，
  尚未经历完整关账验证——关账后升"已验证"）。
> 首个应用：足球重建 v2（`.scratch/football-v2/`）。
> 一句话：**聊想法不动手；动手前先建票；逐票用提示词执行；做完划掉，看板永远真实**。
> 用户原话（2026-09-02/03）："准备开始执行时，先建 Ticket 把规范定好，然后用提示词
> 一个一个去执行。这样是按照工程化的思想去做，而不是说完就立马开干。"

## 一、五个阶段（顺序不可跳）

```text
① 想法阶段      聊需求/探索/写设计稿/用户裁决——只产出文档，不动代码不动地图
② 建票阶段      准备执行了 → /to-tickets 拆票 + 建看板（本规范 §二）
③ 逐票执行      每票一个新鲜上下文窗口，启动提示词=一句话（本规范 §四）
④ 收轮          每票收口走「收轮三件套」（本规范 §五）
⑤ 关账          全部票划掉 → 总沉淀（复盘/PKC/技能回灌）
```

**反模式（明令禁止）**：说完就立马开干；把进度堆进 AGENTS.md（自动注入层只放引用）；
一票塞多个不相关变量族；跳过收轮三件套直接开下一票。

## 二、建票阶段产物（缺一不可）

| 产物 | 路径约定 | 内容 |
|---|---|---|
| 推进看板 | `.scratch/<项目_slug>/BOARD.md` | ①资产速查（高频引用的运行时 ID/事实）②当前前沿（现在做哪票）③票据清单（#/票名/blocked by/状态）④已完成划掉区 |
| 票据文件 | `.scratch/<项目_slug>/issues/NN-slug.md` | 一票一文件（禁止合并单文件）：What to build（用户视角端到端）/Blocked by/Status/checkbox 验收项 |
| 看板引用 | 项目目录 AGENTS.md 末节 | **只放引用不放内容**——"进度细节一律进看板/PROGRESS" |

拆票规则（继承 to-tickets 技能）：垂直切片（每票独立可验证、单上下文窗口可完成）、
blocking 边显式声明、破坏性批次操作单独成票、粒度由用户确认后落盘。

## 三、看板纪律

- 看板 = 工程推进**唯一入口**：新会话先读板 → 找前沿票 → 读票干活，不问人。
- **做完划掉、没做继续**：完成票移入划掉区（~~删除线~~+日期+commit）；状态表同步。
- 看板与真实状态强一致：禁止板外另立进度、禁止做完不勾、禁止勾了没做。
- 设计权威仍在设计稿（如 R2-DESIGN.md），看板只管"推进到哪"，不复制设计内容。

## 四、逐票执行：启动提示词 = 一句话

有看板后，启动提示词不再手写七角度长文（那是不建票时代的补偿）：

```text
读 .scratch/<项目>/BOARD.md 和 issues/NN-<slug>.md，开工票据 NN，按票内验收项执行，收轮三件套。
```

上下文衔接链：根 AGENTS/CLAUDE（自动注入）→ 项目 AGENTS 引用节（一行）→ BOARD → 票。
四处指向同一下一拍，互相校验防过时。

## 五、收轮三件套（每票强制，缺一不得宣布收轮）

1. **勾票**：票文件 checkbox 全勾 + 看板移入划掉区 + 前沿指向下一票；
2. **PROGRESS 记轮次**：结果 + 明确「下一步=<票号>」；
3. **精确 git commit**：只暂存本票相关文件。

## 六、适用范围与边界

- 适用：多轮执行类任务（重建/迁移/系列修复）；单轮小事不建票（避免流程税）。
- 首个应用=足球 v2；**跑通全程（关账）后再推广**其他 examples（O-2026-09-03-01）。
- to-tickets/task-prompt-builder 技能承载流程细节；本文件是权威规范，冲突以本文件为准。
