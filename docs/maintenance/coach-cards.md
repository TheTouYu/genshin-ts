# 教练卡片库（coach cards）

> 状态：待验证（数字全部来自 2026-10-17 实测，复现命令见各卡片；机制见
> [design-2026-10-17-telemetry-guidance.md](design-2026-10-17-telemetry-guidance.md)）
> 用途：给人看（知道错在哪）也给机器挑（`tools/agent-coach` 按窗口实测动态生成注入版）。
> 约定：卡片五字段=误区/证据/做法/判据/窗口；注入版只保留证据数字+做法，≤600 字符。

## 在架（优先注入，按可省时间排序）

### C1 shell 读文件 → 内置 read/grep/glob
- 误区：用 shell `cat/sed -n/head/tail` 读文件、`grep|find` 搜文件。
- 证据：30 天 shell 读类 3004 次 1.67h；内置 `read/grep/glob` 同类工作 1512 次仅 2.5 分钟——
  **单价差 20 倍**。二级分布：head 1609 次 47.7m、cat 414 次 36.4m、sed -n 520 次 4.5m。
- 做法：读文件一律 `read`（offset/limit 翻页）；搜索用 `grep`/`glob` 工具；确认存在用 `glob` 不用 `ls`。
- 判据：`cmdmon audit` 中 `explore` 类占比（现 47%/13.24h）两周内 <15%。
- 窗口：两周；复现 `python3 tools/cmdmon-mine --since-days 30`。

### C4 空等后台任务 → 先并行后取
- 误区：`job_output(wait:true)` 一等等到底，期间零调用。
- 证据：167 次 wait:true 中 **104 次是空等（62%），合计 4.19h 纯转**；p50=1.8m、p90=7.4m、max=10m。
- 做法：等待前先把本阶段能做的独立步骤全部发出；长等待改 `wait:false` + 间隔轮询判据；
  预计 >2 分钟的任务先起后台再干别的。
- 判据：空等占比 62% → <20%；复现同 C1（mine §3）。

### C8 裸 sleep → 轮询+判据
- 误区：`sleep 60; tail xxx` 用固定时长冒充同步。
- 证据：30 天裸 sleep **1020 处、合计 3.58h**；AGENTS.md 早有守则但行为未变——静态规则失效的实证。
- 做法：等待一律 wait_until 模式（循环 + 判据 + 上限），如
  `for i in $(seq 60); do grep -q READY log && break; sleep 1; done`。
- 判据：`cmdmon report` 裸 sleep 处数周级趋 0（现 368/30 天口径）。
- 窗口：一周（习惯类，回落快）。

### C7 重复命令 → 一次写对/做成资产
- 误区：同一命令 10 分钟内反复重跑（参数猜错、改一半重来）。
- 证据：10 分钟内同命令第 2 次起共 **4348 次、3.44h**；环境准备类更夸张——
  `export GSTS_LOCALLOW_DIR=…` ×66（其中一组 ×32 合计 16.2 分钟，每次 30s）、
  `browser-harness` ×34 合计 3.2 分钟。
- 做法：重跑前先 diff 上次参数；≥3 次重跑的命令立刻沉淀成 wrapper/脚本再复用。
- 判据：repeat 报警（10 分钟 ≥3 次）周降 50%。
- 窗口：两周。

### C3 重复读同一路径 → 一次读全/缓存进上下文
- 误区：同一文件被 shell 反复读（读完不用，下轮又读）。
- 证据：`tools/ys-editor/` 目录被读 **103 次共 25.8 分钟**；`scripts/acceptance.mjs` ×78 次 25.0 分钟；
  `dsh-memo-river` 目录 ×151 次 10.9 分钟。
- 做法：同文件第二次要读时，先查上下文里是否已有；大文件第一次就带 offset/limit 定位，别 head 全量。
- 判据：mine 重复读 top 无 ×50 以上项。
- 窗口：两周；复现同 C1（mine §1）。

## 候选（证据在，先观察）

### C2 慢命令放后台
- 误区：预计 >20s 的命令前台硬跑。
- 证据：单次 ≥30s 慢调用 **714 次**（30 天）；build 类均 9.4s、GUI 类均 8.5s 是重灾区。
- 做法：预计 >5s 先想缩短；>20s 一律 `run_in_background` + 阶段末统一 `job_output`。
- 判据：慢调用次数周降 50%；复现 `tools/cmdmon audit --since-days 30`。

### C5 失败先读错误信息，不原样重跑
- 误区：失败后 60s 内原样重跑。
- 证据：失败 1075 次中 **316 次在 60s 内被重试，84%（266 次）重试成功**——说明多数失败是
  参数小错而非环境问题；同一命令失败 ≥2 次的重复失败 167 组，大头是秒级 edit 匹配失败（无害但吵）。
- 做法：失败先读 stderr 定位根因；改完再跑；同一命令第 3 次失败必须换方法。
- 判据：重复失败组数（167）周降 40%。
- 窗口：两周。

### C6 失败双通道计数
- 误区：只看 `[exit code: N]` 判失败。
- 证据：1075 次失败里 **539 次只有 isError 无退出码**（工具层错误），429 次 exit=1、80 次 exit=2。
  只盯退出码漏掉一半。
- 做法：脚本化统计失败时同时统计 `is_error` 与退出码两个通道。
- 判据：无（这是统计纪律，不对应行为指标）。
- 窗口：随 C5。

### C9 截图最小化
- 误区：全窗截图后再找目标。
- 证据：全窗截图 2893ms，裁 40×40 仅 **166ms（17 倍差）**；gui 类 1131 次 2.67h、均 8.5s。
- 做法：取判据像素用裁剪坐标；只有布局级问题才全窗；能读日志/进程状态就不用截图。
- 判据：gui 类均时 8.5s → <4s。
- 窗口：两周。

### C10 环境准备一次成型
- 误区：每次都重打 30s 的环境变量准备命令。
- 证据：`export GSTS_LOCALLOW_DIR=…` 全项目 **×66，其中单组 ×32 合计 16.2 分钟**。
- 做法：出现第 2 次就写成 wrapper 脚本（或进入已有 wrapper），以后一条命令带全部前置。
- 判据：该类命令在 repeat 榜消失。
- 窗口：一周。

### C11 pkill 自杀防护
- 误区：`pkill -f "<字符串>"`，该字符串同时出现在自己命令行里。
- 证据：经典事故型（本仓 GUI 轮多次踩）；属低频高危，不设占比判据。
- 做法：pkill 前先 `pgrep -af` 确认目标列表不含自己；或用 pid 文件精确 kill。
- 判据：无 pkill 自杀 fail 记录。
- 窗口：月级。

### C12 长任务等待期间不空转
- 误区：等子代理/后台时反复 `job_output` 轮询或 sleep。
- 证据：`job_output` 类 206 次 **7.28h（占 26%）**，其中空等 4.19h（见 C4）；
  与 C4 的差别：C4 管"等之前"，C12 管"等之中做别的"。
- 做法：等待期做独立线（文档、下一阶段准备、并行子代理）。
- 判据：同 C4。
- 窗口：同 C4。

### C13 慢流程先测再改（仪器开销意识）
- 误区：一轮自动化里仪器开销占 92% 还继续加仪器调用。
- 证据：试玩轮实测 426s 中 **92% 是仪器开销**（切窗/截图/等待）；
  对应守则已入 AGENTS.md「仪器优先」，此卡是它的数据版。
- 做法：动 GUI 前先问"读数能不能从日志/进程/文件拿"。
- 判据：gui 类占比（现 10%）月级 <5%。
- 窗口：月级。

### C14 引用账本数字先去重
- 误区：直接引用 `cmdmon report` 数字。
- 证据：daemon 与 scan 并发导致账本同 callId 重复行——实测 30 分钟窗 1260 行仅 119 个 callId
  （**~10 倍膨胀**）。
- 做法：任何窗口级统计先按 callId 去重（`agent-coach` 已内置）。
- 判据：无行为指标；统计纪律。
- 窗口：随用随查。
