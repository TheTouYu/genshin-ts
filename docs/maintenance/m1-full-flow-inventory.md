## 三、人工操作面：通道实测与成本模型（**决定编排方式**）

**关键实测**：千星编辑器是 **Wine 应用，不暴露 AT-SPI 语义树**。
⇒ 全局 `computer-use` 技能的**首选通道（语义树 `cu click --name`）对它不可用**；
实际可用通道是**坐标 + 像素判据 + 视觉判读**：

- 硬通道 `tools/ys-editor/ys-gui-slot`（KWin 直赋焦点 + 严格回读）；
- 注入 `ydotool`（内核 uinput，`/run/user/1000/.ydotool_socket`）；
- 读回 `xdotool` + 截图（`ys-shot`）+ 像素/模板判据（`ys-lookd`）。

**成本模型（决定性）**：每新增一个编辑器/沙箱界面 = 一轮「坐标 + 判据 + 坑」实测（参照日志窗：3 步坐标 + 1 条机器判据 + 3 个坑）。
⇒ **GUI 面越少越好；能用 CLI 的一律走 CLI**。这解释了用户补充里那句「**打开只需要一次就行，不需要支持**」——
把一次性、低频的编辑器动作留给人工/一次性处理，不为它们建工具。

## 四、此前未落盘的关键官方事实（四条）

1. **千星沙箱「进入编辑时自动开启」**，手动关闭后从**系统菜单左下方**打开（`editor-interface.md:1683-1687`）
   —— 即用户指路的「编辑器点那个像球一样的东西打开千星沙箱」。
2. **日志勾选后必须点【确认选择】**，否则运行时不显示日志（FAQ `official-guide-faq.md:193`）
   —— 我 2026-10-17 落盘的日志窗流程里**缺这条校验**。
3. **试玩中编辑的节点图不会被保存**，会回退到编辑前状态（FAQ `:177`）—— 试玩周期内不要编辑图。
4. **试玩 = 必要的校验 + 上传流程**；试玩设置有：试玩玩家编号 / 存档数据 / 装扮展示开关 / **启用试玩结算** / 试用奇偶 / 试玩语言（`editor-interface.md:1427-1476`）。

### 5.4 选题建议依据（`docs/knowledge-graph/k/k1-选题与赛道.md`，语料实测）

- **首选赛道 = 休闲益智**（实测第一：前八平均推荐率 **95.1**、总热度 **71.1 万**、1.5 万+ **39 个**）——
  上手门槛低 + 可重玩 + 技术难度不高（`:79`、`:86`）。
- **避开七类**：传统 RTS / 自走棋 / TPS-FPS 竞技 / MOBA / 解谜 / 纯剧情 ADV / 氪金页游（`:54`）。
- **三条造题路径**：玩法融合 / 复刻+改造（红线：不照搬人物·单位名·技能数值·地形）/ 蹭热点与抢本体不敢做的（`:92-107`）。
- **复刻必须在动工前验证"关键技术可控"**（失败实录：3D 合成大西瓜卡在"镜头无法被节点图控制"，`:102`）。
- **单人优先 PVP**；**大流程玩法系统性吃亏**（流程越长越易被抓 bug 拉低推荐率，`:146-147`）。
- **地形不是必争项**，精力留给玩法（`:141`）。

### 5.5 建议编排（三段）

1. **阶段 0 · 探路**（1 个最小项目）：走通 A→F 全链，**把"推出来的断点"变成读数**；
   本文 §二 的 🔴 项在此阶段逐条实测确认（预期与实际必然有出入）。
2. **阶段 1-3 · 三个项目**：每个项目独立走 A→F；每条硬通道（坐标/判据）跑通即落盘。
3. **收口**：三个项目的证据链 + 实测缺口清单 + 工具/技能回灌。
