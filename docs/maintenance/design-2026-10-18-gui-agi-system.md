# GUI 能力层的 AGI 实现规格（2026-10-18 用户定义）

> 状态：需求规格（用户定义，最高信源）
> 来源：用户 2026-10-18 反馈轮口述，逐条对应原话
> 读者：实现 GUI 感知/动作层的人；这是**目标态**，不是现状

---

## 0. 一句话目标

**所见所得，点击即达。** 模型看到一帧之后说"加载编辑云阶的存档"，系统直接把它送到**稳态**（载入成功），
并把这段过程如实告诉模型；模型想细看某个局部，直接给它切好的那块。

---

## 1. 用户原话（不可改写，作为验收基准）

> 「我们这里 gui 模型的 agi 实现，应该提供，**所见所得，点击即达**的能力。」

> 「比如模型看到这一帧之后，选择加载编辑云阶的存档，那么会直接进入加载，**最终达到稳态，载入成功**。
> 我们**提高模型下一个状态**。并且**告知，中间还经历了加载状态过程**（比如多少秒，加载状态大致内容）」

> 「模型想关注某个局部细节，我们可以把**切割好的内容直接呈现**。（为什么是切割好，因为在完成解析状态的时候，
> 我们已经完成了切割，并对每个局部执行 ocr，这样可以**并行**，并且**单个图片非常小，速度快，准度高**）」

> 「然后继续，模型可能选择下一个动作，或者**增加一个加载判断条件**，设定什么情况算加载完成了。」

> 「这些一套系统就是我们要完成的 gui 模型的 agi 实现」

---

## 2. 这套系统的五个组成部分

### ① 感知：对象检测 + 切块 + 分块并行 OCR（关键架构选择）

不是"全帧 OCR 后猜结构"，而是：

```
全帧 → 对象检测（object detection）→ 每个对象切出一张**小图**
     → 每张小图**独立 OCR**（并行）
     → 对象 = { bbox, 类型, 自身 OCR 文本, 状态, 可点性 }
```

**为什么必须切块**（用户给的理由，也是性能来源）：
- **并行**：N 个小图可同时 OCR
- **小图快且准**：现在全帧 OCR ~500ms 且小字漏检（W/S 抓不到、皇冠角标不认）；
  切成 100~300px 的小块后，单块识别又快又准
- **一次解析产出可复用的切片**：模型要细看时**不需要重新处理**，直接给已有切片

> ⚠️ 这一条推翻当前实现：现在是「全帧 OCR（~500ms）+ 从文本反推结构」，
> 应该改成「**对象检测先行 → 分块 OCR**」。

### ② 状态：返回"下一状态"，不是返回像素

模型发出动作后，系统**不返回截图**，返回的是**结构化稳态**：

```
{ state: <稳态标识>, objects: [...], evidence: <怎么证明到了这个状态>, duration_ms, transitions: [...] }
```

模型据此决定下一个动作。**模型不需要看像素就能规划**——这是"提升模型下一个状态"的具体含义。

### ③ 过程：过渡态必须如实报告

从"点击加载"到"载入成功"之间的**加载态**也要报，且带：

- **耗时**（多少秒）
- **加载态大致内容**（进度条？转圈？文字提示？）
- 中间经过了哪些状态

不允许"跳变"式汇报（点击 → 直接说成功），因为模型需要知道"现在卡在加载中"还是"已经失败"。

### ④ 按需细节：给切好的局部

模型说"我想看云阶那个存档卡的缩略图/日期"，系统直接把**已经切好的那块图**给它
（+ 该块的 OCR 文本 + 该块的局部坐标），**不重新处理整帧**。

### ⑤ 控制：模型可以定义"什么算完成"

模型可以说"加载完成 = 出现'编辑器'界面 或 '存档已载入'文字"，
系统按这个判据等待并回报（而不是用系统内置的固定超时）。

⇒ 需要一个**判据注入通道**：模型给条件，系统等待到条件成立或超时，**并报告是哪一种**。

## 3. 与现有实现的关系（差距表）

| 用户要求 | 现状 | 差距 |
|---|---|---|
| 对象检测 | 手工经典 CV（flat+rect），14 帧语料上除"不透明纯色格子"外覆盖率 0~50% | **换算法**；实测 GPU 上 U-Net 级 5.3ms，算力过剩 |
| 切块 + 分块 OCR | 全帧 OCR（~500ms），无切块 | **架构改动**：改为对象先行、分块并行 OCR |
| 返回下一状态 | 返回原始帧 + 一堆字段（text/controls/regions/structure/containers） | **缺状态机**：没有"稳态"概念，没有状态转移图 |
| 过渡态报告 | 无 | 缺：加载态识别 + 耗时统计 |
| 按需局部 | 无（每次都要重新读整帧） | 缺：切片缓存 + 局部索引 |
| 判据注入 | 固定超时（如 `ys-do` 的 `wait` 秒数） | 缺：模型可注入的完成判据 |
| 所见所得点击即达 | `ys-do` 有"意图"概念但只有 3 个（playtest-start/stop、paimon-to-activity） | 缺：**意图 → 目标对象**的解析（自然语言到 bbox） |

## 4. 需要建模的五件事（按依赖顺序）

```
① 稳态（steady state）
   可复现的界面状态标识 + 判据。例：GAME_WORLD / GAME_PAIMON / GAME_ACTIVITY / EDITOR / SAVELIST / LOADING
   现状：有 10 个态 + 两个通道，但**没有 LOADING**，也没有"态之间的合法转移"

② 过渡态（transition）
   LOADING / 动画中 / 灰屏。必须有**最小时长**与**超时判据**，否则模型无法区分"慢"与"卡死"
   现状：无

③ 对象（object）
   每个可交互单元：bbox + 类型 + 自身 OCR + 状态（选中/禁用/红点/已领取）+ 可点性
   现状：containers[] 有 bbox/text/badges，**缺 state、缺 clickable、缺分组**

④ 动作（action）
   自然语言目标 → 对象 → 点击坐标 → 验证下一状态
   现状：ys-do 有意图框架（pre/post 硬约束），但意图极少且要手写 JSON

⑤ 判据（criterion）
   模型可注入的完成条件（文字出现/状态切换/像素变化/超时）
   现状：只有固定 wait 秒数
```

## 5. 验收体系：两层，上限是「用户在环」，不是脚本用例

> ⚠️ 本节的初版写成"场景 A / 场景 B"两个脚本用例——**那是把上限降级成了下限，错的**。
> 用户 2026-10-18 明确指出：「这个验收标准太低了，我说了，**最稳的是把我加入到反馈轮，完成进化**，
> 我们走到现在不就是靠的这个吗？」

### 5.1 两层结构

| 层 | 判据 | 作用 | 谁执行 |
|---|---|---|---|
| **下限（机器，自动）** | 回归集不退化、性能门禁不超阈、判据单一源、失败账本每笔有防线 | **防止倒退** | `ys-gates` / `ys-perf` / `failure-ledger` |
| **上限（用户在环，每轮）** | 用户真实操作 → 系统读 → 差异暴露 → 修 → 再操作 | **驱动进化** | 用户 + 我，逐轮 |

**关键认知**：下限只能证明"没变坏"，永远证明不了"够好了"。
真正定义"够好"的是**用户在真实使用中遇到的第一个不顺**。
这就是 2026-10-18 这一整轮的方式：用户操作 14 帧 → 我逐帧对比「人眼 vs 工具」→ 差异即缺口 → 修 → 再看。
**这条路产出的东西比任何我预先设计的用例都硬**（因为用例只能测我想到的东西）。

### 5.2 每轮反馈轮要产出什么

1. **界面语料**：新帧 + 逐帧「人眼看到的 vs 工具输出的」差异表（`.scratch/gui-corpus/`）
2. **缺口登记**：差异归入能力分类，进 `open-items` 或失败的账本
3. **修复 + 复验**：改完用**同一批帧**重跑，给出前后数字
4. **语料沉淀**：新帧进回归集或成为下一轮的设计素材

### 5.3 脚本用例的正确位置

脚本用例（如"加载云阶存档直到稳态"）**降为下限的补充**——一旦某个能力在某轮反馈中被确认，
就把那个场景**固化成脚本用例防退化**。即：**用户先发现，脚本后锁定**，不是脚本先行。

## 6. 性能预算（已被实测纠正过的口径）

| 环节 | 目标 | 依据 |
|---|---|---|
| 对象检测 | ≤200ms/帧（常驻），缓存 ≤5ms | 现 flat+rect 实测 113~149ms；学习型 5.3ms(fP16 算力实测) |
| 分块 OCR | 目标 < 全帧 OCR 的 1/3 | 小图更快更准，且可并行 |
| 局部切片返回 | < 50ms | 切片已存在，只需索引 |
| 稳态判定 | ≤1s | 现 `ys-state --fast` 实测 ~200ms |

| # | 缺口 | 证据 |
|---|---|---|
| 1 | 对象检测覆盖率低（除不透明纯色格子外 0~50%） | f04/f05/f09/f10/f12/f13 |

## 8. 落地顺序建议

1. **对象检测换路线**（手工 CV → 学习型或混合）——这是 L1 地基，不换后面全部受限
2. **切块 + 分块 OCR**——同时解决覆盖率与速度
3. **state 字段 + 组（group）**——状态是组内相对属性，没有组判不出选中
4. **LOADING 态 + 过渡态报告**
5. **切片索引 + 按需局部返回**
6. **判据注入 + 意图解析（自然语言 → 对象 → 点击）**
7. **「不存在」闸门**——任何否定结论前必须扫全
