## 4. 纪律（这些都是踩过坑换来的，别重犯）

**验证纪律**
- 判据**只能有一处实现**：红点判据只在 `ys-afford`、变化判据只在 `ys-watch`、滑条判据只在 `ys-slider`。新工具只做编排，**不许复制判据**（这是门槛⑤在打的靶子）。
- **负样本先过再谈召回**：新检测器先在"不该检出"的帧上做到 0，再修召回家。
- 自测只给**机器一行**（`XXX-RESULT … verdict=PASS`）；失败必须打印**期望 vs 实测 + 数值依据**。
- `rc≠0` **先读消息文本**再归因（曾把"命令里路径漏 `/h`"归因成"槽内文件系统不同"，写进契约才发现是笔误）。

**操作纪律**
- 真实窗口：每段 **<30s**、一动作一断言、结束核对焦点已回落；注入类动作一律经 `tools/ys-editor/ys-gui-slot`。
- **禁裸坐标连点**：列表会滚动（领奖时踩过），一律"行标签 + `--offset`"。
- **禁裸 `pkill -f`**（会自匹配）→ `tools/ys-editor/ys-safe-kill`；删文件用 `ys-safe-rm`。
- 写动作必须带身份（`target{desc,must_assert}`）；点一次没反应 → **同元素换交互方式**（`ys-probe`），别急着换目标。
- 决策类动作（下注/提交/领取）先 `ys-brief`，`verdict=BLOCK` 就停下来改参数或先读规则。
- 每个写动作都走 `ys-act` 拿回执（变化事件 + 红点 delta）——"我点了"和"界面变了"必须写在同一张回执上。

**工程纪律**
- 路径是 `/home/h/genshin-ts`（漏 `/h` 会 ENOENT）；仓库有 `doc_health` 提交钩子与根 `AGENTS.md` 16KB 硬上限，**不要 `--no-verify`**。
- 零新增依赖；测试脚本放 `tools/ys-editor/tests/`（仓库根 `tests/` 是 TS 测试入口）。
- 每条新失败入账：`prevented`（带 gate + 注入用例）或 `open`（进真债清单），二选一，不许含糊。

## 8. 交付形态与完成度（锁定）

- **交付形态**：不新增产品形态。每轮交付 = **一个可运行的工具/修复 + 它的离线自测 + 文档落点**，同轮提交；
  工具一律 `python3` 单文件可执行（`tools/ys-*`），**零新增依赖**（numpy/PIL 已是既有依赖），
  自测放 `tools/ys-editor/tests/<name>-selftest.sh` 并给机读行。
- **完成度档位**：`maximum effort`（可交付级）——过负样本、过错误路径、给读数，不交"能跑但没验证"的东西。
- **参照锚定**：新工具的形状照抄已有八个工具（`tools/ys-act` + `tools/ys-editor/tests/act-selftest.sh` 是标准模板：
  输入 PNG / `--json` 输出 + stderr 机读行 / 失败打印期望 vs 实测 / 退出码语义化）。
- **输出协议**：直接输出完整代码与读数，不要解释性铺垫（不要「下面我将…」式开场，也不要复述我给你的文件内容）；报告五段（本轮/读数/证据/下一步/卡点）。
- **输出风格**：读数优先——一屏内给出机读行与数字，中文诊断，拒绝装饰性输出与截图堆砌。
