## 一、总纲：自进化机制的三根支柱

长期目标的本质是**学到一套可自主进化的机制**——不是做完一个项目，而是让"做游戏的能力"成为
可以积累、度量、自动改进的资产。它由三根支柱支撑：

1. **闭环**：任务 → 路由（技能 + 知识树）→ 执行 → 验证（自动回归 / 真实 GIA / 用户游戏验收）→
   归因（用法 / 设计 / 实现三层）→ 修复（生产代码 / 技能 / 知识树）→ 沉淀 → 进入下一轮。
2. **度量**：测评回路（isolated-model-evaluator）量化"教会大模型做游戏"的**可转移性**——
   换一个干净模型、只带技能和知识，能否完成同样的任务？成功率、卡点、绕路、成本、知识缺口，
   这些数据是"自进化"从口号变成机制的关键。
3. **沉淀**：四层落盘——技能（`.agents/skills/`）→ 权威文档（`docs/game-engine-knowledge/` 等）→
   知识树（PKC）→ 账本（`docs/maintenance/open-items.md` + 各 PROGRESS/TASKS）。

## 六、执行机制（每轮铁律）

1. **每轮一个可归因变量**（协作手册 B1）；复杂任务拆分后逐项推进。
2. **证据分层报告**（B3）：自动回归 / 真实 GIA / 用户游戏验收 分开表述，不混淆。
3. **红绿先证后修**（B2）；未知规则未闭合前不改生产代码（B5）。
4. **完成链**：实现 → 自动验证 → 用户核验 → 提交（含文档同步）→ 沉淀四层。
5. **卡住三问**：①知识库/文档/技能是否已有此规则？②能否让用户做 10 秒编辑器最小差分？
   ③现有状态能否做天然实验？（分层归因：用法 / 设计 / 实现）
6. **防丢失**：每轮结束更新 PROGRESS/TASKS/open-items；跨会话锚点写入文档，供
   dsh-session-history 检索恢复。
7. **测评优先派活**：确定型任务走 isolated-model-evaluator（默认 deepseek-v4-flash，
   任务文件含背景 + 验收命令 + 约束），主会话只读摘要；子代理任务完成后跑 task-trace-review。
