### 唯一目标

基于用户确认正常的真实“新测试球体4”样本，定位脚本复制组件时装饰物丢失的完整原因；在没有成功结构证据前不要继续写回新组件。

### 当前范围

- 对比真实编辑器生成的“新测试球体4”和脚本生成失败的“新测试球体5”。
- 重点反查 `field 4`、`field 8`、`field 27`、所有元件/实例/资源 ID 和未知引用。

### 完成标准

1. 自动验证：给出真实正常样本与脚本失败样本的字段 presence、raw wire 和 ID 反查差异。

3. 写回：默认不写回；若确需实验，先创建备份并说明目标字段。

### 易错点与禁止事项

- 用户确认的正常版本优先于单字段推断；`field 40.field 501` 为空不等于装饰物为空。
- 不要把脚本复制成功的定义记录当作装饰物复制成功；用户游戏结果是当前验收标准。
- 不要把元件 ID、场景实例 ID、资源 ID 混为一谈；必须记录父路径。
- 不要覆盖正常真实样本；写回前必须保留 SHA-256 和备份。
- 注入/写回成功、自动扫描成功和游戏内装饰物显示是不同证据等级。

### 18.1 正常“新测试球体4”的完整关系

正常样本中，元件定义和场景实例均使用 ID `1077936135`，但其装饰物/子项关系还指向两组辅助记录：

```text
field 4 定义 1077936135：
  field 6.field 50.field 501 = [1073741842, 1073741843]

field 8 实例 1077936135：
  field 5.field 50.field 501 = [1073741844, 1073741845]
```

同时，顶层登记区存在对应记录：

```text
field 27：
  1073741842 → resource 10009002，名称样式“装饰物_1”，关系字段携带 1077936135
  1073741843 → resource 10009001，名称样式“装饰物_2”，关系字段携带 1077936135
```

当前进一步扫描显示：`field 9` 没有新增 `1073741844`、`1073741845` 记录；它不是本组差异中已证实的新增登记区，先不要把它当作装饰物辅助记录。

原始 wire 中可以直接看到 `field 27` 的关系引用，例如：

```text
27.1.4.field 50.field 502 = 1077936135
27.2.4.field 50.field 502 = 1077936135
```

这里记录的是 wire 事实，正式语义仍待验证。

### 18.2 失败“新测试球体5”的差异

失败样本新增了元件定义/场景实例 `1077936136`，但没有为它复制出新的辅助记录：

```text
field 4 定义 1077936136：
  field 6.field 50.field 501 = [1073741842, 1073741843]

field 8 实例 1077936136：
  field 5.field 50.field 501 = [1073741844, 1073741845]

field 27：没有新增指向 1077936136 的记录
field 9：与正常样本相比没有新增记录；当前不把它列为本差异的缺失项
```

也就是说，脚本复制只完成了“主定义 + 主实例 + 名称/Transform”，却让新组件继续共享正常组件的 `field 27` 装饰物登记记录。正常样本中，`1073741842..1845` 是 `1077936135` 这一组件链的两组定义侧/实例侧记录；失败样本没有建立 `1077936136` 对应的新 `field 27` 记录和反向关系。

### 18.3 当前结构结论与边界

当前最强结构结论是：

```text
复制自定义元件
≠ 复制 field 4 定义 + field 8 实例
复制自定义元件
= 主定义/实例 + field 27 登记记录
  + 两侧 field 50.field 501 引用 + 所有者/反向引用同步重映射

`field 9` 当前未证明是该组件装饰物复制的必需新增记录。
```

这解释了为什么失败样本可以在游戏中生成新元件并显示主组件，但装饰物列表为空。它仍不能单独证明 `field 27` 或 `field 9` 哪一个是运行时决定因素；需要再找一个真实编辑器连续创建的“新测试球体6”或同等 A/B 样本，确认新增辅助记录是否始终按上述 ID 族同步增长。

本轮没有写回地图，没有修改 `user_edit/`，没有继续追加测试组件。下一步应先实现只读校验器，检查每个自定义元件的：

1. 定义记录中的子项 ID 列表；
2. 实例记录中的子项 ID 列表；
3. `field 27` 中资源/关系记录；
4. `field 9` 是否发生同步变化（当前作为排除项检查，而非预设必需记录）；
5. 所有 ID 是否被旧组件和新组件错误共享。
