# Stage 3 协作经验手册维护规则

> 状态：当前推荐 / 持续维护
> 来源：项目重构执行协议 + 用户确认的稳定性要求
> 最近校验：2026-07-12
> 适用范围：[COLLABORATION-PLAYBOOK.md](COLLABORATION-PLAYBOOK.md) 的每次新增、修改、合并或删除

本文件规定如何维护经验手册；它不记录具体经验。目标是让手册像低学习率训练一样缓慢、稳定地收敛，而不是随着每轮工作膨胀成日志。

## 1. 收录门槛

一条内容只有同时满足下列条件才可进入经验手册：

1. **高频**：大多数相近工作包可能触发；
2. **可复用**：不依赖本轮的节点 ID、变量名、fixture 或样本路径；
3. **可行动**：能明确改变下一位执行者的步骤、检查项或停止条件；
4. **已证实**：有真实 GIA、用户编辑器反馈或重复自动回归支撑；
5. **可压缩**：能在一个短段落内表达。

具体工作包的时间线、路径、SHA-256、命令、节点 ID、完整失败过程和测试细节，必须留在 `STATUS.md`、phase 文档、focused test 或真实文件，不进入经验手册。

## 2. 低学习率更新规则

每个工作包结束时先问：**是否出现了未来大多数相近工作包都会重复遇到、且当前手册尚未覆盖的规律？**

- 答案为否：不修改经验手册。
- 答案为是：优先精修已有条目；只有无合适条目时才新增。
- 默认每个工作包最多变更 **一条经验**；一次变更只解决一个概念。
- 不新增大章节、不重排目录、不批量改写措辞，除非用户明确授权。
- 新证据与旧经验冲突时，替换或删除旧条目，不并列堆叠矛盾版本。

这是一项稳定性约束，不以“文档更全面”为目标；宁可暂不写，也不要把尚未泛化的局部发现写成规则。

## 3. 最小变更格式

每条经验只包含：

```text
标题：触发条件或适用范围
行动：下一位执行者应做什么
边界：不能据此推断什么（仅在必要时）
```

通常 2–4 句即可。不得复制聊天记录、完成报告或代码 diff。

## 4. 维护流程

1. 读取经验手册与本文件；
2. 对照当前 `STATUS.md`、phase 文档、真实证据和测试，确认候选经验已证实；
3. 判断是“不更新”、精修一条，还是新增一条；
4. 只做最小编辑；
5. 在完成报告中说明：为何更新或为何刻意不更新；
6. 运行 `git diff --check`。

## 5. 与执行协议的关系

`EXECUTION.md` 负责要求相关工作包读取和维护经验体系；本文件负责限制维护幅度；经验手册负责提供下一轮可执行规则。三者不得互相复制内容。
