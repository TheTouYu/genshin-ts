### 1.2 真实世界对照

| 物理量 | 真实足球 | 本实现 | 偏差 |
|---|---|---|---|
| 射门初速 | 25-35 m/s（职业） | 24.5 | ✓ 合理 |
| 弹道峰值（y 初速 5m/s） | ~1.53m（无阻力抛体） | **0.95m** | **低平 38%**——无"高弧线"感 |
| 空气阻力 | a≈5 m/s²（v=20，Cd≈0.25） | **9.5 m/s²**（KD=0.02·v²） | 大 1.9 倍——球速衰减过快 |
| 滚动摩擦 | 0.2-0.6 m/s²（μ_r 0.02-0.06） | **3.0 m/s²**（ROLL_DECEL） | **大 5-15 倍**——球只滚 0.84m 就停（真实 1.5m/s 应滚 10m+） |

### 1.3 源码对照

- **弹道低平根因 1：半隐式位移用段末速度**。`physIntegrate`（physics.ts:51-77）：
  `nvel = v + a·DT`；`npos = p + nvel·DT`——位移用**积分后速度**。kickLaunch 与 physFlyTick 都按此写回并驱动设备。
  上升段第一段：v0_y=5 → v1_y=2.55 → 位移 2.55×0.2=0.51m（真实梯形 (5+2.55)/2×0.2=0.755m）。
  **视觉与逻辑都因此低估上升** → 低平弹道。
- **弹道低平根因 2：视觉/逻辑双轨错位**。球位置有两个真相：`ballPos`（图变量，tick 内积分）与
  实体视觉位置（physics 设备驱动）。kickLaunch 用 clampedPos 同步一次，之后 fly_tick 从逻辑 ballPos
  积分、设备从**视觉位置**移动——两轨独立演化，飞行中持续错位（rec96 视觉 x=-6.70 vs 逻辑 x=-8.28）。
- **阻力偏大**：KD=0.02（physics.ts:14）——a=KD·v²=9.5 m/s²。
- **滚动摩擦**：ROLL_DECEL=3.0（physics.ts:21），注释明确"真实带球球滚 1-3m 球员追上，不滚到停"——
  **这是游戏性选择**（快速停球便于追球），与真实物理冲突，需用户裁决取舍。

### 1.4 问题清单

- **P1 弹道低平**：半隐式段末速度位移 → 峰值 0.95 vs 理想 1.53（无高弧线感）
- **P2 逻辑/视觉双轨错位**：飞行中持续错位（无同步点）——落地/反弹时误差放大
- **P3 空气阻力偏大 1.9 倍**（KD=0.02 → 建议 0.01 附近）
- **P4 滚动摩擦过大 5-15 倍**（ROLL_DECEL=3.0 → 真实 0.2-0.6；与游戏性冲突，待裁决）
- **P5 自旋过低 + 马格努斯弱**（kick 给的 ω 只有 ~8 rad/s；KM=0.01）——弧线球不可见
- **P6 滑动段偏长**（9 tick=1.8s；真实高速落地后滑动 0.3-0.8s 即转滚动）——SLIDE_DECEL 6 略小或
  SLIDE_TO_ROLL=2.5 阈值偏高

### 2.3 源码对照

- `SPEED_GAIN = 1.2`（dribble-field.ts:31 附近）：合成球速 = 玩家速度 × 1.2。
- `PULL_DIST2 = 2.25`（半径 1.5m）、`PULL_FWD_MIN = -0.3`（身后判定）：牵引区几何。
- 速度场：`dir = normalize(0.7·F + 0.3·Dn)`（FWD_WEIGHT/REL_WEIGHT 0.7/0.3），vTarget = 玩家速度×1.2，
  k1/k2 分段 clamp，DAMP=0.95 旧速衰减——算法本身合理（参考版逆向），**问题在增益与距离参数**。

### 2.4 问题清单

- **P7 球速增益 1.2**：球永远比玩家快 20%——真实带球球速 ≤ 人速；脱脚时球以 1.2×玩家速度飞出（实测 7.4 m/s）——"失控"感
- **P8 牵引区偏宽（1.5m）**：球离脚 1.5m 仍被吸——真实触球 0.5-1m；且侧前方 0.38m 也可被带（PULL_FWD_MIN=-0.3 太宽松）
- **P9（非问题，实证修正）带球启动前 3 tick 不动**（rec234-240）：rec234 玩家在 (-32.77,-3.74) 朝向 288°（**背对球**，dot≈-1.3 < PULL_FWD_MIN），球不拉是朝向门控的正常行为；rec240 玩家转身后球立即被带——**朝向门控符合真实**（背对球带不动）

### 3.2 真实世界对照

| 物理量 | 真实 | 本实现 | 偏差 |
|---|---|---|---|
| 脱脚后球 | 以当前速度惯性滚动（摩擦减速） | 旧版冻结；新版按 physRollTick 滚（待测） | 已修断链 |
| 运动中射门 | 球以**合成速度**（旧速+冲量）立即飞出 | 设备速度=**纯冲量 dv**（0.2s），逻辑=nv | 视觉 0.2s 失真：球先按 dv 走、0.2s 后才按 nv |
| 射门后高度 | 从当前高度（贴地 0.25）以新弹道上升 | 旧版悬空冻结；新版从逻辑位置飞（**逻辑/视觉错位残留**） | 高度错位累积 |

### 3.3 源码对照

- `kickApplyImpulse`（kick.ts:122-）：`add_uniform_basic_linear_motion_device [e, impName, 0.2, dv]`——
  设备速度 = **dv（纯冲量）**，不是 nv（合成速度）。设计注释："不同名叠加"依赖 physics 链在跑时
  v_old+dv=nv 才自洽；**无 physics 链场景（脱脚冻结后）0.2s 视觉按 dv 走 → 失真**。
- kickApplyImpulse **不写 ballPos**（只写 ballVel/ballSpin）→ 逻辑位置不更新 → 与视觉错位累积。
- 断链（已修）：旧分发器只响应 name==physics；a45bf3b 改为按 state 分发 + 脱脚立即启动物理。

### 3.4 问题清单

- **P10 impulse 设备速度失真**：无 physics 链时 0.2s 视觉按纯冲量 dv 移动（真实应按合成 nv）
- **P11 impulse 不写 ballPos**：逻辑/视觉错位在运动中射门场景放大（悬空高度来自 0.2s 纯 dv 段）
- **P12 脱脚速度过大**：源于 P7（1.2 增益）——7.4 m/s 脱脚不符合真实带球脱控场景（应 1-3 m/s）

## 5. 为最佳物理足球的前置准备（下一步候选）

### 5.1 参数级（低风险，先做）

1. **ROLL_DECEL 裁决**：真实 0.2-0.6 vs 游戏性 3.0。候选：0.8-1.2（折中：球速 6 滚 15-22m，
   球员可追但不至于滚到停）——**需用户拍板"真实优先还是游戏性优先"**。
2. **KD 0.02 → 0.01**：阻力减半（真实 5 m/s²）。
3. **SPEED_GAIN 1.2 → 1.0-1.05**：带球球速 ≈ 玩家速度；脱脚速度自然降到 3-6 m/s。
4. **PULL_DIST2 2.25 → 1.2-1.5**（半径 1.1-1.2m）、PULL_FWD_MIN -0.3 → 0（必须在前方）。
5. **自旋提升**：kick 各 tab 的 spin 放大（0,-6→0,-15 等，ω 20-30 rad/s）；KM 0.01 → 0.015-0.02。
6. **弹道修正**：physIntegrate `npos = p + nvel·DT` → `p + (vel+nvel)/2·DT`（梯形）——峰值回升到 ~1.3m；
   或 kickLaunch 目标点同步改梯形。

### 5.2 架构级（中风险，需设计）

7. **统一位置真相**（P2/P11）：候选 A：每 tick 把 ballPos 写回实体视觉位置（`set_custom_variable`/瞬移？
   引擎无"设置位置"节点？——motion_instant 可瞬移但会触发停止事件）；候选 B：设备速度始终用
   "逻辑速度的段平均"且 kick/impulse 等所有改速点都同步 ballPos；候选 C：放弃 ballPos 逻辑积分，
   直接读实体视觉位置做碰撞/判定（视觉即真相）——**需实验验证引擎能力后再定**。
8. **impulse 语义**（P10）：验证"同名设备替换"（PKC clm_36A5D97 未确认）→ 若成立，kickApplyImpulse
   改 physics 设备 + nv（最真实）；否则保留唯一名但设备速度按状态选 dv/nv。

### 5.3 待验证项（需要日志/实验）

- 引擎是否有"设置实体位置"原语（决定 P2 架构路线）
