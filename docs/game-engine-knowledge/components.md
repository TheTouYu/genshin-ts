# 组件

> 状态：部分已验证（铭牌组件编码已确认，其余组件仍为框架草案）
> 来源：用户对实体组件的说明 + 真实 GIL 相邻快照（nameplate-component 实验 exp1–14，2026-08-03）
> 最近校验：2026-08-03
> 适用范围：官方预置组件、实体能力、组件事件和开关

组件是游戏官方预置的功能模块。用户把组件配置到实体后，实体就获得该组件提供的能力。

## 基本关系

```text
实体
└── 配置组件
    ├── 获得组件功能
    ├── 可以配置组件参数
    ├── 可能产生组件事件
    └── 可以开启或关闭
```

组件本身不是用户自定义节点。组件负责给实体增加能力；节点图通过事件和 API 响应或控制这些能力。

## 选项卡

选项卡组件可以配置多个选项。

当玩家进入设定范围后，游戏向玩家展示这些选项。玩家选中某一项时，会触发该实体挂载节点图中的“选项卡选中”事件，随后节点图执行对应逻辑。

```text
实体配置选项卡组件
→ 玩家进入设定范围
→ 游戏显示多个选项
→ 玩家选择一项
→ 触发“选项卡选中”事件
→ 实体挂载的节点图继续执行
```

选项内容、触发范围、事件参数和选项身份的具体规则仍需通过真实关卡增量逐项还原。

### 选项卡 GIL 编码（code 17）

> 状态：真实 GIL 已观察 + 当前实现 + 自动回归
> 来源：`1073741849.gil`（SHA-256 `d3be30fc...dfa51`）元件定义 1077936180 “空模型_选项卡组件”
> 验证层级：真实只读观察 + 编码器自动回归（与真实 313-byte 槽逐字节一致）；尚未编辑器/游戏验证

选项卡组件槽位于元件定义的 `field 8` 与实体的 `field 7`（槽结构：`f1=类型码、f2=1、f{code+10}=配置`），类型码为 `17`。真实样本槽结构：

```text
f1 = 17（类型码）
f2 = 1
f27 = 配置：
  f1 = 区域配置：
    f11 = 区域几何：f1=空、f2={f1,f2,f3=float32(1.0)}、f3=空
    f502 = 区域名称（如 “区域1”)
    f503 = 1
  f2 × N = 选项：
    f1 = 序号（1..N）
    f2 = 短名（如 ‘U’、‘逆/顺时针切换’）
    f3 = 1、f4 = 1、f5 = 1、f6 = 空字符串
    f503 = 显示名（自动生成：“{短名}  序号: {序号}”）
    f504 = 13
```

当前公开配置只暴露 `regionName`（区域名称）与 `options`（短名列表）；序号、显示名、区域几何与内部数值由编码器按真实样本固定生成。已确认：实体从元件创建时，组件槽从定义 `field 8` 逐字节复制到实体 `field 7`。

## 基础运动器

实体配置基础运动器后，可以在游戏中改变速度和旋转。

它为实体提供直接运动能力。具体速度、旋转、启停和参数单位仍需后续验证。

## 跟随运动器

实体配置跟随运动器后，可以在运行时切换目标实体，并跟随目标的位置或旋转关系。

### 魔方示例

制作 3×3 魔方旋转面时，可以让一个面的 9 个小块预先跟随中心块。旋转中心块时，其余 8 个小块随中心块一起转动，不需要分别计算和设置每个小块的旋转。

```text
中心块旋转
→ 该面的其他小块跟随中心块
→ 整个 3×3 面同步旋转
```

### 互斥规则

跟随运动器和基础运动器不能同时配置在同一个实体上。

这是组件组合的合法性约束。后续记录其他组件时，也需要检查是否存在类似的依赖或互斥关系。

## 铭牌

铭牌是挂载在实体上的 3D 显示组件。它可以跟随实体移动，并自动面向观察它的玩家，使玩家从不同方向都能读到内容。

铭牌可以展示变量值，而不是只能显示预先写死的固定内容。例如，一个移动实体可以挂载两个铭牌内容：

- 当前距离；
- 当前生命值。

当变量变化时，铭牌显示的内容也可以随之变化。

```text
实体移动或旋转
→ 铭牌跟随实体
→ 铭牌朝向观察玩家
→ 展示实体状态变量
```

### 与选项卡的区别

| 能力 | 选项卡 | 铭牌 |
|---|---|---|
| 主要用途 | 给玩家选择固定选项 | 展示实体信息 |
| 是否挂在实体上 | 通常是，也可以挂在玩家上 | 是 |
| 是否显示变量 | 当前说明中不支持 | 支持（文本模板内嵌占位符） |
| 是否朝向观察者 | 不是主要能力 | 可以跟随旋转并面向玩家 |
| 主要事件 | 选项被选中 | 显示行为，具体事件待验证 |

铭牌存在于 3D 世界中，不同于固定在玩家屏幕上的[屏幕控件与 UI](ui-controls.md)。

### 编码规则（真实关卡确认）

以下规则来自同一地图（mapId 1073741851）的 14 轮单变化相邻快照差分（
`~/genshin-ts-evidence/nameplate-component/exp1..14`），证据链：每次仅一个编辑器
操作，前后快照均保存 SHA-256；definition 与 instance 两侧字节双写一致。验证层级：
真实编辑器观察 + 自动结构断言；尚未做游戏内行为验证。

#### 组件条目

组件挂在元件（静态资源）上。元件在 GIL 中有一对同构记录：definition（root 4 的
field-1 记录）和 instance（root 8 的 field-1 记录），两者都有**组件配置列表**：

```text
definition 侧：f8 系列条目   {1=<组件类型 ID>, 2=1, <类型配置字段>=...}
instance 侧：  f7 系列条目   （与 definition 侧逐字节相同）
```

- 组件类型 ID：**27 = 铭牌**；其他已见类型：1、3、6、14、18、19（语义未确认）
- 添加组件 = 在列表末尾追加一条；每条条目独立，顺序即列表顺序
- 删除/修改组件应同样只动对应条目（未实测删除）

#### 铭牌配置（38）

铭牌组件的类型配置字段是 **38**，它是一份**配置列表**（重复字段 501）：

```text
38.501[n]              一个铭牌配置
 ├─ 501  varint        配置序号（v1、v2 递增，身份标识；wire 顺序不可靠）
 ├─ 505  fixed32 f32   显示范围（米），默认 5.0
 ├─ 507  fixed32 f32   数值属性，默认 20.0（语义待确认）
 ├─ 508  fixed32 f32   数值属性，默认 1.0（语义待确认）
 ├─ 512  [重复]        内容组列表（见下）
 ├─ 602  UTF-8         配置名称（编辑器自动命名，如“铭牌 配置ID1”）
 └─ 605  varint        13（语义待确认）
```

- 新增配置 = 追加一条 501，序号与名称自动递增，自带一个默认内容组
- 配置可独立编辑，互不影响；游戏节点图按配置序号切换显示

#### 内容组（512）

每个配置可有多个内容组（重复字段 512），每组显示一段内容：

```text
512[n]                  一个内容组
 ├─ 502                 主条目
 │   ├─ 502  varint     字号，默认 18
 │   ├─ 503             尺寸
 │   │   ├─ 501  f32    宽度（UI 宽度的一半，疑似半宽）
 │   │   └─ 502  f32    高度（与 UI 值相等）
 │   ├─ 504             文本
 │   │   └─ 501  UTF-8  显示内容；支持内嵌变量占位符 {<id>:<变量名>}
 │   ├─ 505             偏移
 │   │   ├─ 501  f32    偏移 X
 │   │   └─ 502  f32    偏移 Y
 │   └─ 510  varint     12（语义待确认）
 ├─ 503/504/505/506/507 辅助容器（默认字节，语义待确认）
 └─ 602  varint        组序号（v1、v2 递增）
```

- 新增默认内容组 = 追加一条 512，组序号递增；各组独立编辑
- **显示变量机制**：文本模板内直接写 `{<id>:<变量名>}` 占位符，例如
  `"这是显示内容{2:PDist}"`；变量名可不在关卡文件其他位置出现（游戏内部另有关联
  逻辑解析），生成时按此格式写即可
- 已确认字段值样本：字号 18→30、宽度 UI 2000→wire 1000.0、高度 30→300、
  偏移 X/Y 333/444、显示范围 5→25（米）

#### 待确认

- 配置级 507（默认 20.0）、508（默认 1.0）的编辑器属性名
- 内容组辅助容器 503/504/505/506/507、主条目 510=12 的语义
- 配置 605=13 的语义
- 组件删除、组件开关、组件事件、运行时（节点图）创建实体并挂载组件的编码
- 游戏内实际显示行为（未验证）

## 开启与关闭

组件可以被开启或关闭。组件关闭后，其能力和事件是否立即停止、已有状态如何保留，需要按具体组件分别验证，不能统一推断。

## 组件与节点图

- 组件给实体增加能力。
- 节点图必须挂载在实体或元件上才能运行。
- 组件事件可以成为节点图的执行起点。
- 节点图可以通过 API 查询、修改或启停组件。
- 铭牌等显示组件可以读取或展示[变量](variables.md)。
- 选项卡事件可以触发运动、交互或玩家[镜头](camera-system.md)切换。

节点图的运行条件见[节点图挂载与生命周期](graph-mounting.md)，事件后的执行方式见[控制流](control-flow.md)。

- 产生的事件及事件参数。

- 已通过编辑器或游戏验证的行为范围。
