**配置字段号规律**：普通组件 = 类型码+10（如 12→f22、6→f16、13→f23）；含 501 配置列表的组件（27/28/29） = 类型码+11（27→f38、28→f39、29→f40）。

**引用绑定模式**（物件镜头/计时器）：组件配置内以**名称引用**（如 f4.f2="自定义镜头_1"、f26.f1="全局计时器1"），目标注册表在 root（root18 镜头容器、root12 计时器容器）以同名条目 + 自增 ID 存在。

**资源 ID 存储**（特效 exp10 确认）：资源只存 ID 不存名字（游戏运行时用 ID 引用）；特效条目 ID 双处存储（f1 + f10={f2:ID}），音效条目单处（f2）。

## 基本关系

```text
实体
└── 配置组件
    ├── 获得组件功能
    ├── 可以配置组件参数
    ├── 可能产生组件事件
    └── 可以开启或关闭
```

组件本身不是用户自定义节点。组件负责给实体增加能力；节点图通过事件和 API 响应或控制这些能力。

## 选项卡

选项卡组件可以配置多个选项。

当玩家进入设定范围后，游戏向玩家展示这些选项。玩家选中某一项时，会触发该实体挂载节点图中的“选项卡选中”事件，随后节点图执行对应逻辑。

```text
实体配置选项卡组件
→ 玩家进入设定范围
→ 游戏显示多个选项
→ 玩家选择一项
→ 触发“选项卡选中”事件
→ 实体挂载的节点图继续执行
```

选项内容、触发范围、事件参数和选项身份的具体规则仍需通过真实关卡增量逐项还原。

## 命中检测（code 12）

> 状态：真实编辑器添加确认（component-investigation exp6 轮 1，2026-08-04）+ 官方文档语义
> 验证层级：用户明确告知组件名 + 唯一归因相邻快照 + definition/instance 双写一致 + 千星知识库文档；尚未游戏验证

命中检测组件在组件内定义的命中区域碰到其他实体或场景地形（以及水面）时，向服务端节点图发送命中事件，常用于投射物攻击盒。官方文档参数：触发类型（单次/不重复/重复）、触发间隔、检测延迟时间、连续碰撞检测（CCD）与类型/速度阈值/检测半径、过滤器节点图、阵营/实体类型/命中层筛选、命中时执行能力单元；命中区域支持长方体/球体/胶囊体（中心/旋转/缩放/半径/角度/高度），可配置多个。

类型码为 **12**，默认槽 81B（配置字段 f22 = 12+10）：

```text
f22 = 配置（74B，默认样本）：
  f1 = 区域配置（与选项卡同构）：
    f11 = 区域几何：f1=空、f2={fixed32 1.0,1.0,1.0}、f3=空
    f502 = UTF-8 区域名（“区域1”）
    f503 = varint 1
  f2  varint 1（疑似触发类型枚举）
  f3  varint 2101（疑似位域/标志）
  f4  fixed32 1.0（疑似半径/延迟）
  f6/f7 空（疑似过滤器节点图引用）
  f8  varint 2002（疑似引用 ID/标志）
  f9  sub 2B = fd 0a（varint 1405，字段 175/wire5 长度不足，编辑器怪字节）
  f11 fixed32 0.3（疑似触发间隔/检测延迟）
  f13 sub 2B = a9 14（varint 2601，字段 325/wire1 长度不足，编辑器怪字节）
  f503 varint 13（与组件 18 f507、铭牌 605 同值 13，疑似通用类型码）
  f1002 varint 1
```

- 配置内多数数字段（f2/f3/f4/f8/f9/f11/f13/f503/f1002）语义待改参数后归因

## 跟随运动器

实体配置跟随运动器后，可以在运行时切换目标实体，并跟随目标的位置或旋转关系。

### 魔方示例

制作 3×3 魔方旋转面时，可以让一个面的 9 个小块预先跟随中心块。旋转中心块时，其余 8 个小块随中心块一起转动，不需要分别计算和设置每个小块的旋转。

```text
中心块旋转
→ 该面的其他小块跟随中心块
→ 整个 3×3 面同步旋转
```

### 互斥规则

跟随运动器和基础运动器不能同时配置在同一个实体上。

这是组件组合的合法性约束。后续记录其他组件时，也需要检查是否存在类似的依赖或互斥关系。

## 铭牌

铭牌是挂载在实体上的 3D 显示组件。它可以跟随实体移动，并自动面向观察它的玩家，使玩家从不同方向都能读到内容。

铭牌可以展示变量值，而不是只能显示预先写死的固定内容。例如，一个移动实体可以挂载两个铭牌内容：

- 当前距离；
- 当前生命值。

当变量变化时，铭牌显示的内容也可以随之变化。

```text
实体移动或旋转
→ 铭牌跟随实体
→ 铭牌朝向观察玩家
→ 展示实体状态变量
```

### 与选项卡的区别

| 能力 | 选项卡 | 铭牌 |
|---|---|---|
| 主要用途 | 给玩家选择固定选项 | 展示实体信息 |
| 是否挂在实体上 | 通常是，也可以挂在玩家上 | 是 |
| 是否显示变量 | 当前说明中不支持 | 支持（文本模板内嵌占位符） |
| 是否朝向观察者 | 不是主要能力 | 可以跟随旋转并面向玩家 |
| 主要事件 | 选项被选中 | 显示行为，具体事件待验证 |

铭牌存在于 3D 世界中，不同于固定在玩家屏幕上的[屏幕控件与 UI](ui-controls.md)。

### 编码规则（真实关卡确认）

以下规则来自同一地图（mapId 1073741851）的 14 轮单变化相邻快照差分（
`~/genshin-ts-evidence/nameplate-component/exp1..14`），证据链：每次仅一个编辑器
操作，前后快照均保存 SHA-256；definition 与 instance 两侧字节双写一致。验证层级：
真实编辑器观察 + 自动结构断言；尚未做游戏内行为验证。

#### 组件条目

组件挂在元件（静态资源）上。元件在 GIL 中有一对同构记录：definition（root 4 的
field-1 记录）和 instance（root 8 的 field-1 记录），两者都有**组件配置列表**：

```text
definition 侧：f8 系列条目   {1=<组件类型 ID>, 2=1, <类型配置字段>=...}
instance 侧：  f7 系列条目   （与 definition 侧逐字节相同）
```

- 组件类型 ID 已确认：**27=铭牌、1=自定义变量组件、6=特效播放、12=命中检测、13=物件镜头组件、16=全局计时器、17=选项卡、28=文本气泡、29=音效播放器**（见顶部映射表）；未确认：3、14、18、19、4
- 添加组件 = 在列表末尾追加一条；每条条目独立，顺序即列表顺序
- 删除组件 = 移除对应条目（exp16 移除物件镜头绑定实测：槽恢复 7B 空配置）；修改组件 = 只动对应条目（exp18 铭牌文本实测）

#### 自定义变量组件（1）

组件类型 ID **1 = 自定义变量组件**（编辑器“自定义变量组件”是单位默认挂载组件，元件/实体创建时自动带
上）。其类型配置字段是 **11**，内为**变量列表**（重复字段 1）：

```text
1.11.1[n]               一个自定义变量条目（38B，同构）
 ├─ 2  UTF-8            变量名（同一组件内不允许重名）
 ├─ 3  varint           类型码（全局通用 VarType，见 parameter-types.md）
 ├─ 4  length-delimited 默认值容器 {1: 类型码, 2: {1:类型码, 2:0}, (10+类型码): 默认分支}
 ├─ 5  varint           1（疑似 exposed/可见标记，恒定）
 └─ 6  length-delimited 类型引用 {1: 类型码, 2: 0}
```

- 新增变量 = 追加一条同构 field-1 条目；复制新建的变量与原条目字节一致（仅名称不同）
- 类型码与信号参数/关卡变量共用同一枚举（已三方核对：GIA proto VarType、信号 InParam、
  GIL wire 类型码）；类型 6=String、15=VectorList（本次样本）
- definition f8 与 instance f7 双写一致
- 证据：component-investigation exp1/exp2 相邻快照（2026-08-04，真实编辑器保存）

#### 铭牌配置（38）

铭牌组件的类型配置字段是 **38**，它是一份**配置列表**（重复字段 501）：

```text
38.501[n]              一个铭牌配置
 ├─ 501  varint        配置序号（v1、v2 递增，身份标识；wire 顺序不可靠）
 ├─ 505  fixed32 f32   显示范围（米），默认 5.0
 ├─ 507  fixed32 f32   数值属性，默认 20.0（语义待确认）
 ├─ 508  fixed32 f32   数值属性，默认 1.0（语义待确认）
 ├─ 512  [重复]        内容组列表（见下）
 ├─ 602  UTF-8         配置名称（编辑器自动命名，如“铭牌 配置ID1”）
 └─ 605  varint        13（语义待确认）
```

- 新增配置 = 追加一条 501，序号与名称自动递增，自带一个默认内容组
- 配置可独立编辑，互不影响；游戏节点图按配置序号切换显示

#### 内容组（512）

每个配置可有多个内容组（重复字段 512），每组显示一段内容：

```text
512[n]                  一个内容组
 ├─ 502                 主条目
 │   ├─ 502  varint     字号，默认 18
 │   ├─ 503             尺寸
```

## 开启与关闭

组件可以被开启或关闭。组件关闭后，其能力和事件是否立即停止、已有状态如何保留，需要按具体组件分别验证，不能统一推断。

## 组件与节点图

- 组件给实体增加能力。
- 节点图必须挂载在实体或元件上才能运行。
- 组件事件可以成为节点图的执行起点。
- 节点图可以通过 API 查询、修改或启停组件。
- 铭牌等显示组件可以读取或展示[变量](variables.md)。
- 选项卡事件可以触发运动、交互或玩家[镜头](camera-system.md)切换。

节点图的运行条件见[节点图挂载与生命周期](graph-mounting.md)，事件后的执行方式见[控制流](control-flow.md)。

## 待逐步还原

每种组件至少需要记录：

- 组件名称和用途。

- 配置参数和默认值。
- 开启、关闭和状态切换规则。
- 提供的节点 API。
- 产生的事件及事件参数。
- 与其他组件的依赖或互斥关系。
- 关卡文件中的注册、实例和参数编码。
- 已通过编辑器或游戏验证的行为范围。
