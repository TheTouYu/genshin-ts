**资源 ID 存储**（特效 exp10 确认）：资源只存 ID 不存名字（游戏运行时用 ID 引用）；特效条目 ID 双处存储（f1 + f10={f2:ID}），音效条目单处（f2）。

## 基本关系

```text
实体
└── 配置组件
    ├── 获得组件功能
    ├── 可以配置组件参数
    ├── 可能产生组件事件
    └── 可以开启或关闭
```

组件本身不是用户自定义节点。组件负责给实体增加能力；节点图通过事件和 API 响应或控制这些能力。

## 选项卡

选项卡组件可以配置多个选项。

当玩家进入设定范围后，游戏向玩家展示这些选项。玩家选中某一项时，会触发该实体挂载节点图中的“选项卡选中”事件，随后节点图执行对应逻辑。

```text
实体配置选项卡组件
→ 玩家进入设定范围
→ 游戏显示多个选项
→ 玩家选择一项
→ 触发“选项卡选中”事件
→ 实体挂载的节点图继续执行
```

选项内容、触发范围、事件参数和选项身份的具体规则仍需通过真实关卡增量逐项还原。

### 选项卡选中事件链路（2026-08-13 魔方 P4 最小实验闭合）

> 验证层级：用户游戏核验 + 真实 Beyond_Debug_Log 逐帧确认（7 次点击全部完整执行）

- 事件名：**whenTabIsSelected**（“选项卡选中”）；节点图挂载在**挂载选项卡组件的实体**上触发（魔方控制器实体 1077936138，`assets:mounts attach --entity`）。
- 事件 payload（与 `events-payload.ts` 一致）：`eventSourceEntity`（事件源实体）/ `eventSourceGuid` / **`tabId`** / `selectorEntity`（选择者角色实体）。
- **tabId 从 1 开始**（1~6 对应配置的选项顺序，魔方 R/L/U/D/F/B = 1/2/3/4/5/6；用户直接确认）。
- 日志帧特征：单帧 `head=图内节点序号`，OUT0:Entity=2、OUT1:GUID=实体ID、OUT2:Integer=tabId、OUT3:Entity=选择者。

### 选项卡 GIL 编码（code 17）

> 状态：真实 GIL 已观察 + 当前实现 + 自动回归 + 编辑器手动添加确认
> 来源：`1073741849.gil`（SHA-256 `d3be30fc...dfa51`）元件定义 1077936180 “空模型_选项卡组件”；
> component-investigation exp4 轮 1（2026-08-04，用户在同一地图 1073741851 手动添加默认选项卡，94B 槽，双写一致）
> 验证层级：真实只读观察 + 编码器自动回归（与真实 313-byte 槽逐字节一致）+ 编辑器手动添加样本逐字段吻合；尚未游戏验证

选项卡组件槽位于元件定义的 `field 8` 与实体的 `field 7`（槽结构：`f1=类型码、f2=1、f{code+10}=配置`），类型码为 `17`。真实样本槽结构：

```text
f1 = 17（类型码）
f2 = 1
f27 = 配置：
  f1 = 区域配置：
    f11 = 区域几何：f1=空、f2={f1,f2,f3=float32(1.0)}、f3=空
    f502 = 区域名称（如 “区域1”)
    f503 = 1
  f2 × N = 选项：
    f1 = 序号（1..N）
    f2 = 短名（如 ‘U’、‘逆/顺时针切换’）
    f3 = 1、f4 = 1、f5 = 1、f6 = 空字符串
    f503 = 显示名（自动生成：“{短名}  序号: {序号}”）
    f504 = 13
```

当前公开配置只暴露 `regionName`（区域名称）与 `options`（短名列表）；序号、显示名、区域几何与内部数值由编码器按真实样本固定生成。已确认：实体从元件创建时，组件槽从定义 `field 8` 逐字节复制到实体 `field 7`。

### 选项卡区域几何（已闭合：盒体尺寸 + 球体半径；类型标记待往返样本）

> 2026-08-12 exp5/exp6 相邻快照：`1073741882.gil`，元件 def 1077936137 / 实体 1077936138
> exp5：触发范围 1×1×1 → 3×3×3（盒体尺寸）；exp6：长方体 → 球体（默认半径 1）
> 验证层级：真实编辑器保存 + raw-wire 定点差分（before/after 逐字节）；尚未游戏验证

真实样本槽结构（区域配置块）：

```text
盒体（默认）：
  f27.f1 区域配置 = {
    f11 区域几何 = { f1=空, f2 = { f1=X, f2=Y, f3=Z }（float32 三轴尺寸，米）},  默认 1,1,1
    f502 = 区域名（UTF-8），f503 = 1
  }
球体：
  f27.f1 区域配置 = {
    f1 = 1（类型标记：球体；盒体时 f1 不落盘，推断 0=盒省略 / 1=球；未经盒↔球往返样本验证，不影响已实现的两种形态）
    f12 区域几何 = { f1=空, f2 = float32 半径（米）},  默认 1
    f502 = 区域名（UTF-8），f503 = 1
  }
```

- 区域语义（用户确认）：以组件挂载实体中心为中心；玩家进入该体积 → 选项卡显示。
- 盒体尺寸 1→3 实测：f11.f2 三个 float 全部 1.0→3.0；实体槽与定义槽双写一致。
- 球体半径 = f12.f2 float32（默认半径 1 = 0x3f800000）。
- **球心偏移 = f12.f1 子块 {f1=X, f2=Y, f3=Z} float32（2026-08-12 游戏验证通过）**：v9 写回（球体 r=3、中心 [0.1,0,0]）用户实测——选项卡触发区域球心在实体中心 +X 0.1m 处，偏移准确、半径 3 生效、选项配置正确。偏移全 0 时 f12.f1 为空块（与 exp6 样本一致）。
- **未闭合**：f1=1 类型标记的精确语义（盒体时 f1 不落盘）；CLI 现仅支持盒体（f11 三 float）。

### 编辑器首次保存自动补全（2026-08-12 用户解释 + exp6 验证）

> CLI 从零创建/写入的地图（紧凑布局，如 12 个 root occurrences）被用户在游戏编辑器里**首次手动保存**时，编辑器会自动补全：

1. 默认实体 11 个：「默认模版」×9（1086324737–745，共用 def 1086324737）+「默认模版(角色编辑)」（1090519041）+「关卡实体」（1094713345，def 10003004）及对应定义记录；
2. 文件布局规范化：12 → 41 个 root occurrences（补齐大量默认字段/注册表），部分记录字段顺序重排（如 f10 与 f8 交换）；
3. 首次保存后布局稳定：exp6 第二次保存 root 数 41→41，仅选项卡槽变化（-36B）。

> 手动保存的自动补全**与信号无关**——是地图刚创建后第一次保存时引擎补全地图**骨架定义**（默认实体、布局规范化，见上）；CLI 注入的图无需手动补，但编辑器保存后必须重新比对/回读，不能假设磁盘与编辑器内存一致。

这是编辑器固有行为，不是数据损坏；CLI 能正确读写规范化后的布局（entities export 验证）。因此 CLI 写回后的地图，若用户已在编辑器保存过一次，后续写回不会再有这些补全变化。

## 跟随运动器

实体配置跟随运动器后，可以在运行时切换目标实体，并跟随目标的位置或旋转关系。

### 魔方示例

制作 3×3 魔方旋转面时，可以让一个面的 9 个小块预先跟随中心块。旋转中心块时，其余 8 个小块随中心块一起转动，不需要分别计算和设置每个小块的旋转。

```text
中心块旋转
→ 该面的其他小块跟随中心块
→ 整个 3×3 面同步旋转
```

### 互斥规则

跟随运动器和基础运动器不能同时配置在同一个实体上。

这是组件组合的合法性约束。后续记录其他组件时，也需要检查是否存在类似的依赖或互斥关系。

## 铭牌

铭牌是挂载在实体上的 3D 显示组件。它可以跟随实体移动，并自动面向观察它的玩家，使玩家从不同方向都能读到内容。

铭牌可以展示变量值，而不是只能显示预先写死的固定内容。例如，一个移动实体可以挂载两个铭牌内容：

- 当前距离；
- 当前生命值。

当变量变化时，铭牌显示的内容也可以随之变化。

```text
实体移动或旋转
→ 铭牌跟随实体
→ 铭牌朝向观察玩家
→ 展示实体状态变量
```

### 与选项卡的区别

| 能力 | 选项卡 | 铭牌 |
|---|---|---|
| 主要用途 | 给玩家选择固定选项 | 展示实体信息 |
| 是否挂在实体上 | 通常是，也可以挂在玩家上 | 是 |
| 是否显示变量 | 当前说明中不支持 | 支持（文本模板内嵌占位符） |
| 是否朝向观察者 | 不是主要能力 | 可以跟随旋转并面向玩家 |
| 主要事件 | 选项被选中 | 显示行为，具体事件待验证 |

铭牌存在于 3D 世界中，不同于固定在玩家屏幕上的[屏幕控件与 UI](ui-controls.md)。

  组件族命名空间候选，分配算法仍为 `INSUFFICIENT`。
- 同轮 root 22 的 field 1 追加 `ClientBeyondEntityNameplateCompEditData`；field 2
  value bytes 为 `01→0101`，不是计数 `1→2`。该根字段最多称“编辑数据类型名注册候选”，
  正式语义待文本气泡等第二组件实验确认。

## 开启与关闭

组件可以被开启或关闭。组件关闭后，其能力和事件是否立即停止、已有状态如何保留，需要按具体组件分别验证，不能统一推断。

## 组件与节点图

- 组件给实体增加能力。
- 节点图必须挂载在实体或元件上才能运行。
- 组件事件可以成为节点图的执行起点。
- 节点图可以通过 API 查询、修改或启停组件。
- 铭牌等显示组件可以读取或展示[变量](variables.md)。
- 选项卡事件可以触发运动、交互或玩家[镜头](camera-system.md)切换。

节点图的运行条件见[节点图挂载与生命周期](graph-mounting.md)，事件后的执行方式见[控制流](control-flow.md)。

## 待逐步还原

每种组件至少需要记录：

- 组件名称和用途。
- 可以配置在哪些实体或元件上。
- 配置参数和默认值。
- 开启、关闭和状态切换规则。
- 提供的节点 API。
- 产生的事件及事件参数。
- 与其他组件的依赖或互斥关系。
- 关卡文件中的注册、实例和参数编码。
- 已通过编辑器或游戏验证的行为范围。
