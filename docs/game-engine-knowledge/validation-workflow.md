# 验证与规则学习流程

> 状态：当前工作方法草案
> 来源：用户提出的编辑器增量学习和游戏验证方式
> 最近校验：2026-08-01
> 适用范围：从真实关卡学习规则，并通过 GIA 或 GIL 验证

游戏引擎规则优先通过真实编辑器的小步修改学习，而不是先根据当前代码推测。

## 第一阶段：编辑器增量学习

用户每次只修改一个能够明确描述的内容并保存地图。助手保存前后快照，比较发生变化的目标结构。

```text
保存修改前关卡
→ 用户只做一个小变化
→ 保存修改后关卡
→ 固化相邻快照和 SHA-256
→ 定点比较变化
→ 提炼一条可以验证的规则
```

典型的小变化包括：

- 新增一个节点；
- 给节点填写一个参数；
- 连接一条控制流；
- 连接一条数据流；
- 新增一个变量；
- 给实体增加一个组件；
- 修改一个控件设置。

如果同类规则已经有充分证据，可以一次组合多个已知变化，提高验证效率；但必须保证每项都能由已有规则解释，出现未知增量时停止推广。

## 第二阶段：手工同构重放

规则闭合后，先在临时文件中重放观察到的变化：

```text
读取修改前结构
→ 只应用已确认增量
→ 生成临时候选
→ 注入临时 GIL 副本
→ 回读并与编辑器结果比较
```

这一阶段证明“学到的结构规则可以复现”，不等于已经写入真实地图，也不等于游戏行为正确。

## 第三阶段：选择游戏验证路径

### 路径 A：最小 GIA 资源包

优先产出只包含待验证资产的最小 GIA，由用户直接在游戏编辑器中导入。

适合：

- 单个节点图；
- 单个复合节点；
- 一组模型；
- 一组 UI；
- 不依赖完整关卡状态的最小实验。

优点：

- 导入快；
- 用户测试成本低；
- 失败时影响范围小；
- 更容易判断是哪条规则有问题。

### 路径 B：写回完整 GIL 关卡包

当实验依赖完整关卡、既有挂载关系、静态资源或无法由独立 GIA 表达的状态时，才写回 GIL。

适合：

- 修改指定已有节点图；
- 验证实体、组件和挂载关系；
- 验证关卡初始实体；
- 验证多个资产之间的完整引用。

代价：

- 用户通常需要退出并重新打开关卡；
- 操作耗时更长；
- 写回前必须保存备份并明确确认目标。

## 默认选择原则

```text
能用最小 GIA 验证
→ 优先 GIA

只有完整关卡关系才能验证
→ 使用 GIL
```

不要为了方便生成而扩大测试范围。选择依据是“最小能够证明目标规则的资产边界”。

## 证据层级

以下结果必须分开记录：

1. **真实编辑器观察**：用户修改后，关卡文件确实出现目标增量。
2. **自动结构比较**：工具确认哪些节点、参数或连接发生变化。
3. **临时回读**：手工候选写入临时副本后，目标结构可正确读回。
4. **真实写回**：候选已写入真实 GIL。
5. **编辑器导入**：GIA 或写回关卡能被编辑器正常加载和显示。
6. **游戏行为验证**：用户实际运行后确认行为符合预期。

只有用户完成最后一步并明确反馈，才能写“游戏行为验证通过”。

## GIL 写回安全门

写回完整关卡前必须展示并确认：

- 目标关卡；
- 当前文件 hash；
- 目标节点图或资产；
- 候选文件；
- 具体修改内容；
- 备份位置；
- 回滚方式。

任何 hash 漂移、目标不明确或存在无法解释的差异，都应停止写回。

## 学习结果如何进入本知识目录

每轮完成后，把稳定结论写入对应主题文件：

- 概念和对象关系写入领域文件；
- 具体节点规则写入后续节点目录；
- 参数和值规则写入参数类型目录；
- GIL/GIA 对应关系写入本流程和资产文档；
- 索引文件登记它与其他规则的关联。

临时快照和聊天记录不是长期知识。长期结论必须包含证据范围和验证层级。
