# 复盘：记录执行上限引发的 3 个魔方 bug 修复（2026-08-22）

> 状态：已验证（真实日志 2808 + 2766 + 真实 GIL 读回）
> 证据：`2026-08-22_11-11-36_2808_110170759.gia`（177 记录，3 段"游戏开始"）、
>       日志 2766（列表物化实证）、读回 `1073741899.gil`
> 用途：引擎"每记录执行帧上限 + 截断"规则的铁证与修复模式；下次写高帧复合逻辑前必读。

## 一、背景

2808 日志 3 段"游戏开始"对应 3 个 bug：

1. **bug1** 打乱后自动执行几次后位置错乱
2. **bug2** 整体旋转操作无反应
3. **bug3** 复原后回到数字状态、再点击任何面无反应

## 二、根因（铁证）

### 引擎规则 R1：每记录执行帧上限 ≈3000，≥3002f 截断

- 每"记录"（record，日志含 `status` 字段的条目）执行帧数上限约 3000；
  达到 3002f 左右被**截断**（记录不 COMPLETE，后续帧不再执行）。
- **截断语义**（铁证：2808 日志）：
  - 截断记录中**图变量写回滚**（变量值不落盘）
  - **实体操作保留**（实体已移动/旋转）
  - 先前已 COMPLETE 的记录全部保留
- 后果：变量状态（魔方逻辑层）与实体状态（渲染层）脱节 → 位置错乱/无反应。

### 记录对结构：unlock 记录 + execMove 记录

- 每次转动 = 一对记录：unlock（清输入锁）→ execMove（执行转动）。
- 自动执行链截断：**lock 保持空**（下次可再输入）——bug1 表现为"还能动但位置错乱"。
- 手动分发（点击）截断：**lock=true**（输入被永久阻塞）——bug2/bug3 表现为"无反应"。

### 引擎规则 R2：全 0 int_list 物化怪癖

- 值为全 0 的 int_list 图变量，引擎只物化出**短长度**（如 cornerOrient 只剩 [0,0]）。
- `set_list_value` 写 **0** 到越界下标**不会扩展列表**（写入无效且不报错）。
- 写**非 0** 值则正常扩展。
- 后果：复原复位写 0 失败 → 列表损坏 → 后续读取错乱（bug3 的一部分）。

### 帧预算分解（整体旋转 3002f 截断的构成）

| 段 | 帧 |
|---|---|
| temp 段 26 迭代展开（体小） | ~28 |
| 写回段 6 个运行时 finiteLoop（控制开销） | ~978（36%） |
| 其他（分发/实体/运动器） | ~1300 |
| 合计 | **3002 → 截断** |

## 三、修复方案（折中模式，可复用）

**原则：体小的循环展开（省控制帧）、体大的循环用有限循环（省节点），按预算/帧双约束分配。**

- **logic_apply_whole（整体旋转）**：temp 段 26 迭代**展开**（体 ~2 节点/迭代 → 展开
  0 控制帧）；写回段 3 个 finiteLoop `(0,7)/(0,11)/(0,5)`（体 3 SetListValue → 省节点）。
  结果：**229 节点**，整体旋转 execMove ≈2513f <3000。
- **logic_reset（复原）**：哨兵段**展开**（124 Set List Value，0 控制帧——撑列表必须先于
  循环写 0，且展开索引是编译期常量更稳）；复位段 4 个 finiteLoop `(0,7)/(0,11)/(0,5)/(0,25)`。
  结果：**148 节点**，复原 execMove ≈2138f <3000。
- 哨兵值 = index+1（非 0），先撑满列表再写真实值。

## 五、读图核验要点（本次已验证）

- **finiteLoop 循环变量在 GIA 中物化为 "Finite Loop" 节点输出**：体内直接用该节点输出
  （运行时值），不是编译期常量。读图时确认体内索引连线来自 Finite Loop 节点。
- **闭包提升**：循环外共享变量（GetVar）每变量只建 1 次，体内复用。
- **展开段计数合并验证**：展开段按"哪个列表 × 哪个下标"合并计数与源码 for 循环
  逐一对应（如哨兵段 124 = cornerOrient 8 + edgeOrient 12 + 4 链 × 26）。
- explain 输出中：Finite Loop 的 Branch[0] = 循环体、Branch[1] = 循环结束链。
