## 二、为什么三层叠加——系统性根因

1. **跨图双 loop 是 v4 单图时代不存在的执行模型**：v4 感知-计算-挂设备同拍同图，重求值即使发生也读到本拍值（无害）；v5 的决策图（828）与逻辑层（825）各自 0.5s 独立相位，**任何"读黑板→表达式→晚消费"的链路都可能横跨一次 drain 更新**。重求值家族因此在跨图形态下从"结果偏差"升级为"速度反向爆炸"。
2. **物化纪律没有作为迁移清单随架构重构携带**：v4 的 tmpDribbleVel/tmpBallPos 物化是为防同拍重求值写的；重写决策复合时只继承了位置物化（且丢了），速度物化被"黑板是真相源"的新心智模型挤掉——**黑板读取的消费点仍是表达式引用**。教训：架构迁移时，旧架构的防御性纪律要逐条对照迁移，不能凭新模型的直觉省略。
3. **三层叠加使单点日志结论失真**：第 2 轮日志里 vel 恒 0（drain 未跑）与 vel=24（爆炸后）同帧序列并存——若只看单点帧会误判方向。三轮都是"帧值序列 + 写入帧 IN2 对照计算帧 OUT"交叉定位的。

## 三、方法论（怎么定位的，下次照做）

- **写入帧 IN2 与计算帧 OUT 对照法**（本轮新方法论）：同一值的"计算帧输出"与"消费帧输入"不一致 = 重求值实锤（Subtraction OUT=2.07 vs set IN2=−11.1）。跨图双 loop 场景下这是重求值的一眼判据。
- 覆盖式 vs 累积式的选择：跨消费者队列（多写者/读写异步）用覆盖式 + 单消费者 drain——累积在相位错开时数学上必然爆炸，"概率低"的预判不可信（ARCHITECTURE-V5 第八节的取舍判断被实测推翻，已随 6e870ac 修正）。
- 日志洪泛治理有效：降载 0.5s 后日志 1082→86 条（−92%），三轮定位都在秒级完成。
