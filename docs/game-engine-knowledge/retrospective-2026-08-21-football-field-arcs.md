## 二、最近一次错误的完整调查链（#3/#4：罚球弧端点）

1. **用户反馈**：罚球弧不是半圆，应该正好和禁区横线相交，现在穿过了，画多了。小长方形组件不能超出横线太多。
2. **几何推导**：罚球点 x=±(52.5−11)=±41.5，禁区横线 x=±(52.5−16.5)=±36；交点满足 `cosθ = |41.5−36|/9.15 = 5.5/9.15` → `θ_max = arccos(0.6011) ≈ 53.06°`。
3. **写回前拦截**（#4）：首版公式 `acos((PEN_SPOT−PA_DEPTH)/R)` 传了负数 -5.5 → 得 126.94°，本地端点验证发现弧端点 x=45.9 越界（应 ≤41.5），改 `Math.abs` 后端点精确 x=36.0000、z=±7.312（理论 √(9.15²−5.5²)=7.313）✓。
4. **写回 + 回读**：恢复备份重生成 → 候选 `24a1d5fa…` → 写后地图=Temp=候选，双侧端点 x=±36.0000 误差 0。

## 三、为什么反复出问题——系统性根因

1. **弧线段旋转公式没有从"局部轴→世界方向"推导**：第一版用直觉「段中心角+90°」，没有验证它把局部 X 转到什么方向；实际得到的是切线绕 X 翻转（z 镜像）。正确做法：写出目标世界方向（切线 = dP/dθ 归一化），再解 `(cos rotY, -sin rotY) = 切线方向`。
2. **弧的端点没有几何约束意识**：默认画半圆/整圆，没有先算"弧应与哪条线相交"；罚球弧端点由禁区横线决定，不是任意 180°。
3. **符号/方向没有本地断言护航**：acos 传负值、凸向参数 side 符号，都是写完就跑，靠本地几何验证（端点 x 范围断言）才拦截。生成器自检必须含"端点与约束线距离"级断言，不是只看 bbox 范围。

## 四、流程与方法论教训

1. **用户编辑器最小差分 = 正确公式真值来源**：用户"只调旋转没动位置"保存 → aux 被编辑器重写为新 ID 区间 → 按位置匹配新旧版本提取旋转差异（13.99/8.36/-8.68/-13.34 vs 我的 343/354/365/376）→ 反推出 `atan2(-cosθ,-sinθ)`。这再次验证 AGENTS.md「用户做最小差分学真实 wire」的价值——比任何源码推断都可靠。
2. **aux 比对要点**（复用）：
   - 编辑器保存会把实体 aux 整体重写为新 ID 区间（足球场实体 84 条从 1073742000+ → 1073743124+）；
   - 按**位置**匹配（用户没动位置），不按 ID；
   - transform 编码 = aux `f5{f1:1}.f11` 稀疏 vec3（f1/f2/f3 各 fixed32，缺省 0），不是 packed bytes。
3. **写回前本地几何断言**：弧端点必须断言"与约束线距离 < ε"（本轮 x=36.0000），凸向断言"全部小于/大于罚球点 x"。这条直接拦下了 #4。
4. **恢复备份重生成流程有效**：地图被用户保存过 → 恢复写回前备份（空骨架 SHA 6b42e325）→ 重 plan/候选/实体/写回，全程哈希门控，无残留。

## 五、风险探索与未闭合项
