## 二、asv 回归的完整调查链（核心案例）

现象 → 排查 → 定论路径（方法 > 结论）：

1. **现象分级**：用户编辑器报告多分支无出口 → 日志 3013 铁证 `IN0:Integer=3`（tab3 按下）
   但 `IN1:List=` 空 → 行为与显示同断，排除纯显示问题。
2. **对照排除**：.gia 层 cases entries 完整（[1,2,3]，两种后端同）→ 编译输出有值；
   .gil 层 parse 读出 [] → **值在 .gia→.gil 之间丢**。嫌疑注入器。
3. **反证反转**：副本注入实验（src 注入器直跑）cases 保留 → dist CLI 单文件注入也保留 →
   **只有批量注入丢**？——但单文件实验用的 .gia 是重编后的，两变量未分离。
4. **并发覆盖干扰**：修复被游戏退出回写覆盖（mtime 18:37:41），产生"修复无效"假象，
   一度误导方向。识别后重注入恢复。
5. **用户差分定论**：用户在编辑器给多分支新增 case 保存 → 编辑器实样 cases 容器
   **inner.asv=true**；我们产物 asv=false。唯一字节差异锁定。
6. **git 考古**：`git log -S normalizePinInner` → 79a24a7（08-29 13:53）把归一化从局部变量
   扩到全节点；fc44db1（08-29 23:37）修标量保留漏 bArray。1899（08-28 产物）asv=true
   且 08-24 起默认后端即 vendor → vendor 本来写 asv，被归一化删掉。
7. **修复演进**：第一版"保留"（bArray 命中 return）legacy 生效 vendor 不生效 → 定位
   vendor 惰性物化（encode 时才展开，归一化时 bArray 未解码）→ 第二版**主动置 true**
   双后端一致 → vendor 产物 asv=true + 注入回读 + 用户编辑器实测恢复。
8. **同族扩展**：bDict 容器同漏判（1225 行证明形态存在）→ 同日补判 + 回归绿。

## 三、系统性根因（为什么反复出问题）

1. **编译器回归缺"全节点族 wire 回归"**：79a24a7/fc44db1 的测试只锁局部变量族——
   改的是全节点共享路径，验证只覆盖单族。列表/dict 字面量 pin（多分支 cases、
   assembly list 元素）无回归锁。**规律：改共享归一化路径时，必须枚举受影响节点族
   并至少各锁一个 wire 样本。**
2. **注入路由语义不显性**：单文件注入被 config.nodeGraphId 静默覆盖目标（与批量模式
   "按 gia 内 ID 推断"语义相反），无警告无文档 → 覆盖了 game 图才发现。
   **规律：同一 CLI 入口两种模式语义相反时，必须有显式输出（目标图 ID 打印）或拒绝执行。**
3. **CLI 写地图与游戏/编辑器回写无并发防护**：游戏退出回写地图（本轮实证），
   注入窗口重叠即静默覆盖。**规律：注入前检查游戏进程/提醒用户确认关闭，
   注入后立即核验 mtime 与内容。**

## 四、流程与方法论教训

- **差分定论 > 推理猜测**：本轮两次"编辑器缓存"归因都被用户纠正。正确路径是用户
  10 秒差分（手加 case 保存）拿到编辑器实样，字节差异一锤定音。卡住三问的第二问
  （能不能让用户做 10 秒差分）应更早触发。
- **正常参照物选旧产物**：1899（08-28 注入、2960 会话游戏正常）是完美对照组——
  同图族同注入器，仅编译器版本不同。字节级三样本对照（1899 / 1914 坏版 / 编辑器实样）
  定论 asv。
- **临时 dump 工具有效但会丢**：dump_asv.ts / dump_mb_wire.ts（项目根临时文件，不在 git）
  是本轮关键取证工具——落 PROGRESS 记录其重建方法，防跨会话丢失。
- **注入验证清单升级**：注入后除 list/复合检查外，增加 dump_asv 式列表字面量核验
  （本轮新增步骤）。
