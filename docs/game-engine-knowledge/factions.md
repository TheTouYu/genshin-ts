## 一、官方语义（先读这一节，wire 只是它的落盘形态）

| 概念 | 官方口径 |
| --- | --- |
| 阵营是什么 | 为对抗性玩法划分的实体群体；同阵营玩家有相同游戏目标 |
| 在哪里定义 | **关卡设置 → 阵营页签**（不是元件、不是节点图） |
| 每个阵营可配 | 阵营名称 / **默认阵营对象** / 包含的玩家 / 包含的实体 |
| 实体怎么归属 | 实体「基础信息」里的**阵营**字段；实体也可被节点图动态改 |
| **值 0 = 默认** | 值为 0 时按**该实体类型的默认阵营对象**分配（例：石质球元件创建时未覆写阵营 → 归【初始物件阵营】） |
| 阵营关系 | 任意两阵营之间存在**敌对/友善**；**关系是单向的**（A 对 B 敌对 ≠ B 对 A） |
| 节点图 | `修改实体阵营` / `查询实体阵营` / `实体阵营变化事件` |
| 经典模式 | 玩家与角色=玩家阵营、造物=造物阵营不可改；物件可选 5 种；**不可动态改阵营**、关系不可改 |

## 二、赋值 wire（已验证）

阵营值写在记录的**基础信息区块**里：

```text
记录（root5 场景实体 / root8 元件页面实例）
  f6{ f1=6 }            # 块码 6 = 阵营
    f16{ f1=<阵营id> }  # 值 0 = 空 message（len=0）
```

| 形态 | 字节 | 长度 |
| --- | --- | --- |
| 默认（值 0） | `08 06 82 01 00` | 5 B |
| 阵营 1 / 2 / 3 | `08 06 82 01 02 08 01` / `…02` / `…03` | 7 B |

**三个不踩坑的判据**：

1. **`f6` 不是组件槽**——组件槽是 `f7`（每条必带 `f2=1`、空槽 7 B `08 06 10 01 82 01 00`，其码 6 = 特效播放）。
   两套命名空间都是「码 + 10」，光看字段号（都叫 f16）分不出来。
2. **场景实体有三层**：`f5` = 能力槽（从定义 `f6` 抄来的镜像，含技能/决策图）、`f6` = 基础信息区块、`f7` = 组件槽。
   别拿 `f5` 当基础信息。
3. **`root4` 元件定义本体没有阵营槽**——编辑器里在「元件定义页」改阵营，落盘在 **root8 页面实例**；
   已存在的场景实体**不会**因为定义改动而被覆写（实体自己存「默认」= 空 message，运行期由引擎按类型默认解析）。

**可逆性实证**：实体 `1082130442` 阵营 `1 → 2 → 1`，回来时**记录级 0 叶变化**（SHA 同为 `280920a8`）；
`定义页实例 3 →（实体）默认` 也不互相波及。

## 三、关卡阵营表 wire（部分已验证）

```text
root11（关卡设置）
  f2 (bytes) → 重复 f1 = 阵营条目
      f1 = 阵营名（UTF-8 明文，如「初始玩家阵营」）
      f2 = 阵营 id（varint，1/2/3…）
      f3 = 图标名（UTF-8，如 UI_MarkPlayer_Faction_0）
      f4 = 包含的玩家 id 列表（本图 8 B = 01..08；仅玩家阵营非空）
      f11 = 1 B。【强推断】默认阵营对象类型：0=玩家 / 1=物件 / 2=造物（与本图三个阵营名一一对齐）
      f13 = 变长。【强推断】该阵营敌对的目标阵营 id 列表（单向）：阵营1=[2,3]、阵营2=[1,3]、阵营3=[1,2]
```

`root11.f1` 是关卡级通用设置（f6..f26 varint + f14/f18 f32），**未归因**，本命令不读写。

> ⚠️ `f11` / `f13` 目前是**强推断**（本图取值与官方默认配置自洽，但没做过单变化差分）。
> 要闭合：在关卡设置里改一条阵营关系（敌对↔友善）或改「默认阵营对象」，保存后做一次差分。

## 四、命令（`gsts assets:factions`）

```bash
# 阵营表 + 全局分布（只读）
node dist/src/cli/gsts.js assets:factions list --gil <map.gil> [--format json]
node dist/src/cli/gsts.js assets:factions list --map-id 1073741827

# 单条记录读
gsts assets:factions get --target <记录id> [--layer entity|instance] --gil <map.gil>

# 单条记录写（0 = 默认；也可用阵营名）
gsts assets:factions set --target <记录id> --faction 3 --gil <map.gil> --output <候选.gil>
gsts assets:factions set --target <记录id> --faction 0 --gil <map.gil> --write   # 备份 + Temp 同步
```

读出的 `layer`：

| layer | root | 说明 |
| --- | --- | --- |
| `entity` | 5 | 场景实体（游戏实际读取的那份） |
| `instance` | 8 | 元件页面实例（编辑器「元件定义页」里改的阵营落在这里） |
| ~~`def`~~ | 4 | **不存在**——定义本体没有阵营槽，命令会 fail closed 并提示 |

**id 段重叠闸门**：地图里 root4 定义 / root8 页面实例 / root5 实体的 id 段会重叠——实测 `1082130434`
既是水史莱姆的 root4 定义，又是另一个造物的 root8 页面实例。命令在**未显式给 `--layer`** 且该 id 同时是
root4 定义时 **fail closed**（否则会把阵营写给另一个对象）；确认要操作页面实例请显式 `--layer instance`。

写回安全：`--write` 自动备份到同目录 `.gsts/backups/` 并同步 `Temp/`；写前自动做**回读自检**
（从候选字节重新读出阵营值，必须等于目标，否则报错退出——防「静默零改动」）。
真实地图写回后请让编辑器重载地图再保存，别用旧内存覆盖。
