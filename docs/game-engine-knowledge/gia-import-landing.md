> 来源：真实编辑器导入的前后对照 + CLI 产物与编辑器产物逐字节对拍 + 真机试玩日志

> 来源：一次**真实编辑器导入**（不是 CLI 模拟）的前后对照，地图 hl `1073741834`，包 `tetris-整合包.gia`（40,645 B）。

## 二、三条规律（`--apply` 的实现依据）

### 规律 1：控件的「在布局」还是「在模板」= **只由 `f504` 父指针决定**

同一控件两份记录（能玩的基线里就有，字段逐项对照）：

| 记录 | `f504`（父） | 其余字段 |
|---|---|---|
| `hud` id=1073741858（**布局**，运行时可见） | 1073741856 = 布局的「容器节点」 | 738 B，f501 + f502(15B) + 6×f505(14/47/471/37/81/37) |
| `hud` id=1073741861（控件模板） | 1073741859 = 模板的「容器节点」 | **738 B，字段完全同构** |

⇒ 「把控件放进布局」= 复制记录 + `f504` 改为布局容器节点 + 把新 id 追加进**布局容器节点的 `f503` 成员表**。
不需要额外的"实例化标记"字段。

### 规律 2：导入产生的控件进模板区，**不进布局**

所以导入后 `script.object`（布局容器节点）上 `GetChild('title')` **取不到**（模板里的控件不在运行场景）。
需要"落地可运行"就得按规律 1 再落一份到布局。

### 规律 3：导入脚本 = **新增 `f50` 条目**（`main_2`），不替换在用的 `main_1`

且 `external_lua_file/main.lua` **不被导入触碰**。要让新逻辑生效，必须二选一：

- 更新**被挂载的那条**脚本（`assets:scripts update --name main_1`），或
- 把挂载（`f74`）指向新 guid。

## 三、方法论：差分要按「记录集」比，不要按文件 sha 比

实测：编辑器打开/保存后文件 sha 变了（`111bf483 → edd33a85`），但 **35 条记录集完全相同**（新增/删除/变更 = 0）。
⇒ 判据：**先比记录集（id/kind/name/path），再比字节**；把 sha 变化直接当"地图被改"会误判。

## 四、已知问题

- `tools/gil-guard.py` 对**编辑器自己产出的**导入文件报 `children 悬空引用 15 个`（`3004833062 / 4283220735 …` 等 30 亿~80 亿量级 id，疑似素材/图片引用被当成控件 id）。
  编辑器能接受该文件 ⇒ **guard 这条判据对导入产物是误报**，不能当硬门禁用；需要区分「控件 id」与「素材引用」。
- 第二次"把控件从模板放到布局"的编辑器操作**没有落盘**（差分 0 变化，布局下仍只有 hud/hudNext）——这条规律改由**静态对照**得到（规律 1），不需要再采样本。

## 五、`GIA content` 与 `root9` 记录**字段号完全一致**（2026-10-29 字段级闭合）

GIA 的 `UiControlGroup.content` 与 `.gil` 的 root9 记录是**同一个 protobuf 结构**：

| 字段 | 号 | 含义 |
|---|---|---|
| `guid` | 501 | 记录自身 ID |
| `info` | 502 | 族描述符序列（`f501`=序号/`f502`=类码；`f11`=自身引用、`f12`=模板序号、`f14`=实例列表） |
| `children` | 503 | 成员表（packed ID 列表） |
| `parent` | 504 | 父指针（**模板记录没有**） |
| `data` | 505 | 内容块（`f501`=槽位号 / `f502`=类型码 / payload） |

子消息同样用 `501/502/503…`（见 `src/cli/client_ui/gia_proto.proto:16-20`）。
⇒ 编辑器做一次「GIA 导入」实际只做三件事：
① 重新分配 ID（guid、成员表 `rootChildRef`、nodeRef 自引用 `f504.f4`）；
② 改写模板序号（`f502[1]{f501=2,f502=6} → f12{f501}`，图内全局自增）；
③ 重名去重（`客户端控件容器 → 客户端控件容器_1`；**容器节点不去重**）。

**实测**：`prim/label/hit` 三段 content 与编辑器产物**逐字节同尺寸**（810/755/715 B），
归一化 ID 后**非字段差异 = 0**；容器组 513 B、容器节点 566 B 同样相等。
⇒ 落地 = 克隆 content 字节 + 打三处补丁，**不需要逐类解释控件内容块**（新增一种控件类型从逆向工程降级成查表）。

实现：`ui/src/container-subtree.ts` 的 `importGiaContainerTemplate`；命令 `gsts sim:import --apply`。
证据：`evidence/2026-10-29-server-control-group/manifest.md` R4/R7 节。

> ⚠️ **反向教训**：此前本节所在的技能文档曾断言「服务端控件模板不在 `.gil` 任何 root 里，纯 CLI 无法生成」——
> 那是**解析器读不出 packed varint** 造成的假象（`95 80 80 80 04` 的真身是 packed `[1073741845]`，
> 旧解析读成「字段 134217730 / fixed32 0」这种不存在的字段）。**解析不出 ≠ 不存在。**

## 六、编辑器保存会把 `root50` 内联源码**外置**（2026-10-29 真机往返实证）

编辑器保存时把 `f50` 登记项里的内联 `source` 迁到磁盘 `external_lua_file/<filePath>`，
`root50` 只留引用。**只写内联不写外置 = 首次保存后两边都没有源码**：

| | CLI 落地后 | 编辑器保存一次后（只写内联） |
|---|---|---|
| 文件 | 150,410 B | **29,947 B** |
| `root50` | 含 122 KB 内联源码 | **46 B 引用** |
| `external_lua_file/` | 不存在 | **空目录** |
| `assets:scripts list` | — | `external=MISSING` |

**判据**：任何经 CLI 写脚本的链路，写完必须核
`externalLuaDestOf(<地图.gil>, <entry.filePath>)` 那个文件存在、含 UTF-8 BOM、
且里面写死的模板 GUID 已是本图真实模板 ID。写对之后编辑器保存往返只会动
root6（脚本 folder 登记）/15/35/46，**root9 与 root50 逐字节不动**。

补充两条同轮读数：
- **`root9.f501` 森林根集 = 所有「无 `f504`」记录的 ID 集合**（r3 10=10 / r4 15=15 双向相等）。
- **`root6` 的脚本 folder 登记（folderId=69, typeValue=7900）由编辑器保存时自动补**，CLI 不必写。
