## 三、系统性根因（3 条）

1. **目标贪婪**：把「富版悬浮页」当成一个原子目标一次性实现，没有分解成最小可验证单元。
   正确做法：最小页签（1 个）→ 页签状态（逐个）→ 内容组 → 多页签，每一步都经过
   候选验证 + 编辑器/游戏核验，知识一条一条积累。
2. **知识不足不申请差分**：知识库明确「页签项内部待差分」，正确动作是请求用户做 10 秒
   编辑器最小实验（加 1 个页签→保存→提取 wire→落盘），而不是拿复杂样本硬编码。
   这违反 `editor-incremental-gia-investigator` 的核心纪律。
3. **复用复杂样本当模板**：2305B 页签含 6 页签项、4 状态、max-uint64、大量嵌套字段——
   每个字段都有语义，整体复用 = 把未知字段全部带入，失败概率趋近 100%。

## 四、流程与方法论教训

- **最小单元原则**：任何 UI 控件创建的实现，第一步必须是「编辑器能产生的最小形态」的 wire。
  知识不足 → 申请差分 → 落盘 → 再实现。
- **知识是增量积累的**：一条知识 = 一次最小实验。不能跳步。
- **写回前分层验证**：候选回读 → 引用完整性 → 最小单元注入 → 用户核验 → 再增量。
- **判断标准**：如果实现需要理解 N 个未知字段，而知识库只有 1 条相关记录，
  说明差分不足——先差分再写码，不是先写码再赌。
