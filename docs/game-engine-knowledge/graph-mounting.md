节点图不能脱离游戏对象独立运行。它必须挂载在实体或元件上，并由挂载对象的创建、销毁、[组件](components.md)事件和其他事件驱动。它在完整运行流程中的位置见[游戏运行生命周期](game-lifecycle.md)。

## 挂载在实体上

节点图可以挂载到关卡实体等对象上。

例如，节点图监听“实体创建时”事件：当关卡开始并创建该实体时，事件触发，节点图开始执行对应逻辑。

```text
关卡开始
→ 实体被创建
→ 触发“实体创建时”
→ 执行挂载在该实体上的节点图
```

## 挂载在元件上

一个元件可以挂载多个节点图，让不同节点图分别处理不同职责，例如创建、运行和销毁逻辑。

元件尚未被游戏创建时，它所挂载的节点图不会生效。

完整生命周期示例：

```text
关卡开始
→ 创建元件
→ 触发元件的“创建时”事件
→ 执行创建逻辑节点图
→ 后续逻辑通过 API 销毁元件
→ 触发“元件已销毁”事件
→ 执行销毁逻辑节点图
```

因此，判断一个节点图是否会执行时，不能只看图内拓扑，还必须确认：

- 它挂载在哪里；
- 挂载对象是否已经创建；
- 对应事件是否会在该对象生命周期中发生。

## 特殊实体

### 玩家实体

玩家实体一定会被创建，并且至少存在一个。多人游戏中，每个玩家都有自己的玩家实体。

### 角色实体

角色实体也一定会被创建，并且至少存在一个。它与普通的用户自定义实体不同，不需要由普通关卡逻辑保证首次创建。

角色还是玩家[屏幕控件与 UI](ui-controls.md)事件的接收对象。例如按钮被按下后，事件先进入角色挂载的节点图，再由角色逻辑按需转发给其他实体。

玩家实体和角色实体的数量、所有权及生命周期关系仍需后续细化。

## 多人联机与重复执行

挂载在玩家实体上的节点图会针对每个玩家分别执行。

例如：

```text
玩家创建时 → 设置变量
```

如果当前有 4 个玩家，这段逻辑会执行 4 次，而不是只执行一次。

因此，多人逻辑必须先判断目标语义：

- **每个玩家都应执行**：保留逐玩家执行。
- **全局只应执行一次**：增加去重、主控玩家判断、全局状态判断或其他一次性门控。

具体采用哪种去重方式取决于变量作用域、事件来源和联机权威模型，不能在缺少真实规则时固定为一种方案。

## ⚠️ 关卡实体禁止手动添加（2026-08-14 地图异常实证）

**关卡实体（1094713345，官方 defId=10003004）由游戏运行时默认创建，GIL 文件不预置。
手动通过 `assets:entities import` 往 .gil 添加关卡实体记录 → 游戏启动报"地图异常"**（2026-08-14 实测，1073741885/1073741887 两次作废）。

推论与规则：
- **挂载目标必须用普通场景实体**（官方空模型 10005018 等，static-assemblies 或 entities import 创建），不要用/加关卡实体。
- **tabBar 组件只能加在普通实体上**（魔方控制器 1077936138 已验证），不能加在关卡实体上。
- 全新地图 `maps:create` 无实体（entities=[]）；`--graphs` 只建图不建实体。
- 判断地图是否被破坏：游戏加载报"地图异常"；先检查是否手动加过关卡实体。
