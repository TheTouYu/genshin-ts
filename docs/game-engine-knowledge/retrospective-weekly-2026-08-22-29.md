## 2. 高频根因与防线缺口（为什么反复踩）

1. **R1 图变量重复求值是本周最大错误源（8 次），且防线两道失效**：
   技能铁律已存在却第 3 次被踩（2899 明知故犯）；ESLint 规则存在但 examples 从不跑 lint。
   → 结论：**规则靠自觉不可靠，需要门禁**。本周登记 O-2026-08-26-2（lint 门禁）与
   O-2026-08-27-02（编译器自动物化），两者闭合后 R1 才真正防住。
2. **R5 验证链盲区是「修复质量」的第一杀手**：本周 3 次「修复了但没生效/引入回归」——
   2906（注入失败没看到）、2956（黑块回归）、08-29（pipefail 再犯）。共同点：**验证只看一层就下结论**。
   对照 `AGENTS.md` 读图核验红线，本周每份复盘都证明了「分层证据」的必要性，
   但分层清单分散在各复盘文档里，需要统一的「修复交付前验证清单」（见 §4 缺口 C1）。
3. **R2/R3 引擎硬限清单本周新增 3 条**（列表初始化 ≤100、MB 10-case、记录 3000f 截断语义），
   全部是「静默失败」型（无报错只丢行为）——**静默失败型规则必须在写图前检查，不能靠运行时炸**。
4. **用户纠偏是最高价值证据**：本周用户 10+ 次方向性纠正全部直接命中根因（双触发统计、
   传导链追问×2、渲染≠逻辑、复合两个版本、2000 红线、列表 101、技能实例绑定……）。
   → 已固化为多个技能的「用户追问信号」条目；继续保持「最小复现 + 一个日志」协作链。
