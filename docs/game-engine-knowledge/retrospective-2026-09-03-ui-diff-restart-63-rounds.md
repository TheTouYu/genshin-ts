## 二、为什么反复出问题——系统性根因（3 条可复用规律）

1. **归因顺序律：先排除"未落盘"，再排除"操作合并/样本混杂"，最后才归因"版本/入口/空操作"**。
   三次实证（旧知识差异、同步空操作、模板化差异）都指向：差分结果与预期不符时，最高频真实原因是
   "操作没保存"或"旧样本包含多步操作"，不是引擎行为变了。任何"无变化/差异"结论前必须已排除保存问题
   （hash 比对），差异解释候选清单先列操作层。
2. **语义分层律：wire 观察只写 OBSERVED（结构/值/位置），语义标签等用户澄清后立即回写**。
   本波多次在 wire 与用户口述看似矛盾处（显隐两字节同为 01、页签添加无新记录、控件状态含页签自身）
   靠"先记事实、再问用户、立即修正"闭环，没有一条错误语义进入正式规则。
3. **同构复用律：新控件/新体系先对照已学体系找同构，能省大量轮次**。
   本波闭合的高价值同构：type55 素材组树（按钮/悬浮页按钮/消息队列样式通用）、f19 通用文本配置容器
   （文本框 t25 与图文输入框 type45 共用：字号 f502/对齐 f503/文本 f505/颜色 f510）、几何统一公式
   （wire=中心−(800,450)，布局/悬浮页详情/官方单条通吃）、模板化三合一+私有树克隆（按钮/输入框/消息队列一致）、
   对齐 varint=1 模式（字段号随容器：f19.f503 vs f68.f506）。

## 三、高效方法沉淀（本波验证有效，已/将回灌技能）

1. **difflib 序列对齐定位小片段**：±3B/±6B 等小差分（开关/标记字段增删）用
   `difflib.SequenceMatcher` 的 insert/delete/replace opcode + 上下文 hex 精确定位，
   比逐字节范围猜快得多（轮38 开关 f504=1、轮40 显隐标记、轮42 启用标记、轮57 插入位置、轮58 对齐均一次命中）。
2. **反向实验一次闭合开关语义**：开→关、增→删、容器1↔容器2 互换等反向操作，一次差分即可指认字段
   （轮38/40/49/58 四例）。
3. **等长内容变更必须逐字节**：文件总长不变时 root 大小对比无效（轮7/13/18/55 等），逐字节 ranges 是唯一证据。
4. **小开关字段模式**：启用标记/开关常见 `f50x varint=1`（b0 1f 01/c0 1f 01/d0 1f 01/f8 1f 01 等），
   开=有字段、关=省略（±3B），偶有反向语义（f510 存在=结尾、删除=开头）——以反向实验为准。
5. **用户提示的通用配置概念要跨控件追踪**（对齐/字号/颜色/素材），对照后形成通用规则而非单控件规则。
