# 结构体资产（Structure）wire 语义

> 状态：**已验证**（真实编辑器相邻快照差分）｜最近校验：2026-09-16
> 来源：专用实验图 `1073741918`「差分实验」七轮编辑器单变化差分 + 一次结构体列表长度变化复核
> 证据目录：`.scratch/editor-incremental-evidence/2026-09-16-struct16/`（`FINDINGS.md` C1–C34 + `raw/` 八个快照）
> 适用范围：关卡 `.gil` 的结构体资产（root6 注册 + root10 定义 + 节点族物化）
> **验证层级**：真实编辑器观察（差分）——**未做游戏内验证**

## 一、结构体是**地图级资产**

结构体不是节点图内部对象，而是与自定义元件同级的**地图级资产**：注册在 root6 的 folder 记录里，
定义落在 root10，并且会**物化节点族**到 root10。

## 二、注册（root6 folder）

```text
folderId = 29      typeValue = 4100
条目 f5 = { f1: 4100, f2: <structId> }    ← 追加到**同一条** folder 记录
```

`folderId=29` 这条记录是**类型级常量**：编辑器从不新建 folder 记录，只在既有记录的页签里追加条目
（与节点图的 folder 规则同构）。条目追加在 **`f3`「未分类页签」**（= 编辑器新建路径）。

## 三、id 空间

**结构体 id 与自定义元件共用 id 空间**（`>= 1077936129` / `0x40400001`），逐个顺延 +1。
实测：连续创建三个结构体 → `1077936129` / `1077936130` / `1077936131`。

## 四、定义记录 = **root10 的 `f6`**，一个结构体一条

```text
f6 = { f1{ f1: <structId>
           f3 × N : 成员
           f501: <结构体名>
           f502: 1
           f503: <序号> }        ← 见第九节（会被整表改写）
       f2{ …与 f1 逐字节相同的镜像… }
       f3: <类型码，见下>
       f4: <成员数>              ← proto3 默认 0 省略 ⇒ 0 成员时该字段不出现
       f5: 1 }
```

`f1` 与 `f2` 是**互为镜像的两份**（逐字节相同）——实现时两份都要写。

## 五、成员编码

```text
成员 = { f1{ f1: <类型码>  f2: {} }          ← 类型（f2 对普通标量/列表为空）
         f3{ f1{…}  f3{…}  f<类型码+10>{} }   ← 默认值
         f5:  <成员名>
         f501:<成员名>                         ← 与 f5 重复
         f502:<类型码>
         f503:<成员序号，从 1 起> }
```

## 六、成员引用其它结构体

```text
标量/普通列表：  f2 = {}                                   ← 空
struct/struct_list: f1{ f1: <25|26>  f2{ f1: 1  f2: <structId> } }
```

**struct 与 struct_list 的内嵌引用形态完全相同**，只有外层类型码 25/26 之差。

节点引脚侧的引用（票 17 要用）：

```text
f4{ f1: 10001  f3: 25  f4: 25  f104{ f2: <structId> } }
```

## 七、默认值的展开

- **struct（25）**：默认值 = **把被引用结构体的每个成员连同其默认值展开一份**。
  每个成员一条 `f1`（带 `f501`=成员名），末尾 `f501` = **被引用结构体的 id**，
  `f502{ f2: 28, f4: <实例 uid> }` 的 `f4` 逐个递增。
- **struct_list（26）**：`f36 = { f1 ×N   f501: <被引用结构体 id> }`，每个 `f1` 是一个完整默认实例
  （同上的展开）。**N = 元素个数，由创作者在编辑器里设定**（初始默认 4，可增删）。

> **N 是创作侧输入，不是引擎常量**（2026-09-16 用户澄清 + 差分复核）：
> 用户把 N 由 4 改成 5 后保存 → 文件 **Δ+192B**，且结构体定义记录 1,550B → 1,742B
> （**+192B 恰为一个默认实例的尺寸**，该结构体 2 成员）。
> → **wire 真的编码 N 个完整实例**，改 N 就是增删实例条目，而非写「长度=N」的标量。
> **实现含义**：CLI 生成 `struct_list` 成员默认值时必须支持指定元素个数，不能写死 4。

**uid 连号**：一个 struct 成员的实例 + N 个列表元素的实例**一次性连续分配**
（实测 995–999 连号）——uid 是创建该结构体时按实例总数连续分配，不是逐个成员重置。

## 八、建结构体会物化节点族

创建一个结构体会**向地图物化结构体节点族**：拼装结构体 / 拆分结构体 / 修改结构体 × 四类图
（20000 / 20001 / 20002 / 20007），实测 **+9 条 CompositeDef**。
**节点族记录长度随成员数变化**（0 成员 124–127 B；2 成员 225–226 B）。

## 九、编辑器**整表改写**规律（高频踩坑点）

**`f503 = 2 + （在该结构体之后创建的结构体数量）`**（6 个观测点拟合）。

机制：**编辑器每新增一个结构体，会把地图里所有既有结构体记录一并改写**
（既有记录 +1，新建的写 2）。→ **CLI 建结构体不能只追加，必须同步改写既有记录。**

同一次保存里的其它联动改写（本条已第四次验证）：

```text
那几条 CompositeDef 记录长度完全不变（610 / 400 / 617 B），只有内部 f8 数值变了
（f8=149 vs f8=138）—— 是**重写而非新增**。
```

> **差分配对假象**：`gil-quick-diff.py` 的紧凑文本会把「同一条记录被改写」渲染成
> `-X / +X` **等长配对**，看起来像「A 被 B 替换」。
> **判据：等长配对才是假象高发区；长度各异的新增是真实新增。**
> 凡 `-X/+Y` 长度接近，必须定点复核 occurrence。本实验四次验证（第二/四轮踩、第三/五轮对照）。

## 十二、局内存档结构体（独立资产类型，2026-09-16 新增证据）

> 官方概念：`docs/ui-tutorial/official-guide-concepts.md:10560-10585` ——
> 「一个局内存档模板中，包含了多个**局内存档结构体**……**与基础结构体的配置方式基本一致**」，
> 且明确「实体、实体列表、所有类型的字典以及结构体**不支持**在局内存档结构体中使用」。

**wire 上是独立资产类型**，与基础结构体（folderId 29 / typeValue 4100）不同：

```text
局内存档结构体： folderId = 33    typeValue = 4600
条目追加到同一条 folder 记录的 f3「未分类页签」： f5{ f1: 4600, f2: <structId> }
```

（`4600` 在全库文档与 PKC 曾零命中——本条目是「局内存档零覆盖」缺口的第一份 wire 证据。）

### 记录形态差异：`f1` 块多一个 `f2=2`

```text
局内存档结构体： f1{ f1:<id>  f2:2  f3{…成员…}  f501:<名> f502:1 f503:<n> }
基础结构体：     f1{ f1:<id>        f3{…成员…}  f501:<名> f502:1 f503:<n> }
```

**精确字节验证**（对四个 structId 各搜 `08 <varint id>` 模式，各 14 处）：
只有局内存档结构体的两处（`f1` 块 + `f2` 镜像块）后随 `10 02`，其余三个结构体 0 处。

> ⚠️ **`f2=2` 的语义未定**——实测唯一关联，但**是否即「存档标记」未经确认**，标 OBSERVED。

其余形态与基础结构体一致：`f1` 与 `f2` 互为镜像、成员编码复用第五节、
「默认值字段 = 类型码 + 10」同样成立、物化**同样的 9 条节点族**（拼装/拆分/修改 × 四类图）。

节点族里的结构体引用：`f107{ f1: 1003, f104{ f1: <structId> } }`（拼装侧）
与 `f107{ f1: 1004, f105{ f1: <structId> } }`（拆分侧）。

**未闭合**：局内存档**模板**的 wire（本轮只建了结构体、未建模板）；`f2=2` 的语义；
游戏内读写行为。

## 十三、局内存档模板（root31，2026-09-16 新增证据）

局内存档模板有**自己的语义根 root31**，与结构体（root10 `f6`）不同：

```text
root31 记录 = { f1: <模板 id>
                f2{ f2{ f1: 1
                        f2{ f1: 1  f2: <被引用的结构体 id> }
                        f3: 1
                        f4: "<存档变量名，如 1_chip_1>" }
                    f501: "<模板名>" } }
```

- 模板 id 走 **1073741824+ 段（与节点图同段）**，**不与结构体共用 1077936129+ 段**。
- `f2.f4` 是**存档变量名**——见下方互证。

### 注册：folderId 31 / typeValue 4400

三种资产各自独立注册（`root6` 的 folder 记录）：

| 资产 | folderId | typeValue | 定义根 |
|---|---|---|---|
| 基础结构体 | 29 | 4100 | `root10` 的 `f6` |
| 局内存档结构体 | 33 | 4600 | `root10` 的 `f6` |
| **局内存档模板** | **31** | **4400** | **`root31`** |

> ⚠️ **对「编辑器从不创建 folder 记录」的边界修正**（2026-09-16 实测）：
> 创建模板时 `root6` **新建了**一条记录（35 → 36，无重写配对行），
> 而此前的结构体条目都是**追加到既有记录**（重写、长度变化）。
> 原因：本实验图稀疏，folderId=31 的记录原本不存在。
> → **规则修正为：folder 记录按需创建；已存在则追加到其「未分类页签」。**
> CLI 实现必须能处理「记录不存在 → 创建」。

### 跨知识互证：`1_chip_1` 出身闭合

`f2.f4` 的值 `1_chip_1` **此前只出现在调试日志知识里**：

```text
docs/game-engine-knowledge/debug-log-format.md:328
  「类型码 25/26（结构体，局内存档 1_chip_1/2）：25=列表元素原始字节…」
```

当时只知它是**日志里看到的局内存档变量名**，不知来源；现在确认**它就是模板记录的 `f2.f4`**。
→ 两条独立知识线（调试日志格式 / GIL 资产 wire）在此互证。

（`f4` 是编辑器自动生成还是用户命名：本轮用户只做了「创建模板 + 选结构体」，
未提命名 → **倾向自动生成，但未确认**，标 OBSERVED。）
