## 二、3062 误诊链（现象→差分→根因→修复→验证）

现象：零 ack、零 tear、lane:pub 只 1 次、repub×2（任务悬置 8s+ 无消费）。
排查：记录普查 → 客户端族 f8=4194308 存在，但 20008 执行的是"碰撞计算 1082130441"（277 条），
_GSTS_ztSkill 0 条 → 决策图/状态图是我们的（438/437）→ 矛盾指向槽 81 技能引用 →
dump_entity.py 显示"=我们的"（读的是 after-v3 快照，误诊）→ 重写全量实体 walker 读活图 →
序号 1 实为 1191182338（大佬）→ 字节手术 → 3064 全链通。
方法论：**状态类断言必须读活图并带 SHA**；工具硬编码路径是诊断地雷。

## 三、系统性根因

1. **证据新鲜度缺失**：分析工具默认绑旧快照/旧记忆，结论与活地图脱节。
   对策：活图路径必须显式传参；关键结论附地图 SHA。
2. **同实体多图 = 隐形事件耦合面**：共享挂载换"同拍武装"的便利，代价是定时器事件互相串台。
   对策纪律：whenTimerIsTriggered 一律名单制分支，else 永远空。
3. **节点预算要先算"每操作真实成本"**：setCustomVariable 复合 ≈3-4 节点/次；
   百变量寄存器 = 100×成本×调用点数。优先数学等价压缩（闭式解、单写者降级重提交）而非拆图。

## 四、机制定论（两轮日志铁证）

| 指标 | Round 1（无仲裁，3064） | Round 2（dispatcher，3067） |
|---|---|---|
| 交付 | 串行 5/5；并发 4/6（同拍覆盖丢 2） | **11/11** |
| 撕裂 | 2 次（仅并发相位；门全拒绝，零错算） | **0** |
| 吞吐/延迟 | ~4-5 任务/s；pub→ack 0-1s | **~5 任务/s**（回声补位吃掉轮询延迟）；同秒完成 |
| 恢复路径 | repub/stale 未触发 | repub 实战触发 1 次：对在途回声冗余重提交，幂等吸收零重复计算 |

机制骨架（可复制）：生产者只写邮箱（挂 dispatcher 图实体）→ 唯一 dispatcher（1s 轮询 +
回声补位 + 4s 看门狗重提交）→ 寄存器（N 载荷 + sum + epoch + ack，玩家实体）→ 客户端 15Hz
seqlock 门（epoch≠ack → 读全量 → 求和校验 → 二读 epoch → 计算 → 回声带 epoch）。
求和校验在"载荷随版本严格单调"前提下是**确定性**撕裂检测（非概率）。
