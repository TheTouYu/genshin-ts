## 二、最近一次错误的完整调查链（#5 不动点陷阱）

1. **现象（用户原话）**："落下反弹看起来正常。然后没有进入下一个阶段了，也就是在原地不动了。"
2. **活动分布定死活**：`gia_log_activity.py --graph 1082130433` → 计算拍（>3KB 重执行路径）
   sec6..50 每秒 10~30 个从未停 → **物理链活着**，排除握手/信号/寻址层，聚焦状态机。
3. **text 四层签名**：armed→(5s)→seed→ack(1)✓、fb:tear 2009=E5 观测值（瞬移前差值，非异常）、
   wdgate 仅 1 次（环路基本健康）、dup 为多丘丘人常态。
4. **apply 帧值=状态机现况快照**：`frames --rec 3940` grep `fb_mirror_apply` →
   IN1/IN2 直接给出 `py=0.25 / vy=0.8086 / state=1(Bouncing) @tick161`——会话 40 秒仍卡在贴地微弹。
5. **数学定位**：离散反弹映射 `v→e·(g·DT−v)` 的稳定不动点 `e·g·DT/(1+e)=0.7×9.81×0.2/1.7=0.8079`
   与日志 0.8086 分毫不差——不是猜测，是解析解对上实测值。
6. **根因**：给 v4 五态机新增 Bouncing 瞬态标记时，我把它排在"落地分类"之上；不动点处
   dead=true（0.808<1.0 阈值）但 impact 恒真，旧逃逸路径（dead→Rolling）被新态优先级截断。
7. **修复**：优先级改 停(4)>贴地∧dead（落地转滑/滚，不动点逃逸口）>活弹(1)>空中(0)。
   验证：编译 0 err+重注入 ok 4/0（行为验证待第二次复测）。

方法沉淀：**"想看任何变量现在是什么，找它的写入节点帧（apply 复合 IN 参数），别从源头追"**——
已回灌 debug 技能"行为排查 playbook"。

## 三、为什么出问题——系统性根因（3 条）

1. **新态优先级插入点=旧逃逸路径破坏点**。往已验证状态机加新态时只想可见性收益，没重验
   旧阈值逃逸。带加性源（重力）的离散反射映射必有不动点——新瞬态态若优先于阈值逃逸分类，
   不动点即死锁。已回灌 debug 技能错误谱系。
2. **验收项缺口被"备案化"而不修复**。旋转缺失被我写进 03 执行备注当"遗留观察项（05 收证）"，
   但它同时是 05 票明文验收项"旋转可见"。**规则：验收标准里明确要求的能力，结构层就位时必须
   补齐，禁止降级为观察项**——用户架构评审一针见血（"不然肯定对不上"）。
3. **观测代码默认"每事件"而不自问频率**。E5 对账默认每计算拍发——观测/调试代码也是代码，
   同样要过"负载两笔账"。用户定则已固化：print 只留关键状态入口，高频路径零 print；
   完整数据走按图详情日志（3096 会话 19MB 客户端帧证明其完备性）。
