# 屏幕控件与 UI

> 知识树：用户说明部分已录入 `knowledge/game-engine-knowledge/camera-ui-rules.md`（标注未验证，2026-08-08，bnd_7320a9bd）

> 状态：框架草案
> 来源：用户对屏幕控件、输入和按钮事件的说明
> 最近校验：2026-08-01
> 适用范围：屏幕空间 UI、控件身份、显示状态和输入事件

屏幕控件属于 UI 系统，不存在于关卡的 3D 空间中。无论玩家如何移动或转动视角，控件都显示在玩家看到的长方形屏幕坐标空间里。

## UI 框架总览（2026-08-22 用户补充 + 差分闭合）

> 状态：已验证（用户口述框架 + 真实 .gil 相邻快照差分互证）
> 来源：用户 2026-08-22 口述 UI 框架 + 地图 1073741907 四轮差分。

### 概念层级（用户口述）

```
素材（素材库定义）
  ├── 游戏内置基础图形（三角形/圆形/矩形等），可单独或几张合成一个素材
  └── 用户自定义素材（AI 生成 → 素材库注入）
        ↓ 被引用
图片控件（引用具体素材）
        ↓ 创建为
控件模板（可复用）
        ↓ 被引用
界面布局（玩家屏幕看到的一层视觉）
  ├── 默认布局：官方预置（小地图/技能区/队伍/生命条/退出/网络/聊天等）
  └── 用户布局：引用官方模板或自制模板，选摆放位置
        ↓ 被控制
节点图（控制用哪个布局、布局里哪个控件开/关）
```

官方支持的控件：文本框、图片、特殊数字、交互按钮、自定义按钮、弹窗、计时器等。

### wire 结构（root9 三段，差分闭合）

root9 同时承载三段，都是 field 502 记录，按记录结构区分：

| 段 | 记录 | 关键字段 |
| --- | --- | --- |
| 素材段（素材库） | 容器/组/图元 | 容器 ID = 素材索引 ID（`0x40000000+`） |
| 控件段 | 模板 + 实例 | 见下 |
| 布局段 | 默认布局 + 控件组容器 | `f503` = packed 控件实例 ID 列表 |

### 控件模板 ↔ 实例 双向引用

| 方向 | 路径 | 说明 |
| --- | --- | --- |
| 实例 → 模板 | `f502[type3].f13.f501` | 实例引用模板 ID |
| 模板 → 实例 | `f502[type4].f14.f501` | packed 实例 ID 列表（back-reference） |

- 模板：`f502[type4]` 自标识，无 `f504`，含图片源 `f505[f502=38]`。
- 实例：`f502[type3]` 引用模板，`f504` = 布局/容器 ID。

### 官方预制控件 vs 自定义模板（2026-08-22 第五轮差分闭合）

| 路径 | 记录数 | 结构 |
| --- | --- | --- |
| 自定义模板 | 2 条（模板 + 实例） | 模板 `f502[type4]` 无 `f504`；实例 `f502[type3]` `f504`=布局 |
| 官方预制控件 | 1 条 | `f502[type5]` 单条，`f504`=布局，直接含图片源 `f505[f502=38]` |

**图片源引用素材路径两者完全一致**：`f505[f502=38].f503.f31.f6.f4` = 素材索引 ID。
官方预制控件（文本框/按钮/图片等）直接单条记录进布局，无需模板/实例分离；
自定义模板才需要「模板 + 实例」两条记录。

### 布局引用规律

「把控件模板放进布局」= 三步联动：

1. 新建实例记录（`f504`=布局 ID，`f502[type3]` 引用模板）；
2. 实例 ID 追加进布局的 `f503` packed 列表；
3. 模板的 `f502[type4].f14.f501` 追加实例 ID（back-reference）。

- 默认布局 `1073741825`：`f503` = 14 官方预置（1073741826~1839）+ 用户新增实例。
- 控件组容器 `1073741840`：`f503` = 尚未放入布局的实例列表。

## 与 3D 世界的区别

```text
3D 世界
├── 实体有位置、方向和旋转
├── 玩家移动会改变观察视角
└── 世界内显示可能被遮挡或需要朝向玩家

屏幕控件
├── 位于固定的屏幕空间
├── 不使用 3D 世界位置
├── 不随摄像机视角改变空间关系
└── 直接接收或展示玩家界面输入与内容
```

屏幕控件和实体上的铭牌虽然都能显示内容，但不是同一套系统。铭牌仍属于 3D 世界，见[组件](components.md)。

## 配置与身份

控件需要预先添加和配置。每个控件拥有自己的控件 ID，游戏运行时通过该 ID 操作指定控件。

```text
编辑器中添加控件
→ 配置控件内容和行为
→ 获得控件 ID
→ 游戏运行时按 ID 操作
```

## 运行时状态

游戏中可以对控件执行显示状态操作，例如：

- 启用；
- 显示；
- 隐藏；
- 关闭；
- 其他待逐步确认的状态变化。

“隐藏”“关闭”和“禁用”是否保留内部状态、是否继续接收输入，需要分别验证，不能暂时视为同一种操作。

## 输入与响应

控件用于接收或表达玩家界面的输入，包括：

- 按钮点击；
- 键盘输入；
- 鼠标输入；
- 在指定屏幕区域显示文字、图片或其他内容。

这些能力都需要先在编辑器中配置好，再由运行时接口控制。

## 按钮组件

控件可以包含预置的按钮组件。玩家按下按钮后，事件首先发送给该玩家对应的角色，而不是任意关卡实体。

```text
玩家按下 UI 按钮
→ 角色收到控件按钮事件
→ 角色挂载的节点图处理事件
```

这是 UI 与普通实体组件事件的重要区别：屏幕控件跟随玩家体验，而角色是稳定承接该玩家 UI 事件的对象。

## 转发到其他实体

如果按钮最终需要控制其他实体，可以在角色节点图中增加转发逻辑：

```text
按钮被按下
→ 角色收到事件
→ 角色节点图确定目标实体
→ 转发信号或调用目标逻辑
→ 目标实体执行操作
```

具体采用信号、实体事件还是其他 API，需要按目标功能和真实节点规则选择。

## 多人边界

每个玩家拥有自己的视角、输入和角色。因此 UI 的显示状态、按钮事件和转发逻辑是否按玩家隔离，是后续必须验证的核心规则。

不能因为一个玩家看见或点击了控件，就默认所有玩家都发生相同变化。

## 图片控件引用素材的 wire 编码（2026-08-22 差分闭合）

> 状态：已验证（真实 .gil 相邻快照差分）
> 来源：地图 1073741907（ui-inject-diff）before `f27984bc`（86734B）→ after `14902676`（87356B），
> 唯一变化 = 添加一个「图片控件」，图片源=静态引用，引用素材 guide-tap（容器 ID 1073741927）。
> 快照：`~/genshin-ts-evidence/ui-control-image-ref/exp1/raw/`。
> 证据层级：真实编辑器观察；**尚未游戏验证**（图片是否真的显示待核验）。

### 记录结构：图片控件 = 模板 + 实例 两条记录

添加一个图片控件会在 root9 新增**两条** 502 记录（与素材库「容器+分类副本」同构，但语义是「模板+实例」）：

| 记录 | 特征 | 说明 |
| --- | --- | --- |
| 模板（definition） | 无 `f504`；`f502[type4]` 自标识 | 图片控件的本体，含图片源配置 |
| 实例（instance） | `f504` = 布局 ID；`f502[type3]` = `{f13={f501=模板ID}}` | 引用模板，注册进布局 |

实例通过 `f502[type3].f13.f501` 指向模板 ID；模板通过 `f502[type4]` 自标识。

### 图片源引用素材的 wire 路径（核心）

两条记录都含图片源组件 `f505[f502=38]`，素材索引 ID 存在：

```
f505[f502=38]            ← 图片源组件（type 38）
  f503
    f31 (msg)            ← 图片源 = 静态引用
      f3 (msg) = {f501: -1}   ← 无颜色覆盖（-1 = 默认）
      f4 (varint) = -1        ← 无颜色覆盖
      f6 (msg) = {f2:1, f3:8, f4:<素材索引ID>}  ← 素材引用
      f10 (bytes 0B)
    f501 = 22
    f502 = 38
    f503 = 1
    f504 (msg) = {f2:1, f3:8, f4:<自身ID>}  ← 自引用
```

**关键结论**：素材索引 ID（= 素材库容器 ID，`0x40000000+` 段）存在
`f505[f502=38].f503.f31.f6.f4`。`f6` 是素材引用结构 `{f2:1, f3:8, f4:素材ID}`。

> 两个独立样本确认（2026-08-22）：`f6.f2=1`、`f6.f3=8` 是**固定常量**（非图片源/拉伸类型编码）；
> `f3={f501:-1}`、`f4=-1` 是「无颜色覆盖」标记（两个样本一致）。

### 与素材库注入的衔接

- 素材库注入（`assets:library-inject`）写入的容器 ID = 素材索引 ID；
- 图片控件通过 `f505[f502=38].f503.f31.f6.f4` 引用该 ID；
- 因此「AI 生成素材 → 写入素材库 → 图片控件引用」的完整链路已闭合。

### 位置/尺寸 wire 路径（2026-08-22 第二轮差分闭合）

控件位置/尺寸存在载体组件 `f505[f502=12]` 的 transform 槽里（4 个槽，每个槽同构）：

```
f505[f502=12]              ← 载体（transform）
  f503.f13.f12.f501[n]     ← 4 个 transform 槽
    f502
      f501 = {f1:1, f2:1, f3:1}   ← 缩放 scale
      f502 = {f501:0.5, f502:0.5} ← 锚点 anchor
      f503 = {f501:0.5, f502:0.5} ← 中心 center
      f504 = {f501:X, f502:Y}     ← 位置（屏幕中心相对偏移，f32 fixed32）
      f505 = {f501:W, f502:H}     ← 尺寸
      f506 = {f501:0.5, f502:0.5} ← 锚点相关
      f508 = 空                    ← 旋转
```

**坐标换算**：wire 偏移 = 编辑器绝对坐标 − (800, 450)（1600×900 设计分辨率）。
实测 wire (−660, −250) ↔ 编辑器 (140, 200)。

> ⚠️ **编辑器 UI 坐标原点在左下角**（官方指南：「位置以画布左下角为原点，控件中心点相对位置」），
> x 向右、y 向上。因此 `(300, 200)` = 左下区域（不是左上）、`(1300, 700)` = 右上区域（不是右下）、
> `(800, 450)` = 正中心。**不要按左上角原点理解 editor 坐标**（2026-08-23 游戏核验实测：设 (300,200)
> 实际显示在左下、(1300,700) 显示在右上，与左下角原点语义一致）。

> 与 `assets:ui` 的 `setUiTransform` 实现一致（`gil_ui.ts` 已按此路径写 `f504` 位置 / `f505` 尺寸），
> 无需改生产代码。

## 节点图 UI 控制（2026-08-23 游戏核验闭合）

> 状态：已验证（真实注入 + 用户游戏核验）
> 来源：地图 1073741907 注入 `modifyUiControlStatusWithinTheInterfaceLayout` 节点，
> 把控件 1073741955（文本框）设为 Hidden，用户游戏核验「文本框隐藏」通过。

### 核心节点与参数

| 节点 | 作用 | 参数 |
| --- | --- | --- |
| `modifyUiControlStatusWithinTheInterfaceLayout` | 设置布局内控件(组)状态 | 目标玩家 / 界面控件索引 / 显示状态 |
| `switchCurrentInterfaceLayout` | 切换当前布局 | 目标玩家 / 布局索引 |
| `activateUiControlGroupInControlGroupLibrary` | 激活控件组库内控件组 | 目标玩家 / 界面控件组索引 |
| `getPlayerCurrentInterfaceLayout` | 查询当前布局 | 玩家实体 → 布局索引 |

### 关键规则（游戏核验锁定）

- **界面控件索引 = 控件完整 ID**（`0x40000000+` 段，如 1073741955），不是布局序号。
  DSL 里 `modifyUiControlStatus(player, 控件ID, status)` 直接传控件 ID（bigint）。
- **显示状态枚举**：`Off`（关闭：不可见+逻辑不运行）/ `On`（开启：可见+逻辑运行）/
  `Hidden`（隐藏：不可见+逻辑运行）。
- **玩家实体 = `player(1n)` 全局函数**（`dsl` 里直接调用，**不是 `f.player`**——`f.player`
  会报 `TypeError: f.player is not a function`；玩家序号从 1 开始）。
- **挂载**：图挂到普通实体（非关卡实体），`whenEntityIsCreated` 事件在实体创建时触发。

### DSL 最小示例

```ts
import { g } from 'genshin-ts/runtime/core'
import * as E from 'genshin-ts/definitions/enum'

const graph = g.server({ id: 1073741825 })
  .on('whenEntityIsCreated', (_evt, f) => {
    f.modifyUiControlStatusWithinTheInterfaceLayout(
      player(1n),          // 玩家 1 号实体
      1073741955n,         // 控件 ID（= 素材索引/控件 ID）
      E.UIControlGroupStatus.Hidden
    )
  })
```

编译产物 IR 确认：`modify_ui_control_status_within_the_interface_layout` 节点，
args = `[entity(玩家), int(控件ID), enum(hidden)]`。
