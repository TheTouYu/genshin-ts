# 屏幕控件与 UI

> 状态：框架草案
> 来源：用户对屏幕控件、输入和按钮事件的说明
> 最近校验：2026-08-01
> 适用范围：屏幕空间 UI、控件身份、显示状态和输入事件

屏幕控件属于 UI 系统，不存在于关卡的 3D 空间中。无论玩家如何移动或转动视角，控件都显示在玩家看到的长方形屏幕坐标空间里。

## 与 3D 世界的区别

```text
3D 世界
├── 实体有位置、方向和旋转
├── 玩家移动会改变观察视角
└── 世界内显示可能被遮挡或需要朝向玩家

屏幕控件
├── 位于固定的屏幕空间
├── 不使用 3D 世界位置
├── 不随摄像机视角改变空间关系
└── 直接接收或展示玩家界面输入与内容
```

屏幕控件和实体上的铭牌虽然都能显示内容，但不是同一套系统。铭牌仍属于 3D 世界，见[组件](components.md)。

## 配置与身份

控件需要预先添加和配置。每个控件拥有自己的控件 ID，游戏运行时通过该 ID 操作指定控件。

```text
编辑器中添加控件
→ 配置控件内容和行为
→ 获得控件 ID
→ 游戏运行时按 ID 操作
```

## 运行时状态

游戏中可以对控件执行显示状态操作，例如：

- 启用；
- 显示；
- 隐藏；
- 关闭；
- 其他待逐步确认的状态变化。

“隐藏”“关闭”和“禁用”是否保留内部状态、是否继续接收输入，需要分别验证，不能暂时视为同一种操作。

## 输入与响应

控件用于接收或表达玩家界面的输入，包括：

- 按钮点击；
- 键盘输入；
- 鼠标输入；
- 在指定屏幕区域显示文字、图片或其他内容。

这些能力都需要先在编辑器中配置好，再由运行时接口控制。

## 按钮组件

控件可以包含预置的按钮组件。玩家按下按钮后，事件首先发送给该玩家对应的角色，而不是任意关卡实体。

```text
玩家按下 UI 按钮
→ 角色收到控件按钮事件
→ 角色挂载的节点图处理事件
```

这是 UI 与普通实体组件事件的重要区别：屏幕控件跟随玩家体验，而角色是稳定承接该玩家 UI 事件的对象。

## 转发到其他实体

如果按钮最终需要控制其他实体，可以在角色节点图中增加转发逻辑：

```text
按钮被按下
→ 角色收到事件
→ 角色节点图确定目标实体
→ 转发信号或调用目标逻辑
→ 目标实体执行操作
```

具体采用信号、实体事件还是其他 API，需要按目标功能和真实节点规则选择。

## 多人边界

每个玩家拥有自己的视角、输入和角色。因此 UI 的显示状态、按钮事件和转发逻辑是否按玩家隔离，是后续必须验证的核心规则。

不能因为一个玩家看见或点击了控件，就默认所有玩家都发生相同变化。
