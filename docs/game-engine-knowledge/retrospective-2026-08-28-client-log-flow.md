## 一、方法论（用户启发 → CLI 对应实现）

用户对"游戏引擎日志查看"的启发原文要点：

1. **执行沿一条/多条事件线进行**——看日志就是沿着事件线走；
2. **引擎自动高亮触发的控制流**（未执行的控制流灰白显示）；
3. **顺具体节点倒查输入输出数据**，一直追到第一个数据/最后一个节点。

CLI 对应实现（`gia_log_flow.py --client`）：

| 启发要点 | CLI 实现 |
|---|---|
| 事件线执行 | 按帧序列重建事件线；入口帧（节点图开始）标 `★ 事件线起点`；一条记录 = 一次技能释放的完整事件线 |
| 高亮控制流 | 控制流节点（多分支/双分支/循环/遍历/信号/入口）与写节点（设置局部变量等）全显并标注关键值 |
| 未执行灰白 | 折叠行 `… 数据链 N 帧（get/convert/math 折叠）` = 纯数据节点（get/convert/math），不逐行展开 |
| 倒查数据 | `--trace-node <idx>`：沿真实 dataflow 边回溯每个输入的来源链到源头，每步标注日志实际值；获取局部变量自动跳到写回它的设置局部变量（变量存储跳转）继续倒查 |
| 重复块 | 循环体自动检测折叠：`└─ 【循环体 ×N 重复：每轮 P 帧】` + 展开一次代表循环体 |

## 三、本次验证要点

1. **rec2（整体旋转，指令=x）事件线结构**：入口 `节点图开始` → `设置局部变量[指令]=x` → 7 个多分支
   按指令值（S/S'/S2/d/d'/d2/z'）分发 → 设 旋转层数=3.0 / 旋转角度=90.0 / 旋转轴=(1.0,0.0,0.0) /
   角速度=180.0 / 向量 (90,0,0) → 获取实体列表 → **26 块遍历循环** → 尾部 `n115 向服务器节点图发送信号`
   （6 参数：旋转时长 0.5 / 旋转角度 (90,0,0) / 是否还原 / 魔方整体向前向量 / 魔方整体向上向量 / 指令异常）。
2. **rec163（面旋转，指令=D）事件线结构**：`设置局部变量[指令]=D` → 旋转层数=1.0 / 旋转轴=(0.0,-1.0,0.0) /
   旋转角度=(0.0,-90.0,0.0) → 26 块遍历（每轮 44 帧，9 轮因命中面块多 3 帧=47 帧）→ n115 信号
   IN1:Vector=(0.0,-90.0,0.0)。**O-06 遍历语义日志闭合**：`遍历实体列表` 27 帧 = 26 块迭代 + 1 次完成
   （完成分支 → 发信号一次；每次分支 → 26 块各加一次单位状态）。
3. **26 块循环体折叠**：循环体因分支不同并不逐轮完全相同（rec2 有 3 轮走"相等数值个数+1"路径多 27 帧；
   rec163 有 9 轮多 3 帧），且循环后还有尾部。实现上放弃"末尾锚定精确周期"，改为**迭代边界检测**：
   同一控制流/写节点 idx 反复出现（≥5 次）+ 相邻出现间隔近似均匀（max≤2×min）+ 相邻迭代块公共子序列
   占比 ≥70% → 折叠为 ×N + 一次代表循环体。头部/尾部（循环前配置段与循环后信号段）完整保留。
4. **n115 信号 6 参数倒查**：旋转时长←获取自定义变量（实体上下文链 获取当前角色→归属玩家实体）；
   旋转角度←获取局部变量→设置局部变量→创建三维向量→数据类型转换(801/807 取整链)→乘法；
   是否还原←是否相等（==，IN1←已还原魔方块个数【本事件线内无写回，跨图/外部来源】，IN2=26 常量）；
   向前/向上向量←获取局部变量→设置局部变量→创建三维向量→拆分三维向量→三维向量旋转；
   指令异常=无来源（默认空值）。
5. **客户端节点缺名补录**：n115 generic_id 1610612774 在 client_node_metadata.ts 缺 displayName
   （显示 gid1610612774），脚本内 `META_OVERRIDES` 补 `向服务器节点图发送信号`；信号类节点日志无 OUT
   参数时回退展示 IN 参数。
