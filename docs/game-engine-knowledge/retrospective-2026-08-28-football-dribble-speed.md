## 二、最近一次错误的完整调查链

**现象**：带球循环跑不通——①玩家靠近甚至重叠球，球经常不动；②球动了也跟不上玩家，滚很短。

**第一轮误判**：我看球位置演化（21.3→32.4，11 米）误判"球在滚、滚太快"。用户纠正："球根本不怎么动，滚得很慢，玩家重叠球都不动"。

**用户点破关键**："渲染的逻辑才是我游戏里真实能看到的。你刚看的数据说不定只是计算出来的逻辑，有没有通过 API 正确转化成渲染？"

**铁证链**：
1. 运动器（Add Uniform）39 次 + 旋转运动器 31 次——球逻辑上在动、在转
2. 实体实际位置演化（21.1→28.3，7 米）——渲染也在动
3. **玩家速度 `OUT0:Float=空`、`OUT1:Vector=(0,0,0)`**——玩家速度恒 0！

**根因**：`queryCharacterSCurrentMovementSpd` 官方定义"仅当角色拥有【监听移动速率】单位状态效果时才能查询"。角色没挂 buff → 速度恒 0。

**连锁**：球速目标 = max(0+1.0, 3.0) = 3.0 m/s（VKICK_MIN 兜底）→ 球滚 1.5 米停（ROLL_DECEL=3.0）→ 球速 3.0 < 玩家实际 5，跟不上。

**修复**：位置差分测速——`roleVel = (当前玩家位置 − 上一 tick 位置) × 5`（÷DT），不依赖 buff。

## 三、系统性根因

1. **依赖编辑器前置条件的脆弱设计**：queryCharacter 依赖"监听移动速率"buff，buff 是编辑器手动挂载、易丢失、不可代码校验。**凡是"官方节点需要挂 buff/状态效果"的，都要评估降级方案**（位置差分、事件载荷等）。

2. **逻辑值 ≠ 渲染值，但排查时只盯逻辑**：球位置演化（ballPos 图变量）显示"球在滚"，但那是逻辑值；用户看到的是渲染（实体位置 + 运动器驱动）。**排查"球不动"必须同时核对：逻辑 ballPos、实体实际位置、运动器参数（Add Uniform IN3）三层**，缺一层就误判。

3. **参数调优前没先验证输入正确性**：我调 VKICK_ADD/KICK_DIST/ROLL_DECEL 三轮，但玩家速度一直是 0（输入就错），调参全在错误基线上。**调参前先验证所有输入（玩家速度、球速、距离）的真实值**。

## 四、流程与方法论教训

- **用户是雷达**：两次纠偏（"球不滚"、"渲染才是真实看到的"）直接指向根因。我两次误判（"球滚太快"、"球在动"）都是只看了逻辑值没看渲染/输入。
- **三层核对法**（本轮沉淀）：排查"球不动/跟不上"必须同时看 ①逻辑 ballPos ②实体实际位置（getEntityLocationAndRotation）③运动器参数（Add Uniform IN3 速度 + 旋转运动器）。三层一致才说明渲染正确。
- **输入验证优先于调参**：调参前先确认玩家速度/球速/距离的真实值，否则在错误基线上白调。
