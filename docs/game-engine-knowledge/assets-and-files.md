> 来源：用户对关卡资产的说明 + 真实 GIL/GIA + 编辑器导入验证
> 最近校验：2026-08-01
> 适用范围：游戏编辑器中的关卡保存、GIA 导入包装、资产导出和分享

游戏中的逻辑、模型和界面都属于可保存资产。这些资产可以一起组成完整关卡，也可以按需要单独导出并复用。

## 关卡包含的资产

完整关卡可以包含：

- 屏幕控件和界面；
- 节点图；
- 复合节点；
- 模型元件；
- 关卡初始摆放的实体；
- 元件定义的组件；
- 变量及其他关联数据；
- 这些资产之间的引用关系。

```text
完整关卡
├── 屏幕控件
├── 节点图
│   └── 复合节点
├── 模型元件
│   ├── 组件配置
│   └── 变量定义
├── 初始实体
└── 资产之间的引用
```

完整关卡可以打包并发送给其他玩家，对方加载后得到关卡及其所需资产。

## GIL：完整关卡包

`GIL` 保存完整关卡。

它用于表达整个关卡中的资产、初始状态和相互引用。验证完整关卡行为时，可以把修改写回 GIL，再重新打开关卡检查。

特点：

- 覆盖范围完整；
- 能验证资产之间的整体关系；
- 写回和重新加载成本较高；
- 通常需要退出当前关卡后重新打开。

## GIA：部分资产包

`GIA` 是可以导入游戏的部分资产包。一个 GIA 可以只包含本次需要复用或验证的资产，而不必包含整个关卡。

常见用途：

### 节点图逻辑

把一组可复用节点图或复合节点单独打包，例如：

- 旋转计算；
- 物理运动；
- 通用控制流；
- 数据计算模块。

### 模型

把制作完成的模型元件打包，例如：

- 多面足球；
- 魔方；
- 其他组合模型。

### 界面

把一组屏幕控件和配套节点图打包，供其他关卡导入和调用。

### 数据定义

变量等与资产相关的数据也可以包含在导出包中。具体哪些定义会被自动带入、哪些需要显式选择，仍需逐项验证。

### 正式 GIA 导入包装

“protobuf 能解码”或“injector 能解析”不等于编辑器能检测并导入。2026-08-01 的监听信号实验验证：仅供 injector 单元测试使用的最小 GIA 包装会被编辑器忽略；正式可导入 GIA 至少需要与当前正式包装规则一致的文件头和 Root 元数据，包括：

```text
header fileType = 3
与图类型匹配的 Root graph identity
有效 filePath
当前 gameVersion
Root graph ID 与 inner NodeGraph ID 一致
```

这些字段通过自动解码/回读只能证明结构完整；“编辑器可检测并导入”仍需用户编辑器验证。文件从导出目录消失、被扫描或被移动，也不能单独证明导入成功。具体信号样本见[信号](signals.md)。

## 两种文件的核心区别

| 文件 | 含义 | 主要用途 | 验证成本 |
|---|---|---|---|
| GIL | 完整关卡包 | 保存、分享和写回整个关卡 | 较高，需要重新加载关卡 |
| GIA | 可导入的部分资产包 | 复用或快速验证选定资产 | 较低，可以直接导入 |

## 资产引用边界

部分资产包可能依赖关卡中已有的其他资产，例如：

- 节点图引用信号、变量或控件 ID；
- 节点图操作某个模型元件；
- UI 调用角色或实体上的节点图；
- 复合节点内部引用其他复合节点。

因此，“成功导出 GIA”不一定表示它能在任意关卡独立运行。每个资产包都需要记录：

- 包含哪些资产；
- 依赖哪些外部资产；
- 导入目标需要提前具备什么；
- 资产身份发生冲突时如何处理；
- 是否已经完成编辑器导入和游戏行为验证。
