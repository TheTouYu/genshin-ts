## 二、最近一次错误的完整调查链（#2 常量形态）

现象：编译 0 error，但我的 E0 断言脚本报 5 项失败，其中 `int:1207959581 期望≥3 实得=0` 看起来像
「技能变量槽常量没进图」——如果这是真的，Q1/Q4 探针整轮作废。

差分：定点 dump 该节点原始 pin →
`{"value": {"class":1, "alreadySetVal":true, "itemType":{"type_client":{"type":18}}, "bId":{"val":1207959581}}}`
即值**在**，只是键是 `bId`（type 18 = config_id）而不是 `bInt`。

根因：**常量在 decode JSON 里按 wire 类型分容器**（`bString`/`bFloat`/`bInt`/`bId`/`bEnum`/…），
我的断言脚本与仓库两个现成扫描器都只认前两三类 → 「形态漏分类 = 假报常量未落位」。

修复与扩展：见第四节同族扫描。回归：`analysis/20-e0-assert.py` 38 项 exit 0；
`gia-verify-pin.ts --vals 1207959581` 从 0 命中 → **3 命中（bId）**、`--vals 3132` → 1 命中（bEnum）。

## 三、为什么这类问题会反复出现——系统性根因（3 条）

1. **每个校验器各自"自选常量形态"，不抄权威表。**
   仓库早有完整形态表 `src/cli/variables_verify.ts` 的 `PAYLOAD_KEYS` / `CLIENT_PAYLOAD_BY_CLASS`
   （class 1=`bId`、6=`bEnum`、2=`bInt`…）。但 `tools/gia-verify-pin.ts` 与
   `references/decode-gia-constant-scan.py` 各自硬编码 `['bFloat','bInt']` /
   `('bString','bFloat','bInt','bLong','bDouble')` —— **同一个缺陷在两处独立存在**，
   我只在改技能捆绑脚本时撞上第一处，第二处靠同族扫描才发现。
   → 规律：**写任何"按 wire 键分类值"的新代码，先抄权威表**（已落技能 Step 3.6）。
   更彻底的做法是把扫描器收成一个共享模块（登记 O-2026-09-04-08，本波不做）。

2. **叙述（注释/票面/PROGRESS）容易跑在磁盘事实前面。**
   #1（写了没做的 attach）与 #9（旧证据配新代码）同根：我按"打算做什么"写"做了什么"。
   防线=**下笔前重跑对应只读命令**（`assets:mounts list` / `node-graphs read` / `sha256sum`），
   并让**证据文件与代码在同一次操作里重生成**（本轮 verify.txt 改为从当前实跑输出重建）。
   这与 AGENTS.md「铁证原则/三栏门禁」同源，但本轮暴露的是**写作时点**缺口而非结论缺口。

3. **断言脚本本身是"被测物"，失败要先归因三分。**
   本轮 5 项断言失败：4 项脚本 bug（#2/#3/#4/#5）+ 0 项图缺陷。若我"改断言让它通过"而不取证，
   门禁就变成了自证绿灯。有效姿势（本轮实证）=对每条失败**先 dump 原始 JSON 看真值在不在**，
   再判定「图错 / 脚本错 / 形态错」，最后才是改脚本。
   配套：**噪音甄别用对照实验**——找同形态的**已知良好样本**（`verify/inflow-index/`）跑同一命令，
   它同样报警 = 警告是工具的；它不报 = 我的图有问题。一轮定论，不动图、不占用户轮次。
