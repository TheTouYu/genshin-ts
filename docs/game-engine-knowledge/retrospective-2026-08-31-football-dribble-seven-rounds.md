## 二、最近一次错误的完整调查链（#6，方法论样本）

**有效的方法**：用户 A/B 对比提供精确症状清单 → 日志量化坐实 → 参考图当"解剖标本"提取配套件关系。**无效的路径**：#2/#3 两轮在没有参考图对照的情况下凭日志单点归因，把系统配套件当独立 bug 拆掉。

## 三、为什么反复出问题——系统性根因（3 条）

1. **移植不忠实且偏离无记录**：dribble-field.ts 自称"参考版逆向还原+复合化"，实际改了定时器语义（自重启 vs loop）、挂载（球 vs 玩家）、门控（状态机 vs 几何）、节流（删）——每个偏离单看都"有理由"，合起来摧毁了参考系统的控制拓扑。此后七轮全部在 debug 自己的改编。**规律：引用参考实现时，任何偏离必须显式列表+理由+验证等价性，否则不如不引。**
2. **运动器驱动实体的三条物理不变量未被当作设计约束**：①设备永不断供（断供=冻结）；②速度是带记忆的状态（记忆需配套限幅器：节流/几何门）；③反馈用实时几何（状态机门控引入延时与失效模式）。违反任意一条都会以不同症状爆发（#5 违反①、#2/#6 违反②、#5 延时部分违反③）。
3. **双权威无对账**：图变量运行态与实体位置都跨会话持久（存档层），架构假设"变量=唯一事实源"但引擎不让实体只当显示器（#4）。**规律：凡维护引擎权威值的副本变量，必须在安全边界（会话启动/静止期）对账。**
